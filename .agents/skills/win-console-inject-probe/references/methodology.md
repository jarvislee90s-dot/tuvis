## 已定案的宏观事实（破案时先对照，别重复劳动）

1. 控制台输入缓冲无界（官方文档 + conhost 两代源码 + ReactOS + E8 直证）——「缓冲满」不存在。
2. WriteConsoleInput 正常路径无 122；错误码必在客户端侧找（FFI 布局/参数错位/编码转换）。
3. M6「消费墙」三结论（首读预算 13~43 字符 / 122=缓冲满 / 再武装 30s~10min）均被推翻；旧「停摆」观测的真身候选 = 宿主文本选择模式冻结（写入成功、TUI 读不到、PostMessage 可解冻）。
4. 真实约束 = TUI 事件形态过滤（B 族丢 vk=0 控制字符、吃裸 ESC）+ busy 语义差异。

## 破案流程建议

1. 先复现故障现象（保持条件与报告者一致）；
2. E3 占用率曲线定故障类别（写入层/缓冲层/消费层）；
3. 按类别选实验：写入层→E2；缓冲层→E8；消费层→E1/E7/E12；
4. 版本升级后复验：只跑 P3/P4/P5 + 该族关键分支项（15 分钟级）。
