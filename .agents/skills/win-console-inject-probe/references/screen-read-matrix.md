# 屏读形态矩阵与四闸门（screen-read-matrix）

注入侧的镜像问题域：注入规格定案表回答「**怎么打进去**」，屏读形态矩阵回答「**读出来长什么样、解析器该产出什么**」。

确立背景（2026-10-02，claude 2.1.278 多选/多题验收事故）：实机屏面上单选子题**没有独立 Next/Submit 行**，而解析器只认该锚 → 整屏解析为 0 行 → 切题分类中止、卡片与终端脱钩，且中止文案误报为「读不到问答屏」。事故证明：解析判据的盲区**不是靠穷举屏形发现的**（O(∞)，工具一升级就作废），是靠闭环捕获的（O(1)，每次意外自带证据）。

## 四闸门（违反任意一道 = 该结论作废重做）

1. **样本门槛（事前）**：任何屏读解析判据的新增/修改，前置条件 = **活体 dump**（只读探针，零注入，见下节）。**禁止按取证档案手抄夹具**——手抄 = 翻译，翻译丢信息（本事故实证：fixtures 丢页签栏、丢单选子题形态，无机制拦截）。键序纪律（「全部新键序实机取证」）同样适用于屏形：**全部新屏形活体取证**。
2. **证据自带失败（事中，最重要）**：屏读类中止必须区分「**整窗读不到屏**」与「**屏在但形态不符**」两种文案；后者回执 + 审计附**屏面摘要**。目标：未知形态第一次出现就自带完整证据——发现成本从「验收失败 + 来回截图 + 猜」降到「看一条回执」。
3. **账本吸收文案漂移（事后）**：短锚文案进 `anchor_ledger`（append-only、候选全集试匹配、版本号只做诊断不做判据、evidence 字段禁止手造）。**边界**：结构判据（编号连续、收块方向、锚优先级）留在代码——账本 ≠ 整屏 dump ≠ 解析器，结构层盲区账本救不了。
4. **屏读体检表（验收前）**：镜像 M6R——只读探针对每个活会话跑**全解析器套件**，输出「哪些屏形认识 / 哪些不认识」清单；开发模式启动可自动跑。**验收前先体检，不允许带盲区上实机。**

## 三层漂移与对应机制

| 漂移层 | 实例 | 机制 |
|---|---|---|
| **字形族** | `☐` vs `[ ]`、`✔` vs `✓` vs `[✓]` | 语义判（勾选框内非空 = 已选，不硬编码字形）+ 账本候选全集试匹配 |
| **属性层** | active 页签的高亮是**颜色** | 字符读法（`ReadConsoleOutputCharacterW`）天然不可见 → **判据禁止依赖颜色**；用文本信号（题干区/焦点标记/页签签名）替代 |
| **结构层** | 单选子题无独立推进行；页签栏形态整块缺失 | 样本门槛 + 证据自带失败**发现** → 解析器锚扩展**吸收**（如锚从单一「推进行」扩为「推进行 ∨ 页签栏」） |

编码层（UTF-16 cell 读取 + lossy 转换）实测稳定，不是漂移源——「编码解决不了」的直觉指向的其实是上面三层。

## 屏读探针模式（只读、零注入）

- **形态**：`#[ignore]` lib 测试 + 环境变量传 pid（`MAM_PROBE_PID`）；链路 = 生产同款 `inject::windows_console::read_screen_window(pid)`；输出 = 逐行 dump（带行号）+ **全解析器产物**（`parse_question_rows` / `submit_row_present` / `probe_review_screen` / `advance_stage_screen_ready` 等）。
- **用法**：`MAM_PROBE_PID=<pid> cargo test --lib screen_read_probe -- --ignored --nocapture`；pid 用 `Get-CimInstance Win32_Process` 找目标 CLI 进程。
- **只读保证**：不碰 CONIN$、不发任何键——对活体会话零风险（与注入侧 P0–P7 的本质区别）。
- **纪律继承**：八条铁律 #5（dump 逐字落档）/ #8（结论不得超过证据）逐字适用。
- **缺永久探针时**：可按本节规格写临时探针测试（用完还原），但**定案表入档前必须先落永久探针**——探针本身是矩阵的维护工具。

## 屏读形态定案表模板（逐 工具 × 版本 × 屏形）

主键 = `(tool, version, 屏形名)`。字段：

| 字段 | 说明 |
|---|---|
| **整屏 dump** | 逐字（含空行），证据出处 = dump 文件 / 截图 / 探针日期，**禁止手造** |
| **锚判据** | 解析靠哪些行（独立推进行 / 页签栏复合签名 / footer / 题干区），列全特征清单 |
| **解析期望输出** | rows 逐行 kind / number / checked / focused（与测试夹具断言一一对应） |
| **按键路径** | 每个动作的键序 + 发前定位/发后核验点（引用注入规格定案表对应族） |
| **已知边界** | 该屏形上不可达的动作及原因（如：单选子题无 Next → 「切换到下一题」按键路径不存在） |

判定：**已识别**（解析 + 按键全通）/ **部分识别**（解析通、按键缺）/ **盲区**（解析不出）。归档与注入定案表同处：`docs/research/refs/phase2-消息注入/`（本地不入库），派生夹具随库入库。

## 维护触发点（任一触发即复验 / 补档）

1. **工具大版本升级**——与注入规格复验同一条纪律、同一批次做（AGENTS.md 触发③）。
2. **任何一次屏读类中止回执**（闸门 2 送的货）——比对矩阵：认识 → 按既有行处置；不认识 → 新增一行 + 解析器处置决策。
3. **用户报告**屏面与卡片不符。

## 三批补记（2026-10-08，claude 2.1.287 单题集·单页签——0.5.1 报障闭环）

**事故**：0.5.1 用户实机报「中止于定位选项行并切勾：屏上解析不出问答选项块——已中止，未发任何键」。根因 = **单问题集** AskUserQuestion 的页签栏是**单页签形态 ` ☐ Deploy`**（无 `←`/`→`、无 `✔ Submit`），既有双锚（推进行 ∨ 复合页签栏三特征）全不命中 → 解析 0 行 → 发前安全中止。0.5.0「能选」的旧例全是**多题集**（页签带 Submit 命中锚 B）——非版本回归（v0.5.0↔v0.5.1 该链路代码零差异），是屏形盲区首次被踩中。

### (codex, 0.160.0, 问答面板·按键路径) —— 已活体补档（注入形态见注入规格定案表）

| 键 | 语义 | 证据 |
|---|---|---|
| 数字 `1..9`（`-Char`） | **选中 + 推进原子**（未答题上选中该序号项 + 自动跳下一题 + 计数 −1）；**末题上 ≡ 选中 + 整卷提交（无确认）→ 末题编排禁用数字** | 底料 A/#1 定案 |
| 空格（`-Char ' '`） | toggle：仅选中焦点行（不推进）；再按 = **反选**（计数 +1）；已答题上按非已选焦点行 = 替换旧选（单选互斥） | 底料 C/#5 定案 |
| j/k（`-Vk 0x4A/0x4B` 或 `-Char`） | 选项上下走位，**双向环绕**（末项 j 回首项、首项 k 到末项）——**走位主通道** | 底料 §1 vim 键位新发现 |
| h/l（`-Vk 0x48/0x4C` 或 `-Char`） | 上一题/下一题，**环形**（含未答完可跳题）；单题上无效果（footer 无导航段一致） | 底料 §1 + §3 |
| tab（`-Char '\t'`） | **复合键**：选中焦点行（ensure）+ 开 notes 输入态——任意行可用（非 Other 行专属） | 底料 §6 tab ensure 定案 |
| Enter（`-EnterVK`） | 提交整卷（已答状态）；末题含未答题 = **无提示直接交卷**（确认屏未复现）；notes 态回车 = 连带整卷提交 | 底料 A/H + §6-A |
| esc | **取消语义不可达**：孤立 0x1B 无效；`-Vk 0x1B -Scan 0x01` = **中断整个回答回合**（`■ Conversation interrupted - use /feedback if something went wrong`）——MAM「中止」按钮可用通道，**绝不能当取消键** | 底料 §5 esc 定案 |
| VT 箭头 / 真 VK 箭头 | **全部无效**（屏面零变化）——codex TUI 对箭头族免疫（VT 序列与孤立 ESC 同族免疫） | 底料 §1 方向键两行 |

**⚠ 本节对解析/编排的最重要输出**：面板内导航可用通道 = 数字 + 空格 + tab + EnterVK + vim h/j/k/l；**箭头族不可用**——任何依赖 ↓/↑/←/→ 的键序设计对 codex 0.160.0 无效。

### (codex, 0.160.0, 问答面板·已知边界汇总)

1. **notes 文本不随卷提交**（0.160.0 取证回填，底料 §5）：notes 态打字后回车，摘要 `answer` 落在**焦点行**（打字后焦点跳回第 1 项），用户文本静默丢失——`free_text_supported("codex")` = false，远程自由作答停用（具名中止 `CodexFreeTextRetired`：「请在终端作答」）；**验收批 F1 对照**：验收批 notes 态回车摘要出现 `note: ...` 行（本形态未复现，可能焦点宿主差异）——两批合读不定案，「notes 文本去向 + notes 态回车交卷事件」登记为版本复验触发点；零注入具名中止在两种解读下都安全；
2. **首帧 `?` 形不可达**：200ms 连拍首帧即 `›` 形——判据只认 `›`，无 `?` 分支；
3. **滚回区不可见**：`read_screen_window` 只读可见窗，交卷后面板整体消失、可见窗干净——滚回残留误判的实测面 = 0（解析器 last-pair-wins 仍保留为防御）；
4. **E 实验宽度不够真折行未测出**：120 列下 63 字符 label 单行放下（desc 列浮动右移）——屏幕更窄时的折行行为无证据，不得假设；
5. **状态栏行插入变体**：`deepseek-... · ... Plan mode` 行可插在选项区和 footer 之间（屏高富余时）——解析须容忍（夹具 `codex_s2_q1` 在档）；
6. **确认屏未复现** + esc 取消不可达：未答完提交 = 焦点项直接交卷（用户侧警示，见手工验收清单）；
7. **已选项空格消歧**（验收批 b5 对照，底料 §3 #5 补注）：底料批「焦点在非已选项时空格 = 反选旧选中（计数 +1）」dump 铁证；验收批「焦点在已选项本身时空格」计数未重现（`b5-space-toggle-probe.txt`）——两焦点位置行为可能不同形，**单次空格在两种形态下都不是原子换选**；编排按「已答 ∧ 焦点≠目标 → 零键中止」实现（P1-2），登记为版本复验触发点。
