# 桌面四页导航与输出速度 V2 设计

> 状态：按用户最新裁决定稿，进入实施计划。深色采用冷石墨底与靛蓝/紫罗兰强调（2026-10-27 实机反馈修订），浅色采用纯白底与原蓝紫强调，轻玻璃仅用于导航和浮层。
> 日期：2026-10-26。产品代码基线：`codex/tps-sampling@6b9fc9b5`。
> 上位依据：`docs/MASTER-PLAN.md`。视觉参考：[交互草图](../mockups/2026-10-26-desktop-workspace-v2.html)，其中数值均为演示数据。

## 1. 本轮交付

- 主窗口同窗切换：消息看板、工具资源、模型用量、输出速度。
- 四页统一标题与桌面主题；模型用量保留原排版、折线、分区、内部页签和既有功能。
- 输出速度提供“流式输出”及“响应吞吐（含等待）”，范围汇总和曲线可切换；六个原生来源接入两种观测，Codex接入日志近似的含等待响应吞吐。
- 输出速度使用组合列表、区间四指标、大图、悬停/固定读数及二级采集管理。
- WorkBuddy兼容真实数值字符串，并有界恢复被旧解析器跳过的近期记录。
- 主题统一限定共享样式层与必要可读性修正，保留现有基本布局。移动端、桌宠素材/透明背景和分享图固定版式维持独立。

## 2. 导航、窗口与状态

1. 四个一级页面固定同序，首次启动落消息看板，窗口显示/隐藏不改变当前页面。
2. 设置维持现有独立入口与设置窗口，不占四页。全局偏好归设置，资源安装/启用/配置等具体工作归工具资源。速度页接入管理和设置的采集管理共用同一组件、命令与配置状态。
3. 原标题栏用量入口指向模型用量页签。桌宠、托盘、迷你用量条“详情”等入口统一显示/聚焦主窗口并选中模型用量；不再创建独立usage-dashboard窗口。
4. `/usage`等旧入口保留兼容跳转。跨窗口目标在主窗口监听就绪前到达时，暂存最新目标，不能只依赖一次广播。
5. 提取现有用量页面主体，避免嵌套WindowFrame或重复标题栏。消息看板、工具资源的基本布局和操作流程保留。
6. 本次运行中各页范围、筛选、折叠和滚动位置独立保留；切页不重置。速度首次默认近5h，与用量范围独立；重启不恢复悬停/固定读数。
7. 会话监控、通知和后台采集驻留应用层，切页不停止。离开速度页或窗口隐藏后交还视图租约并停止前端轮询。
8. 支持现有800×600主窗口和宽窗，不强制重置用户窗口尺寸。窄窗把组合列表以紧凑排名表置于详情下方（限高滚动）、指标用2×2排列；宽窗为左列表、右详情。允许页面纵向滚动。

## 3. 桌面视觉

### 3.1 色彩与层次

浅色使用纯白底和原有蓝紫强调，深色采用冷石墨底加靛蓝/紫罗兰强调；不使用黄/青/绿染色作为大面积底色。轻玻璃仅调整导航和浮层材质，保留基本布局与内容对比。颜色方案在本轮固定，实施期间不扩成配色探索。

| 层级          | 浅色    | 深色    |
| ------------- | ------- | ------- |
| 页面/窗口背景 | #FFFFFF | #1B1C20 |
| 内容面板      | #FFFFFF | #242630 |
| 输入/次级面   | #F8F9FC | #1F2128 |
| 边界          | #D9DEE9 | #454854 |
| 主文字        | #202735 | #F0F0F0 |
| 次文字        | #626D80 | #B8BCC8 |
| 强调/主图线   | #4263DC | #8B95FF |
| 辅图/渐变端   | #8B5CF6 | #B49CFF |
| 选中背景      | #EEF1FF | #2C2F45 |

2026-10-27 实机反馈修订：深色由雾银纯灰改为冷石墨底 + 靛蓝/紫罗兰强调（对比主流深色主题的「微冷底 + 有彩强调 + 语义点缀」模式）；浅色列不变。同日二次修订：浅/深「边界」与输入描边（--input）加深（浅 #D9DEE9 / #CDD3E0，深 #454854 / #4A4E5C）——outline 按钮与输入框边缘在白底/深底上均清晰可辨。

状态色和工具品牌色按语义保留，不把深色改版理解为抹去成功/警示/故障区别。

全部映射到语义变量，不在业务组件散落色值。正文和控件主要文字13–14px、次要说明至少12px；图轴和短单位可较小但必须实机可读。普通文本对背景至少4.5:1，选中与焦点不只靠颜色区别。沿用system/light/dark设置及跨窗口同步。

### 3.2 材质

内容区、指标、表格和图表保持稳定平面。2026-10-27 实机反馈修订：弹窗（Dialog）由轻玻璃改实心卡面——backdrop-filter 的合成层在高分屏下整层栅格化发软（用户实测弹窗文字模糊），玻璃保留于导航/下拉等小面浮层。导航和采集管理浮层采用克制的高不透明度轻玻璃：轻微背景模糊、细边界和内侧高光，不叠加多层玻璃，不模糊数字/曲线，不增加自动流光或折射动效。

Tauri WebView以CSS材质实现跨平台近似，不引入原生Liquid Glass依赖。无法使用背景模糊、系统要求减少透明度或效果影响文字可读时使用同色实心面；减少动态效果时关闭装饰过渡。

### 3.3 实施范围

调整桌面主题变量、WindowFrame/页面标题、导航及按钮/输入/选择/卡片/弹层的必要共用样式，修正会话卡和资源区显著对比度例外。保留业务字段、资源双视图、状态语义和操作流程。桌面样式入口为src/index.css，移动端src/mobile/mobile.css不改；桌宠透明面和分享导出单独验收。

## 4. 模型用量

保留A总览、B趋势、C分布、D API等效费用、E工作活动及记录页的原顺序、筛选、折叠、价格/渠道管理、导出和计算口径，只移走TPS区块并接入主窗口。

用量趋势继续折线；查询返回0的日期/时间桶绘制为0。加载失败、来源不可用和未知值不能被补成0。输出速度范围/指标切换不触发Token或费用重算。

## 5. 两种速度观测

### 5.1 名称与计算

| 模式     | 一级名称/单位                | 单次记录                                 | 区间与时间桶                      |
| -------- | ---------------------------- | ---------------------------------------- | --------------------------------- |
| stream   | 流式输出速度 / TPS           | 输出Token ÷ 首个有效输出至生成完成的秒数 | 1000×Σ流式有效输出Token÷Σ生成毫秒 |
| response | 响应吞吐（含等待） / Token/s | 输出Token ÷ 对应响应的含等待秒数         | 1000×Σ响应有效输出Token÷Σ响应毫秒 |

响应分母包含首Token等待及该来源边界内的准备/排队开销，排除响应结束后的工具执行。六个来源优先使用同调用原生完整时长或已验证起止；完整时长已经含等待时不能再加一次TTFT。Codex使用日志输入/生成边界近似，一级显著标注“含等待 · 日志近似”。两者都属于端侧观测，不称服务器纯解码基准。

两种观测独立判定有效性、维护各自分子/分母/样本数。共同要求成功、正输出、正时长及同调用对齐；失败、取消、无法对齐的重试不入速度。缺F但完整响应窗可靠的记录可以只入response。输出已含思考时不再相加；计数含义沿用各源已验证范围。

### 5.2 来源能力

| 来源          | 流式输出           | 含等待响应           | 计时说明                                                                   |
| ------------- | ------------------ | -------------------- | -------------------------------------------------------------------------- |
| DSH           | 支持有效子集       | 支持有效子集         | 同模型step开始至消息结算；重试不能对齐则跳过                               |
| ZCode         | 支持有F的调用      | 支持可靠原生完整调用 | start/completed或可靠native duration，不含后续工具执行                     |
| Kimi          | 支持原生有效子集   | 支持同step完整时长   | 原生latency与stream duration的同事件组合；保留内部重试限制                 |
| WorkBuddy Mac | 修复兼容后支持     | 修复兼容后支持       | qua.end的total_cost_ms；Windows无数值usage路线仍缺证据                     |
| Claude        | 原生近似           | 支持有效span         | first_content为块开始近似；完整span duration含等待；已识别重试不对齐则跳过 |
| OpenCode      | 观察插件支持的宿主 | 支持完整step窗的宿主 | 同session/message/step身份，不用跨工具消息墙钟代替                         |
| Codex         | 暂缺               | 日志近似支持有效子集 | 使用原生响应ID/输出与局部日志边界，不使用整轮duration−TTFT                 |

“支持”指具备计算路径，不表示每条记录都齐全。每个来源返回两项capability及缺失原因；来源整体已接入不能等同于两种速度都可得。

### 5.3 切换与四指标

页面默认偏好stream。六个来源可切stream/response；选择仅有response能力的Codex时，实际视图临时显示response并显著标明，流式按钮禁用并说明缺口。用户显式选择的偏好另存，切回支持该偏好的组合时恢复；显式选择response后可在七来源间统一观察response。

切换同时更新列表速度列、排序依据、主数字名称/单位、图表纵轴、有效n及详情。不能在“流式TPS”标题下混放Codex响应数字，不清空另一模式的事实或重新触发采集。范围与选中组合保持，解除悬停固定。

四格为：当前模式速度、首Token平均等待、累计用时、工具累计用时。TTFT独立平均成功且首点可对齐的记录；Codex尚无可靠逐响应TTFT，显示—，回合TTFT不充当该值。六源累计用时显示可靠模型用时，Codex显示“响应累计用时”并由日志近似标记限定。累计用时覆盖同范围内有可靠时间的候选，含可计时失败/取消；速度分母只取各自成功有效子集，两者不强行相等，独立计数在详情说明。

工具用时仅累计能可靠归属当前series/调用的值，不能拿全工具工作活动时长冒充。当前tool_ms普遍为空，保持—；原模型用量工作活动继续提供原全工具统计。没有当前模式速度但其他指标可靠时，其他格仍独立显示。

## 6. Codex响应观测接入

### 6.1 已有入口

本机GPT订阅日志存在token_usage_record的response_id及整数usage.output_tokens，并有task_started、turn_context、response_item输入/生成/工具返回等边界。依据见[只读结构核对](../evidence/2026-10-26-codex-response-observation.md)。首版仅对这些可恢复的原生结构产生response观测；缺结构的旧日志返回不足，不要求用户改模型、API地址、认证或网关。

### 6.2 同响应关联与窗口

1. 以原生response_id作为稳定调用键，同一宿主跨文件/复制历史只计一次；session/turn/model取原生身份和对应上下文，不用当前配置补历史。
2. 首个响应从该回合最近有效输入/上下文边界开始；后续响应从上一响应封口之后最后一组匹配工具返回或有效输入开始。结束为本次最后模型生成项，不取工具输出或task_complete作响应结束。
3. native token_usage_record提供输出与封口身份；伴随token_count只作对账，不再次发射观察。原生用量与生成项先后有延迟时保存未决状态，边界对齐后才提交。
4. 只接受能区分响应与工具阶段的闭合片段。工具/生成交错、输入边界含义不明、失败/取消或重试无法归属、缺model或响应身份时诊断跳过；不用整轮耗时补洞。回合之后取消，不撤销此前已经可靠结算的成功模型响应。
5. generation_ms与first_token_at_ms保持缺失；response_elapsed_ms保存日志窗口，timing method标log-boundary-approx。不能从完整生成项落盘时刻推造首Token，也不写入native_duration_ms伪装原生测量。
6. 首版支持已核对的JSONL原生profile，按字段能力检查并记录宿主版本。未知/压缩形态无对应既有读取器支持时明确降级；不改安装包或为读数启动另一套Codex/模型进程。

没有attempt字段不等于证明零重试。明确观测到重试/错误而无法定位成功片段时排除；不可见内部重试属于日志近似限制，保留说明。完整生成结束与原生用量封口支持“已完成响应”的判定，失败/取消的未闭合片段不据此补成成功。

### 6.3 增量、恢复与预算

沿用现有工具数据根定位和已配置根，测试显式传影子home。只读新增并保存逐文件字节位置与未决边界，单批最多200观察，读取/解析资源有源级预算；不因新模式每5秒全读会话库。

首次从近期文件有界定位最新完整边界；从截断窗口进入的首条不完整响应跳过，不能将读取起点当请求起点。可用原生元数据完成去重与模型归属后才发射事实。只保存ID摘要、计数、时刻、方法与诊断，不保存prompt、reasoning或工具正文。

新增Codex采集游标版本，旧“不提供流式TPS”占位游标不解释成新的文件位置。事实、未决进度和版本同事务成功后推进。回归包含主/子代理、重复事件、复制历史、工具返回、多响应、取消、不完整尾行和失败不推进。

## 7. 区间、分桶与存储

| 档位            | 每桶时长 | 主要桶数 |
| --------------- | -------- | -------- |
| 近15分钟        | 1分钟    | 约15     |
| 近1小时        | 5分钟    | 约12     |
| 近5小时（默认） | 10分钟   | 约30     |
| 近24小时        | 1小时    | 约24     |

滚动范围按本地墙钟对齐桶，完成时刻归属互不重叠的(from,to]，首尾裁剪。边缘部分桶最多额外增加1个，返回实际起止/isPartialBucket；不向范围外捞数据补满桶。

基于tps_observation的稳定事实去重，series保留tool/model/channel/method。区间与各桶分别聚合其中已采集有效调用，两个速度都不设最近20条截断，不求区间全量覆盖。不合并不同模型/方法为一个总速度，不平均每请求速度或旧滚动点；同调用出现在多个旧点也只计一次。

主任务视图排除已识别辅助标题/自动摘要；失败、取消、缺计时保留候选计数以供详情。两个速度n和TTFT n独立；图底条仅表达当前模式有/无样本，不称完整监控覆盖率。部分桶仅表示范围边缘未满，不表示已证明采集覆盖。

原始数值事实保留24h，查询聚合，不提前物理降精度、不把平均值当原始样本。区间有有效记录即展示，不因模型空闲10分钟清空；最近记录年龄作为中性提示。生成中的精确瞬时速度不在交付范围。

保留usage.enabled总授权、可见5秒有界读取、后台600秒读取、租约与单飞。新页面可见时5秒刷新同一事实快照；展示桶宽不是采集间隔。旧tps_point保留诊断用途，不相加为V2区间值，也不伪造退出期的实时拍点。

## 8. 速度界面与来源管理

1. 左组合列表、右单图与四指标。工具筛选；点列表表头按组合名/当前模式速度/有依据的会话数排序，可升序或降序；默认组合名升序（工具→模型→渠道稳定序），速度与会话数默认降序，无数值一律排末；宽窗左列吸顶自滚、整页只滚一处（图表上下完整可见），窄窗列表以紧凑排名表置于详情下方。
2. 同series跨会话汇总，显示有依据的会话数，不称当前打开窗口数。原生近似/日志近似保留短标记；方法、思考范围、分母、失败计数和诊断进入详情。
3. 默认四格为选中区间汇总。悬停桶显示细竖线、实际起止/桶宽/n并切换四格；空桶不推算速度。移开恢复汇总，点击固定该次读数快照；Esc、返回汇总或切换范围/组合/模式解除固定。键盘和点击可操作。
4. 纵轴从0开始，有数值与当前模式单位；横轴按完整范围/宽度独立排布，一般4–7标签，不用挤在样本位置的首/中/末三个时刻。
5. 缺口用阴影；实测线断开，独立灰虚线只作视觉连接，无样本/无数值，不参与悬停插值。短图例说明“虚线仅连接，无样本”，支持严格断开显示样式。
6. 来源一级只显示名称、接入状态、指标能力与动作。已接入/待配置/待重启/待检查按真实状态显示；Codex可为“已接入 · 仅响应”，不能继续把它整体标为不支持。已安装事实决定卸载入口，卸载后保留历史也可重装。
7. 接入引导为点击设置、必要时原生同意、下次启动生效。Tuvis不主动重启Harness。详情才显示版本、路径、字段与脱敏诊断；Mac界面不默认堆放Windows缺口长文。

来源有效记录计数按任一已支持观测判定，不能只调用旧的流式is_tps_valid而把Codex的响应样本归为无数据。具体模式的缺口归入该指标原因，不抹去另一项可用观测；无区间记录是数据空态，不自动等于采集故障。

## 9. WorkBuddy修复

已核对的17条Mac5.8.3 qua.end，其total_cost_ms/ttft_ms/completion_tokens均为整数字符串，身份和成功收尾完整，model_error为空。统一数字归一接受范围内JSON整数与合法十进制整数字符串，拒绝空值、布尔、非整数、NaN/Infinity和溢出并诊断，不默认0、不经浮点中转Token。

同一条记录同时构造生成时间=total−ttft和响应时间=total。例如输出339、total=6711ms、ttft=1402ms：流式约63.85 TPS，响应约50.51 Token/s。终态、身份、重试和时间合理性继续独立校验；保持本机AM/PM和已有RFC3339时间解析。

WorkBuddy旧TPS游标可能已越过错误记录，必须以版本标记触发一次有界24h恢复，分批保存进度、稳定键UPSERT，事实与游标同事务。只恢复TPS数据，不重置其他来源或旧Token/费用游标；恢复完成后不反复全读。覆盖旧EOF、重复已有事实、中途失败与恢复后只读新增。
