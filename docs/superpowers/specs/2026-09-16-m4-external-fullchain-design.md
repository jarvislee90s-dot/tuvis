## 1. 目标与范围

M4 是一期收尾里程碑：把 M2/M3 已在局域网验证的能力推到**外网全链路**——固定地址接入、新设备配对管控、远程期间不失联。M4 验收全绿即宪法一期验收达成。

**交付五组（T0–T4，顺序固定，前置清账先行——外网开放前必须补齐安全卫生项）**：

| # | 交付 | 来源 |
|---|---|---|
| T0 | 前置清账：SSE 连接即时断开 + TLS 确认撤回文案 | M3 评审遗留（2026-09-16 并入裁决） |
| T1 | 外部通道：命名隧道（主路径）+ 临时隧道 + cloudflared 获取 + Tailscale 指引（2026-09-17 撤销，见 §12.2）（SSE 心跳 M3 已内建，见 T1e） | v6 P7 / B4 |
| T2 | 审批配对 + 设备花名册 | v6 P6 / B2 后半 |
| T3 | 电源保活 | v6 P11 / B5（宪法 D13） |
| T4 | 托盘远程入口 | v6 F1.1 双入口的另一半 |

**M4 不做（边界，非选项）**：系统级推送网关（ntfy/Bark，随 D17 移二期与 APK 壳同期交付）；移动端构建分包（manualChunks，二期套壳期）；任何写操作（宪法一期边界不变）；多用户账号体系。

## 2. T0 · 前置清账

### T0a · SSE 连接即时断开

- **需求**：设备被吊销或「停止远程」后，已建立的实时连接立即断开——不能只是拒绝新连接（M3 已知限制：吊销后旧连接存续期内仍收事件）。
- **输入**：吊销动作（单设备吊销 / 全部吊销 / 停止远程）。
- **输出与效果**：服务端维护「设备 → 活跃实时连接」对应关系；吊销时精准断开目标设备的全部实时连接；设备侧断连后自动重连被拒（403），走既有「回配对页」链路。吊销生效时效从「连接存续期内」收紧为**即时**。
- **边界**：只断已吊销设备的连接，其他在线设备不受影响；连接断开后即清理注册信息，不留句柄泄漏。

### T0b · TLS 确认撤回文案（M2 终审留办）

> **2026-09-17 裁决（§12.1）**：确认入口改为开启动作内一次性 Dialog，常驻复选框退场；本条「一次性且不可在线撤回」的语义与存储不变。以下为原文。

- **需求**：对外绑定前的「已具备加密前置」确认是一次性且不可在线撤回的，界面必须如实表达。
- **输入**：用户取消勾选确认复选框。
- **输出与效果**：复选框回弹为已勾选（不可取消），提示「安全确认不可在线撤回，如需撤销请改绑本机模式」；复选框旁常驻说明文案。
- **边界**：不改确认的存储语义（确认一旦置位持续生效）。

## 3. T1 · 外部通道（隧道）

### T1a · 通道区块（形态定死）

- **需求**：设置页新增「外部通道」区块，与「绑定」（127.0.0.1 / 0.0.0.0 + TLS 确认门）**独立并存**（2026-09-16 用户裁决）。
- **输入**：通道选择（关闭 / 临时隧道 / 命名隧道）。
- **输出与效果**：隧道始终连接本机回环端口，与绑定模式互不干扰——局域网直连与外网隧道可同时使用（在家走局域网、在外走隧道）。通道开启时，设置页地址区块**首条插入隧道地址**（网卡名一栏标注「外部通道」，固定子域或临时地址），二维码随隧道地址生成；其余局域网候选照旧逐条展示（沿用 M3 终审轮的单区块逐条结构）；通道关闭时地址区块回到现状。M2/M3 已实测的绑定 + TLS 门与地址区块语义零改动。
- **边界**：隧道不是绕过 TLS 门的途径——对外暴露面由通道侧加密（Cloudflare 终止 TLS），本地仍走回环；绑定 0.0.0.0 的 TLS 确认门照旧独立生效。

### T1b · 命名隧道（用户主路径）

> **2026-09-17 裁决（§12.3）**：空 Token 选 named 不再被后端拒绝挡死——前端本地展开 Token 待切换面板与三步引导，后端空 Token 拒绝保留为兜底。以下为原文。

- **需求**：填入 Cloudflare Tunnel Token 即得固定接入地址；双机双子域（mam-mac / mam-win 命名模式，域名细节见私有摘选文档）各自独立配置。
- **输入**：设置页粘贴 Tunnel Token（持久化保存）。
- **输出与效果**：远程开启且通道选命名 → 自动拉起 cloudflared（tunnel run 模式）接入本机服务；固定地址即刻可访问（部署方式与用户既有同款隧道部署一致）；进程异常退出自动重启（指数退避；连续失败 3 次即停止并桌面通知报错）；停止远程或切换通道 → 进程一并退出。
- **边界**：Token 存本机应用数据库（与配对设备表同库）；双机各填各的 Token，无任何跨机联动；cloudflared 自身的网络闪断重连之上叠加进程级守护，两层自愈。

### T1c · 临时隧道

- **需求**：零配置拉起 Cloudflare 免费隧道，扫码即用。
- **输入**：通道选临时隧道。
- **输出与效果**：自动拉起 cloudflared（quick tunnel 模式）；解析其分配的临时地址 → 设置页展示 + 二维码（含配对 token 的完整接入地址）+ 桌面通知；地址随重启变化，解析到新地址即通知。
- **边界**：临时地址不持久、不写入配置；隧道进程守护与命名隧道同一套。

### T1d · cloudflared 获取

> **2026-09-17 裁决（§12.5）**：下载加固——系统代理恢复、版本固定 2026.9.1 + 五平台 sha256 校验、官方 + 双镜像回退、超时与完整失败指引；升级 = 改常量 + 重取 sha256 表。以下为原文。

- **需求**：首次启用隧道时自动获取 cloudflared 程序。
- **输入**：首次启用动作；当前平台与架构。
- **输出与效果**：自动从官方发布渠道下载对应平台/架构的二进制到应用数据目录（`~/.mam/bin/`），校验可执行后使用；下载失败 → 设置页给出手动放置指引（放入同一路径即可，不阻塞其他功能）。
- **边界**：不做版本管理与自动升级（cloudflared 自更新关闭）；下载源固定官方渠道。

### T1e · SSE 实时流心跳（M3 已内建，无新增交付）

- **事实**：M3 的实时通道已启用框架自带空闲保活（默认 15 秒注释帧），对 Cloudflare 约 100 秒空闲超时断连的防穿透已覆盖（2026-09-16 rebase 复核确认）。
- **输出与效果**：M4 不做新开发，仅在外网验收中确认——看板页面空闲数分钟不被中间层断连（验收 2 附带项）。
- **边界**：心跳在服务端连接层发送，与状态扫描节奏（零订阅者免扫描）互不影响（M3 既有行为）。

### T1f · Tailscale 指引

> **2026-09-17 裁决：本项撤销（§12.2）**——指引文案已移除（受众过窄）。以下为原文存档。

- **输出与效果**：设置页帮助区给出 Tailscale 用户接入指引文案（链接 + 步骤说明），不写任何代码。
- **边界**：四通道模式（直连 / 临时 / 命名 / Tailscale）共用同一套配对与安全语义（v6 P7 既定）。

## 4. T2 · 审批配对 + 设备花名册

### T2a · 请求接入流

- **需求**：新设备（未配对）打开接入地址，看到「请求接入」页而非死路。
- **输入**：新设备访问；设备名（自动取浏览器标识，可修改）。
- **输出与效果**：页面发起接入请求 → 桌面 MAM 弹系统通知（点击直达配对面板）+ 配对面板出现待审批项（设备名 / 来源 IP / 浏览器标识 / 剩余有效时间）；请求 5 分钟内有效，过期自动消失；待审批队列并发上限 3，同一来源 IP 同时仅 1 个待审批请求，超限提示稍后再试。
- **边界**：请求页对未配对设备可见，但不暴露任何会话数据；请求只在内存队列（重启即清，不落库）。

### T2b · 双批准路径

- **需求**：批准方式两种，等效授权（v6 P6 既定）。
- **输入**：桌面用户操作 / 手机输入确认码。
- **输出与效果**：
  - **路径一 · 桌面批准**：待审批项点「批准」→ 设备侧数秒内拿到凭证进入看板；
  - **路径二 · 4 位确认码**：待审批项**自动显示** 4 位确认码，手机在请求页输入该码即等效授权；单请求限试 3 次，错满 3 次请求作废需重新发起。
- **边界**：两路径先到先得（一条路径生效后请求即消费）；批准/作废均从队列移除并留痕。

### T2c · 设备上限（全配对入口统一强制）

- **需求**：设备上限默认 3 台（设置可改），满员需手动腾位（v6 P6）。
- **输入**：任意配对入口的新设备授权动作（桌面批准 / 4 位码 / 直通扫码）。
- **输出与效果**：已达上限时——审批路径「批准」按钮禁用并提示去花名册腾位；4 位码输入返回「设备已满」；直通扫码拒绝并回「设备已满」。**三个入口同一道门**（设计自审修正：若仅审批路径设限，直通扫码可绕过上限）。
- **边界**：上限按「有效设备」（未吊销）计数；吊销即腾位。

### T2d · 设备花名册

- **需求**：设置页可视化管理已配对设备。
- **输入**：花名册面板操作。
- **输出与效果**：设备列表——名称 / 配对时间 / 最近活跃时间 / **在线状态点**；单设备吊销（吊销后按 T0a 即时断连）；全部吊销；上限配置项。在线口径 = **存在活跃实时连接 或 最近 30 秒内有过闸记录**（设计自审修正：纯实时连接的设备不再发轮询请求，仅看过闸时间会误判离线）。
- **边界**：花名册只展示设备元数据，不含任何会话内容。

### T2e · 审计留痕

- **输出与效果**：配对请求 / 批准 / 4 位码失败 / 吊销 / 停止，逐条留痕（时间、设备、来源 IP、动作、结果），日志可追溯。
- **边界**：留痕只在本机，不外发。

### 直通配对（M2 已交付，M4 不动其语义）

一次性二维码临时分享保持现状，仅叠加 T2c 的上限门。

## 5. T3 · 电源保活

- **需求**：远程开启期间电脑不得休眠失联（宪法 D13）。
- **输入**：远程开关状态；保活开关（设置页，默认开）。
- **输出与效果**：远程开启且保活开 → 持有系统电源锁（阻止系统空闲睡眠与磁盘休眠，**屏幕可熄**）；远程关闭或应用退出 → 释放。Windows 侧：代设硬盘休眠为「永不」，代设前先保存原值，关闭远程时**还原原值**。
- **边界（界面明示）**：macOS 合盖仍会休眠（系统限制）；macOS 系统睡眠锁在电池模式下不完整生效（接电源才完整）、Windows 临界电量强制睡眠不可阻止——两条边界文案写入设置页。
- **边界**：保活跟随远程开关，不提供「保活但远程关」的独立状态。

## 6. T4 · 托盘远程入口

- **需求**：远程开关双入口的托盘一半（v6 F1.1）。
- **输入**：托盘菜单点击。
- **输出与效果**：托盘菜单新增「远程接入」开关项（勾选态 = 当前远程状态，与设置页同一状态源、同一开关链路）；下方常驻展示当前对外地址（通道开启时为隧道地址，否则为绑定口径地址），点击复制；开关失败（如 0.0.0.0 未过 TLS 确认门）→ 勾选态回弹 + 桌面通知报错。
- **边界**：托盘仅开关与地址展示，不放配对面板（配对管理仍在设置页）。

## 8. 非功能需求

- **安全**：吊销即时生效（T0a）；配对三入口统一上限门（T2c）；通道不弱化 TLS 确认门（T1a）；配对动作全程留痕（T2e）。
- **性能**：隧道不劣化既有 2 秒实时口径（空闲保活 M3 已内建）。
- **可靠性**：cloudflared 两层自愈；地址变化通知；应用退出清理子进程与电源锁（不留孤儿进程、不失电源锁）。
- **兼容**：M2/M3 全部已实测行为零回归（绑定 / TLS 门 / 直通配对 / SSE / 降级轮询 / 看板 UI / 会话内容与文件预览）。

## 9. 验收清单（M4 出口 = 宪法一期验收）

外网真机（手机蜂窝网络，非局域网）：

1. **固定地址接入**：手机蜂窝网络访问固定子域 → 看板与任意会话内容可用（T1b）。
2. **实时提醒**：页面开着，桌面杀掉一个 agent 会话 → 手机 2 秒内横幅 + 提醒音（外网环境复验 M3 口径，D17：页面开时 SSE）；附带验证页面空闲数分钟不断连（内建心跳过隧道）。
3. **审批配对全流程**：新设备请求 → 桌面批准进入；另设备请求 → 输 4 位码进入；错 3 次作废；请求放置 5 分钟过期；满员时三入口全部拒绝并提示腾位（T2）。
4. **吊销即时断连**：花名册吊销在线设备 → 该设备看板立即断开回配对页；「停止远程」→ 全部设备 403（T0a + T2d）。
5. **quick tunnel 断网自愈**：临时隧道模式断网数秒再恢复 → 看板自动恢复数据流；地址变化有通知（T1c）。
6. **电源保活**：Windows 实机远程彻夜开启不失联；关闭远程后硬盘休眠设置还原为原值（T3）。
7. **托盘入口**：托盘开关与设置页状态一致；地址可复制；0.0.0.0 未确认时托盘开启失败有报错回弹（T4）。
8. **零回归**：桌面既有功能与 M3 新增能力（文件面板、消息书签条、横向分屏、文件预览主目录边界）全部不变 + 全量门禁绿（Rust / 前端测试、双端构建、clippy / fmt / lint）。

## 13. 2026-09-17 用户裁决追记 II：访问密码制替代审批制（M5 批）

> 本节为 M4 验收后的方向性修订（PR #68 分支上续作，commit f2db12f..fff9f60），只追记不重写前文；与前文冲突处以本节为准。实施记录与 17 条拍板决策全文见计划文档 `docs/superpowers/plans/2026-09-17-m5-access-pin-and-file-pool.md`（UI 契约：`docs/superpowers/wireframes/2026-09-17-remote-settings-redesign.html` v5）。

### 13.1 与宪法的关系（重要）

MASTER-PLAN P6「审批配对 + 直通配对」的**手段**修订为「访问密码 + 设备指纹」——目标（可信设备接入、设备可吊销可管理）**不变**。此为用户在场明确裁决（2026-09-17 多轮对齐），MASTER-PLAN 本体不动，以本节追记记录。

### 13.2 动机（M4 验收实测暴露）

1. **刷新掉线**：`stop_server`「停止 = 全吊销」不变量把改绑定/开关循环变成全设备下线；临时隧道每重启换域名，cookie 按域名隔离。
2. **设备数膨胀**：每次配对新建设备记录，换域名/重新申请即累加。
3. **审批流体验差**：一次性接入码 / 请求审批 + 4 位确认码 / 同 IP 占位 429，入口过多且易锁死。
4. **设置窗口 600×500 过窄**，M4 内容折行严重。

### 13.3 替代设计（密码制要点）

- **常驻访问密码**：仅 4 位数字（KV `remote.access_pin`），自填或随机；仅对 局域网/临时隧道/命名隧道 生效（本机免密）；连续输错 5 次锁 10 分钟（per-IP 内存态限速）；`POST /pair/pin` 单一配对端点，绑定 180 天滑动有效。**重置密码 = 全部设备下线**。
- **本机免密双条件（安全关键）**：来源回环 **且** Host 非隧道域名——只查回环会让 cloudflared 从回环转发的公网隧道流量免密进入（穿透）；快照错误态 fail-closed（豁免整体收口）。
   > **追记（2026-10-14 · #131 历史文档失效标注）**：本条与上条括注的「本机免密」口径**已失效**——
   > 2026-10-06 门禁零豁免裁决（#119）撤销了该豁免（任何中继都把公网流量从回环转进来，
   > 「从回环来」不再等于「人在本机」）；现行权威口径见
   > `docs/superpowers/specs/2026-10-06-remote-fixed-address-and-gate-design.md`（§1.5 ②）。
   > 本文档为历史设计，按裁决不改原文。
- **设备指纹去重**：`sha256(UA + "|" + 来源 IP)` upsert——同浏览器同网络重绑覆盖原记录不新增；保留用户重命名；吊销行不复活。花名册带 via（本机/局域网/临时隧道/命名隧道）徽标与重命名。
- **旧配对面全下线**：`/pair`（直通码）、`/pair/request|poll|confirm`（审批三端点）、`approval.rs` 模块、`remote_issue_token`/`remote_pending_requests`/`remote_approve_request` 命令、`remote-pair-request` 事件、审批 UI 与 i18n 全删。二维码改「常驻地址 + `#pin=`」（密码更换/重置设备随之失效）。
- **吊销收窄**：仅显性关闭「开启远程接入」与重置密码/重置设备吊销；改绑定/改端口走热重启（`restart_listener`，不吊销）；MAM 重启本就不吊销。设备上限默认 3 → 10。
- **通道独立开关**：`remote.chan_lan/chan_quick/chan_named` 三 KV（bind 由 chan_lan 派生，旧 `remote.bind`/`remote.channel` 迁移映射后废弃）；quick/named 双槽位可同开（`stop_channel`/`stop_all`）；`remote_toggle_channel` 为唯一单通道启停入口；总开关重开按各卡状态恢复；TLS 明文确认门触发点 = 开启局域网开关。设置窗口 600×500 → 880×640。
- **未替代项**：设备花名册（列表/在线/踢下线/上限）、SSE 吊销即时断连、托盘总开关口径、cloudflared 下载器——全部沿用 T0a（SSE 注册表）/T2c（花名册）/T1d（下载器）/T4（托盘）既有设计。

### 13.4 2026-09-18 裁决：显性关闭不再吊销设备

- **吊销触发器收敛为两个显式动作**：「重置设备」与「修改访问密码」（含重置）。
  显性关闭「开启远程接入」= 停止对外服务（监听停 + 隧道全停 + 放电源），**设备
  记录与 cookie 全保留**——重新开启后已配对设备凭 cookie 自动恢复，无需重输密码。
- 实现：`stop_server_explicit_close` 由 `stop_server(true)` 翻转为 `stop_server(false)`；
  吊销矩阵、设置页总开关提示文案、M5 计划决策 2 同步修订。内核的 revoke=true
  分支保留（幂等能力，当前无调用方）。
- 实测动机：M5 验收中「关闭再打开开关后全部设备掉线、重配对名字丢失」被用户
  判定为体验缺陷——「知道当前密码的设备是安全的」，开关切换不应惩罚设备。
