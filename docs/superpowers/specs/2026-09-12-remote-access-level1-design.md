## 1. 目标与范围

一期交付两件事，按依赖顺序：

1. **dsh（DeepSeek harness）成为第 8 个受监控工具**：与现有七个工具同等待遇出现在 MAM 看板——状态、内容、预览、跳转（宪法 D14，只读）。
2. **远程接入与移动看板**：手机/外部浏览器经安全通道接入本机 MAM，看到八工具看板与会话内容，状态变化 2 秒级提醒。（**2026-09-15 裁决：APK 壳移至二期收尾**——手机端网页发送消息落地后再做，宪法 D15 已修订）

**一期不做（边界，非选项）**：任何写操作（发消息/切模型/审批应答）；多用户账号体系；端到端加密；HMS 原生推送；iOS 原生应用；dsh 插件开发。**例外（用户 2026-09-14 裁决）**：dsh 的 Skill 符号链接管理（补链/启停，写 `~/.dsh/skills`）纳入一期——属 MAM 资源管理既有能力与其他工具同等待遇，不属消息类写通道（后者仍按宪法 D14 另评）；dsh 会话数据（sessions/storages）仍只读。

## 2. 第一部分：dsh 第 8 工具监控（P1–P5）

### P1 · dsh 会话出现在看板上

- **需求**：MAM 自动发现 dsh 进程与全部会话（含历史会话），生成与其他工具一致的会话卡片。
- **输入**：dsh 在本机留下的运行痕迹（进程、端口、会话索引、会话日志）。
- **输出与效果**：看板新增 dsh 卡片——会话标题、所属项目、三色状态、最后消息预览、运行时长（与其他工具同口径）；后台子任务会话不产生卡片。token/耗时用量为**远期增强**（数据已在 projcache 备妥，当前卡片模型无此字段，一期不做）。
- **边界**：只读取证；不安装任何 dsh 插件；不触碰其鉴权接口。

### P2 · 三色状态准确

- **需求**：dsh 的红/黄/绿与其他工具同义——红=需要用户（等批准/出错/已中断）、黄=运行中、绿=完成或空闲。
- **输入**：会话事件与索引中的回合边界、审批请求、结束原因。
- **输出与效果（一期行为定死）**：
  - 等待批准、运行失败 → **红**（红态颜色 + 桌面通知即注意信号，不另挂未读角标——与七工具实际行为一致，2026-09-14 裁决）；
  - 会话写入方已死（进程崩溃）→ **红 · 中断**；判定依据是"写入者是否存活"，与任务运行时长无关，长任务永不误判；
  - 运行中 → **黄**；刚完成 → **绿**，计未读；已读 → 绿 · 空闲；
  - 用户主动取消 → **绿 · 空闲**，不亮红、不计未读；
  - 回合被阻塞（blocked）→ **黄 · 等待中**（不挂未读角标，同上）；
  - 达到 token 上限（max-tokens）→ **绿 · 完成**，计未读。
  - 全部状态变化接入现有通知与提醒链路。
- **边界**：旧格式目录无存活信号，沿用同一"写入者存活"判定的降级路径（时长兜底，阈值固定 30 分钟）。

### P3 · 消息预览可信

- **需求**：卡片与通知中的"最后消息"必须反映真实对话，绝不混入系统注入内容。
- **输入**：会话消息流。
- **输出与效果**：预览只取真人输入与助手回复；系统指令、技能清单等注入内容一律过滤；助手纯工具调用帧显示「执行 <工具名>」。

### P4 · 一键跳转

- **需求**：点击 dsh 卡片回到 dsh 工作界面。
- **输入**：卡片点击；dsh 服务地址。
- **输出与效果**：dsh 页面已打开 → 连同浏览器标签一起聚焦；未打开 → 打开 dsh 首页且免重复登录；聚焦失败 → 卡片给出"请手动打开"提示。**不做会话级直达**（官方与全部已装插件均无此入口，已穷举验证，此为一期定案而非取舍）。

### P5 · 存量兼容与升级降级

- **需求**：旧格式历史会话照常可见；dsh 升级后 MAM 不崩、可感知地降级。
- **输入**：多代并存的会话文件格式。
- **输出与效果**：存量旧格式会话正常解析展示；遇到未识别格式/版本时跳过该会话，显示"格式待适配"降级卡，不影响其他会话与看板稳定性；已验证 dsh 版本登记研究库跟踪清单，升级后按版本门流程复测。

**第一部分验收（= 一期收尾验证项"DSH 作为第 8 工具的监测效果"）**：真实使用中依次制造等批准 / 运行中 / 完成 / 用户取消 / 强杀进程五种场景，看板状态全部正确、预览无注入内容、跳转可用、桌面通知链路无回归。强杀场景预期（2026-09-14 裁决 D6）：宿主被杀 → 卡片随宿主消失（与全工具统一语义）；"红·中断"的可达场景为杀持锁的无头进程（web 宿主存活）。

## 3. 第二部分：远程接入与移动看板（P6–P12）

### P6 · 远程开关与设备配对

- **需求**：远程访问默认关闭；开启后以**批准制**接入新设备——固定地址不是秘密，批准才是钥匙。一期交付两种配对方式（均已定案，非可选其一）：
  - **审批配对（默认）**：新设备打开接入地址 → "请求接入"页 → 桌面 MAM 弹通知并在配对面板出现待审批项（设备名/来源/浏览器）→ 用户批准，或让手机输入桌面显示的 4 位确认码（等效授权，单设备限试 3 次）；审批请求 5 分钟有效，过期自动失效。
  - **直通配对（设置开关，默认关闭）**：一次性二维码临时分享，刷新即失效，用于快速给同事看一眼。
- **输出与效果**：一次配对默认 180 天有效，期间同一浏览器免任何输入；设备花名册可查看在线状态、单独吊销、全部吊销；设备上限 3 台（可配置），满员需手动腾位；「停止远程」一键断开一切。
- **边界**：无密码输入框（无爆破面）；配对与吊销全程留痕可审计。

> **追记（2026-10-06，门禁零豁免裁决）**：原文「期间同一浏览器免任何输入」所隐含的本机免密豁免**已撤销**（设计说明书 §G1，被零豁免取代）——任何中继都会把公网流量从回环转进来，「从回环来」不再等于「人在本机」，故本机浏览器访问同样需要访问密码（首次输入一次，此后 180 天内免输入）。

### P7 · 固定地址与通道（一期实现范围定死）

> **v6 修正项（M2 实测发现）**：对外绑定（0.0.0.0）时，设置页主显示地址不得为 `http://0.0.0.0:port/m`（绑定地址不可连，用户实测手机打不开）——主显示必须替换为可达的局域网 IP 地址（复用 lanUrls 枚举），0.0.0.0 仅作为绑定态说明出现。归入 M3 首任务。

- **需求**：有公网域名的用户获得永不变化的接入地址；没有公网的用户开箱即用。
- **一期实现范围**：
  - ✅ **直连域名**（内置）：绑端口供用户反向代理，地址固定——本项目用户的主路径（**用户自有域名（托管于 Cloudflare，域名与子域细节见私有摘选文档，公开库脱敏）**，双子域各自独立：两台电脑各挂一个子域（如 mam-mac / mam-win 命名模式）、各自隧道与配对（2026-09-15 裁决）；路径前缀方案已否决——需剥前缀/基路径改造，收益不足；双机=部署两份单机 MAM，不改单机架构假设，无需动宪法）；
  - ✅ **临时隧道**（内置）：自动拉起 Cloudflare 免费隧道，零配置扫码即用；地址随 MAM 重启变化，界面明示当前地址并在变化时桌面通知；隧道程序首次启用时自动下载，下载失败可手动放置（固定旁路机制）；
  - ✅ **命名隧道**（内置）：填入用户自有 Cloudflare Tunnel Token 即得固定地址；
  - ✅ **Tailscale**（仅文档指引，不写代码）：接入指引写入设置页帮助。（**2026-09-17 裁决：指引文案已移除（受众过窄）**，见 M4 spec §12.2）
- **边界**：四模式共用同一套功能与配对安全语义；直接对外绑端口前，界面强制确认已具备加密前置，否则仅允许本机模式。

> **追记（2026-10-06，固定地址通道设计说明书）**：Tailscale 模式由「仅文档指引」升为「**内置通道**」（界面通道名「外部域名（免域名）」，永久地址形如 `https://<机器名>.<尾网名>.ts.net`）。宪法 §0.1 / F1.2 早已把 Tailscale 列为通道四模式之一，本次升级在宪法既有条款内实现，**无需修宪**；2026-09-17「删除 Tailscale 提示行」的裁决由本次取代——当时删的是一行被动指引文案，本次升为一等内置通道（装 Tailscale → 浏览器登录一次 → 开通后强制可达性校验，未验证不显示可用地址）。

### P8 · 移动看板

- **需求**：手机看到与桌面同源同义的八工具会话看板。
- **输入**：已配对设备的访问。
- **输出与效果**：移动版会话卡片（三色/项目/预览/时长），按"等待中→运行中→空闲"排序，可按工具过滤；数据与桌面同源同份；页面可加到手机主屏幕全屏使用。

### P8+ · 看板体验增补（v6，用户 2026-09-15 验收反馈，六条全并入 M3）

- **P8a · 品牌与版本**：看板页头显示「MAM + 版本号」（版本随应用发版）。
  输入：应用版本（构建期注入）。输出：页头品牌行。
- **P8b · 本机名称（双机辨识）**：设置页可自定义本机名称（如「JARVIS 的 Win 电脑」），看板页头同步显示——双机双子域（mam-mac/mam-win）下辨识当前看的是哪台（2026-09-15 裁决）。
  输入：设置项 `remote.host_name`（默认取系统主机名）。输出：API 携带 host 信息（名称+平台），看板页头展示。
- **P8c · 卡片结构对齐桌面**：卡片主行 = 工具名 + 项目名，状态点在主行右侧；副行 = 会话标题（项目在做什么的摘要）+ 最新消息进度——副行内容为现有能力，本条交付的是主行结构重排（2026-09-15 用户澄清：不需要 git 分支）。
- **P8d · 工具筛选与受管名单一致**：筛选 chips 只显示「设置-工具管理」中勾选接受管理的工具（而非全量八工具），且与实际有卡的集合取交集。
- **P8e · 工具品牌色 + 多行折叠 + 活跃排序（2026-09-15 定稿）**：chips 配色参照桌面端品牌色（Claude 橙、Codex 紫等）；多行自动换行，超一行默认折叠为一行并提供折叠/展开按钮；chips 与卡片列表均按"该工具/会话最新一条消息时间"活跃优先排序。
- **P8f · 日/夜双皮肤**：浅色/深色两套皮肤一键切换，默认跟随系统，选择持久化（与桌面端主题策略对齐）。

### P9 · 会话内容查看

- **需求**：点开任意会话卡片可阅读完整对话记录。
- **输入**：卡片点击。
- **输出与效果**：只读对话视图，覆盖全部八工具（含 dsh 与无头会话）；不可编辑、不可发送。**交互范式（2026-09-15 定稿，参照 ZCode 远程 UI）**：
  - **运行中**：展示明细——思考过程默认折叠（可点击展开）、工具调用可点击展开；用户/助手正文直接可见
  - **执行完成后**：过程明细自动折叠，只显示最终总结（点击可重新展开查看完整过程）
  - **消息流为 ZCode 中间区域式对话窗口**——无左侧项目栏（项目切换通过上一层看板卡片列表完成）
  - **markdown 渲染**：代码块/行内代码/加粗/链接
  - **文件产物预览**（探测先行，见 M3 探测项）：消息中涉及的项目文件（markdown/代码/图片）可点击预览；预览形态两选一（按屏幕宽度自适应）——左对话+右文件两分屏，或全屏浮窗。**2026-09-19 修正（用户裁决）**：分屏（`split` 纵向 / `split-h` 横向）是「对话列 + 文件列」的并列布局，**对话列必须保有完整对话能力**——消息发送输入框（composer）与审批红卡（ApproveCard）在分屏态同样挂载可用；原实现把两者排除在分屏分支外（仅在非分屏正文视图挂载）系实现越权、无设计依据，已修。**2026-09-20 裁决：竖屏分屏（`split`）视觉顺序为文件在上、对话在下**——输入框贴底符合移动端竖屏习惯，对话列带最小高度保护（防 composer 压没消息区）；横屏分屏（`split-h`）维持对话在左、文件在右（左右阅读顺序合理），两者语义各自独立、互不跟随
  - 向上滚动加载更早消息；距底超过阈值时右下角出现「跳到最新」浮动按钮（纯 UI 控件，点击瞬时落底并恢复轮询跟随——不改变 P2-B 轮询前采样的既有语义）
  - **工具调用过程的计划正文渲染（2026-09-20）**：ExitPlanMode 类工具的参数为 JSON 串（字符串值换行皆 `\n` 转义），原样上屏不可读——toolArgs 解析出非空字符串 `plan` 字段（claude 与 zcode 的 ExitPlanMode 输入同构）时，该正文按 markdown 渲染；其余工具参数维持原样（用户裁决不做通用美化）
  - **移动端附件上传（2026-09-20）**：composer「+」钮（文件多选）与粘贴图片（clipboard）→ POST `/m/api/v1/session-attachment` → 落盘 **用户项目目录 `<cwd>/.mam-attachments/<会话>/`**，消息自动拼 `<image|file path>` 内联标记行（文件池既有约定 → 自动入池「我上传的」+ agent 可读路径）。git 零污染 = 首份写入时幂等追加 `<cwd>/.git/info/exclude`（**本地管理区，非 .gitignore 跟踪文件**）；非 git 项目跳过。上限 20MB（413 too_large）；无 cwd 会话 422 前端禁用上传。**知情披露**：「+」旁「?」徽标点开说明存储位置。**读取权限边界**：cwd 内读取全工具零审批（权限模型公共下限）；cwd 外读取按工具权限面。附件**不做自动清理**——随项目生命周期、桌面「数据管理」卡片可清理。

### P10 · 实时提醒

- **需求**：状态变化 2 秒级到达手机；页面开与关都有通知路径。
- **输入**：状态跃迁事件（与桌面通知同源同去重）。
- **输出与效果（一期交付双出口，均默认关闭、按需开启）**：
  - 页面开：实时横幅 + 提示音 + 振动；
  - 页面关：系统级推送——**ntfy**（Android/华为，默认出口）与 **Bark**（iOS）两个推送出口，同一事件源；推送服务器地址支持自定义（默认公共 ntfy，隐私提示文案随附设置页）。**2026-09-16 修订：页面关系统推送随宪法 D17 移至二期，与 APK 壳同期交付；一期「2 秒提醒」以页面开时 SSE 为口径**；
  - 提醒内容含工具、项目、变化方向与消息预览。**去重口径（2026-09-15 修正）**：全部在 SessionWatcher 跃迁判定层完成（与桌面通知同一套边沿触发逻辑）——消费者（SSE/推送网关/桌面通知）拿到的已是去重后的边沿事件，移动端**不再独立去重**；删除原"10 秒合并/等待不轰击"的旧表述（SessionWatcher 前时代遗留，与同源架构矛盾）。
  - **提示音口径（2026-09-19 用户裁决，与桌面端统一）**：**仅「变为绿」（任务完成）时发声**——按**目标颜色**判定（`red→green` 与 `yellow→green` 均发声，口径与桌面端 `useNotification` 的 `currColor === "green"` 一致），黄→黄之间的状态细分跃迁（`processing↔thinking↔compacting`）**不发声**；另加 **5 秒同目标颜色去重**（防状态抖动连响），口径照抄桌面端 `lastNotified`。修正前移动端对**任意**状态值变化无条件发声（一轮回合内多次黄态细分跃迁会连响数次，用户实测为噪声）。
    - **与上条「移动端不再独立去重」的关系**：该条针对的是 **SessionWatcher 层**的跃迁去重（删除旧「10 秒合并/等待不轰击」表述），移动端仍不重复实现该层。本条的 5 秒同色去重是**消费者侧 UI 层的防抖兜底**，与桌面端 `lastNotified` 属同一层、同一语义——**两端都保留**，不构成对上述去重口径的推翻。
    - **音源为移动端自有合成音**（两音上行 E5→A5 + 包络淡入淡出），**不复用桌面 `src/lib/audio.ts` 的 12 个 wav 资产**：那套资产在 `public/`（约 9.5MB），移动产物走 `public-mobile`，引用必静默失败；逻辑（何时响）两端统一、音源（怎么响）各自本地渲染。
    - **声音总开关**：看板页头（首页主卡片）提供图标按钮，仅控制**提示音**（不影响横幅与振动——后两者是最低打扰的提醒通道，保留）。开关持久化于移动端独立键（`mam-mobile-sound`），**不复用桌面 `mam-sound-config`**（后者是「12 音效 + 按工具覆盖」体系，移动端只有开/关两态）。
  - **排队回执双钮（2026-09-20 裁决）**：排队态提供「立即发送（插队）/ 修改 / 撤回」三钮——**撤回 = 完全取消**（确认出队后正文丢弃）；**修改 = 从队列拉回输入框继续编辑**（确认出队后正文放回输入框并聚焦，超长截断到发送上限）。两者共用同一后端出队端点，差别仅在是否恢复文本；未确认出队（忙时 failed / 网络错）一律走复核收敛、不恢复文本（防「队里还在 + 输入框也有一份」双份）。
  - **排队条目他端消失留痕（2026-09-20）**：轮询发现排队条目不在队时，落中性 gone 提示「可能已送达，或由电脑端处理」，不再静默清空——队列会话级共享、无归属标记，移动端无法区分触发方；真实归属需后端审计回传，边缘场景不做。

### P11 · 电源保活

- **需求**：远程开启期间电脑不得因休眠失联。
- **输入**：远程开关状态。
- **输出与效果**：开启远程即阻止系统与磁盘休眠（屏幕可熄灭）；Windows 下代设硬盘休眠设置并在关闭远程时还原原值；设置页明示合盖/电池模式边界；开关默认开启。

### P12 · APK 壳（**已移至二期收尾**——2026-09-15 裁决，宪法 D15 修订；一期不再含 APK）

- **需求**：网页链路验收后，交付安卓/华为原生壳版本（宪法 D15）。
- **输入**：与网页版完全相同的后端服务。
- **输出与效果**：同一移动界面的 APK——**内置长连接推送（定案）**：APK 与 MAM 推送网关保持自有长连接，页面关闭仍收系统通知，通知归属 MAM 自身、点击直达具体会话；不注册任何推送厂商账号，不依赖第三方推送应用；后台存活采用前台服务 + 电池白名单引导页。
- **边界**：纯壳复用，无独立功能；M4 验收前不动工；HMS 原生推送为一期外远期项。

**第二部分验收（= 宪法 §5.b 一期标准）**：外网手机扫码→八工具看板与任意会话内容；杀掉一个会话→手机 2 秒内提醒；未批准的新设备进不来；吊销/停止立即失效；临时隧道断网自愈；保活期间彻夜不失联。（APK 项已随 D15 修订移至二期）

## 5. 非功能需求

- **安全**：批准制是唯一入网途径；全程加密（通道侧终止）；最小暴露（不依赖任何第三方插件的开放端点）；配对与吊销全程审计。
- **性能**：状态跃迁到手机 ≤2 秒；看板首屏 ≤1 秒；监控扫描不拖慢桌面现有体验（宪法原则 5）。
- **可靠性**：隧道断线自愈；实时流不可用自动降级轮询；MAM 重启后已配对设备免重连。
- **体验**：中文界面与 MAM 一致；移动页面可安装到主屏幕。
