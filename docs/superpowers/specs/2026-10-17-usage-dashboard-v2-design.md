## 1. 目标、约束与非目标

**产品目标**：保持 Tuvis 现有“只读本地会话/数据库文件 → 七源 Collector → 统一 Token 账本”的统计方式，以紧凑、可截图的 Dashboard 同时解释总 Token、时间趋势、使用归属和**逐模型 API 等效费用**。

**用户故事**：

| ID | 场景 | 期望结果 |
|---|---|---|
| US-1 | 想快速知道这段时间总共用了多少 Token | 不需要配置渠道即可看到总量、输入组成、缓存命中率、输出。 |
| US-2 | 想比较某个工具或渠道的时间使用情况 | 在原有趋势卡内选择“工具/渠道”和具体对象，曲线就地变化；全局总览不受影响。 |
| US-3 | 想知道模型通过哪个订阅或 API 渠道使用 | 记录页可将已观测的工具+模型绑定到用户建立的计费渠道，后续自动归属。 |
| US-4 | 想把模型的 Token 量换算为 API 价格参考 | 在对应渠道/模型行看到等效费用、口径、价格版本及未估价部分。 |
| US-5 | 想在屏幕截图时只展示所需内容 | 用量分布、费用分析、工作活动可折叠；总量与总趋势保持展开。 |

**必须保持**：

- 现有本地采集、去重、`Exclusive/Subset` 缓存语义、子代理计量、时间范围、Token 汇总和历史账本含义不变；新增逻辑不得代理/拦截模型请求，也不得改写真实 Token。
- 沿用现有 React + Tauri + Rust + SQLite 架构，复用项目的 `Card` / `Button` / `Dialog`、主题变量、SVG `TrendChart`、中英文格式化、已有测试约定。**不引入第二套 UI 或图表库。**
- 无遥测：会话原文、路径、密钥、用户的渠道映射不发往定价服务；外部请求仅获取公开价目表。
- “API 等效费用”仅表示给定参考 API 价格下的假设成本；绝不是实际支付、订阅配额、套餐消耗比例或账户余额。

**本期不做**：全局/跨渠道费用总额、总体费用 KPI、费用总趋势、真实账单、各供应商订阅额度抓取、各家单独价格爬虫、自动按会员月费换算 Token 余额、逐请求代理路由。统一额度源未来存在时另立项目评估。

## 2. 页面结构与视觉冻结

### 2.1 现有容器与全局行为

沿用 `src/pages/usage-dashboard.tsx` 的独立窗口、吸顶时间/导出操作区及 **「看板 / 记录」两页签**；不增加“费用”顶层页签。五档时间选择（近 5 小时/当日/近 7 天/近 30 天/自定义）继续共享，各模块同一时区、同一区间；当前导出入口和记录页整体框架保留。

看板由**四个核心板块**顺序组成，末尾一个**辅助折叠区**：

| 顺序 | 板块 | 初始状态 | 一句话职责 |
|---|---|---|---|
| A | **Token 总览** | 固定展开、不能折叠 | 所有工具合计的可信 Token 指标。 |
| B | **用量趋势** | 固定展开、不能折叠 | 默认全局；在卡内切换工具/渠道筛选，不另建模块。 |
| C | **用量分布** | **展开**、可折叠 | 用量按渠道、工具、项目、模型拆分。 |
| D | **API 等效费用** | **展开（默认）**、可折叠 | 按渠道组织、逐模型展示费用估算；无全局金额。 |
| 辅助 | **工作活动** | **折叠**、可展开 | 保留会话/工具/错误信息，高级性能指标展开再看。 |

折叠按钮位于卡头右侧，使用现有小号描边/幽灵按钮风格，带 `aria-expanded`、键盘可操作。折叠时保留卡头、关键说明和可发现的展开入口，隐藏卡体；切换时间范围/页签后**当前窗口内**保留折叠状态，重开窗口恢复上述默认值。本期不新建持久化偏好。

**视觉不可变更项**：当前白/深色主题、轻边框与圆角卡片、灰色辅助文案、黑白选中态胶囊按钮、蓝色趋势线、`tabular-nums` 数字、现有间距与字体层级；所有新组件使用已有设计令牌。**禁止**新配色系统、大面积渐变仪表盘、仪表盘式多列瀑布流或全屏新导航。

**高度/密度**：以现有 1040×720 桌面窗体为目标，保持单列卡片；A 用紧凑网格，B 尽量维持现有短横向趋势图，C 初始只显 **Top 5** 行并提供“显示更多”；D/E 默认收起。不能为了强制一屏容纳全部展开内容而截断表格、缩小到难读字号或破坏滚动；吸顶操作区不覆盖卡头。窗口较窄时，次要指标下移到副行/悬停详情，模型名保留可查看全名的 tooltip。

**分享边界**：普通窗口截图自然反映当前折叠状态。既有“导出图片”属于固定分享模板，**本期不改成所见即所得页面截图**；费用金额不得偷偷加入原 Token 分享图的“合计”。如未来需要“按折叠状态导图”，另立需求。

### 2.2 A：Token 总览（复用 `UsageSummary`）

- 主数字：`总处理 Token = requestTotal + output`，使用完整千分位和原标题风格，保持全局合计，不随 B/C/D 的分组选项变化。
- 核心四项：**请求输入** `requestTotal`；**缓存命中输入** `cacheRead`；**未缓存命中输入** `requestTotal-cacheRead`；**输出 Token** `output`。
- 辅助两项：**缓存命中率** `cacheRead/requestTotal`、请求次数；保留与上一等长时间段比较及截止时间。缓存写入量放到解释性详情，不与上述四项相加。
- **移除“用户输入(估)”展示**及其分享/文本摘要对应指标：其 CJK 字符+英文词估算不是 API Token。V2 暂不强删旧库列及 `user_est_of`，等兼容性迁移单独评估。
- 未测量量 `—` 不假装为 0；有真实数值的 0 保留；总览与现有迷你条 Token 口径一致。

### 2.3 B：用量趋势（复用 `UsageTrendCard` / `TrendChart`）

- 默认曲线仍为所选时间窗口**全局总处理 Token**；沿用现有峰值、Tooltip、小时/日粒度与环比规范。
- 卡头右侧或紧贴卡头下方设置**一组紧凑筛选器**：`全部 / 按工具 / 按渠道`；选“按工具/渠道”后出现具体对象的下拉选择。默认 `全部`，单次只激活一个过滤维度；不在页面额外新增分组趋势卡。
- **“渠道”= 订阅来源（provider）的显示名**：优先使用用户的 provider 别名；显式绑定的计费渠道（`billingProfileId`）作为覆盖，优先级最高。未配置别名的非空 provider 按原始 provider 串聚合；空 provider 且未逐条指派时并入“未指定渠道”，不作为趋势筛选选项。**工具不是渠道分类维度**。
- 不得从同名模型猜测一个渠道；别名与指派必须由用户显式保存。选择某渠道时仅用可靠归属到该渠道（含别名解析）的 Token。
- 筛选只作用于 B 的曲线、峰值及其区间比较；**A 保持全局，C/D 的分组状态不联动**。时间范围是全页唯一联动状态。选项不可得时显示原因、允许返回“全部”。
- 过滤前后不插值补造 Token：继续遵循没有数据不画假零线、加载中不展示旧峰值、环比缺少同口径上期数据时不展示百分比。**V1 不引入费用趋势**。

### 2.4 C：用量分布（增强 `UsageDistributionCard`）

- 默认 **按订阅来源（provider 显示名）** 展示 Token 分布；可切换 `按工具 / 按项目 / 按渠道 / 按模型`，保留现有进度条、排序（按 Token 降序）、完整数值 tooltip 和空态。
- 渠道维度顺序：显式计费绑定 > provider 别名（同显示名跨工具合并）> 原始 provider 串 > “未指定渠道”（合并为一行，不带工具）。工具不参与渠道分类。
- 每行显示 `名称 · Token · 缓存命中率 · 相对条`。模型维度的键 = 显示名（别名；无别名时用原始 provider；空 provider 未指派时用工具）+ 原始 `modelId`；标签为 `显示名 / 模型`。空 provider 未指派时标签必须附工具（如 `未指定渠道 · Codex / gpt-6.1-sol`）以区分来源；`model` 为空统一显示“未知模型”。同显示名跨工具合并，不用“裸模型名”跨订阅合并。
- 默认仅 Top 5 行，`显示更多` 展开剩余行，避免原 10 行及长模型名把页面拉得过长；C 折叠与行数展开是两个独立状态。
- 这里仅展示 **Token** 分布和缓存效率，**不在分布表重复放美元列**。费用入口在 D，渠道归属配置在“记录”页与设置中。
- 现有 `UsageDistributionCard` 的 `provider/model` 显示逻辑需要区分“日志观测供应商”“用户自定义 provider 显示名”和“用户指定计费渠道”；**原始字段不能被覆盖**，原始 provider 保留在行数据与 tooltip 中，别名只在展示/分组层生效。

### 2.5 D：API 等效费用（新增独立卡片，默认折叠）

- 卡头：`API 等效费用` + 灰色说明“按模型参考 API 价估算，非实际支出”，**不得出现 `$总计`**。
- 卡体两种查看方式：**按渠道**（默认）和**按模型**。渠道视图为订阅来源（provider 显示名或显式绑定渠道）分组容器，其下逐模型展示金额；模型视图的每行以 `显示名 / 模型` 为唯一显示身份，provider 不同即使使用同一归一化模型也分行，必要时附来源工具。**不显示跨渠道、跨模型的费用总计，也不自动生成渠道卡头金额小计**。
- **最小可相加单元**：相同（显示渠道 + `pricingReference`（归一化模型）+ `modelId` + `pricingBasis`）、同一币种/计价规则下，在选定时间内把可计价记录聚成**该模型行**的金额。两个不同显示渠道即使使用相同模型也必须分两行；无法区分渠道的日志只能作为“可能混合”的单独行，不得分账。
- 行信息：`显示名/模型`、`API 等效金额 (USD)`、`Token`、`缓存命中率`、`估价覆盖率`；展开单行可看普通输入/缓存读/缓存写/输出的 Token 与各项参考价、价格日期、基准估价说明，以及价格来源（参考 models.dev 的 provider/model 与快照日期）。大量模型默认 Top 5，支持查看更多。
- 不可估价的行仍保留 Token，金额为 `—（未估价）`；部分可计价则写 `已估价部分 $X · 覆盖 Y%`。缺价 ≠ 真正免费；只有上游明确价格 0 且数据可计价时才显示 `$0.00`。
- “按渠道”只决定组织方式，**不代表订阅包或服务商的实际成本**。费用卡可提供“管理渠道”“价格更新时间/刷新”入口，但不新建全局费用主数字。

### 2.6 辅助：工作活动（压缩 `UsageWorkSummary`）

- 放在四个主板块**之后**，默认折叠。卡头摘要可展示会话数与工具调用次数；不适用或不可得时为 `—`。
- 展开再显示逐工具 turn、错误分层、用户打断、最常调用工具；`p50 / 最长 Turn / 工具耗时` 置于**展开后的高级统计区**，保留已有“含挂机、未剔 idle”提示。
- 禁止把不同错误层级直接相加为统一错误总数；不同工具 turn 定义仍不跨工具合计。功能是辅助监测，不成为费用归因输入。

### 2.7 “记录”页与设置入口

- 保留 `UsageRecordsPanel` 的原有“按工具/项目卡片 + 供应商/模型行”框架、筛选、数据可得性标记。**未识别行**新增轻量操作：非空 provider 可修改/新建 provider 显示名；空 provider 的「工具+模型」条目可直接指派显示名；已有显式计费绑定的行提供 `修改关联/查看规则`。
- 选择后打开复用主题的 Dialog：自动展示只读 `来源工具、原始供应商（可空）、完整模型名`，并显示该 provider/条目实际被哪些工具与模型使用；空 provider 的指派按「工具 + 原始模型」保存并**回溯生效**；显式计费渠道的匹配方式默认**精确匹配**；预览命中的来源、记录范围和 Token；确认后才保存。
- `设置 → 用量统计` 增加“供应商别名”“计费渠道与规则”“定价目录状态与价格来源”的可视化管理入口。**不恢复让用户手写 `providerMapRules` JSON**（现有产品已撤下该编辑框）。
- “复制文本/导出 CSV”保持既有 Token 口径；费用 CSV 使用单独动作，按渠道/模型行导出、含估价状态/覆盖率/定价版本，**没有全局费用合计行**。

## 3. 计费身份账本（Billing Profiles）

### 3.1 身份定义

| 概念 | 含义 | 原则 |
|---|---|---|
| `sourceId` | 产生会话的工具，如 codex/claude | 沿用既有七源枚举。 |
| `observedProvider` | 既有账本保留的供应商身份 | 对有直接日志证据者是观测值；旧规则推断值仍保留 `sourceKind=inferred`，不得包装成日志实测。不是付款渠道的证明。 |
| `modelId` | 既有账本保留的完整模型 ID | 参与稳定匹配，不以截断 UI 字符串作键；源解析已规范化或剥前缀的历史字符串不能声称已恢复原文。 |
| `billingProfileId` | 用户维护的实际订阅/API 计费渠道 | 系统生成不可变 ID，显示名可变；作为显式覆盖，优先级高于 provider 别名。 |
| `displayProvider`（provider 别名） | 用户为观测 provider（或空 provider 下的「工具+模型」条目）定义的可读名称 | 仅影响展示与分组，不回写 `observedProvider`；同显示名视为同一订阅来源并合并统计；空 provider 不设自动匹配规则，由用户逐条指派。 |
| `pricingReference` | 参考 API 报价的 provider/model | 与实际订阅分离，不能由套餐价换算。 |
| `attributionKind` | `observed / userAssigned / unknown / ambiguous` | 与既有 `sourceKind`（供应商可得性）分开。 |

配置内容：provider 别名（原始串/空 provider 条目 → 显示名）、渠道显示名、类型（官方订阅/API/第三方 Coding Plan/未知）、可选说明；匹配规则、可选参考价匹配规则独立保存。**渠道类型只作标签，不改变 API 等效计算公式。**

### 3.2 匹配、冲突与时间

- 默认规则键：`sourceId + observedProvider（包括“空”） + 完整 modelId`，**精确匹配**。允许用户显式开启模型名前缀匹配；禁止默认模糊/子串匹配。
- **供应商别名层（查询时解析，不落账本）**：非空 provider 按原始串精确映射到用户显示名；不同原始串可映射到同一显示名，从而跨工具合并。空 provider 不设自动规则，由用户对「工具 + 原始模型」逐条指派，保存后回溯生效。别名与显式计费绑定冲突时，**显式绑定优先**。**已知限制**：若两个订阅在日志中的原始 provider 串完全相同，别名层无法拆分，只能依赖显式计费绑定或逐条指派。
- 优先级：精确 > 明确前缀；匹配范围更窄者优先；相同优先级的冲突**停止自动归属并待用户处理**；不以规则创建先后悄悄覆盖。
- 绑定时先展示预览；默认作用于今后可匹配的记录。用户可选择在有足够证据的历史区间进行**可撤销的归因重算**；只变派生归属，不重采/改写 Token。
- 支持规则可选生效日期范围，用于用户确实换过渠道的情况。若同一时间同一日志身份对应两个真实账户，**无法凭文件恢复两者用量**，显示“渠道可能混合”，不可用规则强制声称准确拆账。
- 归因规则属于**用户指定**而不是日志实测；展示标记不能伪装成 `measured`。按渠道过滤趋势/费用时，含糊记录不参与某个明确渠道的准确值。

### 3.3 仓库核对后的兼容边界

- 旧 `resolve_provider` 已可能把 `providerMapRules` 的结果写入 provider；新渠道规则不得重写这些值，也不得把它们自动迁移成付款渠道。用户仍可基于该既有身份显式指定渠道，界面保留其“推断”标记。付款归因与 provider 可得性是两套标记。
- 历史事实只有小时/日桶，不能用规则时间点准确切分桶内 Token。规则完整覆盖整桶且各子区间都唯一归属同一渠道时才可归属；未覆盖子区间显示未知，跨渠道/冲突显示含糊。禁止按 Token 比例分摊，或用采集更新时间猜事件发生时间。
- “今后”的生效时点必须在预览明确显示并原样用于确认；旧预览失效时重新预览，不暗中回溯历史。用户选择历史日期时只对有足够完整桶证据的范围重算。小时与日粒度的可归属覆盖可能不同，界面解释该限制，全局 Token 不变。
- 规则保存、修改与撤销使用带版本的配置快照。撤销恢复派生规则状态并形成新版本；不删除历史事实，不重采、不改 Token 去重键。

## 4. 外部定价与费用计算

### 4.1 定价目录

- V1 唯一默认来源：[`models.dev/api.json`](https://models.dev/api.json)，通过其 `cost.input/output/cache_read/cache_write` 获取 **USD / 100 万 Token** 参考单价；不依赖各家订阅 API。**不内置种子价目表**：首次启用且拉取失败时显示未估价，成功拉取后自动生效。
- 用户首次启用后后台拉取，**默认每 24 小时刷新一次**，支持手动刷新；只下载公开价目表，不得上传本地用量。下载/解析/校验成功后才原子替换有效缓存；失败**沿用最后成功快照**，展示数据源、快照日期和错误，不得清空既有快照。
- **模型匹配**：先对模型 ID 做机械归一化（剥 vendor/命名空间前缀、日期尾、版本尾、推理档位尾，`.`→`-` 等），按归一化模型 ID 精确匹配；命中多条 provider 报价时先按「直营官方 > Ollama Cloud（托管）> OpenRouter」分层，层内再按 `release_date` 最新优先取一条；provider 同时用于来源展示与优先级判定。精确未命中时可做**前缀回退，但仅当命中唯一且价格一致**时采用，否则未估价。跨模型族的替代参考模型**必须用户明确授权选择**，不可猜测“相似模型同价”。
- **同一归一化模型在同一币种下采用同一参考价**（同 CC-switch；原生人民币价与 USD 价按来源分别保存）：费用行仍按用户显示名/模型拆分，provider 只影响分组展示。价格条目保留来源 provider 与快照日期，界面可核对。
- 定价快照保留来源、更新时刻、哈希/版本与可用于重算的有效报价；历史期间无历史参考价格时标记 `当前价回算`。用户可手动覆盖任意模型的四价（可选 USD/CNY 计价币种，标记“用户覆盖”），后续同步**不得覆盖用户值**。
- 价格有上下文长度阶梯、缓存 TTL、reasoning 等特殊计费条件而日志不能提供充分判据时，按**基础文本价估算并标注**；无法映射到文本桶的缺价部分保持部分计价/未估价，不强行输出伪精确数字。

### 4.2 费用估算规则与覆盖率

- **输入**：规范 Token 桶 `{inputFresh, cacheRead, cacheWrite, output}`、`requestTotal`、原始模型/提供方、归一化模型、显示 provider、渠道规则、价格快照、时间范围以及可计费桶语义。
- **输出**：逐**显示渠道+模型+价格口径**的参考金额、四项分项、已计价/未计价 Token、覆盖率、状态（`priced / partial / unpriced`）、价格来源/更新时间与估价依据。
- **行拆分与单价分离**：费用行按「显示名（provider 别名或显式绑定渠道）/ 原始模型」拆分；同一归一化模型在不同 provider 下使用同一参考单价，但分行展示，不生成渠道小计。
- 只有当各计费桶被证明互斥且适用上游费率时，才使用 `Σ(各桶 Token × 对应 USD/百万 Token 单价)`；`requestTotal` 已含缓存读，禁止再次整体按普通输入价计费；reasoning 已并入既有 output 时不能重复追加。
- `Subset` 中 `cacheWrite` 与普通输入可能重叠；未证明互斥时须将受影响部分列为 `partial/unpriced`，**不能按四桶直接机械相加**。不得用日桶的单一 `cacheSemantics` 覆盖混合请求的真实语义。
- 覆盖率按当前行的**规范处理 Token（请求输入+输出）**明确计算，披露未计价部分；如果部分可计价，只显示“已计价部分估值”，不能冒充完整该模型费用。
- 支持 **USD / CNY 双币种展示**：优先各自原生价，缺失时按当日汇率换算并标注；价格为 0 但已确认可计价，与价格缺失须严格区别。币种和价格类型不一致的行不得合并。

### 4.3 账本兼容性边界

- 现有 `usage_detail` 聚合键含 `(source, session, project, hour, model, provider)`；`usage_daily` 按日期进一步聚合。**不要为了新的展示身份修改现有去重键或重写历史事实**。
- 90 天后明细可能清理，且日聚合不一定保留逐请求的所有缓存计费条件。费用引擎只对足够可靠的数据给金额；无法确认的历史记录标记 `partial/unpriced`。
- 仓库核对确认：`DeltaBuilder` 已先按明细键聚合，`usage_detail.cache_semantics` 的 upsert 为最后写覆盖，日聚合不保留逐请求语义。因此不能把当前列值当成整组真实计费条件，也不能靠新加一个查询返回字段恢复已丢失的事实。
- **本次实施采用保守估价**：只对能证明互斥且参考价适用的桶给金额；条件价按基础文本价估算并标注，重叠、缓存 TTL 或来源形态证据不足的部分保持 `partial/unpriced`。部分计价的分母仍是规范处理 Token，不能通过丢行提高覆盖率。
- 本次不新增逐请求 `CostBasis` 采集链，也不修改七源 Collector。若后续要求把现有信息缺口变成精确可计价能力，需另行评审并行、增量、可回退的事实补充方案；本次执行 Agent 不得自行扩展采集范围。数据不足是明确降级，不是允许省略已可证明安全桶的正常估价实现。

## 6. 空态、性能、安全与验收

### 7.2 2026-10-19 修订：供应商别名与定价自动匹配

用户裁决的增量口径（本节优先于前文冲突表述；2026-10-19 经问答确认）：

1. **渠道维度 = provider 显示名**：非空 provider 按原始串精确映射到用户定义的显示名；不同原始串可映射到同一显示名并跨工具合并。空 provider 不设自动规则，由用户对「工具 + 原始模型」逐条指派，保存后回溯生效。显式计费绑定保留为覆盖，优先级最高；工具不参与渠道分类。
2. **Token 统计与 API 换算分离**：统计键 = 显示名/原始 provider + 原始 `modelId`；API 换算按归一化模型 ID 匹配 models.dev。未配置别名时，非空 provider 按原始串聚合；空 provider 未指派时渠道合并为“未指定渠道”一行、模型维度暂按工具拆行。
3. **定价照搬 CC-switch 的外部数据模型**：仅 models.dev、不内置种子价；默认每日刷新 + 手动刷新；失败沿用最后成功快照并展示数据源与快照日期；同一归一化模型全渠道同价（models.dev 同名模型按 `release_date` 最新优先去重），额外保存来源 provider 与快照日期供核对；允许用户手动覆盖任意模型四价，后续同步不得覆盖用户值。
4. **匹配边界**：机械归一化（剥 vendor/命名空间前缀、日期/版本/推理档位尾等）后精确匹配；前缀回退仅在命中唯一且价格一致时采用；跨模型族替代仍需用户明确授权。保守估价（`partial/unpriced`）规则不变。
5. **展示边界**：费用行按显示名/模型拆分，provider 不同分行但共用同一归一化模型单价；展开行与设置页展示价格来源（models.dev provider/model）与快照日期；原始 provider 始终保留，别名不回写账本、不改变 Token 口径。

### 7.3 2026-10-20 追加修订：配置条目化、原生人民币价与条件价估算

本节优先于前文与 §7.2 的冲突表述；2026-10-20 经用户逐项确认：

1. **配置弹窗只保留「供应商/模型条目」+ 高级覆盖**：删除独立的「供应商显示名（渠道）」分区。每条条目 row2 同时编辑供应商名与模型名；供应商名对**同一原始 provider 全局生效**（空 provider 条目写 `toolModel` 别名），模型名按「显示供应商, 原始模型」批量生效。未编辑 = 原名；清空 = 删除别名（回原名 / 未指定渠道）。
2. **条目默认 Top10**：按最近 7 天（宿主本地日界，含今日）`requestTotal + output` 降序显示前 10 条；底部「展开全部」后显示全部，并提供供应商/模型搜索。历史条目（7 天无用量）只在展开后出现。
3. **来源优先级**：同一归一化模型同时存在多个精选来源时，按「直营官方 > Ollama Cloud（托管）> OpenRouter」取价；直营官方包含中国站变体（`moonshotai-cn`、`alibaba-cn`、`minimax-cn`）。不得再让 `ollama-cloud` 因发布日期或字典序压过 `zhipuai` 等直营官方。
4. **条件价按基础文本价估算**：多模态输入、上下文阶梯、`context_over_200k` 等 `conditional` 标记不再导致整条报价被丢弃。只要目录给出基础文本四价，就按基础价估算，并在行内「不准确原因」标注 `conditionalBaseRate`（按基础文本价估算）。缺价仍为 `None`，绝不显示 0；未知/音频等无法映射到文本桶的条件仍保持未估价。
5. **原生人民币价**：刷新价格快照时，对账本观测到且能匹配到人民币来源（智谱、Moonshot CN、MiniMax CN 等）的模型，读取 models.dev 源 TOML 注释中**明确写出**的人民币四价（支持 `List price: CNY 8/2/28`、`CNY per 1M tokens: 2.1 in / 8.4 out / …`、`input ¥20.00, cache hit ¥2.00, cache write ¥20.00 … output ¥100.00` 三种格式），存入随快照生命周期的 `usage_pricing_native`。没有明确人民币数值的来源（如阿里 CN、DeepSeek）不猜价。已知边界：逐模型拉取源 TOML 会向 models.dev/GitHub 暴露**已观测模型 ID**（不含会话、路径、密钥或渠道映射），这是换取原生人民币价的必要代价；单次刷新按最近 7 天用量取前 **32** 个 CNY 来源目标，超出部分按当日汇率换算。
6. **当日汇率与双币种**：刷新时联网获取当日 USD→CNY 汇率（`open.er-api.com`），存入 `usage_pricing_fx`；失败依次回退最近成功汇率 → 设置页备用汇率 → 内置 7.2，并标记 `fxFallback`。USD 显示优先使用目录 USD 原生价；CNY 显示优先使用原生人民币价；缺失的一侧按当日汇率换算。**原生币种价格正常显示；经汇率换算的金额/单价加虚线下划线**，卡头给出图例。
7. **覆盖价币种**：手动四价覆盖新增 `USD/CNY` 币种选择，按所选币种存储；显示另一币种时按当日汇率换算并同样加虚线下划线。
8. **D 卡呈现**：默认展开、可折叠；每条模型一张卡片，主行五列（显示名/模型 | 估价 | 总 Token | 缓存命中率 | 计费详情），明细在卡片内部展开；主表头与明细列头用实体字（前景色）；明细列头补全「项目 / Token 用量 / 金额 / 单价」。卡头增加「同步价格」按钮，手动强制刷新 models.dev + 人民币来源 + 当日汇率（loading/行内状态），保留每日/过期后台刷新与首次启用刷新，打开卡片不自动联网。
9. **保守契约不变**：仍无全局费用总额、无渠道金额小计、缺价 ≠ 0、同一归一化模型跨渠道单价一致、原始 provider 证据保留、A/C 卡不联动。

### 7.4 2026-10-20 第三轮修订：配置弹窗回归与高级区降级

本节优先于前文与 §7.3 的冲突表述；2026-10-20 经用户确认，当晚进一步裁决把配置放回同一个弹窗：

1. **共用配置弹窗**：设置页与 D 卡共用**一个弹窗**（`UsageConfigDialog`）。设置页用「打开配置」按钮触发；D 卡「管理配置」直接打开同一弹窗。弹窗上半为供应商/模型条目，下半为可折叠的高级覆盖（默认收起，展开才挂载四价覆盖）。弹窗内容只在打开时挂载并拉取观察条目，关闭即卸载、不再新发查询。设置页与 D 卡是两个 WebView；设置页修改后已打开的 D 卡不保证立即刷新，D 卡内配置是主路径。
2. **配置内容**：主区只保留「供应商/模型条目」（供应商名、模型名、计价身份，行为同 §7.3）；高级区只保留**四价覆盖**。计费归属绑定 / 参考价规则属于旧版能力，从配置弹窗移除，入口收在「记录」页页脚的「高级：计费归属与参考价规则」；后端表、已有配置与记录页组件不删除（详见 §7.5）。
3. **帮助说明**：使用 Radix Tooltip（全局 Provider + Info 图标）。配置弹窗、供应商/模型条目、计价身份、高级覆盖、四价覆盖、覆盖模型名、旧版说明均有 hover/focus 浮窗；说明只读，不改变布局。弹窗打开时初始焦点落在标题（`tabIndex=-1`），避免 InfoTip 的 Tooltip 先消费 Esc。
4. **四价覆盖口径**：按**归一化模型名**全局生效，优先级最高；不需要供应商；自定义显示名不参与匹配；不在计价身份或参考价规则里选择。模型条目提供「覆盖此模型价格 / 编辑覆盖价」快捷入口，自动预填原始模型名（保存时后端归一化）；已有覆盖时显示「已应用四价覆盖」徽标。空模型禁用入口。
5. **数据契约**：`ObservedModelEntry` 增加 `normalizedModelId`（后端机械归一化；空模型空串），供快捷入口预填、已有覆盖查找与徽标使用；前端不复制归一化逻辑。
6. **保守契约不变**：无全局费用总额/渠道小计、缺价≠0、同模型同币种同价、原始 provider 证据、A/C 互不影响、账本零改动。

### 7.5 2026-10-21 修订：记录页渠道展示与入口收敛

本节优先于前文关于「记录页行名恒为原始供应商/模型」「未归属行指定渠道 / 已归属行修改关联 / 含糊行查看规则」的表述。

1. **行名别名优先**：记录页卡内行显示 `供应商显示名 / 原始模型`；无别名时回退原始 `供应商 / 模型`（空 provider 无别名仍为裸模型名）。原始 `row.label` 始终保留在 `title` 与行数据中，账本与 IPC 身份不变。同一行映射出多个显示名（project 卡跨工具聚合）时保守回退原始 label；自定义模型名不进入记录页行名（记录页只应用供应商别名）。
2. **计费入口收敛**：普通行（`unassigned` / `observed` / `assigned`）不再显示「指定渠道 / 修改关联」；只有 `ambiguous` 行显示「绑定计费归属」（仍打开 `BillingAssignmentDialog`）。所有行保留「供应商显示名 / 编辑」入口。
3. **旧版管理器降级**：`BillingProfilesManager` 不再从行内「查看规则」打开，改为记录页页脚的「高级：计费归属与参考价规则」入口；后端表、历史配置与撤销能力全部保留，不删除、不迁移。
4. **文案去歧义**：别名层统一称「供应商显示名 / 供应商别名」；计费绑定层统一称「计费归属」；`BillingProfilesManager` 标题改为「计费归属与参考价规则」。
5. **同步口径**：记录页别名浮窗与配置弹窗写同一张 `usage_provider_alias` 表并共用 `["usage"]` 失效链，同一窗口内保存后行名与看板立即更新；设置页与 D 卡跨 WebView 仍不保证即时刷新（本轮不新增广播）。
6. **非目标**：不改后端 schema、不改账本/游标/采集、不改变显式计费绑定的语义；不允许通过别名替代「同一原始 provider 串拆订阅」的显式绑定。
