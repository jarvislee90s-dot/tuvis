# 自动适配与匿名上报设计审查记录

日期：2026-10-23。审查原稿提交 `53bef53c`，产品代码基线 `e98caa16`。

## 审查方式

- `design_state_review`：只读审查状态流、队列、时限、Unknown、重启与人工恢复。
- `design_reporting_review`：只读审查诊断隐私、报告归并、GitHub 竞争及匿名中转的追加契约。
- 主 Agent：修订设计、编写计划，随后自行逐项核查设计覆盖、接口所有者、步骤可验收性与计划比例；未派子 agent 代替计划自查。
- 用户在审查期间追加：手机从电脑取得摘要；匿名中转免 GitHub 账户；关键中转选型在设计阶段确定；外部平台尽量控制在 1—2 种。

## 发现、处置与任务归属

| 问题 | 风险 | 设计修正 | 计划验收归属 |
| --- | --- | --- | --- |
| 暂停硬门与“本条先发送”相互矛盾 | 新意见永远被拒绝或全局解锁旧队列 | 绑定新动作、持久一次性越队授权 | S2/S5 |
| 已受理缺 turnId 没有恢复出口 | 不再 Unknown 却永久冻结队列 | 后续补绑；独立人工运行屏障解除，不重发已受理消息 | S4 |
| 人工继续没撤销旧未来写出权 | 旧编排恢复后与新动作双投 | 撤权、解除指定屏障、建唯一后继一致完成；跨重启守卫 | S4 |
| 不完整报告被客户端查重挡住 | 不同故障被泛 timeout 误吞 | 完整且有效才自动归并；待分类允许独立提交 | R2/R3/R5 |
| 自动关闭后改指纹无法恢复 | 独立问题隐藏在 closed 历史 | 可信自动关闭归属、编辑与补扫撤销过期归并；人工关闭优先 | R6 |
| GitHub create 成功但响应丢失 | 中转重试重复建单 | 持久 claim、待确认、只读恢复、同指纹创建屏障 | R3/R4 |
| 票据/TTL 截断已受理恢复 | 用户失去编号或重复提交 | 首次受理期限与查询分离；终态 30 天、未决最小墓碑保留 | R3/R5 |
| 仓库级锁跨慢网络 | 单一慢请求阻塞所有报告 | 只串行化状态变更，外部请求有界且不持状态锁 | R3 |
| 手机错误与电脑诊断来源分离 | 未配对泄漏、离线乱填、跨机器草稿 | 已有配对通道仅给白名单摘要，离线标缺失 | R1/R5 |
| 无 GitHub 账户不能提交 | 原直提流程不能覆盖普通用户 | 官方匿名反馈页与中转返回编号 | R4/R5 |
| 中转平台/依赖膨胀 | 执行期架构返工和维护面扩大 | 固定 Cloudflare＋GitHub 两平台、无管理后台 | R3/R4/R7 |

主 Agent 自查另补：明确 NotSent 后的用户重试与运输重试分开；新自动适配键不误读旧实验键；本地 7 天诊断清理不删除已受理回执；自动关闭归属不能由用户正文伪造。均已归入相应验收。
