# Windows TPS短窗口与当前回合补测提示词

你在Windows上补测Tuvis模型速度采集。找到上轮`runtime-probe-windows.md`，只补未闭环入口和短窗口能力，不重复全量历史调查，不实施暂停的旧产品计划。先读实际仓库AGENTS.md；区分原生Windows、WSL、CLI/桌面/IDE宿主及版本，不混目录或时钟。

## 最新目标

用户关心当前模型调用/用户回合的TPS以及最近1—2分钟、10分钟、1小时的吞吐；最长不超过当天。只统计有有效生成时间的样本，缺失不补0、不追求全量。区分A生成中滚动速度、B最近完成调用、C当前回合有效调用加权速度、D近期窗口加权速度，不能把事后可算等同生成中可见。

## 授权与边界

允许独立试验目录、小型loopback统计接收器和最小观察插件。一次性统计注册先备份原值、生成具体变更并汇总给用户一次确认，之后由Agent完成；用户只点击原生批准/信任界面，不手写配置、不复制命令。保留已有统计出口和Hook，冲突不覆盖。

不改API地址、Key、provider、网关、代理、证书或认证；不改安装包、不注入、不解密抓包、不启管理员服务。不要主动关闭或重启Harness/Tuvis；等待用户自然重启对应后台服务/CLI/桌面实例后继续观察。不要将新app-server或WSL实例当成用户原会话。新真实请求由用户在独立会话自然发起，不向工作会话注入，不做终端注入/屏读，不批量跑基准测试。

不启动tauri:dev，不调用真实Tuvis采集/迁移，脚本不写真实账本。只读数据库尊重WAL；现有正常请求产生的工具日志是观察对象。只持久化白名单时间/数字/脱敏ID，不输出正文、配置、环境变量或进程完整命令行。无论统计端是否在线，都不能阻塞Harness；不额外安装系统守护进程。

## 定向补测

1. **OpenCode 2.1.2或实际版本：实际加载最小server插件。** 上轮残留v1 SDK不能证明当前事件。核对当前官方接口，捕获同session+assistantMessageID/step的开始、非空text/reasoning/tool-input delta、结束tokens及retry；优先宿主时间，不装TUI插件。验证现有正常TUI确实发事件。未完成插件启用/自然重启时标“未测”，不根据旧SDK直接宣布没有事件。
2. **Claude当前版本：正式本地遥测动态观察。** 在统计注册允许范围内启用官方遥测并接收一条自然新调用的请求/尝试身份、duration/ttft/first_content/output。不要启用raw body。上轮“块窗337.5/348.4 TPS”不能当目标口径：首块完成前已生成的Token缺对应时间。核实原生计时基线，首消息/块开始不是首非空delta；不足就给缺口，不靠thinkingDurationMs倒推发包。
3. **Codex当前实际宿主：启用支持的runtime_metrics及metrics出口。** 不覆盖已有analytics/exporter，不改变API或强迫HTTP/WS切换。等待自然重启，观察当前provider是否真返回服务器timing及count/sum/模型标签。不能把回合TTFT当请求TTFT，不能以全部turn输出除部分item窗口。逐response给出Token与窗口配对证据；没有配对的同时排除Token和时间。TBT/总推理时间未证实含义时不改名为生成时长。
4. **WorkBuddy正常桌面实际路由：补新的有效样本。** 上轮只有一个10月11日CLI日志9组，不能代表daemon/ACP或当前工作路径。自然新请求后核对qua.enqueue/start/end、ttft_ms、total_cost_ms、completion_tokens、finish与身份，优先取得有一定输出量的成功样本，不用6 Token单例宣称平均速度稳定。只在CLI有数据就明确局部支持，不能为了采集改正常工作路由。官方SDK性能JSONL开关只能在核实统计作用并按一次确认流程后使用。
5. **Kimi当前版本：验证一条新成功调用的原生阶段计时。** 同step关联usage与llmFirstTokenLatencyMs/llmStreamDurationMs，确认output是否包含思考；无attempt字段不代表没有SDK内部重试。外层retry与内部retry分开说明，不让错误/取消进入速度。
6. **DSH/ZCode：只补近期新样本及短窗。** DSH首点改取首个非空思考/正文/参数，不用block-start；重试若能以retry-started及最终成功stream无歧义对齐，可单独报告成功尝试，否则排除。ZCode仅有F的有效响应计算生成TPS；纯工具参数缺F的行排除，不用请求总耗时替代。模型与工具窗口分开，保留有效样本量。

每重点工具先取1个成功流式新样本；成功后最少观察一次工具调用后继续生成、一次用户正常取消。自然重启/信任确认需要用户动作时说清具体动作，随后继续；不要反复只报告“开关未启用”。

## 短窗与当前回合验收

用同批已收到事实即时重算60/120/600/3600秒及当天，不为取1小时数据硬等1小时。每窗给n、总有效生成Token、总生成毫秒、加权TPS、平均首token、最近有效完成时间、样本年龄。无近期样本显示暂无，不沿用旧TPS冒充当前。当前回合按模型/渠道ΣToken/Σ生成时间，不用回合墙钟，也不跨模型相加TPS。

若只有最终usage，明确B/C/D事后可用而A不可精确；有增量估算可另列算法/误差，不混入最终供应商Token统计。思考包含关系按源验证，包含则不重复加，互斥才同窗相加。失败/取消、已识别但无法对齐的重试、非法/零生成窗均排除速度。

跨短窗长请求不裁切Token；同时给“完整在窗内”及“完成时落窗整条纳入”两组数量和TPS，用结果反馈短窗是否容易空，不自行决定正式规则。插件如能本地存最小事实，Tuvis退出后可回填；纯易失事件只统计连接后所见，不阻塞Harness、不伪造断连数据。
