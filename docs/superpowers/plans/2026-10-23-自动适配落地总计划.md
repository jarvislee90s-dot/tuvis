# 自动适配与匿名上报落地总计划

> **给执行 Agent：** 必须使用 `superpowers:executing-plans`，或在用户明确授权子 agent 执行时使用 `superpowers:subagent-driven-development`，逐任务实施。步骤使用复选框跟踪。用户选择由外部执行 Agent 实施、本会话 review；不要在设计会话直接开始写产品代码。

**目标：** 交付默认可用且可恢复的 Codex Desktop 自动适配，以及所有工具均可使用、无需 GitHub 账户的适配报告渠道。

**架构：** 发送与诊断分包实施；本地仍由 Tauri/Rust 管理状态，React 提供移动端和桌面入口。匿名中转固定使用 Cloudflare Worker＋SQLite-backed Durable Object＋Turnstile，GitHub App 代提交，Actions 最终去重；不另做管理后台。

**技术栈：** 项目现有 Tauri 2、Rust、React/TypeScript、SQLite；中转采用上述 Cloudflare/GitHub 平台，内部库、模块和测试实现由任务 owner 选择。

**设计依据：** [自动适配与适配问题上报设计](../specs/2026-10-23-自动适配与适配问题上报设计.md)，含末尾审查修订摘要。

## 评审重点

1. **连接 A 的旧证据在 B 上生效**：S1 的定序测试必须证明迟到探测、恢复加载及 schema 推送不跨指纹/epoch 解锁。
2. **pending＋idle、暂停队列与新意见冲突**：S2 验证服务端硬门及一次性越队授权，不能全局解锁旧队列。
3. **30 秒超时与人工继续交错**：S3/S4 覆盖部分写入、旧请求未写出、已受理无 turnId、多设备并发和重启，不能双投或永久冻结。
4. **报告创建成功但响应丢失**：R3/R4 验证 claim 后崩溃、GitHub 已创建后超时、票据/记录过期、不同指纹并发，不能重复 create 或全仓库卡死。
5. **错误自动归并或公开敏感信息**：R1/R2/R6 覆盖秘密诱饵、字段不足、指纹伪造、自动关闭后编辑与维护者主动关闭，不误吞问题、不越权。

以上每项在对应任务中都有明确断言，不以“注意边界”替代测试。
