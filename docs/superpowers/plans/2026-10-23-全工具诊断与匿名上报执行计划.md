# 全工具诊断、匿名中转与 GitHub 实施计划

> **给执行 Agent：** 使用 `superpowers:executing-plans`，或经用户授权使用 `superpowers:subagent-driven-development`。每任务单独验收、提交并停下 review，不跨过依赖任务。

**目标：** 手机或桌面用户无需 GitHub 账户，也能主动提交安全诊断并取得公开工单编号；完全相同问题最终只保留一个开放工单。

**架构：** 电脑采集白名单摘要、已配对手机取摘要；官方反馈页与 Worker 接口同源，Durable Object 持久协调，Turnstile 防刷，GitHub App 代提交，Actions 最终去重。维护者只在 GitHub 处理，无额外管理后台。

**技术栈：** 本地沿用 Rust/Tauri/React/TypeScript；中转固定 Cloudflare Worker＋SQLite-backed Durable Object＋Turnstile，授权固定 GitHub App。其余内部库/测试框架由执行 Agent 选择并解释依赖。

**设计依据：** [设计稿](../specs/2026-10-23-自动适配与适配问题上报设计.md) §7—9、§11、§14；同时阅读[总计划](2026-10-23-自动适配落地总计划.md)中的全局约束、接口登记和 review 门。

## 全局约束

继承总计划全部约束。只引入 Cloudflare＋GitHub 两个平台，不另做登录、数据库或反馈平台；生产凭据不进代码、客户端、日志和报告。主动公开确认前不外发诊断，GitHub 不可用不能影响发送/审批。

## 评审重点

- R1/R5：配对吊销、手机断线、切机器、日志中有 token/命令/路径时不越权或泄漏。
- R2：同版本不同故障可分开；缺字段不被自动当成重复；跨 Rust/浏览器/Worker/Actions 规范一致。
- R3：GitHub create 已成功但响应丢失、claim 后崩溃、不同指纹并发、TTL/密钥轮换不双建、不截断恢复。
- R4：匿名滥用、防刷重放、库/账户配置失效及超额时安全拒绝而非绕过。
- R6：工单并发、分页、自动判重后编辑、维护者关闭和 stale 规则不误关或反复重开。

## Task R1：所有工具的本地安全诊断与手机读取

**文件：** 新 `src-tauri/src/services/diagnostics/`、`commands/diagnostics.rs`、`remote/` 内配对端点及 lib 注册；复用现有 adapter 元数据、审计和错误事件；新增诊断单测/远程权限集成测试。

**功能点：** 白名单快照、7 天及容量限制、全部受管工具的基础报告；手机通过已有配对通道拿摘要，电脑离线不补造。

**输入：** 现有工具标识/版本来源，S1/S3 可用的结构化状态。**输出：** 安全快照模型、读取/冻结预览入口、离线/权限结果；登记字段和 API 给 R2/R5。

- [ ] 红测：把正文、命令、路径、环境变量、token、cookie、threadId/ownerId 混进原始事件，输出仅剩白名单；每个已注册工具可生成基础报告，缺版本如实未知。
- [ ] 红测：未配对和已吊销手机拒绝；不同设备/机器草稿不串；7 天/1000 条/10 MiB 先到上限即清理新诊断，不删业务动作或真实账本；冻结预览不被后续事件覆盖。
- [ ] 实现独立诊断生成/存储及认证端点，选用现有可复用事件，禁止新增“上传整个日志/DB”的便捷路径。接入工具清单从实际注册表枚举并在交付记录列明。
- [ ] 执行 `cargo test --lib diagnostics`、相关远程权限测试及 `cargo check`；新增目标非 0，秘密诱饵断言和全部工具矩阵通过。
- [ ] 提交、登记安全 DTO/接口和存储保留策略，停下 review。

**验收：** 报告从电脑取得但只含安全摘要；本地诊断失败不干扰业务，手机无需下载日志。

## Task R2：报告协议、完整故障指纹与跨端一致性

**文件：** diagnostics 中报告/指纹模块；新共享规则与测试向量（建议 `shared/diagnostics/`、`tests/fixtures/diagnostics/`）；新 `scripts/diagnostics/` 可复用规范化实现；相关 Rust/Node 测试。

**功能点：** 冻结版本化机器段和归并资格，统一版本/枚举规范化、稳定 hash，区分报告编号与故障指纹。

**输入：** R1 安全快照。**输出：** 字段清单、完整/待分类判据、规范化字节规则、指纹算法版本、共同测试向量及中转/Actions 消费入口。

- [ ] 红测：相同结构特征只改描述/时间/耗时/本地编号指纹不变；同 build＋Tuvis 的读取/发送/审批或明确未投递/Unknown 指纹不同；Desktop/CLI、alpha 版本不被抹平。
- [ ] 红测：缺关键版本/故障细分只得待分类，不能阻断新建；粘贴其他指纹但机器段不匹配不能判确定重复；版本原始输出携带路径/秘密不能作为版本外发。
- [ ] 实现报告协议与规则，逐字段确定大小/字符/缺省/排序/Unicode 等规范；不把随机 hash 当作“已证明同根因”。内部模块选择自定，跨端必须消费同一规则或共享测试向量。
- [ ] 运行 `cargo test --lib diagnostics` 与规则 Node 测试（登记准确命令）；同一向量在 Rust、浏览器/Worker 可用实现、Actions 实现中逐字节一致。
- [ ] 提交、将协议/共同向量入口登记到总计划，停下 review。

**验收：** “所有工具都能报告”和“仅完全相同特征自动归并”同时成立；待分类不会被一个泛 timeout 工单吞掉。

## Task R3：Durable Object 提交协调与不确定结果恢复

**文件：** 新独立 package `services/feedback-relay/` 的协调器、存储、票据、GitHub adapter 及 fake 测试；该 package 的锁文件和开发脚本随任务交付。

**功能点：** 选定 SQLite-backed Durable Object，不引入第三方数据库；实现 reportId/指纹创建权、签名票据、持久提交状态和恢复；GitHub HTTP 实现可在 R4 接线。

**输入：** R2 报告规范。**输出：** R4 使用的 prepare/submit/status 领域接口、状态 DTO、GitHub adapter 缝及配置清单；实现后登记准确名称/签名和失败语义。

- [ ] 红测：同票据并发 20 次仅一个 create；同编号异摘要拒绝；不同 reportId 同完整指纹复用/等待同一创建；已有开放工单返回原编号且不逐次评论；只有已关闭历史允许新复发。
- [ ] 红测：GitHub 已创建但返回丢失、成功落库前中断、claim 后实例重启均不自动再次 create；只读暂未找到仍待确认；已受理超过 7 天仍可查，终态 30 天清理不释放未决指纹墓碑；新 reportId 不能绕过墓碑。
- [ ] 红测：慢 GitHub 请求不阻塞其他指纹；状态锁在外部 await 前释放；明确零 GitHub 调用证明与不确定写入分开；容量耗尽拒绝新 claim，不删除未决屏障。
- [ ] 实现并提供 `pnpm --dir services/feedback-relay test`、`pnpm --dir services/feedback-relay check`，两命令实际通过；使用真实 DO 存储测试或可验证本地模拟，不只测一份与实现脱节的 Map 算法。
- [ ] 提交、登记存储状态、票据/密钥轮换、TTL 与恢复接口，停下 review。

**验收：** 重试不会因为 GitHub 搜索索引延迟而双建；“未受理/待确认/已创建/已关联”可恢复且不混淆。

## Task R4：官方反馈页、Worker API、防刷与 GitHub App 接线

**文件：** `services/feedback-relay/` 的 Worker 路由、静态反馈页、Turnstile/限流/GitHub App 适配、部署配置样例及测试；不填写生产秘密。

**功能点：** 无 GitHub 账户的用户能预览、公开确认、受理、提交、查看状态；正式端点职责为 prepare/submit/status；GitHub App 只能固定仓库。

**输入：** R3 协调接口和 R2 协议。**输出：** 给 R5 使用的冻结外部协议、同源官方反馈页与环境配置文档。

- [ ] 红测：未主动确认不外发；fragment 读取后清除，摘要不进 query/分析日志；HTTP 无响应 15 秒内结束等待，已有票据只查原状态，不变 reportId 重投。
- [ ] 红测：伪造/过期/重放 Turnstile、错 hostname/action、32/8/4 KiB 超限、同源/来源校验、防刷不可用、IP 5/10 分钟、仓库 100/日、查询 30/分钟均在 GitHub 写前拒绝或限流；已有受理状态查询不误当新报告。
- [ ] 实现官方静态页与 Worker 同源 API，优先原生 HTTP/Web Crypto；GitHub App secret/短期 token 仅服务端，客户端不能传 repo/API URL/回调去越权；若接事件则验证 webhook 签名/仓库/幂等。
- [ ] 运行 relay 的 `test`、`check`、本地构建及秘密扫描；配置缺失必须明确 unavailable，不能假回真实编号。模拟 token 失效、GitHub 限流/5xx/超时/响应丢失，验证不影响业务且恢复规则符合 R3。
- [ ] 提交协议、资源与权限清单、依赖理由；停下 review，不自行部署生产。

**验收：** 新匿名路径不要求用户 GitHub 身份；中转返回真实 Issue 编号或准确待确认状态；两平台上限和数据最小化可审阅。

## Task R5：手机/桌面报告入口与电脑摘要闭环

**文件：** 新 `src/components/diagnostics/`、`src/lib/api/` 报告入口；`src/mobile/SessionDetail.tsx`、设置入口和中英文 locale；新手机/设置报告测试。

**功能点：** 现场错误带入安全故障引用；设置可选任意受管工具；配对电脑取得摘要、预览、描述、转官方反馈页、持久票据及手动查状态/重试。

**输入：** S5 现场入口、R1 快照、R2 格式、R4 端点协议。**输出：** 用户无需文件操作或 GitHub 账户即可报告；与业务发送状态完全隔离。

- [ ] 红测：手机取摘要经过配对/吊销门；切机器/会话不串草稿；电脑离线标信息缺失而不假造；7 天清理只删本地报告；正文/命令/路径从任何现场都不能混入预览机器段。
- [ ] 红测：打开反馈页不写“已提交”；准备票据先本地保存再 submit；用户关闭/刷新后能查原状态；7 天诊断清理不删已受理回执，票据到期仍可只读查；待确认只读查询，明确未受理才可重试；待分类可独立提交且同指纹不逐次刷评论。
- [ ] 实现公开预览与双平台入口、结果编号/链接、不可达/限流/过期/待确认文案；不再出现“必须登录 GitHub 才能报告”，不默默退回客户端内置 token。
- [ ] 运行 `pnpm check`、`pnpm build:mobile`、报告相关 Vitest；覆盖桌面设置和移动端，真实机器未部署时清晰显示不可用，不假成功。
- [ ] 提交 UI 验收路径及协议接线说明，停下 review。

**验收：** “手机故障、电脑诊断”链清楚，用户只确认公开内容，不需要复制整份日志；中转故障不改变原发送结果。

## Task R6：GitHub 最终去重、编辑恢复与 stale 豁免

**文件：** 新 `.github/workflows/` 适配报告归并工作流、`scripts/diagnostics/` 脚本与测试、专用 `.github/ISSUE_TEMPLATE/`，修改 `.github/workflows/stale.yml`。

**功能点：** 最终每完整指纹一个开放工单；保留历史与复发；防止待分类误吞、自动关闭后编辑藏住独立问题。

**输入：** R2 规则/向量；R4 固定仓库和机器人报告格式。**输出：** 可在默认分支启用的 workflow、补扫入口、操作手册；不依赖匿名提交一定触发所有自生成事件。

- [ ] 红测：两条同时 open 保留最小编号；只有 closed 历史可新建；分页、索引迟到、重开/编辑、事件合并后全量补扫仍最终收敛；重复运行不刷评论。
- [ ] 红测：待分类、伪指纹、PR 混入 issue API、未知模板不误归并；自动关闭后改指纹/变待分类恢复开放；关闭最后重读后又编辑仍能补偿；维护者主动关闭保持关闭，正文伪造机器人关闭标记不触发重开。
- [ ] 实现持久可识别的自动关闭归属与归并规则；不执行用户正文、不拼接 shell、不拉取任意 URL，权限最小；适配报告免 stale 自动关闭，普通旧工作流行为不回退。
- [ ] 运行脚本/规则测试和工作流配置检查，记录准确命令；先 fake API 验证所有分支，再由 R7 在受控仓库验证事件/权限；不在真实用户 issue 上压测。
- [ ] 提交并停下 review；工作流未进默认分支前，不声称生产去重已启用。

**验收：** 去重是最终一致且可恢复的，不靠一次客户端搜索；自动化不推翻维护者明确关闭，也不永久藏住后来修正的独立问题。

## Task R7：受控部署、权限与运维出口

**输入：** R3—R6 已 review 通过；用户可用 Cloudflare 账户/域名、GitHub App 安装权限。**输出：** 受控端点、验证记录和生产启用/回退材料。缺少账户资源就精确标出，不虚构配置。

- [ ] 交付生产配置与默认分支 workflow 启用步骤，生产创建/公开上线作为最后独立授权步骤。提交报告，停下本会话 review，不自行发布或合并。

**验收：** 实际平台可用性有证据；没部署、没权限或 workflow 未激活时明确待验，不把代码测试绿当作匿名上报服务已可用。通过后进入总计划 H1。
