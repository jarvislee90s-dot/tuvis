日期：2026-10-23；2026-10-24 更新。状态：双平台 P0-R 已回报；Windows 另有获授权 E1—E4 实测；主干接入与手机验收未完成。维护者：本对话协调 Agent。

目标：以 Mac、Windows 安装版证据决定看板恢复、发送、审批／问答、打断和新建的后续任务。本文是开发取证手册，不是产品用户手册，不代表能力已交付。本轮只交付文档，不修改产品代码。

## 4. 通用操作纪律

1. 先读 AGENTS.md 和 MASTER-PLAN，记录仓库 SHA、分支、脏状态及 Tuvis 运行版。禁止修改宪法、真实权限／凭据、全局配置、真实会话行；不升级安装版、不启动 Tuvis dev、不改 usage 采集。
2. run_id＝平台＋含时区时间＋随机短码。私有目录：Mac ~/Documents/tuvis-verify-logs/zcode/<run_id>/；Windows 用户 Documents 下 tuvis-verify-logs/zcode/<run_id>/。内含 raw/、sanitized/、report.md；追加新轮次，不覆盖旧记录。
3. P0 不运行 prompt（包括 hi 和空串）、不建会话、不接管当前线程、不审批／打断、不重启 APP、不启动 app-server。doctor 和协议握手不能默认当只读；先看实现，有副作用则跳过。help／version 同样先确认早退路径。
4. 不输出全量进程命令行／环境／配置；它们可能含凭据。只报告白名单字段、文件 hash、键存在性和结构。报告不含正文、真实会话／请求 ID、账户、绝对工作路径、token／cookie、provider 配置值；用本机私有映射的别名。
5. 活 SQLite 只读连接；需要副本时用 SQLite backup API，不只拷贝主文件遗漏 WAL，不强制 checkpoint。禁止直接 UPDATE／DELETE。近期主会话最多 100，每会话最多 200 条消息，记录耗时，不全库扫描正文。
6. 区分 DB 候选、解析门、adapter 结果、HTTP 返回、界面。模拟 parser 查询不是产品出卡。无现有认证接口则 NOT_TESTED，不绕过配对、不改隐藏／已读设置来造结果。
7. 后续真实写探测只用明确开放的专用项目／会话。优先影子目录，但须验证实际落点隔离；若无法隔离则回报，不用生产线程。测试项目注册需用户在场确认，不直接写 recentProjects。只清理本轮专用产物，不删真实历史。
8. 每次写预期和反例，一次变一个条件；仅停止本轮创建且 PID＋启动时间＋映像核对一致的子进程，不用宽泛 pkill，不杀其他 Agent 或用户 APP。
9. Windows ZCode 桌面是 APP／无头面，不套 WriteConsoleInput／屏读按键实验。若另立 TUI 或屏读任务，必须使用项目 win-console-inject-probe 技能。
10. 新起协议进程不等于附着 APP 当前实例；杀 Tuvis 子进程不等于打断 APP 原生回合。权限档不是审批应答。可展示请求不等于可写决策。
11. 任何超时／断链都先判受理证据；只有明确零投递才可讨论自动重试。P0 不发消息探测能力。后续模型调用次数、测试副作用逐项记账。

## 6. 回报、汇总与阶段决策

1. 用户将两份提示词和手册包分别发给两平台 Agent。可同时取证，但不互相修改共享文档。
2. 每端按模板输出 report.md，首轮 P0-01～06 必须每项有一行，P1—P4 写未开放。
3. 用户回传报告及必要 sanitized 附件。本对话不要求 raw、不自动发布 GitHub 工单或发送跨对话消息。
4. 协调 Agent 检查指纹、用例 ID、预期／实际／负例、证据类型及复现步骤；只补缺格，不要求全阶段重跑。
5. 脱敏报告后续原样归档到本目录 reports/<platform>/<run_id>/；下表追加摘要，不覆盖历史。
6. 按能力与平台给 GO／GO_WITH_LIMITS／NO_GO／NEEDS_EVIDENCE、任务候选、依赖及缺口。阶段完成不等于所有功能 GO。用户再选实现或下一探测阶段。
