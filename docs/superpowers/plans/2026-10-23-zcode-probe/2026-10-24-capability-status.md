## 4. 新发现与约束

### 4.1 Windows 版本口径

APP 3.16.3.8992；静态包字符串 0.16.9；运行 help 为 0.17.0；DB 迁移版本 0.16.9。四者不可互推。Mac 的 0.16.9 目前只是静态指纹，不能推断其运行版本也是这个值。

### 4.2 回执缺口已观察到，根因未定

E4 的 last_assistant／tokens 为 None，而 CLI 直连 JSON 有 response／usage。可以登记“回执不完整”，不能直接定案为 pretty-print 或字段改名。

后续需取得脱敏的实际 stdout／stderr、E4 临时测试／注入缝和执行前后库证据，定位 FrameAccumulator、返回 session ID、store probe 的数据根／时序及字段映射。先确定哪个边界丢值，再修复，不把可选 tokens 缺失直接判成整轮失败。

### 4.3 不移植自动 hi 探针

E4 证明旧 gate 能在该构建下运行，不代表这一产品设计应保留。真实 hi 会新增回合和配额，继续遵守 #174：运行时只读预检，真实实验在获授权的专用测试会话中做。第一次用户发送不能被暗中附加一个测试回合。

### 4.4 测试隔离与产品存储不能混淆

影子 HOME／DB 是探测保护措施；产品 resume 需要接入真实目标会话的存储。不能为了隔离把产品发送重定向到空库，再声称已续写用户 APP 的会话。测试时影子已有会话验证 resume，产品阶段再以用户批准的在册测试项目验证共享存储与可见性。

### 4.5 审批／打断是另一控制面

prompt 单发通道没有双向审批客户端；协议 broker 有该能力。新增协议实例有自己的活动 record，不能控制另一个 APP host 持有的回合。厂商 Web 远控需要账号／配对／云 relay，不应未经裁决成为 Tuvis 默认依赖。

## 5. 切换外部入口前的历史建议顺序

以下是取得用户长期实测确认之前的建议，保留追溯。当前近期路线见 §7 及 [读取恢复与官方远控入口设计（待确认）](../../specs/2026-10-24-zcode-unified-remote-design.md)；不再据本节自动安排自研写通道。

1. 独立修复读取 ID 门，补新旧格式、父子会话／过滤、状态／正文／附件与远程验收。
2. 进入 Windows 发送接入准备：优先验证影子已有会话 resume；定位回执缺口；主干按块复用 #117 的 zcode／runner／receipt／turn，并替换真实 hi 自动预检设计。不要先整包合入再查缺口。
3. Mac 补最小真实启动／发送／resume／取消；两平台证据分别解锁。
4. 接手机发送／取消 HTTP、设备授权、H3、审计、回执和界面，验证同一会话与可见性。手机新建另验身份确认。
5. 审批／问答／APP 打断单独做协议路线裁决和受控实验；自持协议回合与已有 APP 回合分表，不承诺与 CLI 发送同批交付。

不再要求重复一整轮泛化 P0。发送路径已有正面运行证据，下一步应围绕缺口做针对性实验和实现。

## 7. 用户长期实测补充：官方远控外部入口

2026-10-24，用户明确确认：已持续使用 ZCode 官方远控约两个月，前述手机访问、发送、审批、打断、切模型／思考强度及链接复用场景均已实际验证。证据归属：用户直接陈述的长期手工实测；本对话没有重新执行，不伪装成 Agent 运行记录。

据此更新近期路线：

- 官方页面作为外部控制入口可采用，不再为已确认的能力要求新一轮平台探测或重复扫码／发送／重启实验。
- 本节补充的是“用户直接打开官方页面”的能力证据；Tuvis 自己实现协议客户端或自动接管 APP 的表格仍保留其原证据边界。
- 近期产品候选为“Tuvis 看板／正文／文件读取＋按设备保存官方链接＋打开官方远控”，后续设计再明确入口位置与配置归属。
- 剩余工作属于实现后的集成验收：链接按设备正确保存／更新／删除，手机打开预期页面并能返回 Tuvis，未配置时能找到配置入口；不承诺链接自带的设备入口可精准定位任意 Tuvis 卡片对应线程。
- 不把官方跳转入口标成 Tuvis 原生消息投递、审批应答或 F2.3 已完成。无需因此继续自研通道的运行探测。
