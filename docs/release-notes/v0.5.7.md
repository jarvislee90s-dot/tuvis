# v0.5.7 发布说明（2026-10-13）

> v0.5.6 正式版以来的全部变更：开机自动启动、桌面看板按工具筛选、设置页重组，
> 以及针对安装版「打开目录/文件报错」与 codex 桌面 APP 会话误操作的修复。
> 升级后无需任何手动配置。

## 新功能

- **开机自动启动**：设置页「通知与桌宠」块新增「开机启动」卡，系统托盘的「显示窗口」
  下方也加了同名勾选项——两处共用同一条读写路径，勾选状态始终一致。开关显示的是
  **系统里的真实状态**（Windows 读注册表启动项，含任务管理器里的启用/禁用标记；
  macOS 读登录项），不是本地记的一笔账，所以不会出现「界面显示已开、其实没开」；
  万一设置失败会自动回滚并如实报错。开机自动拉起时主窗口**静默进托盘**、桌宠照常跟出，
  不会开机弹一屏。Windows 卸载时会清掉本用户的启动项；macOS 目前没有卸载钩子，删掉
  应用后如需彻底清理，请手动移除 `~/Library/LaunchAgents/` 下对应的 plist。
- **桌面看板按工具筛选**：桌面看板标签栏下方新增「全部」+ 8 个工具的筛选 chips 单选，
  图标与文案跟卡片徽章同源。选择会记住（下次打开仍是上次的工具），计数条始终显示全量，
  筛到空时如实报出工具名而不是给一块空板。
- **设置页重组**：一级块标题左侧加了强调色条与大字，13 张设置卡统一为灰底卡头条；
  块序重排为 通知与桌宠 → 外观与皮肤 → 远程接入 → 用量统计 → 工具与体检 → 数据管理，
  默认停在「通知与桌宠」。远程端外观卡改为常展开，桌面端外观卡标题补明「桌面端外观」
  以免两处同名混淆。
- **桌宠「启动时跟出」开关**：控制桌宠是否随兔维斯一起显示，默认开启。关掉它之后，
  下次启动不再自动显示桌宠（这个选择会被记住，不会再被兜底逻辑覆盖）。

## 修复

- **收起桌宠后，它过一会儿又自己冒出来**：旧版启动时先无条件显示桌宠窗口，再由界面按
  上次的记忆把它收回去；而 5 秒后的兜底逻辑分不清「界面还没来得及显示」和「用户就是要
  它隐藏」，于是把刚被收起的桌宠重新弹出来，此后再无人收回。现在显隐由权威标记登记，
  兜底不再覆盖用户的选择（窗口真的卡死时的救援路径保留）。
- **安装版打开目录/文件会报错**：安装版是无控制台窗口的图形进程，此前派发「打开目录 /
  打开 MCP 配置文件」这类系统动作时，子进程继承了无效的句柄而直接失败。现在派发前显式
  置空标准输入输出，并把同类派发收敛到一处。该问题的**根因在代码里仍属未定案**（有两条
  候选机制，需真机取证），但现象已消失；「一键恢复会话」这类需要开终端窗口的路径改动
  前后逐字未变，本轮未在真机复验。
- **codex 桌面 APP 会话的动作「点了没反应」**：codex 桌面 APP（ChatGPT 桌面 GUI）没有
  控制台，兔维斯此前对它走的是面向命令行终端的按键通道——真机上按键发不进去、也读不到
  界面内容、问答还会中途失败。在协议通道落地前，涉及该形态的**模式切换、权限菜单、问答
  作答、审批应答**四类动作现在会在动终端之前直接给出提示
  **「APP 会话该操作走协议通道，开发中——请在 APP 内操作」**，引导你回到 APP 内完成。
  **命令行形态完全不受影响，只能看不能改的功能也照常。** 这些被拒绝的操作会留下审计
  记录，可在设置页「注入审计」里查到。

## 升级须知

- 直接覆盖安装即可，无需手动处理任何配置。
- **收纳过桌宠的用户请注意**：本版新增「启动时跟出」开关且**默认开启**，所以升级后
  桌宠会在每次启动时跟出。如果不想要，到设置页「通知与桌宠」块关掉它即可。
- **开机启动默认是关的**，需要的话在设置页「通知与桌宠 → 开机启动」打开，或在系统托盘的
  「显示窗口」下方勾选。若关闭时提示有管理员权限残留（曾经用管理员身份运行过旧版），
  按提示清理即可。
- codex 桌面 APP 会话的模式/权限/问答/审批动作目前会提示「开发中」——这是有意为之的
  临时限制，协议通道落地后会自动放开。
- 目前仅支持 Windows 与 macOS；Linux 尚未支持。
