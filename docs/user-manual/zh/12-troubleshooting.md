# 故障排查

按「症状 → 可能原因 → 处理」速查。条目按功能分区排列，与正文各章顺序一致（看板与会话 → 通知与体检 → 远程接入 → 安装与数据），先对号入座再动手。

> 自 v0.5.8 起，应用内所有报错统一带**错误码**（中英文案齐备）：反馈问题时请把错误码一并附上，可精确定位。

## 看板与会话

| 症状                         | 可能原因                             | 处理                                                                                                |
| ---------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------- |
| 看板上始终没有某个工具的卡片 | 该工具未勾选启用，或本机没有对应的运行中会话 | 到「设置 → 工具与体检」确认工具已勾选启用；确认终端里确实开了该工具的会话                            |
| 卡片状态灯长时间不变、与终端不符 | Hook 通道未生效，或该工具不支持 Hook、状态只能推导估算 | 完成 Hook 信任后再观察；无 Hook 工具的状态推导存在感知延迟属正常；重启兔维斯后再看                    |

## 通知与体检

| 症状                         | 可能原因                             | 处理                                                                                                |
| ---------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------- |
| 收不到桌面通知               | 应用内通知开关未开，或系统通知权限被关 | 在设置中打开通知开关；检查操作系统的通知中心是否允许兔维斯发送通知                                   |
| 「信号健康度」提示某工具零事件 | 该工具的 Hook 条目尚未信任           | 在该工具的终端输入 `/hooks` 信任兔维斯条目（codex 需在其 TUI 界面内确认信任）；完成后回设置页刷新自查 |

## 远程接入

| 症状                             | 可能原因                                                       | 处理                                                                                                |
| -------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 手机在局域网下连不上             | 路由器开了「终端隔离 / AP 隔离 / 访客网络」；防火墙拦了入站；地址漏了 `/m` 后缀 | 到路由器后台关闭隔离类设置；Windows 放行兔维斯通过防火墙（专用 + 公用都勾）；确认地址以 `/m` 结尾，推荐直接扫码 |
| 手机走隧道时旧链接失效           | 临时隧道的公网地址每次开启都会重新生成                         | 重新开启临时隧道并扫新码取地址；要固定地址请改用「自有域名」或「外部域名（免域名）」通道               |
| 手机页面要求输入访问密码         | 访问密码对全部通道（含本机浏览器访问）一律生效                 | 输入访问密码（新设备输一次，180 天免输入）；扫码接入时密码已含在链接里自动填入                         |
| 局域网地址打开时弹「TLS」确认框   | 局域网直连是明文 HTTP                                         | 勾选表示「我知情 / 我已配 TLS 反代」；家庭局域网直接勾上即可，不需要真配反代                           |
| 自有域名显示「运行中」但域名打不开 | Cloudflare 侧漏配 Public Hostname                             | 检查 Cloudflare 的 Public Hostname（子域 + 域名 + Service 填 `HTTP://localhost:9420`）；设置页「使用教程」有逐步图文 |
| Tailscale 等待公网 DNS | 公网记录仍未发布或负缓存尚未过期 | 保持开启，等待几分钟（可能约 10 分钟）；后台每分钟只读检查，勿反复重开。超时后查看排查提示，只有明确确认的「重新开通」会重置配置 |
| 固定地址显示「尚未生效：地址已解析但连不通」 | 到 Tailscale 海外中继入口的公网链路瞬时抖动（两个入口同设施，常一起失败）；本机开着 TUN / 系统代理类加速工具也可能干扰 | 多数 1–2 分钟内自行恢复——兔维斯每分钟自动复验、恢复后地址自动回来，无需操作；开着加速工具的先关掉再等；持续 10 分钟以上再点向导里的「重试」 |

## 安装与数据

| 症状                         | 可能原因                             | 处理                                                                                                |
| ---------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------- |
| 应用内检查更新失败           | GitHub Releases 访问不畅；或应用仍在 0.5.2 及更早旧版（其更新通道已失效） | 手动到 GitHub Releases 下载最新安装包覆盖安装                                                        |
| 卸载后开机仍自动启动         | 开机自启的注册表项残留               | 任务管理器 →「启动应用」里禁用或删除兔维斯条目；或在注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中删除兔维斯项 |
| 想备份或迁移数据             | 兔维斯数据全部集中在 `~/.tuvis/`     | 整体复制该目录即可（含数据库、设置、日志与技能仓库）；0.5.5 起数据目录一次性 `~/.mam` → `~/.tuvis`，迁移失败时旧数据原地保留并记日志 |

> 💡 以上都对不上时，把日志翻出来对照：兔维斯的日志写在 `~/.tuvis/logs/mam.log`（写满后自动滚动为 `mam.log.old`，可一并翻查）。提 Issue 时附上日志、所用工具及其版本号，更容易定位。
