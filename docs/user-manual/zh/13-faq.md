# 常见问题

每条一句话先给答案，想深入再顺着链接走对应章节。

## 要不要花钱？

不用。兔维斯开源（MIT 许可证）且免费，代码公开，欢迎自行改造与部署。详见[第 01 章](./01-overview.md)。

## 会不会上传我的代码或对话？

不会。兔维斯是 local-first 的桌面应用：所有数据存放在本机 `~/.tuvis/` 目录，没有云端服务器、不发任何遥测；手机看板走的是你自己开启的通道（局域网直连，或你自己的 Cloudflare / Tailscale 隧道）。详见[第 01 章](./01-overview.md)。

## 支持哪些工具？

Claude Code、Codex CLI、OpenCode、OpenClaw、Kimi Code、WorkBuddy、ZCode、dsh 八种。各工具开放程度不同，逐项能力见[第 01 章](./01-overview.md)的能力矩阵。

## 手机端要装 App 吗？

不用装任何 App。开启「设置 → 远程接入」后，手机浏览器打开以 `/m` 结尾的地址即可使用网页看板，入口与配置见[第 08 章](./08-mobile-remote.md)。

## 更新从哪里来？

应用内更新器会提示新版本（更新源即 GitHub Releases），你也可以随时到 Releases 页手动下载安装包覆盖安装。见[第 02 章](./02-installation.md)。

## 卸载干净吗？

Windows 上卸载程序会顺带清理开机自启的注册表项；用户的 `~/.tuvis/` 数据目录会保留在原处，想彻底清掉手动删除该目录即可。升级失败或残留自启的处理见[第 12 章](./12-troubleshooting.md)。

## 为什么有的工具功能少（比如发不了消息）？

各工具的开放程度不同：像 OpenClaw / WorkBuddy 这类黑盒形态工具没有外部写通道，只能监控不能注入；手机注入目前只对 Claude Code / Codex CLI / OpenCode / Kimi Code 四家开放（试验性）。兔维斯如实呈现差异，不假装统一，逐工具能力见[第 01 章](./01-overview.md)的矩阵。

## 用量看板里为什么有的指标是 `—`？

数据不可得的指标显示空态而非 0：「用户输入(估)」只有 claude / codex / kimi 有，WorkBuddy 没有回合概念，dsh 的报错与最长单 turn 依赖原始会话日志（留存比例随清理策略变化）。另外报错是三层分列 + 主动打断单列，互不包含，相加没有意义。口径详见[第 11 章](./11-usage.md)。

## 关闭了用量统计，怎么还能导出 CSV？

导出不受用量总开关门控：关闭后不再采集、不落库，但导的是「已采集的历史账本」，方便备份。该口径不对称是已登记的待裁项，不是故障。详见[第 11 章](./11-usage.md)。

## 看板的红黄绿灯是什么意思？

🔴 红 = 等待你输入 / 待批准，🟡 黄 = 运行中，🟢 绿 = 已完成 / 空闲；卡片按「等待 → 运行 → 空闲」排序。见[第 03 章](./03-quick-start.md)。
