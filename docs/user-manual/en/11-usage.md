# Usage Statistics

One ledger shows at a glance how many tokens each tool burns — collected automatically, read locally, zero telemetry.

## The usage ledger

Tuvis keeps one ledger for seven tools — Claude Code / Codex / Kimi Code / OpenCode / ZCode / WorkBuddy / dsh (OpenClaw is not collected yet). It only reads and aggregates each tool's own session records on this machine and reports no telemetry of any kind; the ledger lives in `~/.tuvis/tuvis.db`, hourly-bucket details are kept for 90 days by default with a 90-day maximum (configurable), and only daily aggregates remain after that.

Collection cadence: one automatic catch-up shortly after app launch, then on the configured interval (single-flight mutex plus a minimum-interval floor — it never rides on the 3-second session polling). **Settings → Usage statistics** offers "collect now" at any time plus a master switch — when off, nothing is collected or written (settings and export keep working, and the export covers the existing ledger). Numeric settings (mini-bar tool rows / detail retention / collection interval) keep a draft while typing and clamp/save only on blur or Enter, so values do not change mid-keystroke.

## Opening the big board

The usage button in the main window's **title bar** opens the standalone usage dashboard window; "Details »" on the pet's minibar gets you there too.

![Usage dashboard](../img/usage-dashboard.png)

The big board contains:

- **Token overview** (always expanded): total processed tokens, new input, cache hit, cache-miss input, output, hit rate and requests, each compared with the previous equal-length window; the former "cache write (explained)" block is removed and meter labels are unified as "new input / cache hit / output / total";
- **Usage trend** (always expanded): a line + gradient area chart whose x-axis granularity follows the time range — peak marked top-right, hover for exact values. The card can filter locally by **All / By tool / By channel**; peak and comparison use the same scope, while the global overview and distribution stay unchanged. Here "channel" means the provider alias (the provider display name, unedited = raw name; an explicit billing binding wins; tools are not a channel dimension; when no alias is configured, non-empty providers aggregate by their raw string; "unassigned channel" and "channel may be mixed" are not filter options);
- **Usage distribution** (expanded by default, collapsible): share bars across **By channel / By tool / By project / By model**, Top 5 by default with "show more"; each row shows name · tokens · cache hit rate · relative bar, with no dollar column. The same display name merges across tools, and identically named models no longer produce indistinguishable duplicate rows; when an empty provider has no assignment, the channel view merges it into one "unassigned channel" row and the model view splits by tool; the channel view also has a "channel may be mixed" row for log identities that may mix multiple accounts and cannot be split; an empty model shows "unknown model";
- **API-equivalent costs** (expanded by default, collapsible): one card per model, with a five-column main row (channel / model | estimate | total tokens | cache hit rate | billing detail), grouped by channel by default with a flat by-model view; no global cost total or channel subtotal (not actual spend); one normalized model shares the same price per currency while different display channels stay on separate rows; the card expands into a four-row × four-column billing detail (new input / cache hit / output / total × item / token usage / amount / unit price — the total row leaves the unit price blank, and a cache-write row appears only when data exists), with solid-foreground main and detail headers and a footnote keeping only the normalized model and the snapshot fetch time; a "Sync prices" button in the card header force-refreshes models.dev + native RMB sources + the daily FX rate (loading / inline status); the header offers a USD / CNY quick switch (display only — the ledger and the cost CSV stay in USD). **CNY prefers native RMB prices and converts at the daily rate when missing; native prices render normally, while converted amounts carry a dashed underline (legend in the card header)**;
- **Work activity** (collapsed by default): the card header shows sessions and tool-call counts; expanding reveals turns, the three error layers, user interrupts and the top tool, while p50 / longest turn / tool duration live in the advanced stats section;
- **Export**: copy as text / export image (a share image including the pet's portrait) / export CSV (UTF-8 BOM, Excel-friendly, structured ledger columns only) / **Cost CSV** (all channel / model cost rows for the current window, no totals, no extra BOM added by the frontend; seven columns — channel key / channel kind / display name / normalized model / catalog release date / override flag / price-rule kind — are appended after the existing 17 columns; the single-value `observed_provider` column is left empty when a row merges multiple raw providers or includes an unlabeled source, with the full evidence available in the UI tooltip). Shared summaries no longer contain "user input (est.)" and now include cache-miss input.

Five time ranges are switchable, with custom spans up to 31 days. The "Records" tab in the same window shows one card per tool, one row per "provider / model" spend, groupable by tool / project, with measured / inferred / unknown markers; **row names prefer the provider alias** ("alias / raw model", falling back to the raw "provider / model" when no alias exists), while the raw identity stays in the title and the row data; **the channel / model dimensions of "Usage distribution" and the "API-equivalent costs" row tooltips** show raw provider evidence — when multiple raw providers merge, the complete list is shown, and groups that contain a non-empty provider together with an unlabeled source are marked "includes unlabeled source" (the tool / project dimensions show no provider evidence); ordinary rows no longer show "Assign channel / Edit assignment"; only ambiguous rows offer "Bind billing attribution", and the legacy billing attribution / reference rules live behind the footer's "Advanced" entry, each row keeping a lightweight "User assigned / Observed / Ambiguous" marker; every row also has a "Provider display name" entry (shown as "Edit" when an alias exists), and the dialog previews the rule's matching tools, models and total tokens for the last 30 days before saving. **Settings → Usage statistics → Display & pricing config** and "Custom price rules" now live in **one shared dialog** (the cost card's "Manage config" opens the same dialog): the settings page and the D card share it, with provider/model entries in the upper part and a collapsible custom price rules section in the lower part (collapsed by default). Settings and the D card are separate WebViews; changes in Settings do not guarantee an immediate refresh of an already-open usage dashboard, and the in-dashboard config is the primary path. Entries default to the top 10 by usage in the last 7 days, sortable by usage / raw provider / raw model (click the same key to reverse), with "show all" and search at the bottom; each entry has three rows — raw identity (read-only), provider name + model name (both editable: a provider name applies globally to the same raw provider, and empty-provider entries write a toolModel alias; model names apply per (display provider, raw model)), and the pricing identity (dropdown / search selection only). The advanced area's "Custom price rules" supports fixed and time-of-day pricing (USD/CNY denominated); legacy billing attribution / reference rules moved to the usage dashboard Records page's footer "Advanced" entry. Every advanced option has an Info icon with a hover/focus explanation; each model entry has a "Set custom price / Edit custom price" shortcut that pre-fills the raw model name (normalized on save) and shows a "Custom price applied" badge when present. **Pricing catalog status** stays in Settings and enables / refreshes the public models.dev catalog, falling back to the last valid snapshot on failure.

## Provider display names (aliases) and automatic pricing

- **Channel display names**: a channel is the provider alias. A non-empty provider maps exactly from its raw string to an alias — unedited = raw name; different raw strings can map to the same display name and merge across tools; an explicit billing binding has the highest priority; aliases only affect display and grouping — they never rewrite the ledger or change the token basis. **When no alias is configured, a non-empty provider aggregates by its raw string.** Records-page row names prefer the provider alias (the raw "provider / model" stays in the title and row data); aliases also appear in the "Usage trend" filter options, "Usage distribution" / "API-equivalent costs", the config dialog and the alias dialog; the channel / model dimensions of "Usage distribution" and the "API-equivalent costs" row tooltips show raw provider evidence — when multiple raw providers merge, the complete list is shown, and groups that contain a non-empty provider together with an unlabeled source are marked "includes unlabeled source" (the tool / project dimensions show no provider evidence).
- **Empty providers**: no automatic rule — set aliases individually for "tool + raw model" entries, and the change applies retroactively once saved; without an assignment the channel view shows one merged "unassigned channel" row and the model view splits by tool; an empty model shows "unknown model".
- **Provider and custom model names**: the provider / model entries section of the config dialog edits both names. A provider name applies globally to the same raw provider (empty-provider entries write a toolModel alias; unnamed = unassigned channel); a model name supports one-click copy of the raw name and clear-to-raw, with the display key (display provider, raw model) renaming all raw sources under it; the custom model name applies only to D-card row names ("Usage distribution" and the records page keep the raw model name; the records page shows the provider alias).
- **Pricing identity**: each model entry can be explicitly pointed at a catalog provider / model — dropdown / search selection only, no free-form input, so illegal keys are impossible; the curated auto-match result is shown by default and can be overridden or cleared; its priority sits below custom price rules and reference price rules, above auto-matching.
- **Known limitation**: when two subscriptions log the exact same raw provider string, aliases cannot split them and the channels stay merged; only the ambiguous row's "Bind billing attribution" or the footer's "Advanced" entry (explicit billing binding) can help, and tokens are never split proportionally.
- **Automatic matching (curated sources)**: only the public models.dev catalog is used (no built-in seed prices), with curated sources ranked **direct official providers (including China-site variants) > OpenRouter**, skipping all-zero quotes; model IDs are mechanically normalized then matched exactly, and within a tier the latest `release_date` wins with one price per currency; when exact matching misses, prefix fallback is used only when the candidate is unique, or when multiple candidates match but all share exactly the same price; cross-family substitution requires an explicitly chosen reference model. Conditional quotes (multimodal input, context tiers, etc.) are estimated at base text rates with a caveat; missing prices still render `—`, never 0. Models missing from the curated set stay unpriced by default — pick a catalog entry explicitly via the pricing identity (the catalog search is curated-only by default, with a "show all N sources" switch).
- **Cost granularity**: costs for the last 7 days / 30 days / custom spans (≤31 days) are computed from hourly details aggregated per day, so dsh is fully priced across input / cache hit / output; when a time-of-day rule exists, hourly buckets are classified as peak/off-peak before aggregation and the row unit price is a weighted average; when a lowered detail retention or cleanup leaves days without details, the whole span falls back to daily aggregation (dsh stays output-only; time-of-day rules are estimated at off-peak rates and disclosed in the accuracy caveats); the last 5 hours / today and the billing-channel preview are unchanged.
- **Refresh and verification**: refreshed daily by default and manually on demand (the D-card "Sync prices" button force-refreshes models.dev + native RMB sources + the daily FX rate); on failure the last valid snapshot is kept and the data source plus snapshot date remain visible; the D-card expanded footnote shows the normalized model and the snapshot fetch time. **A model release date is not a price date** — the catalog entry's release date only drives same-name dedup, while pricing always uses the rates as of the snapshot fetch time.
- **Custom price rules (fixed / time-of-day)**: inside the config dialog's "Custom price rules" you can set prices by **normalized model name**. A fixed rule overrides the input / cache read / cache write / output rates (USD / CNY, stored in that currency; the other display currency is converted at the daily rate and dashed-underlined). A time-of-day rule uses peak rates inside multiple Monday–Friday peak windows (whole hours, cross-midnight allowed) and off-peak rates elsewhere, including weekends; a blank off-peak component falls back to the catalog rate. The time zone can be China Standard Time, UTC or system local and only affects API billing peak/off-peak calculation; a "peak × %" helper fills the off-peak rates. **No provider is needed**; custom display names do not participate; once saved, all channels sharing the same normalized model use the price; it is not selected in pricing identities or reference rules. The list shows the catalog source, release date and snapshot date; later catalog syncs never overwrite user values. When only daily aggregation is available, the whole span is estimated at off-peak rates and the caveat is disclosed.

## Minibar

Hover the pet for about half a second and the popup that appears is the minibar (the pet's right-click "Today's usage" brings it back anytime): its 5 metric rows are pinned in order (new input + hit rate / cache hit + output / four-bucket breakdown / errors / longest single turn); the time range (today / last 5 hours / last 7 days) and the tool row count (1–7) follow the settings; the trailing "Details »" jumps straight to the big board. The "Today" figures in **Settings → Usage statistics** share the same source.

## Collection criteria at a glance

- **Four buckets** = uncached input / cache read / cache write / output; hit rate derives from cache semantics (mutually exclusive / inclusive / totals-only) — when in doubt it assumes mutually exclusive: better an under-reported hit rate than silent over-counting;
- **Total processed tokens = new input + output**; **cache-miss input = new input − cache read** (same formula for current and previous windows; "new input" is the ledger's request total — the basis is unchanged, only the on-screen wording is unified);
- **Sub-agents included**: token totals include sub-agent usage; turns are never summed across tools;
- **Unavailable shows `—`, not 0**: some metrics exist for some tools only. V2 removes "user input (est.)" from the dashboard and shared summaries (it is not API tokens); the ledger field and raw Token CSV column remain for compatibility;
- **Privacy**: the UI and the CSV contain structured numbers plus tool / model / project / session titles only — no raw prompts, no code content.

> 💡 A `—` in a column is not a malfunction — the true value is unobtainable under that criterion; when a hit rate defies common sense it is usually a cache-semantics misjudgment, so attach the tool version when reporting it.
