## C01 · P2（R03 残留）：慢轮询不断换票，后续重启仍永久无法恢复

位置：`src/mobile/useCodexThread.ts:235–238`；固定轮询周期为 3000ms。

每个跨 instance 拒绝都会调用 `mintHandshakeTicket()`，即使已经存在未消费的有效票，也替换成新票。请求重叠时，旧票请求的拒绝会把正确在途请求的票作废，形成稳定饥饿。

**已复现序列：** SSE 建立 A→降级 poll 成功建立 B→服务重启 C。API 每个请求固定 4500ms，poll 每 3000ms 发起。首个 C 响应被拒并补票，随后流水线里的响应不断替换当前票。48 秒后、超过 10 个成功返回的 C 响应后，页面仍显示 B。

这是稳定慢网条件下的可达错误，不是要求猜测任意未来输入；原先低延迟再次重启和同票乱序的正反例已通过，不能据此证明慢请求恢复。

**修复：** 没有有效待消费票时才发放恢复票，旧票请求的拒绝不得作废新票；或者将恢复握手串行化并显式管理其世系。不能通过放开所有跨 instance 响应修复。

**验收：** 保留原禁止面，新增固定 RTT 大于 poll 周期、连续请求重叠、再次重启的真实 hook 测试；有界恢复到 C，迟到 A／B 不装回。独立审阅的失败测试保留在 `/tmp/tuvis-review-slow-handshake-a19b0b1a.test.tsx`，仓库临时文件已删除。

## C02 · P2（R05 残留）：事后记录 Unknown，没覆盖停止帧发出后的取消／崩溃窗口

位置：`src-tauri/src/remote/codex_ipc.rs:4435`、`:4508–4518`、`:4586`。

当前先 await 停止 RPC，返回 Unknown 或等待终态超时后才写 `stop_attempt_reason`。若 writer 已接收／写出 interrupt，handler 在回执到达前被取消，或服务此时退出，原消息仍 queued，暂停行在，但停止标记仍为 NULL。重新调用同一优先请求会再次停止。底层 interrupt 没有 action 账本归属，新的调用使用新 envelope，不能代为消除此窗口。

现有“Unknown 返回后重放／重建 SQLite”测试是有效覆盖，但只证明记录已成功写完之后的幂等。读取标记时忽略错误、写失败仅记录日志，也不能保证该保护成立。

**修复：** 在首次可能写出之前，持久 CAS 占有与原 action／冻结目标绑定的停止尝试。明确首写前零投递才允许释放或进入新的显式尝试；已经写出或不能确认是否写出的取消保持待核对。读／写尝试归属失败时不得继续向 Desktop 发新停止。保留原暂停 token 归属和消息唯一派发语义。

**验收：** 真实 peer 收到 interrupt→取消 handler→重放同请求，累计 interrupt 仍一帧、消息零帧；以同一 SQLite 重建后重复验证。另测首写前明确零投递可以恢复重试，不能因预先登记而永久封死未发送动作。

## C03 · P2（R07 残留）：展示身份仍可能把旧包的 SHA 结论归给新包

位置：`src-tauri/src/services/codex_desktop_ipc/adapter.rs:2401–2405`、`:2413–2423`、`:2817–2821`。

展示记录继承只比较 `(len, mtime_ms)`，不验证内容 SHA；记录中的 capabilityIdentity 却取旧 evidence 的 SHA。

两个缺口：

1. 已识别 A→关闭自动适配→用不同内容但相同长度、保留 mtime 的 B 替换→同 build 重连。stat 相同导致继续发布 A 的 SHA 身份和支持展示，关闭适配又使重新识别不发生，错误可长期存在。现有换包测试仅改变长度。
2. 异步读完 A、安装证据之前包换成 B，展示记录在安装时重新 stat，可能把 A 的 SHA／支持与 B 的文件指纹配对；随后普通重连也会命中。这不需要 B 保留 A 的 mtime。

**影响校准：** 没有证明它解锁写权限，allowed／实时 evidence 的隔离仍在。问题是承诺“同完整身份才继承”的展示归属没有兑现，不应宣传 stat 相等已证明 SHA 相等。

**修复：** 记录使用取证时绑定并核验的包指纹；重连继承之前异步完成一次内容 SHA 核验，可以按连接代际复用，不要求每帧读取整个包。核验未完成时只能如实展示“上次识别结果，当前包身份待核对”，不能把旧 SHA 当作当前已确认身份；该替代展示必须与已确认的当前能力明确区分。

**验收：** 同 len／mtime 不同 SHA 不继承当前支持身份；取证完成→安装前换包不能把 A 结论和 B 指纹绑定；同一未变包重连仍可恢复展示。auto-adapt off、失败门和零新写的反例继续保持。
