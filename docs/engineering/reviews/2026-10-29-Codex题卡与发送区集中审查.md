## R01 · P1：优先处理没有校验 action 与会话的线程一致

位置：`src-tauri/src/remote/codex_ipc.rs:4381`、`:4466`；`src-tauri/src/services/codex_control/router.rs:1004`。

端点只用 `get_for_device(actionId, deviceId)` 验证设备归属，随后按 `sessionId` 解析出的线程执行停止；没有在停止／建授权之前核对动作完整 ThreadKey。router 按 actionId 取原动作，再用请求线程创建 grant，两个来源可不同。

**反例：** 同设备有 A 会话的 queued 动作，提交 B 的 sessionId 与 A 的 actionId。B 若在运行，可能被停止；随后 A 的动作取出，消费与 A 不匹配的授权失败并终态拒绝。它不是未授权设备入侵，但会破坏已授权动作的目标归属和原消息。

**修复／验收：** 在任何停止、暂停、授权或动作 mutation 前，验证设备及完整线程归属；不一致明确拒绝且所有这些面零 mutation／零帧。补两个会话、同设备交叉配对的真实 HTTP 测试，并在 router 接缝保留一致性防御。

## R02 · P2：共享停止控制器缺目标硬门和计时器归属

位置：`src/mobile/useCodexTurnControl.ts:138`、`:157`、`:171`；`src/mobile/CodexQueuePanel.tsx:462`。

1. `stop()` 只检查 stopping，没有检查 canStop。队列入口仍可使用独立 queue GET 的 canInterrupt，因此线程投影已经 stale／activeTurnId 为空时，旧队列确认仍可调用 `stop()`，发送不带 turnId 的请求。后端随后选取服务器当时的回合，失去点击时冻结目标的保证。
2. 旧请求 finally 无条件清共享 timerRef。A 请求挂起→切 B 并发起停止→A 迟到完成，会清掉 B 的 30 秒计时器，B 可永久停留在 stopping。

**修复／验收：** 控制器自身检查当前可执行资格和非空冻结目标，所有消费者复用它，不能只靠按钮隐藏；无目标新入口不允许回退服务器当前回合。timer 由局部 handle 和提交代际共同拥有，旧 finally 只清自己的 timer。补队列可停但投影 stale／目标缺失的零 POST 测试，以及 A→B→A 迟到、B 到期退出等待的定序测试。

第二条已由根审阅用真实 hook + deferred API／fake timers 复现，30,001ms 后 `stopping` 仍为 true。

## R03 · P2：实例握手既可能耗尽后锁死，也可能被旧响应重复使用

位置：`src/mobile/useCodexThread.ts:265–272`、`:280–291`；`src/mobile/codex-projection-order.ts:87`。

- SSE→poll 只再武装一次。首个 poll 成功后 handshake=true，之后服务再重启，新的 instance 永远被普通 GET／手动刷新拒绝，直到重挂页面。该冻结由本轮新增 instance 守卫引入，不能称为基线原有问题。
- 降级后重叠的两个 GET 都可能捕获 handshake=false。B 先确立新 instance 后，A 的迟到响应仍携带跨 instance 权限；historyToken 相同（包括空投影均为空串）时可装回 A，继而拒绝 B。发出时捕获握手位没有消费落地资格。

**修复／验收：** 使用可更新且可消费的连接／握手代际，支持轮询期间后续重启；响应落地时核对它是否仍拥有当前握手资格。不能简单允许所有跨 instance GET。覆盖“poll 已成功→再次重启→新 instance 恢复”和“两个握手 GET 同 token→B 先到→A 后到不能回退”，兼顾旧订阅迟到响应。

## R04 · P2：Clear 未暂停直通不符合已裁决的越队边界

位置：`src-tauri/src/remote/codex_ipc.rs:4450`；`router.rs:1008`。

Clear 直接建授权并派指定 queued 动作，不要求队列已暂停。回合刚结束、scheduler 尚未取锁时，对 Q3 的优先请求可先发 Q3，随后 Q1／Q2 自动发送：既重排普通 FIFO，也没有“旧队列仍暂停”的保证。窗口短不使它成为合理行为。

**修复／验收：** 按原设计限制为空闲且已暂停的单次越队；未暂停的 Clear 保持原 FIFO并明确返回状态，不需要改宪法。补 Q1/Q2/Q3 未暂停、idle、scheduler 受控停在取锁之前的测试。若要扩大成一般 FIFO 调序，必须另经用户裁决。

## R05 · P2：停止 Unknown 后同一优先请求重放会再次停止

位置：`src-tauri/src/remote/codex_ipc.rs:4466`、`:4538–4546`。

Unknown 只保留队列暂停，原 action 仍 queued，没有保存本次停止尝试的幂等归属。线程锁只防同时请求；第一次返回 Unknown 释放锁后，同一请求再次进入，可创建新 envelope 再发一次 interrupt。现有测试仅证明没有后台自动重发，没有测试同请求重放。

**修复／验收：** 按原 action／明确编排身份持久关联停止尝试与未知结果；重放先读原结果或只读核对，不再停止。覆盖“首次 interrupt Unknown→请求结束→完全相同优先请求再发”，累计 interrupt 一帧、Q3 零帧，重启后也不能忘记未知状态。不得借此新建 Q3 副本。

## R06 · P2：busy 回队后重试优先处理会把未发送消息终态拒绝

位置：`router.rs:1008`、`:1674–1690`；`remote/codex_ipc.rs:4610–4634`。

本批复用的一次性 grant 在首次 writer 前被消费；`busy_before_write` 可把消息退回 queued。界面仍允许重试 prioritize，但原 grant 不会重新变成未消费，下一次 reserve 后命中 grant_consumed，调用 finish 将原消息终态拒绝并返回 queued=false。这是原动作的恢复语义问题，不只是缺少一条可读文案。

**修复／验收：** 不退还旧 grant，也不复制消息。给明确零投递后的下一次用户授权独立、可 CAS 的尝试归属，或保留原行 queued 并要求用户选择正常恢复；不能因为旧授权已消费就丢弃原消息。补“首次消费→writer busy 零帧→留队→用户再次优先／恢复”的测试，原消息最终最多投递一次，旧 grant 永不复活。
