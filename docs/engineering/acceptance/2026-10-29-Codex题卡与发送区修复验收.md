## 三、API 变更（契约面，均纯增量）

1. **`projectionVersion`（T02，Rust → 前端）**：`ThreadProjection` 新增可选 `projectionVersion`（camelCase：`instanceId / ownerEpoch / ownerGeneration / revision / localSeq`）；`instanceId` 复用 `CodexControlHub.owner_boot`（hub 构造时生成一次的进程级身份，非每次 GET 随机）。盖章点只在远程层发射点（GET 序列化 + SSE 四个发射点），镜像/adapter 构造点保持 `None`；未盖章不输出该字段（`skip_serializing_if`），旧客户端兼容。
2. **`support` / `capabilityIdentity` / `activeTurnId`（T03）**：`OperationStatus.support`（`supported / identifying / unmatched / not_implemented`，Rust 侧必备字段，旧载荷兼容放前端归一化层按 evidence 推导、仅展示、不产生新写资格）；`EffectiveOperations.capabilityIdentity`（SHA-256 前 16 hex，None 时整字段省略）；`ThreadProjection.activeTurnId`（canonical 序最后一个 inProgress Turn，与投影同次观察填充，idle/stale/无镜像为 None 时省略）。support 不参与 allowed 计算，Send 门与既有策略未动。
3. **`POST /codex/queue/prioritize`（T06）**：请求 `{sessionId, actionId, expectedTurnId?, confirmInterrupt, frontBudgetMs?}`（camelCase、`deny_unknown_fields`、设备鉴权与属主隔离同 retract）；响应判别联合 `prioritized | already_dispatched | not_sent | unknown`，全部携带原 actionId。编排保留：30 秒前台预算、expectedTurnId 安全阀、一次性 grant CAS 恰好消费、旧队列保持暂停（resume 是唯一恢复出口）、FIFO 不重排。

兼容性口径：新字段对旧客户端纯增量；新客户端遇缺字段降级（脏束不透传、不获得新写资格），均有测试锁（T02 `projection_version_absent_or_dirty_degrades` 等、T03 DTO 3 条）。
