# Codex Desktop 纯文本热修 · Windows 交接

本页给接手 Windows 真机验证的人。以 Draft PR 的**实际提交**为候选，不把 macOS 通过当成 Windows 通过。验证现有官方 Codex Desktop 已打开的原线程，不启动新宿主，不恢复到 CLI 或无头进程。

## 从 Draft PR 开始

在已装好项目所需的 Node.js、pnpm、Rust、MSVC Build Tools 和 WebView2 的 Windows 工作区运行。若是已有工作树，先保护本地修改。用 PR 页面给出的编号，或把完整 PR URL 传给 `gh pr checkout`。

```powershell
gh pr checkout <PR 编号>
git rev-parse HEAD
pnpm install --frozen-lockfile
pnpm tauri:dev
```

用 Tuvis 正常的远程接入和设备配对打开同一 dev 实例的真实手机页面。不要沿用日用设备账本或复制凭据到报告。Windows 不需要 `TUVIS_CODEX_AX_SEND`，这个开关仅影响 macOS 候选。工程方先确认页面、资源和后端属于同一次构建，再开始测。测试消息只用无害且互异的文本，不用生产会话。

## 先测当前安装版，再补回归对照

1. **记录环境。** Windows 版本和架构、Codex 实装构建及安装渠道（例如 Store）、启动形态及权限、Tuvis commit、配对方式。不要为使探测通过而以管理员运行、改变启动形态或改日用数据。记录旧版对照的构建和结果，不能把两个构建的证据合并。
2. **检查当前安装版的同宿主 IPC。** 从 Tuvis 的适配详情和只读连接诊断看实际状态。区分端点不可达、端点在场但归属不明、已连接但操作证据缺失、逐项可用。只读确认 App 原宿主、同一登录会话、原线程 A/B 和准确的端点归属。只有匹配当前适用契约、已审核的操作，才继续第 3 步。历史只在某些构建和实例观察到旧命名管道不可达，不能外推到最新版或其它入口。
3. **走真实手机页。** 同一个已运行 App 内准备 A、B 两条获准原线程。初始桌面显示 A，先从 B 卡片发一条，再从 A 卡片发另一条。分别读回同一线程的实际回复，可刷新。核对各收一次、不串话、不另起会话、不自动换通道或重发。记录实际通道和原线程结果，直打 HTTP、CLI 示例或合成测试只作工程回归。
4. **没有可用入口就验安全降级。** 手机可查看已有记录、保留 Tuvis 本地草稿，发送状态如实解释，浏览和编辑无桌面副作用，不能把点击发送暗改为入队。报「入口不可达／归属未证／能力未证，发送未测」，不报成功，也不把没跑到的动作报失败。再从确认的进程身份、可观察的端点与当前能力日志继续只读取证。不要连接不明私有端点，不写实验消息来猜接口。
5. **补旧 IPC 回归。** 若环境有保留的已证旧版，在对应官方常规启动形态跑发送、读回及该构建原已证的独立操作。空闲异步答题参考 [Windows 旧版验收](2026-11-04-codex-async-contract-windows-layout-acceptance.md)。未能取得旧构建写「未测」，不要降级日用 App 来填表。审批、答题、停止和附件分别记账，不因文本通过一并勾选。

## 若需要 Windows 新实现

先复用 Tuvis 现有 `src-tauri/src/services/codex_desktop_ipc/` 的能力证据和 `src-tauri/src/remote/api.rs` 的发送入口。新版有已经可用的同实例 IPC 就继续用它。若 IPC 不可用，另立 Windows UI Automation 只读取证，先确定官方进程、当前会话与唯一目标行的结构化标识，再评估能否具备草稿、切换和提交保护。Mac AX 只是可比较的用户流程，不是可移植的 Windows 提供方。外部 [Codex Control](https://github.com/gantrol/codex-control) 仅供 UIA 思路对照，不是真机兼容结论，不引入代码。未完成新通道审核和本次实机授权，不做真实派发。

## 回填

在 PR 回报一张表，每行写「候选 commit／Codex 构建与启动形态／通道／操作／结果（通过、未测、受阻、失败）／脱敏证据」。文件只保留最小状态与可重复步骤，不附真实消息、原始线程 ID、设备令牌或个人路径。只有各原线程实际恰一次接收并在手机读回，才可回填 `P2-WIN-TEXT`。Windows 结论不影响已记录的 macOS 手测，Draft PR 不等于批准合并或正式开放。
