# C5 实名普通启动链写正例（脱敏摘要，2026-11-17）

> 本文是该轮隔离虚拟机实测的**独立摘要**：不保留虚拟机名、宿主绝对路径、传输包路径、SSH 口令与密钥位置、原始 PID/启动时刻、端口与凭据、逐条日志。
> **本文不是产品验收**：只回填证据与现势，不写产品 PASS；兼容路径覆盖与降级范围另由规格裁决。

## 1. 结论

- **实名普通启动链的正例成立**：普通命名的 TUI 自托管实名 `serve --service` 并登记在位，全局 `opencode serve` 计数 = 1 → 写门开放 → 手机页面发送唯一标记得到 confirmed，原生 `msg_act_*` 派发生效。
- **三方对账一致**：共享库的 `session_message` 中用户记录恰两条、其中恰一条 `msg_act_*` 且标记逐字；实名 serve 的 argv、登记与候选账本的 `service_id` / `runtime_pid` 逐字一致且 rejections = 0；serve API 消息列表与 TUI 面板显示同文，插件的回声 challenge ack 标题在案。
- **零模型**：隔离环境无 provider 凭据、无 auth 配置，死代理 env 全量在位；agent 回合以连接被拒结束（这正是死代理的活体证据）。

## 2. 隔离形态

| 要素 | 形态                                                                                          |
| ---- | --------------------------------------------------------------------------------------------- |
| 宿主 | 隔离 macOS 虚拟机（独立磁盘，客体版本不高于宿主），与宿主真实服务、真实 TUI、真实候选完全隔离 |
| 网络 | 宿主内 NAT：客体可出网但入站无端口映射，隔离面 = 虚拟机边界；配对经宿主本地转发完成           |
| 传输 | 只读共享目录拷入客体，落盘后逐项核对指纹，无 quarantine 属性，不重签                          |
| 目标 | 普通命名 TUI 自托管实名服务（登记在位），全局 `opencode serve` 计数 = 1，候选以隔离数据根启动 |

**传输包三方指纹逐字一致**（宿主侧期望 = 客体实测）：候选可执行、OpenCode 2.2.5 二进制、TUI 侧观察资产。OpenCode 二进制指纹与 H02 锚一致：

```
opencode 2.2.5  sha256 abe4d88594bffb12b364375b8a6732d2d1f7a977195ed1a35c5c76f8e89c9e0e
```

## 3. 关键步骤与观测

1. **预检**：客体侧预检项全部通过（服务登记、端口、口令、运行形态、计数门、死代理生效等）。
2. **起候选**：候选以专用数据根启动；首启引导完成后，远程面绑定成功，TUI 自托管实名服务登记在位。
3. **写链**：手机页面发送唯一标记 → 候选账本决策时延约 0.95 s（UI 全链约 2.7 s）→ confirmed，原生消息 ID 为 `msg_act_*` 且派生命中。
4. **三方对账**：见第 1 节三项；命中计数为恰一次，零重复投递（outbox 单行）。

## 4. 环境适配（复现备忘）

- 隔离客体缺少宿主侧若干运行时依赖（终端复用器与 terminfo 树）时，按「拷入同路径二进制 + 补齐 terminfo」处置，脚本本身不做改动。
- 候选启动脚本的默认 `.app` 路径耦合在仓库树，隔离客体须以显式形参传入候选包路径（脚本已支持该形参，逐字节未改）。
- GUI 会话与启动用户必须同 uid，否则候选无法连 WindowServer、webview 不起、远程面不绑；跨 uid 时按平台方式配置控制台自动登录后重启客体。
- 隔离根内新增体积与宿主新增体积合计受预算约束（本轮两端各不超过 0.5 GB）。

## 5. 边界

- 单一平台、单一启动形态（普通启动 + 托管服务）的正例；显式 `--server`、分裂脑、多服务等形态各有自己的证据，不得互相借用。
- 手机实机验收不包含在内：本轮是浏览器（含窄屏）经真实 LAN 入口访问隔离宿主，属「已运行的隔离点验现场」，不等于物理手机验收。
- 零模型样本只证明「正式消息送达与账本一致」，不证明模型回合质量；结论不延伸到速度、成本或内容正确性。
