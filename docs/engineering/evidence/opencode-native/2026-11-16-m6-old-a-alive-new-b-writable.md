# M6「旧 A 仍存活、新 B 可写」活体记录（脱敏摘要，2026-11-16）

> 本文是该轮隔离真机实测的**独立摘要**：删除本机绝对路径、原始 PID + 启动时刻清单、配对 PIN、设备 cookie、原始命令回显与逐条日志行。保留机制、判据、观测结论与失败面。
> **本文不是产品验收**：目标是回答「双服务同时存活时，写是否只落在当前绑定的实例上」，不构成正式候选或手机验收结论。

## 2. 拓扑（脱敏）

```
候选（隔离数据根 + 回环端口 + 死代理）
  └─ 发现链：根 state 登记缺席 → 全部会话走显式发现（argv --server + 口令 env + ESTABLISHED + /api/info）
旧 A：serve --service --port A，自有 config/state 目录（候选不可见），全程在场
  └─ 窗口 w1：--server <A> --session <ses_A>
新 B：serve --service --port B，自有 config/state 目录（候选不可见）
  └─ 窗口 w2：--server <B> --session <ses_B>
共享层：两实例共用同一 opencode.db 与同一测试项目目录
独立层：state / config / cache 每实例一套（互不触碰对方登记，规避 registration replaced 自杀）
```

关键前置（踩坑，复现必读）：

- `serve --service` 实例以 **config 侧端口**识别自身后台服务锚；config 端口与实例实际端口不自洽时，项目类 API 一律 503 `service_failed`（`/api/info` 仍正常）。双 serve 拓扑**必须**每实例独立 config 目录。
- 候选自带的脚本 TUI 会自托管一个实名 serve 并向根 state 写登记；该登记在位时所有会话都会被解析到它，双服务显式发现不成立。必须停掉该 TUI 与它自托管的 serve，等根登记自清后再由旧 A 接管端口，使全局 `opencode serve` 计数 = 1（否则写门按 `production_service_conflict` 拒绝）。
- 观察插件可一次安装到两份 config（各自 `Current`），TUI 侧资产与仓库资产逐字节一致。

## 3. 活体流程与观测

1. **配对与认领**：回环节点 + 独立设备 cookie 配对后，看板同时显示 A、B 两张卡（OpenCode · 同一测试项目 · 等待操作）。打开 A 详情得到原生投影（route = `opencode_native`，`serviceId` 为显式端点，`servicePid` = A 的 pid，路由版本 v1），并落一条固定的窗口绑定行（服务代际 + 窗口 pid + boot）。
2. **写 A**：API 设备与 UI composer 各发一条带唯一标记的消息。API 路径 ~3.7 s 返回 confirmed，`nativeId` 为 `msg_act_*` 形态；UI 路径先取到受理面（ACK 门通过 = 语义准入 + 窗口回声 + ack pid 比对），agent 回合因死代理失败转空闲后由 inbox 投递落地，随后「只读核对」确认为原生记录。三方对账：共享库 user 记录含两条 `msg_act_*`、旧 A 总线命中两次、新 B 总线零次、w1 窗格显示同文。
3. **显式重选 B**：view B（认领）200、preview B 200（候选 pid = B，带 previewToken），`POST route/native`（原 bindingToken + routeVersion + candidateToken）2.41 s 返回成功；**同代际重选幂等**——路由版本维持、bindingToken 不变、仅刷新 `updated_at`，伴表新增 B→(服务 pid, 窗口 pid, boot) 的绑定行。
4. **写 B**：1.77 s 返回 confirmed，`nativeId` 为 `msg_act_*`；B 详情 UI 显示「原生记录已确认」并列入记录；w2 窗格显示同文。
5. **终态对账**：全库 `msg_act_%` 计数 = A×3 + B×1；B 无重复投递；A 零新写；旧 A 的活性 sweep 从 T0 到 T5 共七次全部在场。

## 4. 边界判定（N1 分界）

- **「窗口已导航」不构成拒绝**：w1 导航离开甲会话（OpenCode 窗口本身仍在）后，写 A 仍 confirmed（2.31 s）。代码判据 = 锁定窗口身份（pid / boot）+ 回声 ack 的 pid，不含「窗口当前打开的是哪个会话」。
- **「窗口已退出」构成拒绝**：w1 退出后，API 与 UI 双面返回 409 `OC_SERVICE_NOT_REGISTERED`（0.05 s），rejections 账本两行，零写出。拒绝面锚定**窗口 / 客户端绑定**，而不是服务是否存活——同一时刻旧 A 服务仍活（sweep 在案）。
- **同代际重选是幂等的**，不得据此推断「可以跨代际复用绑定」：跨代际、换服务、换端口都必须重新核验（凭据轮换、同端口不同进程也要拒旧绑定）。

## 5. 隔离与脱敏纪律

- 数据根、config/state/cache、tmux 套接字、端口段全部隔离；真实 OpenCode 服务与用户 TUI 全程只读（开轮/收尾的启动时刻逐字一致）。
- 零模型：脚本层死代理 + 轮内手工 env 双保险；配置内模型引用不可用、关闭自动更新与分享。
- 候选经专用启动脚本以隔离数据根启停；测试构建的产品代码与待验构建一致（构建后源码无更新）。
- 本文不保留隔离凭据、配对 PIN、设备 cookie、完整命令回显、原始日志行与逐进程 PID/启动时刻表；需要复现时按第 2 节拓扑与第 3 节步骤在**新的隔离根**重新取证，不得引用旧凭据。
