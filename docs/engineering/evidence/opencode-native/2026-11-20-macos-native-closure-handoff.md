# OpenCode macOS 原生复审核验交接（脱敏摘要，2026-11-20）

> 本文是该轮复审核验的**独立摘要**：不保留本机工作区路径、分支 SHA、原生会话 ID、动作 ID、请求哈希、浏览器对端 IP/端口、配对密码、候选进程号、构建产物 inode 与签名指纹、冻结产物目录。
> **本文不是产品验收**：R9 属**历史候选**；窄屏浏览器与受控审批不能代替物理手机验收，一次创建正例也不能证明所有目录或关窗竞态。

## 1. 覆盖范围

五项工程验收（每项均有 RED → GREEN → 独立复审 → 活体验证）：

| 项  | 主题                        | 活体结果（摘要）                                                                                                                                                                                                                                               |
| --- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 目录、服务及代际核验（D21） | 非规范目录 / 错配 / 断开核验连接分别验证零创建或零起窗、零首句；真实多服务场景产品页明确拒绝，创建与动作账本为空；残余风险：OpenCode 仍按字符串重新解析目录，宿主终验与上游解析之间存在竞窗                                                                    |
| 2   | 创建防重与首句              | 原子请求占位、一次上游创建、预分配 ID 与关联 metadata；只读核对不起窗；刷新只查询同一请求。活体：实际 LAN 请求创建一个会话，原终端与正式库各见一次首句；另有一次首回「窗口待确认」，从页面继续原请求后收敛为已打开/已确认                                      |
| 3   | 按本次请求核对重选          | 稳定请求 ID + 窗口身份 + 路由版本同事务；迟到提交、已证未应用、并发确认、同令牌换窗、旧回执历史化均有夹具。活体：自然换代后主会话版本前进一步；旧窗退出后拒写，新窗提交成功并查询到同一请求的窗口回执；停止绝对截止与丢回执按原 ID 核对有回归证据              |
| 4   | 恢复区按最新清单重建        | 成功按当前会话与新清单重建、失败保留未决并提示；终态、历史容量、状态代际与设备属主受定向与后端测试覆盖。活体：空本地锚新标签页旧视图 409、属主清单 200、原 ID 核对成功并去行；另一独立配对浏览器清单不可见，读取与归档均 404                                   |
| 5   | 签名运行与原生流程          | 真歧义明确拒绝；早期内置浏览器代理不通、确认框一次驱动失去响应、诊断候选另一次未解释退出。活体：仅触发身份匹配的专用测试进程，真实 OpenCode 服务持续运行；策略全程 `native_only`，直连 Chrome 与实际对端互证；失去响应时核对重选账本后用同一配对配置恢复浏览器 |

## 2. 实际 LAN 产品验收（R9 历史候选）

| 场景                           | 观测摘要                                                                                                                                                                                                                                                 |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 普通启动、配对与发送           | 专用 TUI + 实际 LAN 看板进入测试会话，发送前置标记并确认；前置标记在正式库一条                                                                                                                                                                           |
| 自然换代、核对、预览与显式重选 | 专用服务换代，原 TUI 在约 5.4 s 内自行拉起新进程；原发送记录保留，页面重新读取后进入预览；确认前零重选 POST，确认后路由版本前进一步，窗口三元组保持                                                                                                      |
| 换代后恰一次                   | 页面只发送一次，动作 confirmed；原 TUI 与正式库各一条                                                                                                                                                                                                    |
| 文件选择器与附件发送           | 页面选中测试附件，隔离项目落盘，浏览器发送约 2.2 s，正式消息带原文件名，原 TUI 与正式库各一次                                                                                                                                                            |
| 排队、恢复与插队               | 页面暂停后原动作 queued、正式库为零；恢复后同动作 confirmed 且各一条；忙回合显式「插队发送」的 delivery 为 steer；按原动作 ID 核对为 confirmed，零重发                                                                                                   |
| 停止与继续                     | 停止动作 settled/interrupted，原生会话记 interrupted；从同一页面继续发送，新回合成功，继续标记各一条                                                                                                                                                     |
| 切模式                         | 页面 Plan→Build，动作 settled/agent_switched，正式会话读回目标 agent                                                                                                                                                                                     |
| 空锚恢复与设备隔离             | 二次换代后，空本地锚的新标签页旧视图 409，属主清单仍找到原已受理动作，三个原 ID 经页面核对均 confirmed、待核对行移除、零发送 POST；另一独立配对浏览器不含目标动作，详情与归档各 404                                                                      |
| 整组答题                       | 只填第一项时禁止提交；完整提交 confirmed，原生表单正式回读 answered，两项内容一致                                                                                                                                                                        |
| 审批允许与拒绝                 | 两条专用待审批夹具不执行工具；产品页分别允许一次、拒绝，动作各 confirmed，原生待审批清空；临时会话规则还原为空，持久保存规则计数与验收前相同                                                                                                             |
| 远程新建和首句                 | 请求约 7.8 s 完成；规范目录、设备号、inode、服务 PID 与账本一致；原生关联恰一条；固定首句动作 confirmed，原终端与正式消息库各一次；重载原配对浏览器查询返回同一会话、窗口和首句，零创建 POST                                                             |
| 同服务换窗                     | 新 LAN 地址另建专用会话，首回待确认，继续原请求后窗口与首句 confirmed；原附着窗口退出后用同代际端点打开新窗，旧窗写入返回 409 `OC_GATE_PID_UNVERIFIED`，正式库零旧标记；产品显式重选提交后绑定令牌一致、原请求指向新窗，新标记正式库一条、TUI 对话区一次 |

产品全程 `native_only`。原 TUI 的完成验收使用专用窗口屏幕取证，写入走产品原生通道；既有审计能区分附件正式上传与按键等写入，未覆盖各历史路径的屏读调用计数。

## 3. 门禁结果（摘要）

- Rust 库测试全量通过（含停止预算与迟到发包保护），OpenCode 原生远程集成测试与定向重选回执测试通过；clippy `-D warnings`、fmt、`git diff --check` 通过。
- 前端全量测试通过；构建并发下个别用例超时，降低并发复跑通过；`pnpm check`（能力矩阵、tsc/Vite、格式、i18n 键集、错误码检查）通过；ESLint 既有警告、零错误。
- 实际映像与冻结副本互相核对，严格验签通过。

## 4. 恢复现场与遗留

- 次日用仓库隔离启动器从冻结包恢复同一签名包：LAN 入口、配对、会话清单、原生视图、旧绑定提示、预览与显式确认均在场；一次显式重选返回 `OC_INSTANCE_AMBIGUOUS` 并按同请求状态持久化为 `not_applied`，路由仍指向旧服务 —— 宿主多服务歧义按设计保守拒绝，**没有发送消息**。
- 随后在隔离虚拟机内以只读备份的账本复验：单一普通命名服务 + 测试 TUI 双向端点吻合并通过确认框显式重选，路由版本前进一步，随后发送得到 confirmed；另一独立窄屏浏览器配对后读取成功、可见正式消息、输入框启用，未决动作为零。
- 遗留边界：真实物理手机全链验收未完成；同服务换窗后的模型回复与额度错误时输入框残留仍属验收边界；产品验收进程在验收后被退出（未见崩溃报告，具体菜单项未能确认），已用隔离启动器恢复同一签名包并复验。
