# H02 归属复核：SSE 回声 challenge 机制（脱敏摘要，2026-11-14）

> 本文是该轮隔离实测的**独立摘要**，不含本机路径、进程清单原始时点、隔离凭据与原始日志行；原轮次记录只在当时隔离环境留存，不入库。
> 本文**不是**产品验收结论，也**不是**正式候选或手机验收记录：测试在一个临时隔离根内以零模型配置完成，仅回答「归属判据能否成对取证」。

## 1. 结论

- **机制可用（带边界）**：用「回声 challenge」可以在**零上游改动**下取得成对的正例与反例——同一轮、同一分裂脑拓扑内，经真实绑定实例能收到锁定 TUI 的应答，经仍存活的旧实例收不到任何应答。
- **放行判据只看内容，不看写路径**：分裂脑下 ack 的写入可能落在旧实例，这是实测形态；因此判据必须是「我发出的 nonce 在窗口内被**锁定 pid 的 TUI** 应答」。
- **pid（配合启动时间）是唯一的 TUI 身份防线**：多 TUI 场景里，写错实例同样会得到「另一个 TUI 的合法 ack」，只有 pid 比对能识破。
- **缓存失效粒度是实测行为事实，不是契约**：判据依赖的「TUI 数据层只随所连实例的 SSE 事件流刷新、且失效为 per-session」是锚定版本的实测行为，上游可静默改变；升级后**必须复验**正向闭环与 per-session 判别两项才能继续引用。

## 2. 机制定义

1. **challenge**：发起方经**目标实例**的 HTTP API，向一个自建专用探针会话覆盖写标题 `chal:<nonce>:<writetime_ms>`（PATCH，成功返回 204 无 body）。该写由目标实例执行并在**目标实例的事件总线**发布。
2. **ack**：TUI 侧只读插件按 tick 轮询探针会话（读的是 TUI 数据层缓存），看到未应答的 challenge 后用 fresh client 写回 `ack:<nonce>:<tui_pid>:<acktime_ms>`。
3. **守卫三件套**：`ack.nonce == 自己发出的未过期 nonce` ∧ `ack.tui_pid == 锁定 TUI pid`（前置：pid + 启动时间换代核对）∧ `writetime ≤ acktime ≤ now ≤ writetime + W`。任一不满足或窗口内零 ack → **拒绝**（宁拒勿错派）。

```
放行 = challenge 经目标实例写入探针会话
      ∧ 窗口 W 内该探针会话标题出现同 nonce 的 ack
      ∧ ack 的 pid == 锁定 TUI pid
      ∧ acktime − writetime ≤ W
拒绝 = 窗口内零 ack ∨ pid 不匹配 ∨ 超窗 ∨ 探针会话不可写
```

**禁止信号**（不得单独作为放行依据）：经 client 对象的写通道心跳、RPC 接触型「新鲜度」、自写自捕的 nonce、登记 / api info / LISTEN 单项、共享库内容标记、`server.connected`、re-setup。长连观察只用作**拒绝条件**（无指向登记端点的持久 SSE 长连即拒写）。

## 3. 实测要点（脱敏）

| 用例             | 拓扑                                                        | 结果                                                                                             |
| ---------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 正例             | TUI 持久 SSE 连新实例 B，写路径仍经代理落旧实例 A（分裂脑） | 经 B 的 challenge 在窗口内被锁定 pid 应答；应答写落在 A 并在 A 总线发布——判据看内容成立          |
| 反例             | 同上，challenge 经仍存活的 A                                | 窗口内 TUI 数据层零刷新、零 ack；共享库真值与 TUI 视图持续分叉                                   |
| 探针会话免导航   | 探针会话由 API 创建、从未被 TUI 打开                        | 创建事件经 SSE 到达后约 1.2 秒内即可被 TUI 数据层读到完整会话                                    |
| 多 TUI           | 两个 TUI 分别 SSE 连 B / 连 A                               | 各自只应答自己那侧实例的 challenge；但 ack 携带应答方自己的 pid，写错实例时 pid 不匹配，必须拒收 |
| 退出             | 杀 TUI 后发 challenge                                       | 窗口内零 ack（fail-closed）；进程不存在时无任何 ESTABLISHED 长连                                 |
| 换代             | 官方同端口 restart                                          | 旧代死亡、登记与 `/api/info` 全部翻转到新代；pid + 启动时间是换代唯一的事前核对                  |
| 凭据重载         | 同端口换密码（显式形态）                                    | 旧凭据请求持续 401、SSE 不再投递、数据层冻结、零新 ack；显式 TUI 以旧凭据启动即被拒绝连接        |
| per-session 判别 | 分裂脑稳态下让他会话改名 / 新建                             | 12 秒内探针键不刷新、零 ack——「任意事件触发重读」的误放行链不成立                                |

延迟分布（loopback）：challenge 写入到实例总线发布约 10 ms，总线发布到 TUI 读到并 ack 为 56 ms – 1.2 s（主因是 TUI 的 2 秒 tick 量化），ack 落地后外部可读受轮询粒度约束（≤ 300 ms）。

## 4. 生产参数与边界

- **窗口 W = 10 秒**（保守上限 15 秒），覆盖 2–3 个 tick 加写往返与守卫读取轮询；超窗一律 fail-closed。
- **探针写是写**：challenge 属低风险但真实的写动作，必须限频、每次换 nonce、串行或按协议退避；探针会话只由发起方写入。
- **并发未实测**：原轮用受控单飞时序等价覆盖并发竞争；生产实现需按协议做「写前读标题、见未过期未应答的他者 challenge 则退避到其 deadline」。
- **升级即失效**：锚定二进制 SHA-256 见本文末；上游改变缓存刷新或失效粒度时，单独失效方向是可用性损失（收不到 ack → 拒写），与语义漂移叠加才可能错误放行，因此两项复验都不可省。
- **不替代既有准入**：本机制与「登记 + 进程事实 + `/api/info` 互证」串联使用（前者过 → 本机制过 → 才放行新写），任何一环失败都不得向对端写入。

## 5. 锚定与复验要求

- 平台：macOS；启动形态：默认托管服务与显式 `--server` 两种（分别取证，不互相借用）。
- 锚定 OpenCode 构建（TUI 与服务为同一二进制）：

  ```
  sha256 abe4d88594bffb12b364375b8a6732d2d1f7a977195ed1a35c5c76f8e89c9e0e
  ```

  该值与代码内登记表（`src-tauri/src/services/opencode_native/attribution_evidence.rs`）逐字一致；改锚必须同时换证据。

- 复验清单：正向闭环、旧实例存活反例、per-session 判别、凭据重载/换代 fail-closed。任一项未复验 → 该构建按「语义未证」拒绝，不得沿用旧结论。
- 隔离纪律：隔离根内各实例独立 HOME / XDG_CONFIG / XDG_STATE / XDG_CACHE / TMPDIR 与独立数据根；仅构造分裂脑拓扑时共享同一数据库；隔离环境无 provider 凭据、配置无效模型引用，全程零模型调用；探针凭据只在隔离环境内生成并随隔离根销毁。
