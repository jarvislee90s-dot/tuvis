# 动作路径快照补扫超时 · 根因诊断（2026-11-16）

## 现象量化（mam.log 实测）
- 真实 home（~/.dsh/sessions，563 会话/最大转写 9MB）上单轮扫描耗时**双峰**：
  - 常态 3-5s（缓存热、VFS 健康——06:08:46→06:09:10 四轮连发完成）
  - 偶发 >45s（06:09:10 起的一轮撞 45s 扫描预算 → 「扫描遍历超预算…本轮按无新数据处理」→ worker 代次重启；旧楔死实例曾代次 65 连续重启）
- 动作路径 `ensure_fresh(2s 龄, 3s 等待)`（remote/mod.rs:781-795）：快照龄>2s 即触发补扫并等 3s——**3s 等待 vs 偶发 >45s 的扫描耗时结构性不匹配** → 动作路径稳态 degraded（584 次告警）。

## 根因分层
1. **已修层**：VFS 楔死/git 卡死（真机发现①②）——曾致扫描 100% 挂死；死线加固后扫描有界、常 3-5s。
2. **当前层（待修）**：真实大库的扫描成本本身偶发 >45s（冷缓存/大转写解码/并发 VFS 压力的相位）。
   9s（旧裁决口径）/3s（等待）在「真实大库」上结构性达不成——不是楔死回归，是成本与预算不匹配。

## 影响面
- 发送面带陈旧快照 degraded 继续（本轮 M1 的 dsh:failed 上游之一；另一因子=完结会话被宿主拒，属正确行为）。
- 看板偶发陈旧（45s 预算中止轮保留旧快照，worker 重启自愈——有界，不再永挂）。

## 修复方向（下一轮，待裁决）
1. **扫描成本剖析**：已布置看门狗（超预算出现即 sample detached 遍历线程栈）→ 定位 >45s 的成本中心
   （疑点：dsh 大转写解码映射 / codex IPC 探针 / 冷缓存首扫；M1 已登记的 dsh「冷启动豁免」在此库上的真实成本首实测）。
2. **口径重裁决**（数据到手后）：动作路径放弃「等补扫」改纯缓存+显式 staleness（degraded 即稳态，
   前端明示）；或 dsh 适配器做增量映射（mtime 门控 message map，大转写不每轮重解码）。
3. 45s 扫描预算视剖析结果调优（预算内完不成的相位单独预算或跳过）。
