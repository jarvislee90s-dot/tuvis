# Mac / Windows 模型速度采集探测提示词

请在当前电脑探测 Tuvis 能否以最小侵入方式采集各 Harness 的模型生成速度。这是取证任务，不是执行旧实施计划。先识别操作系统、仓库位置并阅读现有 AGENTS.md；旧模型速度 spec/计划已暂停，其“禁用”表不得直接作为本次结论。即使没有该仓库，也可独立完成本机探测。

## 目标与边界

目标是从同一次模型调用取得：请求开始S、首个有效输出F、生成结束G（或原生响应结算E，须说明边界）、供应商总输出Token（含思考的包含关系），计算TTFT和排除等待的TPS。优先使用原生阶段计时；不要求每个工具都保存逐Token轨迹，不能因缺逐片段日志就直接判不可用。也不能用整个回合或请求总时长冒充生成时间。

- 不改变模型API地址、密钥、provider、网关、代理、证书或现有认证；不修改工具安装包、不注入进程、不拦截解密流量。
- 允许准备独立的统计观察脚本、插件和影子目录。一次性注册统计入口前，给出明确变更预览、备份/卸载方式；用户确认后由Agent完成，用户只需点击原生信任/批准界面。不要要求用户手写配置或复制终端命令。
- 保留已有Hook、插件和遥测目标；只维护自己登记的条目，冲突不覆盖。不得将整个旧配置文件恢复覆盖用户后续修改。
- 不主动关闭、重启任何Harness或Tuvis；需重启时标明哪个进程下次启动生效，等待用户正常重启。不能把关开TUI视为共享后台服务已重启。
- 优先观察现有或自然产生的请求。新真实请求先由用户同意，在独立测试会话进行；不向工作会话注入，不制造网络故障或修改路由来模拟重试。
- 不启动pnpm tauri:dev，不调用真实Tuvis采集/迁移，不写真实用量账本；观察器只写独立试验目录。不得增加随Tuvis退出仍常驻的采集守护进程。
- 只输出字段、数字、脱敏关联ID和计时证据；不输出完整环境变量、进程命令行、配置、提示词、回答、工具参数、凭据或raw API body。

## 第一阶段：只读库存与原生数据

逐一检查实际安装的Claude Code、Codex、OpenCode、DSH、Kimi Code、ZCode、WorkBuddy；未安装如实列出，不安装来凑齐七个工具。

Mac：区分.app、终端CLI及IDE宿主，读取实际运行二进制/安装包版本；检查用户目录、应用日志和环境覆盖路径，不能用npm版本代表桌面宿主。

Windows：分别识别原生Windows、WSL、桌面、CLI和IDE实例，不混用其HOME、时钟或数据目录；从安装/进程元数据与现有路径解析代码发现真实路径，不照搬Mac路径。无需管理员权限、终端注入或屏读；若要靠这些才能取证，先报告原因。本任务不是Windows终端注入探测。

SQLite使用只读连接/事务并尊重WAL；不能裸复制主库丢失WAL，也不调用应用初始化。日志先stat选样，每源先取最近3—5文件，每文件最多尾2MiB；记录截断与解析失败，需扩样时明确预算，禁止无界解压历史。使用已安装工具，缺解码器就报告依赖缺口，不直接说Harness没有数据。

重点入口（只是线索，必须核对本机版本）：

1. DSH：持久session日志的step/start、assistant/message.stream、同消息usage/source/replay profile，以及retry/attempt；展开time0+dt紧凑流。缓存累计值不能直接拆任意区间或历史模型。
2. ZCode：model_usage的started_at、first_token_at、completed_at、duration_ms、TTFT、output/reasoning、retry_count。原生首点可能仅含正文/思考、不含工具参数；区分这个边界，不因无法证明服务端无缓冲就禁止客户端原生吞吐。
3. WorkBuddy：优先找原生SseStreamMonitor日志qua.enqueue/start/end或旧First meaningful token received/Stream completed，核对ttft_ms、total_cost_ms、usage、chunks及请求身份。源码有日志写入不等于实际已落盘；先等自然新请求验证，不直接安装Hook。
4. OpenCode：识别v1/v2。v2全局server观察插件可订阅step.started、text/reasoning/tool-input delta、step.ended、retry.scheduled；检查sessionID+assistantMessageID及宿主created时间，不需要TUI插件。v1接口另查，不照搬v2。
5. Kimi：检查step.end自带usage及llmFirstTokenLatencyMs/llmStreamDurationMs；核对重试首点是否重置。若本机已有正常server，查其WS输出投影及关联；debug事件只有名称而无payload时不能补首输出。不要擅自把普通TUI改为web启动。
6. Claude：原生OTel可以一次注册，但message_start、content_block_start不能直接等于首非空delta；检查同请求usage、重试基线和实际导出。普通生命周期Hook或MessageDisplay不等于完整思考/工具参数流。
7. Codex：区分普通OTel、rollout trace与服务器runtime_metrics。若版本支持runtime_metrics，查原生WebSocket timing及metrics_exporter；确认原值是总推理、TTFT、TBT均值还是生成耗时，不能仅凭名称相减或将histogram与另一批Token硬配。功能开关存在不等于当前provider会返回计时；不得覆盖已有exporter或analytics选择。

## 第二阶段：最小动态观察

仅对有明确入口的工具继续。先展示试验入口及变更预览，用户确认后完成一次设置；需原生信任时引导点击，需重启时等待自然重启。不要批量装多个候选插件或整套Grafana平台。

每个工具先取一个成功流式调用：至少保留同请求/步骤的S、F、G/E或原生阶段时长、最终用量、模型、终态和重试标记。缺字段照实列出，不假设补齐。成功取得这一条后，再最少验证：

- 一轮先调用工具、再继续模型输出：第二次模型调用要独立计时，工具等待不进生成窗。
- 用户正常取消一次：可靠耗时可保存，但取消样本不进入TPS。没有取消或重试样本就标未测试，不主动破坏网络。
- 用户同意且方便时，Tuvis真正退出后自然运行一次Harness，再打开Tuvis：区分可从已有日志/插件事实回填的数据与断连期间丢失的实时事件。统计端不可用不得阻塞Harness。

只持久化数字和最小身份。插件若自身能落盘，Tuvis退出后也能回填TPS；不按指标名称武断规定TPS一定在线。只有易失订阅时，明确只能从连接后采集，不把断连数据填0。

## 计算与证据要求

- TTFT=F−S；TPS=总生成Token/生成秒。原生生成时长可直接使用；只有总时长与TTFT同基线、同尝试时才允许相减。
- 分别标注“原生阶段计时”“事件观测计时”“仅候选/无法对齐”；不要把服务器TBT或总推理时间直接改名为生成时间。
- 说明output是否已含reasoning；包含则不再加，互斥则在时间覆盖一致时相加。最终用供应商用量，不以字符/4估算作为通过证据。
- 失败/取消不参与速度；已识别重试而不能对齐尝试时排除。没有完整内部重试证据时说明限制，不谎称零重试。
- 不混合宿主墙钟、单调时钟、服务端相对时间。F=G/E、负时间、单块返回或统计范围不一致要列原因。
- 原生TTFT、客户端首字、首思考及首工具参数可以不同。保留实际定义，不为凑统一数字改名；客户端收尾误差也要说明，但不能要求证明纯服务端解码才认可所有端侧统计。

## 回传格式

报告保存为`docs/engineering/evidence/2026-10-24-model-speed/runtime-probe-macos.md`或`runtime-probe-windows.md`；无仓库时保存在独立试验目录，告诉用户绝对路径。

最后回复一份可直接贴回原设计会话的摘要，包含：

1. OS/架构/Windows或WSL/工具宿主与精确版本。
2. 七工具矩阵：原生来源、一次设置方式、是否需自然重启、TTFT/TPS可得性、Tuvis退出后是否可回填。状态分清未安装、未测试、仅静态候选、样本实测通过、该入口实测不满足。
3. 每个实测通过来源至少一行脱敏原始数字：同请求ID、模型、S/F/G或E、原生总时长/TTFT/生成时长、output/reasoning、终态、重试情况、时间单位、实际计算值。
4. 引用真实字段路径/日志类型或短小脱敏事件形态；不贴整段日志。代码中存在、现实样本存在、实际计算通过三者分开。
5. 本次具体新增的文件/统计键、是否已卸载、待用户点击/重启的事项；没有做的测试明确写未做。
6. 仍不能采集的来源，给出最小缺口及下一步；不要把“没有查到”写成永远不支持，也不要把能配Hook写成TPS已支持。

若来源很多，摘要控制在约1500中文字，详细数字和证据放报告；不要以“全部完成/都可以”代替逐工具结果。
