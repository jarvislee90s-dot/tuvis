## 2. 必须保持的不变量

1. 异步提问不阻塞模型。回合完成、对话变长、进入新回合，均不能自动等同题目已答。
2. 正式已答以同线程精确题目标识与合法作答信封配对。题干相似度、普通正文和本地发送记忆均不能代替。
3. `Accepted` 只表示受理；已答事实需要原会话记录或已经核验的对应证据。
4. 未知状态不伪装成待答或已答。没有看到记录时先检查覆盖范围。
5. 收纳只改变 Tuvis 展示，不发送消息、批准、取消或打断 Desktop。
6. 新题身份变化后不得沿用旧题答案、旧 context token 或旧收纳结果。
7. 包身份、内容 SHA、连接代际与操作守卫继续有效；不得用“自动兼容”绕过。
8. Desktop 会话不自动切到 headless；结果未知的写操作不自动重发。
9. 不向日志或 hints 表新增题干、答案、信封正文；诊断以身份摘要、阶段、机器码和覆盖信息为主。
10. Console 屏读纪律适用于终端 TUI。本手册处理 Desktop GUI/IPC，不将终端注入探针套用于 GUI。

## 4. A1：修复首次快照阻止历史提示加载

### 4.1 缺陷与通过标准

顺序：`ensure_thread → follow_thread → 收到 snapshot → persist → projection → ensure_interaction_hints`。

现状中 persist 可以创建只包含新题的缓存，ensure 再因 `contains_key` 早退。复现结果为 DB 有 `old-item/new-item`，缓存仅有 `new-item`，store 加载次数为 0。

**通过标准：** 首次持久化前完成本线程提示加载；读失败不得冒充“已加载”；加载与更新不会互相覆盖；L1 能以旧题 hint 配对当前窗口中的答案。

#[cfg(test)]
mod pr202_hint_init_tests {
    use super::*;
    use std::sync::atomic::{AtomicBool, AtomicUsize};
    use crate::database::dao::codex_interactions::StoredInteractionHint;
    use crate::services::codex_desktop_ipc::async_question::{
        AsyncQuestionView, InteractionHint, InteractionHintStore, InteractionState,
    };

    #[derive(Default)]
    struct MemoryHints {
        rows: std::sync::Mutex<Vec<StoredInteractionHint>>,
        loads: AtomicUsize,
        fail_next_load: AtomicBool,
    }

    impl InteractionHintStore for MemoryHints {
        fn load(&self, thread_id: &str) -> Option<Vec<StoredInteractionHint>> {
            self.loads.fetch_add(1, Ordering::SeqCst);
            if self.fail_next_load.swap(false, Ordering::SeqCst) {
                return None;
            }
            Some(self.rows.lock().unwrap().iter()
                .filter(|row| row.thread_id == thread_id).cloned().collect())
        }

        fn upsert(&self, hint: &InteractionHint, at_ms: i64) {
            let row = StoredInteractionHint {
                thread_id: hint.thread_id.clone(),
                source_turn_id: hint.source_turn_id.clone(),
                source_item_id: hint.source_item_id.clone(),
                question_index: hint.question_index,
                last_fact: hint.last_fact.clone(),
                updated_at: at_ms,
            };
            let mut rows = self.rows.lock().unwrap();
            if let Some(slot) = rows.iter_mut().find(|old| {
                old.thread_id == row.thread_id
                    && old.source_turn_id == row.source_turn_id
                    && old.source_item_id == row.source_item_id
                    && old.question_index == row.question_index
            }) {
                *slot = row;
            } else {
                rows.push(row);
            }
        }
    }

    fn setup() -> (DesktopIpcAdapter, ThreadKey, Arc<MemoryHints>) {
        let adapter = DesktopIpcAdapter::new(
            Arc::new(super::publish_protocol_tests::NoopConnector),
            ProtocolProfile::closed(),
        );
        let key = ThreadKey { host_id: "local".into(), thread_id: "th".into() };
        let store = Arc::new(MemoryHints::default());
        store.rows.lock().unwrap().push(StoredInteractionHint {
            thread_id: "th".into(), source_turn_id: "t-old".into(),
            source_item_id: "old-item".into(), question_index: 0,
            last_fact: "pending".into(), updated_at: 1,
        });
        adapter.set_interaction_hint_store(Some(store.clone()));
        (adapter, key, store)
    }

    fn new_question() -> AsyncQuestionView {
        AsyncQuestionView {
            question_key: "[\"request_user_input_async\",\"new-item\",0]".into(),
            context_token: "test-only".into(), source_turn_id: "t-new".into(),
            source_item_id: "new-item".into(), question_index: 0,
            title: "测试题".into(), options: vec![],
            state: InteractionState::Pending, actionable: true,
            disabled_reason_code: None,
        }
    }

    #[tokio::test]
    async fn pr202_first_persist_loads_old_hints() {
        let (adapter, key, store) = setup();
        adapter.persist_interaction_hints(&key, &[new_question()]).await;
        adapter.ensure_interaction_hints(&key).await;
        assert_eq!(store.loads.load(Ordering::SeqCst), 1);
        let cache = adapter.inner.interaction_hints_cache.lock().unwrap();
        let rows = cache.get("th").unwrap();
        assert!(rows.iter().any(|row| row.source_item_id == "old-item"));
        assert!(rows.iter().any(|row| row.source_item_id == "new-item"));
    }

    #[tokio::test]
    async fn pr202_load_failure_does_not_mark_cache_loaded() {

### 4.3 最小修法

当前批次推荐使用同一把异步 I/O 闸，串行化 hints 的初始化与写穿。缓存槽位仅在 store 成功返回 `Some(rows)` 后创建，包含 `Some([])` 的真实空库。不另引入“局部缓存也算已加载”的语义。

在 `AdapterInner` 添加并在构造器初始化：

```rust
interaction_hint_io: tokio::sync::Mutex<()>,
```

```rust
interaction_hint_io: tokio::sync::Mutex::new(()),
```

将现有 ensure 的加载主体提取为持锁内部方法。以下为方法的完整内容；公开入口与 persist 不得在持有此闸时互相调用。

```rust
pub async fn ensure_interaction_hints(&self, key: &ThreadKey) {
    let _io = self.inner.interaction_hint_io.lock().await;
    self.load_interaction_hints_locked(key).await;
}

// 调用者持有 interaction_hint_io；DB 操作时不持有 mirrors/std 缓存锁。
async fn load_interaction_hints_locked(&self, key: &ThreadKey) -> bool {
    if self.inner.interaction_hints_cache.lock()
        .unwrap_or_else(|e| e.into_inner()).contains_key(&key.thread_id)
    {
        return true;
    }
    let store = self.inner.interaction_hint_store.lock()
        .unwrap_or_else(|e| e.into_inner()).clone();
    let Some(store) = store else { return false };
    let thread_id = key.thread_id.clone();
    let loaded = tokio::task::spawn_blocking(move || store.load(&thread_id))
        .await.ok().flatten();
    let Some(rows) = loaded else { return false };
    let hints = rows.into_iter().map(|row| {
        super::async_question::InteractionHint {
            thread_id: row.thread_id, source_turn_id: row.source_turn_id,
            source_item_id: row.source_item_id, question_index: row.question_index,
            last_fact: row.last_fact,
        }
    }).collect();
    self.inner.interaction_hints_cache.lock()
        .unwrap_or_else(|e| e.into_inner())
        .insert(key.thread_id.clone(), Arc::new(hints));
    true
}
```

在原 `persist_interaction_hints` 的空问题早退之后、读取 store 和计算 changed 之前加入：

```rust
let _io = self.inner.interaction_hint_io.lock().await;
if !self.load_interaction_hints_locked(key).await {
    return;
}
```

保留原 persist 的去重、写库与缓存合并主体，持有该异步闸直到合并完成。这一修法在加载失败时暂不写穿本次 hints，后续投影或事件可再次尝试；当前镜像读模型仍照常显示，不把失败当成空历史。

- [x] 核查所有缓存写入点均受闸保护，不新增 std 锁跨 await。
- [x] L2 仍位于正常 `handle_state_changed` 分支，不能只移到异常恢复路径。
- [x] 不在镜像临界区获取新异步闸；不为了装载提示而阻塞底层 RPC 读帧。

该方案按 adapter 串行化低频 hints I/O，是 A1 的有限修补。跨线程慢库隔离与写入排队属于 B1，不在 A1 顺手改造。

## 6. A3：收紧内联题目标识的绑定识别

### 6.1 缺陷与通过标准

`inline_synthesis_bound` 只比较表达式文本，没有保留首个 map 参数。外层 `e` 被回调的 `e` 遮蔽后，错误的 question.id 仍被认成原 item.id。

| -------- | ---------------------------------------- | ------------------------------------------ |
| 目标定位 | 无运行包、安装多义、平台不支持           | 运行身份变化或显式重新探测                 |
| 包读取   | 不可读、读取中被替换、超预算、格式损坏   | 暂时错误退避；确定损坏等待包变化           |
| 规则识别 | 已识别且某操作不匹配                     | 同包同规则不循环重读；规则或包变化后重识别 |
| 策略门控 | 自动适配关闭、运行中、原生阻塞、队列暂停 | 随真实策略/状态变化重新计算                |
| 答题核对 | 历史不足、信封未进镜像、证据过期         | 只读按需核对；不自动发送                   |

不能仅按 `Disconnected` 枚举就把所有错误判为可重试，它可能表示长期缺失的安装路径。分类应在实际失败阶段携带信息。

### 11.2 执行工作单

- [ ] 逐阶段产生结构化诊断事实，保留现有逐操作 `allowed` 语义；诊断展示不产生写资格。
- [ ] 审核 `capability.rs`、`reason_code.rs`、远程序列化和前端文案，区分“探测没完成”和“完成但不匹配”。
- [ ] 真正暂时失败采用有界退避，例如同目标当前连接在首次失败后最多 3 次重试，分别延迟 1/4/16 秒；每次仍受独立读取预算限制，后台退避不延长当前请求的反馈时限。超时与安装切换立即收尾旧任务。
- [ ] 同包同规则的确定失配不反复扫描；手动重探只重做只读探测，不重放原 mutation。
- [ ] 开关关闭或 stop 后不继续探测/安装；新 target 不接受旧 target 的迟到证据。
- [ ] 日志输出阶段、机器码、规则版本、包摘要、耗时与预算命中情况，不输出正文和敏感路径。
- [ ] 新机器码登记到集中映射并同步中英文语义；跑 `pnpm check` 覆盖错误码/i18n 门禁。

验收：首次读取失败后恢复、确定失配不热循环、关闭适配取消待重试、旧目标迟到结果拒收、只读成功不能解锁未经证明的审批能力。

## 12. C3：以静态语义识别替代不断追加词法形态

本节不是要求重写全套识别器。先限定 `async_answer_idle` 做技术验证，确认成本与误判边界后再扩展到其他操作。

### 12.1 必须识别的语义链

```text
协议标记绑定
  → 同一文本接收者的开闭标记守卫
  → 对应长度裁剪 + JSON 解析
  → questionItemId/question/answer 的实际 schema
  → 源条目身份 + 题序的绑定关系
  → 实际使用的消息 carrier 与 handler
```

只找到方法名、字段名或不被使用的辅助函数，不构成完整证据。允许归一化变量名、括号、格式、命名函数与内联等已证明等价形态；参数交换、作用域遮蔽、来源变化和 guard 绕过必须拒绝。

### 12.2 执行工作单

- [ ] 先写技术验证方案：比较增强现有有限词法与引入 Rust 静态 JS 解析库，记录体积、解析预算和绑定支持。
- [ ] 选库时查对应版本的官方资料与项目依赖纪律；本手册不预先指定未验证的新依赖。
- [ ] 提取有限 AST 子图并做符号作用域核对；不执行包内 JS、不起包内脚本、不引入运行时求值。
- [ ] AST 失败或超预算时保留旧的已核验规则作为有限兜底，诊断标明采用的识别器；不能因 AST 失败放松已有守卫。
- [ ] 保留现有包读取的候选数量、单文件字节、总时限限制，不把整包解压进内存。
- [ ] 增加完整阳性/阴性矩阵：一致改名、内联、长度推导、成员链、形参遮蔽、参数反序、错误 schema、无 guard、未使用死代码、错误 carrier。
- [ ] 对新 build 归档真实脱敏片段与索引，记录平台、包版本、SHA、采集阶段、规则结果；合成变异只放 synthetic，不能冒充真实取证。
- [ ] 至少验证新变化组合同时存在。仅分别替换旧夹具的两处字符串不等于已覆盖新包。
- [ ] Windows/macOS 分别声明验收状态；单平台静态匹配不冒称双平台真机可用。

交付标准：旧金样保持结论；新增真实金样可识别；阴性不误解锁；预算有确定失败结果；每个匹配可输出不含正文的证据链摘要。

## 13. C4：按能力维护规则版本与复用

当前全局 `CONTRACT_RULE_VERSION` 简单可靠，A3 继续使用。只有在单项规则频繁变化导致无关重识别的成本已被测量后，才实施本节。

- [ ] 为操作分别定义规则版本与语义指纹，明确共享包扫描产物和单项规则结果的关系。
- [ ] 缓存键仍绑定平台、目标身份、包内容 SHA、对应规则版本及必要的 CLI/schema 指纹。
- [ ] 旧全局版本证据迁移时，缺少逐项语义信息的行重新识别；不能直接赋予新规则版本。
- [ ] 同一 CLI 版本不代表同一个 Desktop 私有 IPC 契约；禁止只因 CLI 相同就跨 build 沿用写资格。
- [ ] 已观察成功只在同一完整契约身份与精确操作关联下复用；全局 revision 前进不算动作成功。
- [ ] 未知 build 可继续逐操作自动识别，但未证明的操作仍关闭；支持展示继承继续与真实授权分离。

验收：只修改异步题规则时，无关能力的有效证据无需重跑其规则；包内容变化使相关证据失效；不完整迁移不会解锁任何操作。

## 14. 发布前与故障处置对照表

| 现场现象                 | 先查                                         | 允许动作                   | 不能据此做的结论             |
| ------------------------ | -------------------------------------------- | -------------------------- | ---------------------------- |
| 全部题不能提交           | 目标身份、包读取阶段、逐操作证据             | 只读重新探测，展示具体原因 | “新 build 所有功能均不支持”  |

正式版发版仍执行 AGENTS.md 的 diff 覆盖与中英对照两轮检查。若本轮影响能力矩阵，同时更新 README 两语和 `docs/capabilities.json`；只修缺陷且矩阵未变，不虚增能力声明。
