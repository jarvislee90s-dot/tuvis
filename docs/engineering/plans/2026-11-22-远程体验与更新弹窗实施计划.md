# 远程体验与更新弹窗实施计划

> 执行代理使用 `subagent-driven-development`，用复选框跟踪执行。测试先复现缺陷，再验证最小修复。各执行线独占所列文件，最终验收由主代理完成。

**目标**　解决旧历史对账阻塞显式插队、文件预览误报和 Codex 投影显示无效过程开关，完成现有 Windows 更新弹窗的布局与交互验收。

**架构**　Rust HTTP 层只等待原动作派发所需的证据，历史归账由既有调度循环继续处理。文件错误沿既有 `/m/api/v1/file` 传至两种预览。移动端用既有可见消息源派生书签栏属性。更新弹窗沿用已修改的独立组件。

**技术栈**　Rust、Tokio、Axum、SQLite、Tauri WebView2、React、TypeScript、Vitest。

基线 `c4d8bf9b`（v0.6.7），对应 [11 月 22 日规格](../specs/2026-11-22-远程体验续作与更新弹窗设计.md) 和 [MASTER-PLAN](../../MASTER-PLAN.md) §0.2、D21／D22。保留目前 `main` 工作区及原有改动。各代理不得提交、推送、修改总纲或实际安装更新。
