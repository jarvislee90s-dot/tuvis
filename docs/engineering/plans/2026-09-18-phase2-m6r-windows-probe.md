# 二期 M6R · Windows 注入修正版探测计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans（或 subagent-driven-development）。步骤用 checkbox 跟踪。
> 上位文档：批次设计 `docs/engineering/specs/2026-09-18-phase2-m6r-m9r-injection-hardening-design.md`（R1）· 调研依据 `docs/research/refs/phase2-消息注入/`（三文档 + cc-dr 核实结论）。
> 执行环境：Windows 实机（本机）。**探测先行——本计划是 M6R–M9R 批次的唯一先行交付，其结论 gate 批次全部实现任务。**
> 红线：不动 main、不 push、不改宪法与设计文档；探测脚本与日志全部落在 `%USERPROFILE%\mam-probe-m6r\`（新目录，不覆盖旧 mam-probe）。

**Goal:** 以修正后的方法论重做 Windows 终端注入探测，对 M6 旧结论逐条「推翻 / 证实 / 修正」定案，产出 M9R 引擎重写的**参数定案表**与**事件构造规格确认**；报告 v2 + 独立评审落盘 research 库。

**背景一句话：** M6 的「消费墙」（首读 13~43 字符/错误 122=缓冲满/再武装 30s~10min）与官方文档及 conhost/ReactOS 源码三重矛盾，方法论有硬伤（BP 转义 bug、日志覆盖、错误码未采集、无模式/占用率观测）；cc-discord-remote 以同路径实证任意长度可行。

## 全局纪律（每个实验隐含遵守，吸取 M6 审计教训）

1. **日志**：追加式、带 run-id（`<脚本>-<yyyymmdd-HHmmss>.log`），**永不覆盖**；每次写入调用必记录：BOOL 结果、**实写记录数**、**GetLastWin32Error 错误码**。
2. **脚本先行修正**（E0 完成）：probe-bp 的 ESC 转义（PS 5.1 用 `[char]27`）；所有分块循环补错误码与实写数采集；`ok=true 但 written<分片长` 按**部分写**处理（从偏移续写），不得直接前进。
3. **控制变量**：同一实验内消息文本/长度/事件模式/宿主固定；每条件 ≥5 次取样；**逐 CLI × 宿主分表记录，禁止合并陈述**。
4. **证据链**：每实验 = 日志 + 截图（关键态）+ 会话文件命中（可适用时）三重；环境与版本（CLI/宿主/OS/PS）开局记录一次。
5. 探测用一次性子进程执行（Attach→写→Free），与 M6 同形态；探测进程自身不滞留附加态。

- [ ] E0.2 ConIn.ps1 修订：①新增 `GetConsoleMode(CONIN$ 句柄)` 打印（一行 DllImport）；②新增 `GetNumberOfConsoleInputEvents`；③所有 WriteConsoleInput 调用点记录 BOOL/written/err；④ESC 构造改 `[char]27`。
- [ ] E0.3 分块循环修订：部分写续写；失败必采错误码；日志追加式。
- [ ] E0.4 环境记录：OS build、WT 版本、conhost 路径、claude/codex/kimi 版本、PS 版本（对齐旧 T0-env 格式）。
- [ ] E0.5 会话准备：conhost（`conhost cmd /k claude`，M9 拓扑）与 WT 各开 claude/codex/kimi 会话（同一临时项目目录），记录 PID 树。

## E1 · 目标输入模式四态采样（判别力最强，最先做）

- [ ] 对每家 CLI 的 CONIN$ 句柄，在 ①idle（输入框空）②读武装期（正在打字/刚打过）③busy（turn 运行中）④建议/审批 UI 态，各采一次 GetConsoleMode 标志位。
- [ ] **判据**：idle 态若 ENABLE_LINE_INPUT=1 → 「墙=TUI 挂起的 cooked-read 行缓冲」假说强证（与退格不停摆互证）；全程 LINE_INPUT=0（raw）→ 行编辑器假说削弱，倾向客户端侧错误归因。
- 产出：模式 × 状态 × CLI 分表。

## E2 · 错误码实采（旧「122」叙事的真伪）

- [ ] 用修订脚本重跑一次 110 字符（220 事件）注入（与 M6 原条件对齐），逐次记录错误码。
- [ ] **判据**：第一个失败的真实码——5(ACCESS_DENIED)/6(INVALID_HANDLE)/87(INVALID_PARAMETER) → 客户端/句柄侧问题实锤；122 若真出现于 WriteConsoleInput 本身 → 属反常，记原始上下文上报（与源码矛盾，需进一步归因 FFI/编码转换）。

## E3 · 缓冲占用率曲线

- [ ] 注入期间后台线程每 50ms 采 GetNumberOfConsoleInputEvents，与写入日志并排对齐时间戳。
- [ ] **判据**：写失败+占用高=真积压；写成功+占用恒 0+输入框不涨=TUI 边读边丢；占用先涨后骤降=延迟消费（旧「再武装」实为排空时刻；骤降也可能是 FlushConsoleInputBuffer）。

## E4 · 消费感知节流（假墙裁定的核心实验）

- [ ] 形态：写 1 字符 → 轮询占用归零（或截图确认字符上框）→ 等 200ms → 写下一字符；总预算 10 分钟。
- [ ] 三家 CLI 各跑 110 字符与 1000 字符两档。
- [ ] **判据**：全量到达 → **假墙定案**，M9R 节流形态成立；中途永久停摆 → 记录停摆点/状态/恢复时刻，真约束存在 → 触发**回调条款**（批次设计 §4）。

## E5 · ccdr 参数组合验证（M9R 默认参数的实机依据）

- [ ] 80 字符/块 + 块间 50ms + 正文后 150ms 提交回车；keydown+keyup 成对；vk=VkKeyScanW、scan=MapVirtualKeyW 非零。
- [ ] 三家 × 双宿主 × 200/2000/10000 字符三档（一万字符预计 6~7 秒，记录全程耗时）。
- [ ] **判据**：全档全量送达 = M9R 参数定案表直接落库；任何一档失败记录细节（哪块/什么错误/占用）。

## E6 · 修正版 bracketed-paste

- [ ] ESC 用 `[char]27` 构造 200~/201~ 序列；先注入序列头部并用 PeekConsoleInput 抽样确认 ESC 真实入缓冲。
- [ ] idle 态各家发 80 字符 BP 包裹消息。
- [ ] **判据**：BP 通道是否绕过逐字符行编辑（若 E1 判 LINE_INPUT，BP 可能是长消息替代通道——只登记，不改变 M9R 主形态）。

## E7 · 退格对照

- [ ] 墙态（E4 停摆点或旧墙现象复现时）交替发「文本 2 事件 / 退格 2 事件」各 10 次，逐对记录。
- [ ] **判据**：退格持续成功+文本持续失败 → 行编辑器假说坐实。

## E8 · 无人读控制台直证（OS 语义自证）

- [ ] 残留控制台（如 `conhost cmd /k timeout 600`）一次性写 200 记录。
- [ ] **判据**：全量写入成功 → 「OS 输入缓冲容量墙」彻底证伪（与文档/源码三方一致）。

## E9 · busy 态全程观测（插队语义的逐家依据）

- [ ] turn 运行期间每 1s 发 2 事件探针 + 记占用 + 每 5s 截图，覆盖整个 turn 至回到输入态。
- [ ] **判据**：各家 busy 期注入是缓冲排队、忽略还是丢弃；恢复时刻对应哪个 UI 转态 → 输出「插队逐家标注表」（行为不明家禁用插队）。

## E10 · 文本与回车分离

- [ ] 长消息只发文本不带回车，截图输入框内容确认无截断；5s 后单独发回车。
- [ ] **判据**：区分「文本被截」与「回车丢失」；顺带验证「回车被吞、文本滞留输入框」现象（ccdr 实测踩过的坑）是否复现 → 写入确认机制的必要性证据。

## E11 · codex 双写疑点（事件构造规格的最后一块）

- [ ] codex（crossterm 系）会话：同一字符分别用「成对事件」与「仅 keydown」注入，对照输入框字符数与行为。
- [ ] **判据**：成对=双写 → M9R 对 crossterm 系家只发 keydown（按家分支）；无差异 → 统一成对（与 ccdr 一致）。

## E12 · 非零扫描码与 VT 方向键原子批对照

- [ ] 同一字符/方向键分别以「scan=0」「scan=MapVirtualKeyW 派生」注入 claude 与 codex，对照接受度。
- [ ] 方向键 VT 序列（ESC[A 等）以「整条序列单批原子写」注入，验证导航生效且无孤立 ESC 读作取消。
- [ ] **判据**：确认 M9R 事件构造规格两条硬约束（非零扫描码、VT 序列原子批）在本机三家成立。
