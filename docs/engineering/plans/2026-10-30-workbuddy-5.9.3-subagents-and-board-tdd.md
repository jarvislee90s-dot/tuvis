> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal：** 让 Tuvis 完整采集 WorkBuddy 5.9.3 子代理用量，并让运行中的 WorkBuddy 会话稳定出现在会话看板。

**Architecture：** R1 在现有 WorkBuddy 采集器内增加 `<parent>/subagents/*.jsonl` 的独立游标与会话入账（token 计、会话数不计）；R2 用「心跳文件存在 + 内容 pid 存活 + sessionId 匹配」判定会话在场，`status='working'` 保持 Processing，300s 只用于 completed / DB-only 候选。两处独立，不改 schema、TPS、国际版。

**Tech Stack：** Rust（Tauri 2、rusqlite、sysinfo）、TypeScript/React（现有）、SQLite。

**Spec：** [需求](../specs/2026-10-30-workbuddy-5.9.3-subagents-and-board-spec.md) · [设计](../specs/2026-10-30-workbuddy-5.9.3-subagents-and-board-design.md) · [证据](../evidence/2026-10-30-workbuddy-5.9.3/evidence.md)

## 2. Task B：看板活性兜底（R2）

### B1. 宿主 pid 辅助函数

**文件**：`src-tauri/src/monitor/host.rs`

- 新增 `pub fn tool_host_pid(system: &sysinfo::System, tool_id: &str) -> Option<u32>`：把 `tool_host_alive_in` 的现有谓词（exe + `is_session_runtime_cmdline` 排除 + zcode/dsh 门）抽成「找 pid」。

- 测试：WorkBuddy Electron 宿主返回 pid；`codebuddy` 会话运行时/Helper 不返回；zcode/dsh 既有用例保持绿。

### B2. DB 活跃会话读取

**文件**：`src-tauri/src/monitor/workbuddy_parser.rs`

- 新增 `struct WbDbSession { id, cwd, title, status, activity_ms }` 与 `recent_db_sessions(home, since_ms) -> Vec<WbDbSession>`。
- 只读连接：`open_readonly_with_timeout`；失败 → 返回空 + `log::warn!`（看板降级，不 panic、不报错）。
- SQL：

```sql
SELECT id, cwd, COALESCE(NULLIF(custom_title,''), title), status,
       MAX(last_activity_at, updated_at)
FROM sessions
WHERE (deleted_at IS NULL OR deleted_at <= 0)   -- cloud 形态以 -1 表示未删（schema 索引口径）
  AND MAX(last_activity_at, updated_at) >= ?1
ORDER BY MAX(last_activity_at, updated_at) DESC
```

- 跳过 `id` 为 NULL/非字符串的行；`cwd`/`status` 缺失按空串。
- 测试：临时 DB 构造活跃/过期/已删行，断言只返回窗口内未删行；DB 不存在 → 空。

### B3. `find_processes` 兜底

**文件**：`src-tauri/src/monitor/workbuddy_parser.rs`、`src-tauri/src/adapter/workbuddy.rs`

- 抽出可测核心 `discover_workbuddy_processes_with(home, process_info, now_ms, recent: &HashMap<String, WbDbSession>, host_pid: Option<u32>)`。
- 规则（design §3.3）：
  - 心跳文件：严格 UUID、`kind != prewarm`、pid 文件/内容一致、pid 存活；
  - **不要求心跳新鲜**：有效心跳 + pid 存活即返回（新鲜度/DB/jsonl 活性由 B4 判定）；
  - 没有可用心跳进程但 `recent` 非空且 `host_pid` 存在 → 返回一条宿主哨兵 `AgentProcess { pid: host_pid, cwd: None, form: App }`；
  - 否则空。
- `discover_workbuddy_processes` 用 `tool_host_pid(system, "workbuddy")` + `recent_db_sessions` 组装调用。
- 更新既有 discovery 测试：
  - `stale_heartbeat_is_skipped` → 改为「过期但 pid 存活 → 返回」（活性过滤在 B4）；
  - 新增「过期且 pid 不存活 → 跳过」；
  - 新增「无心跳 + DB 活跃 + 宿主 → 哨兵」；
  - 新增「无宿主无心跳无 DB → 空」。
- 保持 `all_adapters_yield_no_sessions_without_processes` 绿（空进程 → `find_sessions` 空）。

### B4. `get_workbuddy_sessions` 合并与判活

**文件**：`src-tauri/src/monitor/workbuddy_parser.rs`

- 抽出可测核心 `get_workbuddy_sessions_with(home, processes, now_ms, recent: &HashMap<String, WbDbSession>)`；生产入口用 `dirs::home_dir()` + `recent_db_sessions`。
- 候选与规则（design §3.4）：
  - **入口先 L1**：`if processes.is_empty() { return vec![] }`，在任何 `recent_db_sessions` 之前；保证 `all_adapters_yield_no_sessions_without_processes` 绿且单测不读真实 home。
  - **心跳候选必须合并 DB 行**：`db_by_id = recent.into_map();` 心跳候选带 `db = db_by_id.get(hb.sessionId)`；否则正常路径拿不到 `status='working'`，AC9 失效。
  - **删除 90s 过滤**：`get_workbuddy_sessions` 现有 `!heartbeat_is_alive(...)`（`workbuddy_parser.rs:402-408`）必须删掉，只保留 UUID/kind/pid；新鲜度统一由本层判活。
  - 心跳候选 + DB 候选按 `sessionId` 去重（心跳优先）；
  - 先 `find_session_jsonl` 再判活；不活跃 → 只 stat，不读尾部；
  - 活性：`runtime_present = 心跳文件存在 ∧ 内容 pid 存活 ∧ hb.sessionId == sid`；`runtime_present ∧ db.status == "working"` → 在场（**不因父会话静默而掉卡**）；否则 `MAX(last_activity_at, updated_at)` 在 300s 内 ∪ 主 jsonl mtime 在 300s 内（completed / DB-only 兜底）。**禁止 COALESCE；禁止用 90s 心跳新鲜度做在场判据。**
  - 状态：`c.db.status == "working"` → `Processing`（对心跳候选同样生效）；否则现有尾部推导（10s 防抖 + 300s 叠加），`eff_age` 基于 `max(jsonl_mtime, db.activity, hb.lastHeartbeat)`；
  - `pid`：心跳候选用心跳 pid；DB-only 用 0；
  - `LAST_SEEN_SESSIONS` 只记录有心跳文件的候选（DB-only 不记录，见已知限制）；
  - 标题：DB 优先，回退 `resolve_title`。
- 新增常量 `SESSION_ACTIVE_WINDOW_MS = 300_000`（引用 `APP_STATUS_STALE_MS` 或同值，注释说明同源）。
- 更新/新增测试（design §3.7）。

### B5. 补偿对齐

**文件**：`src-tauri/src/monitor/workbuddy_parser.rs`

- `compensate_vanished_heartbeats_in` 增加 `is_live: &dyn Fn(&str) -> bool` 参数：
  - vanished = 心跳缺失/过期 **且** `!is_live(session_id)`；
  - `is_live` = `runtime_present`（心跳文件存在 + pid 存活 + sessionId 匹配）**或** `MAX(last_activity_at, updated_at)` 在 300s 内 **或** 主 jsonl mtime 在 300s 内。`runtime_present` 优先，避免正常工作的会话被补偿。
- `compensate_vanished_heartbeats()` 用真实 home/now/DB 构建闭包；保持 `status_of` / `was_read` 护栏。
- 更新既有补偿测试的调用签名；新增：

- 若必须撤销回填（需用户批准）：
  1. 备份 DB；
  2. 删除 `usage_cursor` 中 `session_id LIKE '%:subagents:%'` 的游标；
  3. 按时间范围删除 `usage_detail` 中对应子代理 `session_id` 的行（先从 `usage_session` 找出 `is_subagent=1` 且 `parent_session_id` 非空的 id）；

  5. 校验主会话数值不变。
- 本计划不提供自动清理脚本；任何删除前必须人工确认范围。
