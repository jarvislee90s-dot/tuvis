### 关键实现口径（对齐用户拍板决策）

1. **排序键 = 会话出现序**：后端按 `lastSeq` 降序输出，前端零重排（`lastTs` 仅供展示，`null` 显示 `—`）。
2. **窗口机制零新增**：`limit` 直接透传 `read_session_messages_impl`——条数窗、字节窗（512KB×⌈limit/200⌉ 封顶 4MB）与 `truncated` 全部复用主会话同一套管线（Bug 1 的产物），后端未新增任何预算代码。
3. **scope 独立三档 200/500/1000**：`truncated && scope < 1000` 显示「范围内还有更早文件」；1000 到顶不显示。
4. **方案 A 后端富化**：提取/排序/去重/计数全在后端（`files.rs` 单一数据源），前端纯渲染。
5. **chips 全部/文档/图片**：`fileKindOf` 判扩展名（文档 md/markdown/txt；图片 png/jpg/jpeg/gif/webp/svg/bmp）；代码文件仅在「全部」可见，不做代码专属档。
6. **列表行**：主行 = 末段文件名（加粗，即超链接）；次行 = 目录前缀（可点击弹全路径浮窗）+ 相对时间。~~`N×` hits 徽标~~——**2026-09-16 用户裁决废除**：次数信息用户不在意，前端不再展示（后端 `hits` 字段保留，供后续排序/统计消费）。
7. **归一化去重 v1**：比较键 = `\`→`/` + Windows 语义小写（平台参数注入，跨平台可测）；**展示保留最后一次出现的原始形态**。
8. **v1 不做**（v2 池）：图片缩略图、代码类型档、文件名搜索、读/写标记、磁盘 mtime 徽标。

### 附带口径

- 面板挂载复用详情页已有的提取结果（scope=200 那次拉取一份数据两用：正文链接化 Set 派生自 `fileEntries`），**切档才重拉**。
- 面板默认布局：宽屏（≥768px）`split-h`（左对话右列表）、窄屏 `fullscreen`；三态随时可切（复用 `PreviewModeSwitcher`）。
- 不可预览文件（cwd/主目录外、敏感目录）照列不预过滤，点击走既有 403 错误态。
- 预览来源区分：从面板进入显示「返回文件列表」按钮；从消息正文链接进入无按钮（既有行为不变）。

## 风险与已知边界

- `extract_chain_*` 七工具链路用例按「出现序降序」修正了期望值（原为插入序）——属契约变更的预期结果，非回归。
- 面板 `truncated` 是**文件表窗口**的截断标记，与消息区「加载更早消息」的 `truncated` 语义同源但独立（各自档位）。
- 不可预览文件照列不预过滤（用户裁决）：列表可见性与可读性解耦，点击后才暴露 403。
