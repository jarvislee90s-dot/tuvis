# Codex 自动适配与发送恢复实施计划

> **给执行 Agent：** 使用 `superpowers:executing-plans`，或经用户授权使用 `superpowers:subagent-driven-development`，逐任务执行并打勾；每任务提交后停下，等待本会话 review。

**目标：** 默认尝试 Desktop 自动适配，并在审批、超时、重启和人工继续时保持正确目标、明确结果与可恢复队列。

**架构：** 复用现有 adapter、动作账本和 router，分开能力证据、连接健康和动作结果。对齐 main 的打断能力；Desktop 不转 headless；界面消费同一服务端状态。

**技术栈：** 现有 Rust/Tauri/React/TypeScript/SQLite；内部模块、数据结构和库由执行 Agent 选择，不改本计划的行为与验收。

**设计依据：** [设计稿](../specs/2026-10-23-自动适配与适配问题上报设计.md) §1—6、§10—11；必须同时阅读[总计划](2026-10-23-自动适配落地总计划.md)。

## 全局约束

继承总计划全部约束。特别是 30/120/10 秒、持久成功证据、pending 硬门、不自动重发、不转无头；所有步骤只改当前功能分支，不合并到 main、不推送。

## 评审重点

- S1：旧 epoch/指纹/schema 结果不解锁新连接，成功缓存恢复不是重复探测。
- S2：pending＋idle 和打断后越队不能穿透服务端守卫。
- S3：前台超时、部分写入、等待者取消和迟到响应不能双投或丢结果。
- S4：已受理无 turnId 也有出口；人工继续原子撤销旧写出权且最多一个后继。
- S5/S6：刷新、关闭适配和重启不丢草稿、重复提交或展示旧审批上下文。

## Task S2：Desktop 专属路由、审批硬门与打断队列

**文件：** `services/codex_control/{router.rs,queue.rs}`、`remote/{api.rs,codex_ipc.rs}`、`services/codex_desktop_ipc/adapter.rs`、`database/dao/codex_actions.rs`；测试 `codex_ipc_remote.rs`、`codex_control_remote.rs`、同域单测。

**功能点：** Desktop 永不自动 headless；服务端 pending 拦截；打断后旧队列保留暂停；新意见显式一次性越队，其他守卫不变。

**输入：** S1 状态/开关，S0 的 main 打断。**输出：** 可发送原因、队列暂停/继续/一次性越队契约及持久状态，供 S3—S5 使用。

- [ ] 新增红测：已验证/未知 build 的 NotSent 都不调用 headless；headless 原生会话仍正常；pending＋idle、新 HTTP、后台 flush、unsupported pending 均零普通投递；打断受理未确认不恢复。
- [ ] 新增队列红测：两条旧队列在打断后保持暂停；用户授权的新意见恰发一次且旧两条不动；没有授权不能越队；授权不能跨 thread/action、重复消费或穿透 pending。
- [ ] 实现服务端入队与写出两道门、持久暂停、打断确认及有限越队授权；同步 send-info 与实际发送理由，删除相矛盾的 Desktop 自动兜底臂。
- [ ] 运行 `cargo test --test codex_ipc_remote --test codex_control_remote` 与相关 lib 测试；重启后暂停仍在，设备吊销仍拒绝，正常无 pending 的忙态 FIFO 继续有效。
- [ ] 提交、登记消费接口及语义，停下 review。

**验收：** 前端按钮不是唯一保证；普通消息不能被用作审批响应，也不会在打断后突然冲出旧队列。

## Task S3：统一预算与有界迟到收尾

**文件：** `services/codex_desktop_ipc/connection.rs`、`services/codex_control/{router.rs,queue.rs}`、`remote/codex_ipc.rs`、动作 DAO；测试 `codex_desktop_ipc.rs`、`codex_ipc_remote.rs` 及连接单测。

**功能点：** 发送编排消费剩余预算；前台 30 秒；后台收尾最多 120 秒；保留原请求迟到关联；等待者取消不丢动作、不重发。

**输入：** S2 发送/队列门。**输出：** 稳定动作查询、投递阶段、截止原因、迟到结果通知，供 S4/S5/R1 消费。

- [ ] 写定序红测：连接＋探测＋RPC 串联不重置预算；前台 30 秒结束；部分写入/代理超时不能记 NotSent；HTTP future 被取消仍保留动作；15 秒 RPC 超时后有效迟到响应可归原动作。
- [ ] 写容量/队列红测：跟踪槽位不足在写前拒绝；120 秒主动收尾退出但持久动作保留；队列等候超过 30 秒仍可正常派发，开始派发才计后台预算；旧 epoch 响应不改变新连接能力。
- [ ] 实现预算和动作收尾。30 秒是前台保证，不以两端时钟同步或“前台到期后绝不可能迟到”作承诺；超时不触发第二次写入。
- [ ] 运行 `cargo test --lib codex_desktop_ipc`、`cargo test --test codex_desktop_ipc --test codex_ipc_remote`，使用受控时间/屏障避免用真实长 sleep 镜像实现；结果无新增失败。
- [ ] 提交、登记状态与迟到关联边界，停下 review。

**验收：** 有界资源、单次写入、明确未送达/已受理/待确认分类；没有“超时移除 pending 以后再也无法识别迟到结果”的盲区。

## Task S4：只读核对、Unknown 与无 turnId 恢复出口

**文件：** 控制 router/queue、`remote/codex_ipc.rs`、`adapter.rs`/`mirror.rs`、动作 DAO；测试 `codex_ipc_remote.rs`、`codex_control_remote.rs` 及账本单测。

**功能点：** 10 秒只读核对；正式消息强关联；Unknown 人工继续；已受理无 turnId 的独立运行屏障出口；旧派发权与唯一后继一致更新。

**输入：** S2 守卫、S3 动作/迟到状态。**输出：** 查询/核对/人工继续/仅解除运行屏障的接口和冲突语义，供 S5 使用。

- [ ] 红测：相同文本、revision 增加、泛 idle、临时 input、查不到消息均不能证明送达；正式 clientUserMessageId/绑定 Turn 可以；单次核对不超过 10 秒且零 mutation。
- [ ] 红测：无 turnId 已受理可后续补绑，仍未绑定时可显式解除运行屏障且不重发原消息；旧请求停在探测时人工继续，旧编排恢复仍零首次写出。
- [ ] 红测：两设备并发人工继续最多一个后继；同 ID 异载荷拒绝；人工确认期间已收敛返回新状态而不按旧确认重发；重启、旧响应迟到不复活写出权/队列自动 flush。
- [ ] 实现并运行 `cargo test --test codex_ipc_remote --test codex_control_remote` 及 DAO 测试；Unknown 保持原事实，人工风险选择留痕，新动作仍过审批/目标等守卫。
- [ ] 提交、登记恢复 DTO/动作接口，停下 review。

**验收：** 同时避免“重复发送”和“永久卡住”；已受理的执行状态不确定不能被误写成未送达。
