# 远程端横竖屏自适应默认布局 · 需求说明书

- 日期：2026-10-27
- 状态：用户已裁决（U1–U6 全部落定），实施中
- 调研依据：本仓库代码实测，现状行号见 §3
- 体例约定：本文为**需求说明书**——只写功能点与验收口径；实现路线由实现方自定（本次实现见 §4 附注）。**【用户裁决】** = 用户明文裁定，实现不得偏离。
- 覆盖范围：远程操控端手机页（本仓库 `/m`，源码 `src/mobile/`）。桌面端不涉及。

---

## 1. 统一原则（【用户裁决】）

1. **方向判定只按宽高比**：`宽 > 高 × 1.2` → **横屏**；其余（含高 > 宽的竖屏、以及宽 > 高但未超 1.2 倍的近方形）→ **竖屏**。不掺屏幕宽度阈值、不区分设备类型。
2. **竖屏默认 = 聊天框**（不渲染任何预览窗格），与改造前一致。
3. **横屏默认 = 左消息 + 右文件窗格**（文件看板态 + 左右分屏）。
4. **只在分辨率 / 方向变化时检查一次**：每次变化都回到该方向的默认；用户的手动选择有效期 = 到下一次变化为止。
5. **不持久化**：不做「记住上次布局」，不做跨会话记忆，不新增设置项。

## 2. 用户裁决记录

| # | 裁决 | 说明 |
| --- | --- | --- |
| U1 | 判定口径 = 纯宽高比 `宽 > 高 × 1.2` | 明确否决「宽度 ≥768px」等宽度阈值作为方向判据 |
| U2 | 竖屏默认 = 聊天框 | 即现状，竖屏交互一律不改 |
| U3 | 横屏默认 = 左消息 + 右文件窗格 | 右栏落在**文件看板（列表）态**，不是自动打开某个文件 |
| U4 | 分辨率变化时检查一次并回该方向默认 | 横→竖：关掉预览回聊天框；竖→横：打开右栏左右分屏 |
| U5 | 竖屏下**手动点文件**的默认布局不改 | 沿用既有「宽 ≥768px → 左右分屏 / 否则全屏」 |
| U6 | 分屏栏不改 | 现有「上下分屏 / 左右分屏 / 全屏预览」三图标 + ✕ 已覆盖四态；「全屏消息」= ✕ 关闭窗格。页头「文件面板」钮（开/收窗格）保持原样 |
| U7 | **例外：当前处于全屏阅读文件的状态时，比例变化一律维持全屏** | 判据是**当前状态**（`mode === "fullscreen"`），不是「用户是否手动切过」：竖屏窄屏点文件本来就默认全屏，此刻同样算「正在全屏阅读」，旋转一并豁免。全屏下旋转 / 换比例既不降级成左右分屏，也不关掉。例外只豁免自动重排，不冻结界面——用户仍可点分屏栏切回分屏、点 ✕ 关窗格 |

## 3. 现状与差距（改造前实测）

| 现状 | 位置 |
| --- | --- |
| 预览态 `preview === null` 即聊天框；`PreviewMode = "split" \| "split-h" \| "fullscreen"` | `src/mobile/PreviewModeSwitcher.tsx:10`、`src/mobile/SessionDetail.tsx`（`PreviewState`） |
| 打开预览的默认布局只看宽度（`min-width: 768px`），4 个入口各自写三元 | `SessionDetail.tsx` 的 `isWideViewport()` 与 `openFile` / `openSubagent` / `togglePanel` / `showFilePanel` |
| 分屏渲染：`split` / `split-h` 内联分屏、`fullscreen` 全屏浮层、`null` 单列对话 | `SessionDetail.tsx` 三个互斥分支 |
| **无**任何 `orientation` / `aspect-ratio` / `resize` 监听；布局与比例完全不持久化 | 全仓 grep 确认 |

**差距**：进入详情时不存在「按方向给默认」的概念；旋转屏幕后布局保持原样，横屏手机会停在窄屏单列、竖屏手机会保留用户上次拉出的分屏。

## 4. 功能需求

| # | 需求 | 验收口径 |
| --- | --- | --- |
| M1 | 进入会话详情时按当前方向给默认布局 | 横屏：左消息 + 右文件看板（左右分屏），页头「文件面板」钮为高亮态；竖屏：纯聊天框，无预览窗格 |
| M2 | 方向 / 分辨率变化时重新判定一次 | 竖→横：右栏自动出现并左右分屏（若此前已打开某个文件，保留该内容只改布局）；横→竖：预览关闭回到聊天框。**例外（U7）**：若当前是**全屏阅读文件**，两个方向都原样维持全屏 |
| M3 | 手动切换不受默认限制 | 变化之后仍可用分屏栏在「上下分屏 / 左右分屏 / 全屏预览」间切换，用 ✕ 回到全屏消息；手动选择有效到下一次方向变化 |
| M4 | 横屏下打开文件 / 子 Agent 的默认布局 | 恒为左右分屏（不掉回全屏浮层）；竖屏保持既有宽度口径（U5） |

实现附注（非需求）：方向判据用媒体查询 `(min-aspect-ratio: 6/5)`（即 `≥1.2`）而非 `window.innerWidth/innerHeight`，理由见计划 §3.1（旋转可靠、软键盘免疫、jsdom 测试零回归）。

## 5. 已知限制（如实申报）

| # | 限制 |
| --- | --- |
| L1 | 媒体查询只能表达 `≥1.2`，与「大于 1.2」在临界点差一像素级 |
| L2 | 近方形设备（如展开态折叠屏约 1.25）在浏览器地址栏收放时可能跨 1.2 边界，右栏会开合一次；本轮不加迟滞 / 去抖 |
| L3 | 横 → 竖会**关闭正在看的文件**（U4 直译；**全屏阅读态除外**，见 U7）；文件栏比例、面板筛选 / 搜索态随卸载丢失 |
| L4 | 布局切换等于换 React 子树：消息滚动位置回到底部、输入框未发送草稿丢失（既有行为，旋转会放大触发频率） |
| L5 | 横屏小屏（如 667×375）默认左右分屏后每栏约 333px，文件面板三个下拉 + 搜索框偏挤；如需加最小宽度门槛另行裁决 |
| L6 | 横屏进详情会让文件面板多打一次 `GET /m/api/v1/channel`（与输入区重复，静默、无副作用） |
| L7 | 预览已开时再点正文文件链接 / chip 直达，仍按该方向的默认布局重设 mode（改造前的既有行为，本轮未收口） |
| L8 | 「横屏首屏不闪文件面板空态」靠 `fileLoading` 初值 true 保证，jsdom 无 paint、无法自动化断言，列入真机留验 |

## 6. 验收标准

- `g1` 新增「方向判定」单测：媒体查询缺失 / 抛错 → 竖屏；命中 → 横屏；订阅与退订、legacy API、兜底通道全覆盖。
- `g2` 详情页集成用例：横屏进入 / 竖屏进入 / 竖→横 / 横→竖 / 横屏点文件 / 竖屏点文件回退锁 / 首屏不闪空态 / iPhone SE 横屏 / iPad 竖屏（判据锁定）/ 竖→横保留已打开文件 / 手动布局不记忆 / 同值唤醒不重置 / 全屏阅读两方向维持全屏（U7，2 条），共 13 条通过。
- `g3` 既有移动端用例全绿（`matchMedia` 缺失 = 竖屏的既有口径不被破坏）。
- `g4` `pnpm check`、`pnpm build:mobile` 通过。
- `g5` 真机留验（jsdom 无布局引擎，像素级不可自动化）：iOS Safari / Android Chrome / PWA standalone 旋转；横屏打字时键盘不触发重排。

---

## 7. 明确不做

- 不持久化布局；不加移动端设置项；不改桌面端外观配置下发（`remote_ui_config`）。
- 不改分屏栏（U6），不新增「全屏消息」按钮（✕ 已等价）。
- 不改 `mobile.html` 的 viewport（加 `interactive-widget` 会让键盘缩小布局视口，反而制造误判）。
- 不改 `docs/MASTER-PLAN.md`；不改 `docs/design/remote-ui/` 线稿（02 详情层线稿未覆盖布局切换器，本次无视觉新增、无冲突）。
- 不动桌面端任何代码。
