## 0. 背景与目标

以 Claude Code 的问答交互为标杆，把其屏读与交互机制抽象为**公共模式**推广到 codex CLI / kimi code / opencode，终结「一家一套、逐家纠正」的现状。本任务交付后：

1. 自由作答（type something/own answer/Other/notes）链路在 kimi/codex/opencode 走**同一台通用编排器**，各家差异以方言表（数据）表达；
2. **屏读快照**（题干/勾选态/已填文字）从 claude 独有扩展为**按取证状态逐步可用**——opencode 必得；kimi/codex 以探测定案为前提，未取证不给值；
3. kimi 多选、codex 弹窗键序经实机探测定案后接入方言表，未取证的能力位保持关闭（未取证不出手；codex 以 relay 可用为前提，不可达则留位登记）。

**范围红线**：claude 现有六台阶段机一行不动；select/toggle/submit/advance 的各家已验证编排不动；探测遵守八条铁律；锚文案禁止手造；测试不触真实 `~/.mam`；不碰 MASTER-PLAN。

## 2. 功能点明细

### F1 交互方言表 `QuestionDialect`

- **输入**：四家已定案的交互语义（键序大词典、戊探A/B/C、2026-10-04 用户实测、探测批 K/C 新定案）。
- **输出**：一张纯数据表（每工具一条），字段覆盖：行语法（编号/勾选框标记集合）、own-answer 入口标签、勾选动词、编辑门序列（进编辑态前要按的键，含"已勾选时双 enter"这类条件分支）、已存文本抽取规则、清空动词（光标位置方言：末尾回删 / 推到行尾再回删）、保存动词（是否附带推进）、切题方式、提交流形态、终态回执锚（账本键）、高亮是否字符层可见。
- **实现效果**：编排器读表办事；新增/变更工具交互 = 改表 + 账本加行，不再新写阶段机。表与代码分离，表上每条填制值注明证据出处（探针档案/用户实测）。
- **机制复用**：`anchor_ledger` 的 append-only + 证据字段纪律；`dialog::parse_option_line` 的行解析扩展勾选段。
- **验收**：表的单元测试逐字段锁值；四家表能完整表达现状定案（与矩阵手册 §7 一致）。

### F2 通用自由作答编排器 `generic_own_answer_stages`

- **输入**：目标文本、overwrite 标志、方言表条目、屏读/按键终端缝（既有 `FreeTextTerminal`）。
- **输出**：统一回执 `{已发键序, 屏读文本真值, 勾选态真值, 终态锚是否命中}`；失败 = 带屏面摘要的中止（零误发键）。
- **实现效果**：opencode 现编排（toggle 双 enter、退格清空、保存不推进）泛化为按方言表驱动；kimi（Other 行）与 codex（notes）改走同一编排器，行为与各自已定案语义一致；「非覆盖 + 已有保存内容 → 中止提示覆盖写入」「清空 = 空文本+覆盖」语义按方言表**适用面**统一表达（kimi/codex 不存在"已保存内容"概念的槽位不启用）。
- **机制复用**：`FreeTextTerminal` 缝、裸打字守卫（占位行/输入行判定）、首错即停、`stage_receipt_seen` 终态锚轮询；claude 六机不迁移、仅作语义参照。
- **验收**：每家键序脚本锁（鲜态/已保存/守卫失败/中止路径）全绿。

### F3 opencode 屏读快照 + 走位弱校验

- **输入**：终端可见窗行集。
- **输出**：`QuestionScreenModel{heading, checked[], freeText, freeTextPresent, review?}`（schema 对齐 claude 快照），接入 GET `/session-question` 的 `screen` 字段与 freeText/toggle 等 action 回执。
- **实现效果**：opencode 问答卡的勾选态/已填文字由终端屏读纠偏（与 claude 同权）；用户在终端手动操作后回手机不再漂移。另：↓ 盲走（高亮字符层不可见）加编号连续性弱校验——走位前后读屏核验目标行仍在、编号未跳变，异常即中止（降险不消除，已知边界仍登记）。
- **机制复用**：claude `question_screen_snapshot` 的协议与前端对位逻辑零改动复用（前端只认 schema）；行块解析按 F1 方言表的 opencode 行语法新写。
- **验收**：快照单测（夹具=真实屏面形态）+ GET 载荷含 screen 的端点测试。

### F4 kimi 多选形态探测与接入（探测批 K）

- **输入**：自建 kimi 会话（conhost 探测纪律：run-id 日志/截图/会话文件三重证据/taskkill 清场）。
- **输出**：多选题交互定案记录——toggle 键（space/enter/数字）、勾选态屏读形态（有无 `[ ]`/`[✓]` 标记）、Review 链在多选下的形态、Other 行编号面、编辑后光标位置（清空方言依据）→ 全部回填 F1 方言表。
- **实现效果**：kimi 多选题手机端点亮自由作答（`multiFreeText` 旗标）+ 屏读快照（按定案程度给值）；探不到的槽位保持关闭并登记。
- **机制复用**：win-console-inject-probe 技能流程；F2 编排器 + F3 快照层。
- **验收**：探测档案归档 docs/research/；接入后 kimi 键序脚本锁绿。

### F5 codex 弹窗键序实机复验与接入（探测批 C）

- **输入**：自建 codex 会话（Plan 模式触发 `request_user_input`）；**前提 = 用户侧 relay 已修复**（此前 403）。
- **输出**：源码级键位（数字直选/↑↓+Enter/Tab notes/Space 选中/多题切换/未答确认弹窗）逐项实机复核定案 → 回填方言表；notes 流与既有 `CodexNotes` 对齐；快照按弹窗形态接入。
- **实现效果**：codex 问答键位从「源码级推断」升级为「实测定案」；方言表 codex 条目补全。
- **降级分支（relay 仍不可达）**：本功能点**留位登记**——方言表 codex 条目标注「源码级未实测」，编排与快照接入点预留但不点亮任何新能力，探测批移出本任务（其余功能点交付不受阻）。
- **机制复用**：同 F4；既有 `CodexNotes` 编排与账本行。
- **验收**：探测档案或留位登记；接入部分脚本锁绿。

### F6 能力位与快照字段扩展

- **输入**：F3–F5 的取证状态。
- **输出**：GET `/session-question` 载荷——`screen` 对取证完成的工具开放（opencode 必有；kimi/codex 按探测结果）；`multiFreeText`/`freeText` 等旗标按方言表+取证状态给值；各 action 回执统一带 `screen`（未取证工具不给，前端缺字段兼容不变）。
- **实现效果**：前端零改动扩展（消费统一 schema + 缺字段兼容既有契约）；「未取证不出手」在载荷层可观测。
- **验收**：载荷契约测试逐工具断言。

### F7 质量资产与交付

- **输出**：①方言表单测 + 四家键序脚本锁（含既有锁迁移/保留）；②新账本行（探测新增锚，若有）；③门禁全绿：cargo fmt/check/clippy --all-targets/test（本机）+ windows-gnu 交叉 + pnpm lint/vitest/build:mobile；④commit（本地）；⑤**逐家手工测试清单**（见 §4）。
- **说明**：门禁按既有约定一次性补跑（用户此前豁免快修批次，本任务为完整交付不再豁免）。

## 3. 执行说明

- **单任务推进**：F1→F2→F3 顺序实施（依赖链），F4/F5 探测批可与代码并行穿插；全部完成后统一门禁+commit+清单，**中途不停点等确认**（探测异常、relay 不可达等按各功能点内置降级分支处理并如实汇报）。
- **探测批纪律**：只碰自建会话、追加式日志带 run-id、结束 taskkill 清场、锚文案逐字取证据、结论不超证据。
- **交付物清单**：设计文档（本文件）、执行计划（writing-plans 产出）、探测档案（docs/research/）、代码+测试、手册 §7 增量行、手工测试清单。
