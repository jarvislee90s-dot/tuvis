本次用户请求替代 [F01—F08 设计](2026-10-26-Codex-F01-F08阶段需求与设计.md) §6.2/§6.3/总验收中的“运行中只存稿、不派发、不接 steer”，以及 [10 月 29 日计划](../plans/2026-10-29-Codex题卡状态与发送区修复计划.md) T03 对全部异步答题固定 `active.allowed=false` 的阶段限制。AsyncAnswerIdle 本身仍只限 idle；新增 active 操作独立判定。分组、暂停及 [B1 设计](2026-11-05-codex-异步答题持久事实可靠性设计.md) 的历史完整性、唯一身份、撤销和预算要求继续适用。

**取舍：** 只补正式答题路由与事实来源，增加一列内部持久 route，换取迟到/恢复不混淆引导与新回合；不改公开 HTTP/command/ControlRoute，不扩 B1.3、不覆盖现有队列或其他脏稿。

## 4. 内部接口与冻结规则

服务内部使用 `AsyncAnswerRoute::{IdleStart,ActiveSteer}`，不加 AsyncAnswerCommand/HTTP 请求字段，不改公开 ControlRoute。

| 映射              | IdleStart       | ActiveSteer       |
| ----------------- | --------------- | ----------------- |
| 存储词            | `idle_start`    | `active_steer`    |
| operation()       | AsyncAnswerIdle | AsyncAnswerActive |
| opens_turn()      | true            | false             |
| runtime_matches() | 仅新鲜 idle     | 仅新鲜 active     |
| RPC               | start-turn v2   | steer-turn v1     |

1. remote 单题/整组入口从用于题目、token、组成员验证的**同一份新鲜投影**捕获 route；unknown/stale/原生阻塞/相应契约不足拒发。队列暂停时，只允许该单题/整组动作携带的显式 grant；不清旧暂停，不放行其他排队动作。
2. 保留 `Router::answer_async(ctx,command,front,effect)` 为 IdleStart 兼容包装；crate 内 `answer_async_with_route(ctx,command,front,effect,route)` 接生产入口，Router 不再自行选另一模式。
3. reserve CAS 胜者同事务冻结持久 route/effect/起始审计；相同 actionId 重放只读旧动作，不能因当前 runtime 改 route/effect/clientUserMessageId。
4. `LeasedAnswerContext`、adapter `AnswerDispatchContext` 带同 route；保留 `DesktopDispatch.answer_async` 签名。旧无伴随派发缝仅支持 IdleStart，ActiveSteer 零投递，不退回旧方法。
5. 扩展现有 GroupBinding：单题/整组均绑定 action、route、来源和完整成员/token，仅胜者安装，冲突请求不能覆盖。最终 writer claim **从 row 读取 route**，传入 `with_interaction_verdict`，核对 action 绑定，在原 interaction_gate 内按 route.operation/runtime_matches 复核并竞争原首次写权 CAS。
6. 新动作 reserve 后不能仍为 NULL；旧 NULL 只解释为 legacy IdleStart。未知非 NULL 词严格拒绝相关写入/提升，不能 fallback。写前 route 对应运行态、包/owner/能力、来源/token/题组或设备资格发生漂移，均零帧并保稿；不自动跨路由重试，不重置预算。

**取舍：** 通过 crate 伴随与持久 row 同源传递，避免改全部 command literal 和公开客户端；独立 operation 防止旧 idle 证据解锁 active。最终写权内复核增加一次资格检查，换取 reserve 与实际写入之间仍能拒绝漂移目标。

ActiveSteer 请求形状如下；方法版本只从 `profile.rs::method_table()` 取得，本地不另造 hostId/expectedTurnId。

```text
method: thread-follower-steer-turn
params: { conversationId, clientUserMessageId,
  input:[{type:"text",text:正式信封,text_elements:[]}], attachments:[],
  restoreMessage:{id:clientUserMessageId,text:正式信封,cwd:已解析线程目录,createdAt:构造时间,
    context:{prompt:正式信封,turnTrigger:"send_user_message_async_question",addedFiles:[],fileAttachments:[],imageAttachments:[],ideContext:null,workspaceRoots:既有工作区根},
    responsesapiClientMetadata:{source:"codex"}} }
response: result.result = {turnId}
```

serviceTier/additionalContext 仅复用可信现有上下文，不传 toolOutput。后端从有效题目生成标识/title/信封，不接远程 raw 信封。turnId 是作用的已有回合，不证明新开回合。

## 5. 一列持久路由、旧 book 与效果隔离

**唯一选择：** `codex_actions` 新增 `async_answer_route TEXT NULL`；新动作 reserve 同事务写显式词，旧行不回填。schema 与幂等旧库迁移得到同一结构，旧 NULL 沿原 idle 保守恢复规则，不授 active。相比 effect 列 NULL 推断，多一列可明确区分“active”与“idle 未捕获效果目标”，保住旧重启保护；不再保留无 schema 备选，不扩 B1.3 结构。

queue/DAO 使用专用 `reserve_async_answer(action_id,route,effect_target)` 接缝。事务内**先通过严格 row reader 读取原行，再执行 queued→reserved CAS**，胜者一并冻结 route/effect 并写起始审计；未知非 NULL 存储词须在覆盖前报错，不能被请求参数洗成合法 route。输家零修改；CAS 或审计失败则同事务回滚，不留下部分冻结事实。

Router 在 reserve 后运行态复核、取得 writer、检查旧 book、mark 及 bind 各接缝按 route 分流：IdleStart/旧 NULL 保留原开回合保护；ActiveSteer 允许旧 A 运行 book 在场，仍取得同一真实 writer/租约，但**不 mark 新 book、不 bind/forget/clear A、不接管 A 的 fence**。只有真正 writer 在途才需要等待其退场，模型 active 本身不等于 writer 一直占用。

DAO `finish_and_settle_claim_conn`、`finish_with_turn_barrier_conn`、`finish_late_result_conn`、`recover_one_conn`、`mark_stale_reserved_unknown_conn`、turn 补绑及 remote `settle_turn_evidence` 均从 row 取冻结 route，不看当前 runtime，不按 kind 固定推断。ActiveSteer 的 Accepted/Unknown/Rejected/NotSent、迟到、取消及重启都只收尾本动作/同题 claim，不生成或复活新 turn fence/book、不改 A/旧暂停；Unknown 保留本题排他与核对，不自动重发。IdleStart/旧 NULL 原 fence 恢复保护不退化；旧 A 仍由原归属路径核销。

**成功归属：** EffectSettlement 的目标仅包含 probe/SHA，不能仅凭 `kind=async_question` 固定写 idle 成功。ActiveSteer 的 `effect.target=None`；`settle_confirmed_effect` 再按持久 route 显式跳过 active，即使存在残留 target 也不得写 idle 或 active ObservedSuccess。IdleStart 原效果确认后记 idle 成功保持。迟到、观察器、手动核对及重启均遵守该边界；active 授权只用 §2 的独立当前包契约及适配开关。

**取舍：** active 复用原串行 writer 和本题排他，却不取得开回合资源的所有权，避免 steer 返回已有 turnId 后误清旧 A。保留 Unknown 的核对成本，换取未知投递不自动重发；暂不积累 active 成功证据，避免扩大本批证据授权面。

## 6. 正式事实与 B1.3 增量路径

### 6.1 共享正文判据与增量依赖

共享纯内部 `formal_answer_text`：userMessage 读 `content[]`；steeringUserMessage 仅在同对象 `status=="accepted" || steerAcknowledged==true` 时读 `input[]`。只取 `type=="text"` 且 text 为字符串的块，按官方顺序以 `"\n"` join；不另作空白归一化来合并来源。另一确认条件仍为 true 时，按实际 OR 处理。

`analyze_answer_witnesses`、`answered_map`、`malformed_envelope` 与 mirror 答案分析共同使用该判据。pending 未确认、RPC ACK、请求参数回声、本地发送记忆、助手引用、turn 终态或时间经过均不能清题。accepted/ack steering 的非法正式信封须在严格分析和 malformed 检查中共同拒绝，不能因漏扫被误造 Pending/Answered。

保留原 canonical 唯一引用、唯一 item.id、题后顺序、相关覆盖、摘要和撤销规则。B1.3 item 增量缓存/相关性分类纳入 type/id/content/input/status/steerAcknowledged 和稳定消息关联字段；pending→accepted/ack true 必须重新分析。确认条件整体失效、正文/题目/来源删除或改写不得沿用旧 witness。镜像只在整批状态成功采用后登记证明；缺页本身不构成来源退役。同次分析/索引复用，热路径读内存，不按每题重复全历史扫描。

**取舍：** 统一正文提取及依赖判据，减少投影、严格分析和镜像缓存各认一种来源的分歧；仍需把确认与关联元数据列入相关补丁，接受这些补丁引起的必要重分析。

### 6.2 唯一 S→U 关联与物理 witness

本节 S 指已确认的 steeringUserMessage，U 指后续正式 userMessage，与 §2 的资源别名无关。单个合法来源可独立形成物理 witness；S/U 共存时，仅在以下条件全部成立时视为一份逻辑答复，并优先 U 为当前物理 witness：

1. 存在唯一稳定关联：`S.serverUserMessageId==U.id`，或 `S.clientUserMessageId==U.clientId`；关联计数唯一，同时出现的 server/client 关联不得互相矛盾。
2. 两者指向同一正式题目，`formal_answer_text` 提取的**全文 SHA-256 相同**；仅某一题答案相同或仅信封解析结果相近不足以合并。
3. S、U 都在题目之后，且 canonical 顺序严格为 S 先 U；同 turn 依 items 顺序，跨 turn 依引用顺序。

无关联、多义、矛盾、异文、不合法顺序或多于可唯一证明的一对来源，均保守 Unknown。禁止按同文或时间接近猜配，也禁止借新来源洗白退役 witness。

`AnswerWitness` 保持 `proof_version`、`answer_turn_id`、`answer_item_id`、`answer_digest` **四字段**，proof v1 及既有物理 Eq 语义不变；不增加持久别名。单次严格分析的临时 `AnalyzedAnswer` 包含 physical witness 和可选 `LinkedSteeringProof`；后者借用 S 的 item ID，并携带 S 的 **32 字节物理 digest**。该临时证明只允许精确的 S→U 接力：必须匹配原 S 的 proof v1、item ID 及原物理摘要，不能仅凭“有一个 companion”豁免替换退役。

**取舍：** 优先 U 可兼容原生正式消息落地，保持已有 witness 的存储与相等性契约；使用严格全文和物理摘要会保守拒绝一些无法唯一证明的来源变化，避免扩大为通用别名合并。

### 6.3 共享撤销账本的单一联带来源

`answer_validity.rs` 的共享运行期账本继续按 `(ThreadKey, question)` 管理 Entry。每个 Entry 在当前完整 physical witness 旁最多额外保存一个 `linked_steering_id`；绑定对象是当前四字段物理证明，不只是 item ID。临时分析证明及该联带 ID 均不进入 hint/持久 witness，不新增 DB 字段，不建立别名图，也不保存题干或答案正文。

| 变化                                               | 同锁核验及退役规则                                                                                                                                |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 精确 S→U 接力                                      | 临时物理证明精确匹配原 S，才可换为 U 而不退役 S；登记 S 为 U 的唯一联带来源。                                                                     |
| 同一完整 physical witness 未再带 companion         | 保留已知 linked ID，覆盖跨 mirror 及原 S 已消失后的后续核验；不能因本次分析只看见 U 就丢失关联。                                                  |
| 同一完整 physical witness 出现不同 companion       | 不换绑、不累积第二个别名，隔离该题；只读候选核验也拒绝该冲突。                                                                                    |
| 明确退役、题目依赖失效、同 ID 物理改写、非接力替换 | 当前 physical 与已绑定 linked ID 在同一账本锁内联带退役；原证明不能经另一来源复活。                                                               |
| 接力后 linked S 的确认整体失效或 input 被显式改写  | 按 §6.5 的 canonical/显式 patch 边界取证，即使 U 的完整 physical witness 不变也不能跳过；确认撤销/正文改写成立则联带退役 S 与 U。                 |
| `retire_if_observed` / `quarantine_if_observed`    | getter 取得完整 witness 与 linked ID 的一致快照；写回时同锁比较完整 witness Eq 及 linked ID，仍为原值才联带退役或条件隔离，旧取证不能影响新证明。 |
| 已退役 S 随 U 到达                                 | 拒绝 U，并将 U 本身登记退役；预算不足则隔离/关闭准入，不能仅拒绝本次显示后留下 U 可重新放行。                                                     |

这些约束由共享账本承担，不依赖某个 mirror 仍保有 S。linked 来源核验属于既有撤销纪律，具体取证资格按 §6.5 执行。纯删除、滚窗、卸载及合法关联元数据补齐均不能当成确认撤销或正文改写；确认条件仍按 OR 处理。正常接力后删除原 S、保留唯一有效 U 且题目依赖不变，仍可 Answered；之后明确退役 S 或 U，均须联带阻断另一物理来源。缺页仍沿 B1 保守规则处理，不把暂未加载当成明确删除。

**取舍：** 一个联带 ID 足以保住已确认接力的撤销关系，且跨 mirror 可核验；增加有限来源核验成本以防止物理 U 掩盖 S 失效。出现不同 companion 时选择隔离，接受保守 Unknown，避免引入无界别名图及持久迁移。

### 6.4 预算与失败边界

既有上限保持：每题最多 256 个退役来源、全局最多 4096 个 key、总字节预算 4 MiB。新增联带成本为 `linked=None → 0`、`linked=Some(id) → 96 + id.len()`，其中长度按 UTF-8 字节计算；普通无关联 witness 保持原成本。

更新当前 witness/联带 ID 前先核算替换后的总预算，再为新增 linked ID 分配 String。超预算进入既有 Quarantined/AdmissionClosed 保守路径；退役 physical/linked 所需预算不足也不得放行。禁止丢弃关联后接纳 U，或以临时 proof 绕过 Entry/退役集合的预算。

**取舍：** 联带成本显式纳入原账本，不另设容量池；达到预算时牺牲该题可用性，保住有界内存及已知撤销事实。

### 6.5 接力后来源取证与条件隔离

账本提供只读短锁 getter，一次返回当前完整 physical witness 与单一 linked ID 的一致快照。mirror 按本次题目依赖收集需核验的关联，在锁外定位来源、提取正式正文并比较摘要；snapshot 和新 mirror 同样从共享账本取得已知关联，不依赖 old 分析结果仍包含 S。`retire_linked_if_observed` 与 `quarantine_linked_if_observed` 写回时必须同锁比较 getter 快照的**完整 witness + linked ID**；任一已变则丢弃旧取证，不退役或隔离当前新值。getter 和这些条件写回不改变四字段持久 witness 契约。

取证只针对已成功采用的整批状态，并遵守以下资格边界：

| 当前来源位置                                         | 可用证据及处理                                                                                                                                                                                            |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| U 在当前 canonical                                   | U 必须属于当前 canonical 引用链，turn/item 与账本当前 physical witness 匹配，且正式正文可读取、可核对。实体表中同 ID 的孤儿条目不能替代该 U；本节不豁免 U 自身的 B1 来源有效性检查。                      |
| S 在当前 canonical                                   | 可按完整已采用状态核验 S 的确认 OR 条件与正式正文；确认整体失效或正式全文 SHA 与 U 不等时，联带退役 S/U。该路径不要求 old 分析仍有 S，适用于 snapshot/新 mirror。                                         |
| S 只在当前实体表中、已不属 canonical                 | 仅在 **old 中可唯一定位该 S，且本批显式 patch 触及其确认/正式正文语义并实际改变该语义**时取证；不额外要求 old 中的 S 属 canonical。满足此资格后，确认整体失效或正式全文 SHA 与 U 不等才构成联带退役证据。 |
| snapshot 中只有孤儿 S 旧残留，或本批未实际改变其语义 | 不能从孤儿旧值直接推导撤销；保留已知 linked ID，不因其旧 status/input 与 U 不符就退役 U。合法关联元数据补齐不构成上述语义变化。                                                                           |
| linked S 纯删除、滚窗、卸载或暂未加载                | 不作为确认撤销/正文改写，不因 S 消失退役仍合法的 U；保持账本已知关联。                                                                                                                                    |

S 的 OR 条件仍为 true 时不能仅因另一确认字段改变而判撤销；正文比较使用 §6.1 的正式文本及全文 SHA，不能把不影响正式文本的元数据修改当正文改写。孤儿 S 的显式语义变更路径必须与纯删除/卸载区分，不能仅凭“当前非 canonical”跳过已成立的 patch 证据，也不能凭 snapshot 孤儿残留制造退役。

每次状态采用最多构建一次共用的 `OldItemIndex::current(next)`，并复用 old 定位索引；实体定位与 canonical 归属分别核验。正式文本 SHA 按 item 在本次已采用状态中缓存，每个可定位 item 最多提取/散列一次，供同信封多题共享；状态变化后重新核算，不把旧正文摘要沿用到同 ID 新内容。

若 next 实体索引为 `items=None`（包括超 4096、重复 ID 或无法建立有效索引），本次相关的已登记 linked Entry 须通过 `quarantine_linked_if_observed` 条件隔离，不能跳过取证后继续接受 U，也不回退逐题全历史扫描。索引拒绝只表示无法证明身份，**不构成退役证据**；隔离仅标记匹配的既有 Entry，不新建 key、别名或退役来源，不丢 linked ID 后放行，并沿用原 Quarantined/AdmissionClosed 门控。

**取舍：** canonical 状态可直接核验，孤儿实体则要求同批显式语义变更，兼顾有效撤销和滚窗残留。完整 witness 与 linked ID 的条件比较保护并发新证明；索引失败选择隔离而非追加扫描，牺牲该题可用性以保住身份与性能预算，且不把“无法取证”伪造为“已证实撤销”。
