# 移动端历史会话区（归档 + 重新激活闭环）设计文档

- 日期：2026-09-20
- 状态：待用户评审
- 来源：resume「在电脑上打开」体验问题 brainstorming（对话全程裁决记录见 §3）
- 上游依赖：`feat/phase2-injection` fba50c9（resume 效果回查 + 孤儿豁免修复批，Mac 快测 Q1/Q2 已 PASS）

## 1. 背景与问题

现行「在电脑上打开」（R5 一键 resume）只对**活会话**可达：移动端看板卡片来自活进程扫描（L1 契约：零进程零解析），详情页只要 cwd 与工具在 `RESUME_TABLE` 就亮按钮——**不判终端死活**。由此产生两个体验缺陷：

1. **双终端**：终端已开着的活会话上点按钮，会再开一个同 id 的 resume 终端（Mac 实测确认：板上出现同 id 双卡），消息在远程端汇总但不在各自窗口展示。
2. **死会话不可达**：终端关闭 → 进程死 → 卡片消失 → 会话在系统里不复存在，「在电脑上打开」无从谈起——而这恰恰是该功能最有价值的场景（恢复昨天关掉的工作）。

**死结根源**：看板宇宙 = 活进程集合，无死会话的持久化记忆。

## 2. 目标与非目标

### 目标

1. 死会话进入**独立历史页**（移动端）：保留 session id、工具、项目目录、最后状态/时间，可浏览历史对话内容。
2. 历史页内点「在桌面端打开」→ 走既有 resume 链（起进程 + cd 原目录 + resume 原 id）→ 会话回到活板，形成闭环。
3. 历史页支持双维筛选：工具 chips（沿用现有组件）× 项目下拉（动态聚合）× 追溯窗口 1/3/7 天。
4. 活会话详情页**隐藏**「在电脑上打开」按钮。
5. 归档不参与消息提醒（unread/通知）。

### 非目标（明确不做）

- **桌面端归档 UI**：人在桌面直接在各终端 APP 里找，本轮仅移动端。
- **活会话看板的项目筛选**：并发会话 ≤10 个，一眼可辨，不需要（用户裁决）。
- **死会话文件系统扫描**：不碰 L1/L3 扫描预算红线——归档数据只来自「在职登记」。
- **冷启动补捞**：MAM 未运行期间死掉的会话不入档（用户裁决 A：登记制，接受空洞）。
- 「聚焦既有终端窗口」按钮：本轮不做（活会话按钮直接隐藏；聚焦作为后续可选增强）。
- 通知/unread 管道改动：归档天然不进提醒，零改动。

## 3. 用户裁决记录（对话定案，实现不得偏离）

| # | 决策点 | 裁决 |
|---|---|---|
| 1 | 归档数据来源 | 纯登记制：只收 MAM 运行期间上过板的会话；不做磁盘扫描/启动补捞 |
| 2 | 活会话按钮 | 整体隐藏（不换聚焦）——桌面端有桌面端的跳转，不重复设卡 |
| 3 | 客户端范围 | 仅移动端；桌面端不动 |
| 4 | 读取触发 | 懒加载：进入历史页才请求；默认 1 天追溯，用户点选扩到 3/7 天（上限 7 天）；历史页内不轮询（死数据静态） |
| 5 | UI 形态 | 独立历史页（看板右上角入口），不占主看板纵向空间 |
| 6 | 打开按钮位置 | 只在归档**详情页**内，不浮在列表卡片上（省卡片纵向空间 + 用户先看内容再决定恢复） |
| 7 | 项目筛选范围 | 只做历史页（第二行下拉）；活会话看板不加 |
| 8 | 保留策略 | 只增不删 + 手动管理（单条移除 + 清空归档），不做自动过期 |

## 4. 总体数据流

```
活板轮询（3s，不变）
  └─ 扫描产出 Session[] ──(顺手)──> session_archive 表 upsert「在职登记」
                                        │
MAM 关闭终端/进程死 ──> 行留在表内 =「离职归档」（无任何主动动作）
                                        │
移动端进入历史页 ──(懒加载，仅此时)──> GET /sessions-archived?days=N
                                        │  查询期：登记表 − 活板同 id（不删行）
                                        ▼
                          历史页列表（工具 × 项目 × 天数筛选）
                                        │ 点卡片
                                        ▼
                          归档详情页：会话内容（既有 /session-messages，
                          按 id 直读文件，零改动）+「在桌面端打开」
                                        │ 点击
                                        ▼
              POST /session-open（既有端点，查找链扩归档回退）
                  └─ 既有 resume 链：起进程 + cd + resume + 效果回查（不改）
                                        │ 新进程上板
                                        ▼
              活板出现同 id 卡片，归档条目在下次查询自动隐藏（闭环）
```

## 5. 数据层：`session_archive` 表

新表（不扩展 `session_status_cache`——该表服务状态跃迁检测，语义与生命周期独立，复用会互相牵制）：

```sql
CREATE TABLE session_archive (
    session_id   TEXT PRIMARY KEY,
    agent_type   TEXT NOT NULL,
    project_path TEXT NOT NULL,   -- cwd；resume 的 cd 落点（不可空：无 cwd 会话不登记）
    project_name TEXT NOT NULL,   -- 卡片与筛选显示名
    title        TEXT,            -- 最后会话标题（可空）
    last_status  TEXT NOT NULL,   -- 结束前最后状态
    first_seen   TEXT NOT NULL,   -- 首次上板（ISO8601）
    last_seen    TEXT NOT NULL,   -- 最后在板（追溯窗口的排序/过滤依据）
    updated_at   TEXT NOT NULL    -- 登记行最后写入时间
);
```

**登记写入**：挂在每轮会话扫描完成后（具体点位——扫描编排层或 watcher——留实现计划期定，判据：**每轮可见全量会话快照**）。注意**不得**挂在状态跃迁事件上（`session_status_cache` 的挂法）：静止但活着的会话不产生跃迁，挂跃迁会让 `last_seen` 停更、追溯窗口把活会话误判为已死。逐会话 upsert，**写放大守卫**：仅当 `last_status / title / project_path` 变化，或 `last_seen` 距上次写入 ≥60s 才落盘——3 秒轮询下最坏每会话每分钟一次写。多客户端（桌面/移动）都触发扫描，登记不依赖移动端在线。

**不登记项**：`project_path` 为空的会话（无法 resume，归档无价值）；`agent_tools` 未启用工具的会话（本来不上板）。

## 6. 后端

### 6.1 `GET /m/api/v1/sessions-archived?days=N`

- **门禁**：挂在既有 `/m/api/v1` 内层 PIN gate 下（与 sessions/session-send 同路由器注册，结构性覆盖，无新增鉴权代码）。
- **参数**：`days ∈ {1,3,7}`，缺省 1；非法值夹取到 1（宽容口径，移动端始终传合法值）。
- **查询**：`last_seen ≥ now − N 天` **且** session_id 不在当前活板快照（`st.session_source()` 查期比对，不删行）。按 `last_seen` 降序。
- **响应**（camelCase，与既有会话端点风格一致）：

```json
{
  "archived": [
    { "sessionId": "…", "agentType": "codex", "projectPath": "/path",
      "projectName": "proj-x", "title": "修复登录超时",
      "lastStatus": "idle", "lastSeenAt": "2026-09-20T14:26:05Z" }
  ],
  "projects": ["MultiAgents-Manager", "proj-x", "proj-y"]
}
```

- `projects` = 本次结果集内 distinct projectName，按该项目的最大 last_seen 降序（下拉选项即当前窗口内可筛的项目）。
- **删除**（手动管理）：
  - `DELETE /m/api/v1/sessions-archived?session_id=…` — 单条移除（详情页「从归档移除」）；
  - `DELETE /m/api/v1/sessions-archived?all=1` — 清空（历史页菜单「清空归档」）。
  - 归档管理不写 `write_audit`（W5 词表是注入动作域，归档浏览/清理不属于，避免词表膨胀）。

### 6.2 `POST /session-open` 归档回退（唯一改动既有端点处）

现查找链：活快照 `find(|s| s.id == sid)` → 未命中 404 `no_session`。扩展为：**活快照未命中 → 查 `session_archive` 表 → 命中则构造 Session**（id / agent_type / project_path 来自登记行——同「id 取自本机数据、不回显远端输入」的安全口径，`resume.rs` 既有注释语义不变；其余字段缺省值即可，resume 链只消费这三个）→ 走既有 `open_session_terminal_with`（通道顺序/效果回查/审计全复用，零改动）。

审计行为不变：出手即写 `open`（ok/failed），归档来源与活板来源同账。

### 6.3 会话内容读取：零改动

`GET /session-messages` → `read_session_messages` 按 `agent_type + session_id` 从文件/存储直读（`content.rs:117`，不查活快照），文件在会话死后仍在磁盘——归档详情页直接复用。**计划期验证项**：逐工具确认 id→文件定位不依赖活进程上下文（claude 系按项目目录 `join("{sid}.jsonl")`，需确认跨项目目录按 id 检索路径；若有工具强依赖活上下文，该工具详情页降级显示「内容暂不可读」+ 打开按钮仍可用，逐工具验收时记录）。

### 6.4 扫描管道：零改动

登记是扫描的**旁路消费者**，不改扫描本身；L1/L3 预算红线无触碰。

## 7. 移动端 UI（`src/mobile/`）

### 7.1 看板（Board.tsx）——两处小改

- 页头右侧加「🕘 历史」入口（跳历史页）。
- 活会话详情页（SessionDetail）删除「在电脑上打开」按钮及其 opening 状态（`resumeUnavailableReason` 等逻辑**保留并复用**到归档详情页）。

### 7.2 历史页（新组件 `ArchiveBoard.tsx`）

- 页头：`‹ 返回` + 「历史会话」+ 右上「刷新」与「清空归档」两个文字入口（直接摆按钮，不做 ··· 菜单嵌套——动作单一，少一层点击）。
- 第一行：工具 chips（复用 `board-logic.ts` 的 chips 组件与 `filterByAgent`，独立 filter 状态——与活板选择互不干扰）。
- 第二行：项目下拉（原生 select 即可，选项 = 响应 `projects`，首项「全部」）+ 右侧 **1天/3天/7天** 分段控件（默认 1 天；切换即重新拉取）。
- 卡片：工具色点/图标 + projectName + title + 相对时间（「2 小时前结束」，客户端按 lastSeenAt 换算）。**卡片上无任何按钮**。
- 拉取时机：进入页面（days=1）、切换天数、页头刷新按钮（手动刷新）；**页内不轮询**。失败重试按钮 + 空态文案三档（1 天/3 天空 → 提示扩大窗口，7 天空 → 「暂无归档记录」）。

### 7.3 归档详情页（新组件或 SessionDetail 归档态分支）

- 复用既有会话内容渲染（消息列表、文件面板入口可选，首版只读消息列表即可）。
- 顶部信息行：工具 + 项目路径 + 最后状态 + 结束时间。
- 唯一动作按钮：「在桌面端打开」——复用 `RESUME_SUPPORTED_TOOLS` 镜像表与 `resumeUnavailableReason` 门（无 cwd 场景在登记层已排除，工具不支持时禁用 + 原因文案）。
- 次要动作：「从归档移除」（确认弹层 → DELETE → 返回历史页）。
- 点击打开：按钮转「正在电脑上打开终端…」（复用既有 opening 文案逻辑）→ 收到 `opening` 后 **乐观移除**该条并返回看板（服务端 SSOT：下次拉取自然排除；轮询空窗 3–6s 由乐观更新抹平）。failed 则停留展示错误。

### 7.4 i18n

移动端无 i18n 契约，中文内联（与现有一致）。

## 8. 边界与已知限制

| # | 场景 | 处理 |
|---|---|---|
| 1 | 冷启动空洞：MAM 未运行期间死掉的会话 | 不入档（裁决 A）。历史页为空是诚实表现 |
| 2 | 同 id 反复激活/死亡 | 登记行原地 upsert：first_seen 不变，last_seen/last_status 刷新 |
| 3 | 激活瞬间活板与归档并存的轮询空窗 | 服务端查询期已排除；移动端 opening 成功后乐观移除兜底 |
| 4 | 同 id 双终端双卡（既有现象，Mac 实测） | 本设计移除主要诱因（活会话按钮隐藏）；板上同 id 去重**不在本轮**，留待后续批次 |
| 5 | 归档表增长 | 登记制增速有限（MAM 运行期会话量级）；手动清空兜底；自动修剪后续按需 |
| 6 | 移动端离线/隧道断 | 历史页与其他端点同失败路径（错误态 + 重试），无特殊处理 |
| 7 | 会话文件已被工具自身清理（如 codex 归档策略） | 详情页内容读取 404 → 「内容暂不可读」降级；打开按钮仍可用（resume 由工具自身处理找不到 id 的情况，属工具侧行为） |
| 8 | 多设备共享归档 | 归档是服务端数据，所有配对设备同视图；删除全局生效（与队列/审计口径一致） |

## 附：与既有架构原则的对齐说明

- **扫描预算契约（AGENTS.md）**：登记是扫描旁路消费者，零新增文件扫描，L1/L3 无触碰。
- **W5 审计只增不改**：审计管道零改动；归档管理不入审计词表（§6.1）。
- **数据同源铁律**：历史页会话列表虽来自登记表（快照的沉淀），但「激活后回到活板」的闭环终点仍是活快照本身，注入/内容仍走既有同源端点。
- **resume 安全口径**（`resume.rs` 注释）：归档回退保持「id 取自本机数据」——登记表是本机数据，不引入远端输入面。
