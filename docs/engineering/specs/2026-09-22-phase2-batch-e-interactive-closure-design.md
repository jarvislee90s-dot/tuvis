## 1. 目标与非目标

**目标**：远程端（手机）= 桌面端全部交互能力，用户在任何卡片状态下不被卡死。四域：问答（单选/多选/多题/自由作答）、审批（二元/N 选项）、模式与权限（切换+回读）、插队与队列。

**非目标（本批不做，边界非选项）**：kimi server API；opencode 会话内权限切档；codex Permission Profiles（beta）；协议路线（三期）；zcode/dsh/workbuddy/openclaw。**已知边界**：claude 问答多题（一次调用多题的分页键序）Stage 1 未探测、键序未定案——按裁14 维持只读卡，下批探测后接入；claude 输入行清空键未实测——撤回防护采「中止+如实回执」不自动清空。

## 2. 问答能力规格（行为契约）

图例：〔键序〕=词典清淤版行；「回执」=用户可见结果+审计/落账。

| 能力 | claude | codex | kimi | opencode |
|---|---|---|---|---|
| 单选 | 数字即选即答（维持） | 数字即选即答+自动推进 | 数字单键直达 Review→'1'/Enter 确认 | VK 数字即选即答（维持） |
| 多选 | 数字切换+三段式提交（维持） | ➖（官方单选为主） | 切勾单次（数字/回车/空格任一）→tab→Submit→'1'/Enter；**[数字,回车] 双切抵消为已修缺陷** | enter 或数字=toggle（空格无效）→tab Confirm→enter 提交 |
| 多题 | **只读（键序未探，非目标边界）** | 数字即答+自动推进；Tab=备注文本框；←→ 切题；末题 Enter=submit all | 数字直选+**自动推进（禁尾 Enter——会误作用下一题）**；Review 汇总屏（`Ready to submit your answers?` [1]/[2]）为提交判据 | tab 前向切页；逐题作答；Confirm 页 enter 一次提交 |
| 自由作答 | Type something 行（维持 K4–K7） | Tab 开文本框（框内数字入文本、框内 Esc 退回选项）；落账 `user_note:` 数组元素 | Other 行数字→打字→回车→Review→提交 | own answer 行：enter 开输入行→打字→enter（裸打字守卫：未开行不发文本） |
| 取消 | Esc=拒答（is_error 回执） | 弹窗选项模式 Esc=中断整个会话（产品仅在「取消」语义且屏读确认后使用） | Esc=整题作废（无 resolved 落账） | Esc=`state.error`+dismissed 回执 |
| 回执/落账 | 会话 JSONL tool_result | rollout `answers.<qid>`（含 `user_note:`） | wire `interaction.resolved`（method 字段） | SQLite `answers` 二维数组按题序+`multiple` |

**约束**：多题键序不得复用单题序列的尾随确认键（kimi A3 禁令）；注入前屏读确认选项簇已渲染（裁18 通用规则）。

## 3. 审批能力规格

- **N 选项对话框**：codex=数字直选；**claude=数字优先+屏读验证+导航回退双路径**（裁18）；**kimi=导航确认（`↓×k+Enter`），数字通道禁用**（'2'+Enter 误批准实证，未被推翻）。
- **二元审批**：维持现状。
- **解析锚点**：选项簇定位=「离底栏最近合格簇+标题行锚」（`Claude has written up a plan…` 实测逐字节稳定），弃最长簇；解析失败降级二元卡+防重警示（红线 3 维持）。
- **布局契约（裁12）**：任何卡片/浮窗不得把 composer 顶出首屏或遮挡输入框——卡体总高度上限+长内容默认折叠+点开。

## 4. 模式与权限规格

- **切换可用态**：空闲与 busy 均可切换且直接生效（裁17：codex 含 Full Access 二段确认、kimi 同——busy 一律不拦）。
- **待决拦截（硬）**：问答/弹窗待决时权限/模式按钮**置灰+原因透出**（codex：切档键被弹窗吞+Enter 会误交默认答案；kimi：Enter 会误选污染待决态）；后端对 kimi **含回车的整条注入硬拒绝**。
- **菜单解析**：codex=标题/footer 短语窗+编号项（折行不产新项）+`(current)`；kimi=标题/footer 窗+两行组+`▶`/`← current`（关键词簇判据退役）。kimi「总是询问」必须可达（TUI ↓ 恰移一档已实证，失败只在解析层）。
- **回读与高亮**：kimi 权限档=切档回执锚 `Permission mode: <档名>`+菜单 `← current`；codex Default=底栏无模式词的缺席推断+菜单 `(current)`；claude=环序四档底栏词表。前端模式栏当前档高亮；漂移如实显示（kimi 批准后自动切出 plan=已知漂移口径）。

## 5. 插队与队列规格

| 工具 | 插队键序 | 队列语义 |
|---|---|---|
| claude | busy 注正文+Enter 入队 → Esc×1 → 整队取出开新回合；**投递前撤回窗口防护**：屏读输入行残留（疑似被撤回消息）→中止+回执「未投递…请人工确认」（不自动清空） | 整队批量（取出/插队/撤回均作用全部条目，裁16）；已发出无输出消息 Esc=撤回回编辑（功能） |
| codex | 打字→**Tab 入队**→Esc×1 直插（回退=草稿+Esc+手动 Enter） | Ctrl+C=打断+内容回框（撤回编辑，用户已接受副作用） |
| kimi | busy 直接投递=**排队制**（回合结束自动开新回合，无需 Esc）；**条件项**：Ctrl+S 立即插队（产品引擎通道 `#[ignore]` 复验通过才上，不通过只留排队制，结论落档） | Ctrl+S 多条=整队批量；↑=再编辑；Ctrl+C=取消编辑 |
| opencode | Esc=打断+直插（**全链键序未定面**：草稿 Esc 后去向待实机首测定案，实现不得预填） | 队列不可撤回编辑；⛔ **Ctrl+C 一律禁注**（退出应用，裁19） |

**回执纪律**：整队批量语义（裁16）；送达确认以会话文件/屏读为准，**不得谎报 delivered**（假成功禁令）；Esc 类注入单次+屏读确认。

## 6. 回执与落账规格

审计字段（action/reason）随新语义扩展（如 jump 中止 reason=输入行残留）；回执三态语义维持（Sent/Submitted/未投递如实）；所有「已投递」断言必须有会话文件或屏读对账支撑。

## 7. UI 契约

配色（裁11）：审批**对话框卡**并入问答同族蓝系（sky）；**二元审批**默认保留红系警示（可随 UI 方案并入蓝系）。composer 占位四态与实际行为一致（承诺/不承诺逐档对齐）；只读卡不承诺发送；freeText 入口文案跨家一致。
