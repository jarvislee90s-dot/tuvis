# F6 R-1 事件文件清理并发边界

## 目标

每 60 秒清理超过 5 分钟的 `events/*.json`。当前实现以 `stat` 得到的旧 mtime 直接 `remove_file(path)`，并在清理折叠时无条件豁免事件目录 stamp。检查与删除之间同一路径可被 hook 原子替换：清理器随后会删掉新事件；`read_dir` 之后到重新取 signature 前新建的事件也可能被目录豁免吞掉。`mtime == since` 还会被严格 `>` 判成旧物。

目标是仅删除“清理器实际移走且再次核实仍是同一个陈旧对象”的文件；事件目录的变化仅在已确认的清理删除能完整解释该变化时才豁免。

## 方案比较

1. **保留 stat 后删除并再 stat**：不能消除第二次 stat 到 `remove_file` 之间的替换窗口，拒绝。
2. **同目录唯一隔离名 + 对象身份核验 + 无覆盖恢复**：原子地移走当前目录项，再检查实际被移走的对象；只删除身份未变且仍陈旧的对象。其他情况无覆盖恢复，原路径已有后到事件时不覆盖它。推荐此方案。
3. **并发不确定时完全停用清理**：不会误删，但会长期积累事件文件。作为身份未知、目录不可读或安全恢复失败时的保守回退，而非正常路径。

## 清理算法

1. 清理拍对事件目录取成员快照：只纳入普通 `*.json` 文件，记录路径、平台文件身份、长度与 mtime。身份使用 Unix `dev + ino`、Windows volume serial + file index；Windows 身份字段缺失/为零、身份不可用、遇到 symlink 或目录读取失败时，不删除相关对象并标记 `uncertain`。
2. 仅将当前 mtime 年龄超过 300 秒的条目作为清理候选。对清理窗口的事件判定使用 `mtime >= since`，相等也算新鲜；同时依赖成员增删和文件身份/长度/mtime 变化对账，时间戳不单独证明对象身份。
3. 为每个候选用 `create_dir` 原子预留同目录唯一隔离目录，再将源路径 `rename` 到其中的 `.tmp` 文件。重新读取隔离对象身份、长度与 mtime：只有身份/长度/mtime 均与枚举记录相同且当前仍超过 300 秒，才允许删除隔离对象；`removed` 仅记录删除成功的原路径。
4. 身份变化或对象不再陈旧时，按新鲜事件处理。若原路径仍空，使用同卷、无覆盖的硬链接恢复到原名，再删除隔离文件与空隔离目录；若原路径已有不同身份的普通文件，仅在 `hard_link` 明确返回 `AlreadyExists` 且两边身份均可读时，才认定它是隔离后新建的同 sid canonical 事件，保留它、不覆盖，并移除被后到事件取代的隔离对象。其他恢复错误保留隔离副本、标记不确定并唤醒；不能把错误类型或目标身份未知当成后到事件。
5. 清理后重取成员快照，并在 `run_cleanup_tick` 取完签名后再做一次成员核对。新路径、同路径身份变化及无法解释的差异加入 `fresh`/`uncertain`。
6. 折叠规则：没有成功删除文件时，绝不豁免事件目录 mtime；有删除时，仅当目录成员变化完全由 `removed` 解释且无新鲜/不确定对象，才豁免目录 stamp。已监控文件的未解释变化仍触发扫描。

隔离目录以原子 `create_dir` 预留，不会覆盖先前对象；隔离文件使用 `.tmp` 后缀，不会进入 hook 读取面。清理失败只会保留文件，不会删掉其内容。算法不解析 hook JSON，不增加扫描线程或进程刷新。

## 可测边界

清理内核提供只在测试使用的同步停点：枚举完成后、候选身份采样完成后、隔离 rename 后恢复前。测试通过真实临时目录和 hook 同款同目录原子替换制造并发，不依赖 `sleep` 猜竞争时序。

必须覆盖：枚举后新建 sid 文件；`mtime == since`；旧文件 stat 后同路径原子替换；实际只清陈旧文件不唤醒；无成功删除但发生并发目录写仍唤醒；恢复目标已有新对象时不覆盖；未知身份/无法安全恢复时保留对象并唤醒。

## 非目标

- 不改 hook 文件协议、事件 TTL、1 秒唤醒拍或 500ms/5 秒扫描合批。
- 不引入 JSON 解析、文件系统 watcher、第二个进程扫描器或新依赖。
- 不为未知/不支持身份的文件系统强行删除；安全性优先于清理率。
