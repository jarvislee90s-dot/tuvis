# Codex Desktop macOS 原会话纯文本热修

归属：[总体设计与完成台账](2026-11-25-Codex-Desktop连接诊断与能力边界.md#6-完成台账)。适用范围是已运行的官方 Codex Desktop 原宿主、已存在的原会话。以同一 App 内的会话视图定向，不按系统窗口数量验收。

## 通道与界面

- IPC 以当前运行实例、线程及对应操作的有效契约与证据为准，版本号用于识别证据和诊断。不让 macOS 候选 AX 通道抢占可用的 IPC。未决动作、忙碌、原生待处理和暂停队列不是改走 AX 的理由。
- macOS AX 是默认关闭的纯文本专测候选。只在明确启用、符合运行条件与原会话写入前置时尝试。采用正常系统权限，窗口路径不能作为 IPC 结果不明后的重试。Windows 使用既有 IPC 路径，本文不承诺 UIA 收发。参见[项目宪法](../../MASTER-PLAN.md) F2.1、F2.5、F2.8、F2.10 与 D7，正式开放另行裁决。
- 打开、浏览和编辑手机卡片不改变 Mac。仅显式发送可按需切到目标已存在的会话，发送后不自动切回。当前目标与本次动作不是同一个概念，手机按服务器实际发送资格显示，IPC 的连接状态和 AX 权限在详情分开解释。落盘刷新查看不等于实时订阅。

## Mac 关键路径

1. 通过配对设备鉴权，解析原线程和官方运行宿主。持久登记设备、会话、通道及动作阶段，检查跨通道未决屏障，同宿主只允许一个 AX 写动作在飞。已存在的动作只按原身份核对，不更换通道或 ID 重放。
2. 用 AX 唯一 current 行、项目归属和本地索引核证目标。如果目标不是当前会话，只允许一次明确的侧栏语义点击，重新采样核证已加载目标。导航使用获准的原会话，不能用标题、窗口焦点、文件活跃或单个按钮回执代替身份。若无法核证、已有草稿或本机交互不安全则拒绝，不自动清稿或切回。
3. 目标、真空稿和输入控件通过核证后仅填一次，等待采纳后重新读取当前视图，满足目标、正文、编辑器和发送控件检查时仅提交一次。只读核对原线程的新消息与效果。可见编辑器状态和落盘记录有边界，AX 两次读取和 Tuvis 单飞不能锁定 App 自身的本机编辑或消除检查到写入之间的竞态。
4. 回执区分无副作用、已切但未发、可能已改编辑区、可能已提交、确认送达。仅确认送达才按原草稿版本清理。无法确认则保留草稿和未决保护，只读核对，零自动重投。

主要落点为 `src-tauri/src/remote/{api,codex_ax_send}.rs`、`src-tauri/src/services/codex_desktop_ax_{macos,sample,sender,ledger}.rs`、`src/mobile/{SessionDetail,MessageComposer,CodexAdaptSheet}.tsx`。Windows 可参考鉴权、账本、路由和验收判据，不复用平台 AX 控件绑定。

## 验收边界

此前 macOS `26.1120.50957`／`30866` 候选已取得同一官方 App 的隔离 A→B 导航、不经新宿主的填发试验，以及用户从真实远程页面发当前 A、从 A 发 B 并自动切到 B 的手测。不同来源的证据不互相替代。反方向产品操作、竞态、跨构建和最终候选的重新实机复验均按实际结果记录，不能从导航或发送回执中推定。纯文本不开放正式附件、答题、审批、停止和忙时自动排队。现场事实以[验收记录](../acceptance/codex-desktop-macos-text-hotfix.md)为准。
