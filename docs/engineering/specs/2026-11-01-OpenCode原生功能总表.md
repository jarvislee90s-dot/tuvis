# OpenCode 原生功能总表

依据[项目总纲](../../MASTER-PLAN.md)的 D21、D22、D23 和[四 CLI 消息交互规范](2026-10-29-CLI整组答题与双端一致性顶层设计.md)。本规格定义 OpenCode 的功能和协议边界。实际远程写入分配、旧链退役与复查按[远程写入收口规格](2026-11-23-OpenCode远程写入原生化收口与复查标准.md)执行。原生接入按功能逐项验证，进度跟踪见 [#188](https://github.com/jarvislee90s-dot/tuvis/issues/188)。

## 1. 功能范围

用户从手机进入其已配对桌面上的原 OpenCode 会话，读取真实结果，准备并确认操作。平台、启动形态与操作分别验证。产品设计保留本机看板、历史和辅助操作，并控制远程写入权限。新增模型切换、通用 shell、任意权限规则编辑、跨工具流转及永久授权需独立确定范围。

| 功能 | 产品契约 | 核验重点 |
| --- | --- | --- |
| M1 原会话连接 | 看板显示 TUI 实际打开的会话。首页无会话时无卡，明确打开的空闲会话仍显示。手机选 A 后固定操作 A。同一服务中浏览 B 可更新看板，手机目标仍为 A | 同目录双窗口、空窗口旁有旧活跃会话、切换、返回首页、关窗、实际服务换代分别对账 |
| M2 消息和结果 | 正文、已有工具结果、等待及回合终态在同一会话详情。工具参数随过程折叠，保留历史补读和继续加载。单个连接阻断提示原因及下一步，详细服务信息在连接详情 | 合并原生事件与分页记录，按自己的顺序和 ID 去重，断流后补读。未读到的结果继续按未知或不完整显示 |
| M3 发送和附件 | 确认后一次交付正文、纯附件或混合消息。附件在受控目录准备，原生交付上限为 5 MiB/文件、20 MiB/消息、10 文件 | 实际原会话送达、同名并发附件隔离、大小和路径限制、受理后掉线及预览保护 |
| M4 队列管理 | 分列兔维斯未发、原生已受理及结果待核对。暂停和恢复只控制本地派发。撤回和插队按条目所有者走各自通道 | 已认领项零重投，原生已受理项不因本地暂停停止，实际消费按动作或原生队列条目核对 |
| M5 停止、继续和插队 | 会话级停止服务收到请求时所选会话正在执行的回合。继续是用户主动发送新消息，使用新动作 ID。显式插队的实际消费独立取证 | 原进程存活、其他会话与 inbox 不受停止影响。空闲诚实回执。晚到旧代际的结果仅归原动作 |
| M6 审批 | 对真实待审批请求提供允许一次与拒绝，权限读写与工作模式独立。永久授权、独立计划反馈本期未接入 | 两端先后及同时决定、有效请求、实际工具效果和正式决定分别核对 |
| M7 整组答题 | 手机本地逐题编辑，一次确认原题组。支持已证字段及规则，桌面先答或取消后显示正式结果。手机主动取消题组本期未接入 | 题干对位、合法跳过、条件字段、自由输入后下一题、重开和两端竞争 |
| M8 本地草稿 | 正文、选择、自由输入、翻题和清空属于本地。放弃草稿或解除某个未提交选择只修改本地状态 | 断网仍能编辑；编辑、清空、放弃以及翻题零远程写；已提交结果独立显示 |
| M9 工作模式与权限 | 空闲时将原生 primary agent 切到有效的 Build/Plan 目标，按后续回合语义回读。权限规则仅在已有证实的只读面提供 | 忙时拒绝，拒绝未知目标，核对切换前已受理及切换后消息实际使用的 agent；保存规则无新增 |
| M10 兼容与恢复 | 按操作检查协议、当前目标和语义证据。明确可写、只读、受阻与结果待核对。用户在换代时预览并确认新目标 | 查原动作、原会话和原代际；重复点击、刷新、晚到回执及重启零自动重发。旧 `pending` 和 `draining` 按收口规格处置 |

收窄规则与文件能力会留下部分操作缺口，但能够让正式结果、权限和故障影响分别解释。现有可靠的 SQLite、历史和预览读取可复用，写入仍独立经过原生准入。

## 2. 归属、协议和产品边界

### 窗口与执行服务

- **窗口观察。** 通过可信的本机原生观察取得窗口进程及其实际打开的会话。窗口记录、会话逻辑 ID、规范化项目目录和服务进程是独立事实。`cwd`、最新记录、`active`、共享库、启动参数或单个 TCP 连接仅提供辅助事实。允许使用一次性、可撤销的 GUI 插件配置补齐原生观察。安装和卸载只操作自身配置和产物，默认保护现有设置与备份。
- **服务绑定。** 核对登记、服务 ID、PID、启动代际、端点和原生 `/api/info`，并通过可信窗口记录及 H02 回声证明确认 TUI 实际连接的实例。固定端口、相同数据库或桥连接本身不足以授权。可信宿主和用户允许安装的桥属于产品信任范围。凭据和绑定令牌只用于授权路径，证据、诊断和日志须脱敏。发现／过期读取可用时仍应在派发前核对写权，失败保守拒绝。
- **H02 写权条件。** 归属挑战依靠发送实例的 SSE 事件使对应 TUI 读取专用探针会话；验证单次 nonce、锁定窗口 PID、启动身份与限时应答。应答路径可经旧实例，因此以应答内容与有效期判定。TUI 与服务的构建指纹、平台和启动形态需同时命中有效证据。逐会话缓存失效是锚定二进制的实测行为，升级需复验正例、旧实例存活反例和缓存粒度。挑战对隔离探针有写副作用，须限频、串行和保守拒绝。登记、共享库或已陈旧 client 信号不得单独放行。细节见 [H02](../evidence/opencode-native/2026-11-14-h02-echo-challenge-attribution.md)。
- **代际与范围。** 读取和写入都按当前授权设备、OpenCode、会话及规范目录限域。窗口退出、服务换代、凭据变化或目标歧义时保留只读核对，并中止新写，目标变化走 D-1。发现或认证重试不能复用已提交写请求，也不能借默认服务凭据接入未绑定的特殊启动形态。现有服务可用时直接接入，避免为替代写入另起引擎。

窗口观察与执行归属分别取证，带来额外的核验和可能的等待，但允许看板如实更新，同时让手机已选目标稳定，防止同库双服务或陈旧连接写错进程。

### 消息、问答和结果

- 优先读取目标会话的消息、表单及审批详情。需要全局列表时显式使用该接口认可的目录参数并核验目录、分页完整性和对象身份。只有范围正确且读取完整时才确认空列表。HTTP/SSE 有界读取，超量时按受控分页补读并标注部分结果。兼容已证的正文层级与已完成工具的实际输出。缺消息或输出不补造，提示数据可能不完整。SSE 作为变更通知，丢事件、断流或重连时靠正式记录补读。
- 确认时冻结正文、附件和动作意图。客户端复用持久 action ID 查询，服务端结合设备、会话、路由版本和代际判断使用权限。同一命令只认领一次，重启后有权继续处置已确认但明确未认领的条目。丢回执、回读异常、同文消息或 idle 状态都不足以认定动作成功或未发送。结果以动作相关的原生消息、队列项、表单、审批或回合回读归因。
- 问答前后端共同验证当前题组。仅提交已证规则下适用的字段，允许合法跳过。遇题干、选项或规则变化，保留旧稿供用户核对，逐项检查后才可重新确认。一次回复可能定案整组，`409`／`FormAlreadySettledError` 时回读同会话同表单的正式状态和答案，禁止补交。已定案、由哪端决定及实际答案分别举证。答案正文来自该会话的正式读取，本地恢复仅保存必要的引用标识。
- 附件准备校验会话归属、数量、大小和路径，确认时冻结所用副本。纯附件可使用空正文交付；回读保留名称、类型等元数据，仅同会话受控路径开放预览。独立上传准备只产生本机文件，未经确认不得让 OpenCode 消费。超预算的实际送达待另行举证。
- 模式只接受当前原生 agent 列表中可用的 primary 目标。用工况与回读核对新值和后续回合，保留忙时限制。审批只决定有效请求的已支持选项，实际权限结果单独核查。工作模式变化不会开启永久授权或权限档编辑。

本地准备减少每次按键等待；后端再验与回读多一次交互，换得最终请求与用户所见内容一致。复用正式读取可减少重复存储，需对分页不足、迟到事件和读写竞争给出明确状态。

## 3. 平台、启动形态与实测范围

| 范围 | 已有证据 | 验收边界 |
| --- | --- | --- |
| macOS 普通 TUI + 默认登记服务 | macOS／OpenCode 2.2.5 的实名隔离 VM，原生发送、原进程与登记、原 TUI 及消息账本三方对账。[普通启动正例](../evidence/opencode-native/2026-11-17-c5-realname-normal-startup-write-positive.md) | 独立配对窄屏浏览器和隔离候选；零模型样本只证明正式消息送达。新产品候选与真实手机分别复验 |
| macOS 显式 `--server` 及同库双服务 | H02 分裂脑成对结果。真机隔离测试中旧 A 存活，原窗口退出后 A 拒写，经显式重选后新 B 恰收一次。[旧 A 存活及 B 可写](../evidence/opencode-native/2026-11-16-m6-old-a-alive-new-b-writable.md) | 绑定固定窗口身份与服务。只在证据覆盖的端点、构建和拓扑内成立；凭据轮换以及同端口不同进程须拒绝旧绑定 |
| macOS 实际 LAN 产品入口 | 11 月 20 日 R9 曾用独立 Chrome 验证普通收发、附件、暂停和恢复、插队发送、停止和继续、切模式、受控审批与整组作答、显式重选、新建及首句。11 月 21 日宿主复开仍触发多服务歧义；隔离 VM 复验重选与恰一次发送成功。[R9 构建与活验证据](../evidence/opencode-native/2026-11-20-macos-native-closure-handoff.md) | R9 为历史候选。LAN 窄屏浏览器与受控审批不能代替物理手机和完整真实工具竞争验收。一次创建正例不能证明所有目录或关窗竞态 |
| macOS `--standalone` 与其他非默认形态 | 启动探测与独立证据记录 | 尚无完整凭据发现、服务归属及端到端正例。另行验证后才放行，禁止借其它服务或形态证据 |
| Windows | 有 2.2.2 协议材料和离线解析证据。旧新建及终端注入首句有独立真机证据 | 原生仍未形成产品闭环。沿用已验证旧能力及平台防护，待原生替代逐项通过再退役。macOS 结果不计入 Windows |

任何实测样本只覆盖记录的版本、构建、平台、目标及操作。版本变化先确认兼容和语义证据是否仍适用。对 H02 采用运行二进制实证组合，其他已证操作按必需的请求、返回、语义与目标条件核验，避免把不相干的响应变化扩大为全工具禁用。

## 4. 验收标准 / 测试要点

同一候选贯通普通启动、上板、配对、原会话读取、发送／排队、过程折叠、审批／答题、正式结果、下一条消息以及关窗下板。覆盖两窗口、两标签、断流、停开、换代、设备隔离和丢回执复查，并按收口规格追踪具体副作用。

| 验收层 | 记录要求 |
| --- | --- |
| 工程 | 记录候选源码、构建及前端资产；核对 HTTP、IPC、后台入口，确认副作用、授权检查和兼容拒绝 |
| 原生实测 | 锁定原服务与 TUI，再核对正式原生记录、实际回复／处理结果及两端状态。区分零模型、夹具、真实模型或真实工具效果 |
| 产品 | 在实际配对入口验浏览器及可用构建。实体手机的触控、前后台恢复和远程链路单列；Windows、standalone 逐项单列 |

未闭合项包括最终候选与实际物理手机、Windows 原生替代、standalone、真实工具审批与两端并发、双标签及断线完整收敛、目标 TUI 关闭的竞态、历史会话退出后恢复、新目录并发落点，以及超预算附件。旧行为如有已验证适用范围，在收口规格标实际产品通道。历史候选的工程结果按原范围保留。
