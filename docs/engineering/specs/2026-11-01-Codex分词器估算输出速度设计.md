# Codex 分词器估算输出速度设计

> 状态：用户已确认设计；本轮完成一致性补充，配套执行计划已编写，产品尚未实现。
> 日期：2026-11-01。
> 上位依据：[项目宪法](../../MASTER-PLAN.md)。本稿为[桌面四页导航与输出速度 V2 设计](2026-10-26-desktop-workspace-speed-v2-design.md)的增量补充，仅扩展速度口径、相应采集和展示，不取代前两个口径。

## 1. 目标与范围

在现有“流式输出”“响应吞吐（含等待）”右侧增加第三个可切换标签“分词器估算”。沿用当前速度看板，在图表下现有计算注释位置补充公式及边界。三个标签分别驱动指标、曲线和排行榜，不新增独立页面。

首版提供 Codex Desktop 可见正文的参考 Token 输出速度。正文计时来自实时 Desktop IPC，Token 数由固定参考分词器计算；不要求确认 GPT 实际使用相同编码，不宣称测得原生输出或隐藏思考的生成速度。

首版范围为已取得实时增量证据的 macOS Codex Desktop。其它模型在同一受支持宿主和协议结构下可以按相同方法采集；模型显示为回合参数中的模型，详情注明“模型来源：回合配置，服务端响应模型未独立确认”。Windows Desktop、Codex CLI 和其它工具不凭本次证据自动启用；未来具备等价增量与身份边界时可以接入同一估算口径。

首版固定参考编码为 `o200k_base`，用于建立统一的正文分词尺度，并非指定 GPT-6 的真实编码。

## 3. F01：第三个口径标签

标签固定顺序如下，样式与现有两个切换按钮一致：

```text
[流式输出]  [响应吞吐（含等待）]  [分词器估算]
```

- “分词器估算”是可点击的口径切换按钮，不是说明徽标，也不另开窗口或页面。
- 选择后，主数字、四格标签、图表、纵轴单位、有效样本数、排行榜的数值和排序同步切换。
- 保留当前时间范围、工具筛选、搜索和排序方向；优先保留同一工具／模型／渠道组合，并切换到该组合的对应数据方法。
- 切换时解除图表悬停和固定读数，避免把旧口径的读数带入新口径。已经发出的旧查询不得覆盖当前口径。
- 点击第三标签后，缺样本时保持在该标签，不能自动回退显示响应吞吐。
- 默认口径和现有 Codex 的 stream→response 能力回退规则保持原设计；第三口径只在用户选择时展示。
- 新标签始终可发现。未支持的来源显示明确空态，不借用另一模式的速度。针对 Codex 的旧提示“仅支持响应吞吐”应按实际能力改为“流式输出暂不可用”，不再否认第三口径。

## 4. F02：计算与参考分词规则

### 4.1 单条正文

每条 `agentMessage` 是一个候选样本，身份至少绑定宿主、会话、回合和完整 item ID。

- `F`：已连续观测到该消息空正文后，首次非空正文增长的 IPC 到达时间。
- `L`：该消息最后一次正文增长的 IPC 到达时间。
- `D = L − F`：正文观测时长，使用单调时钟计算。
- `N`：对该条最终完整正文使用固定参考编码得到的 Token 数。
- 单条速度：`N ÷ (D / 1000)`，单位为“参考 Token/s”。沿用当前产品定义，不机械扣除一个 Token。

每条正文分别计算。两条正文之间的工具执行、审批等待、调度和下一次首输出等待均不拼进正文窗口；正文窗口内部的停顿原样保留，不自行扣除。它是客户端收到正文增长的速度，不是服务器纯解码速度。

消息是否成功可稍后确认，但确认过程不延长 `L`。例如正文停止增长后 682 毫秒才收到回合完成，682 毫秒不加入正文观测时长。

### 4.2 固定参考编码

- 首版参考配置为 `o200k_base`，记录编码名、规则版本和分词资源身份。它是统一参考尺，不根据未知模型名猜测真实编码。
- 对完整最终正文分词一次，不逐增量分词再相加，避免分块边界改变分词结果。
- 正文保留原始 Unicode、空白、换行、代码和 Markdown；不使用渲染后的 HTML，不 trim、不规范化后再计数。
- 协议控制内容不属于可见正文。含正式答题信封或无法证明为模型正文的控制消息不计入，不能将内部协议标签当输出正文。
- 不计思考摘要、隐藏思考、工具参数、工具 stdout/stderr、用户消息和附件。
- 正文中的特殊标记样式字符串按普通文本处理，不作为分词器的特殊控制 Token，也不因此使整条采集失败。
- 分词器和词表随 Tuvis 离线提供，不要求用户安装 Codex 插件、Python 或独立服务；不在首次使用时联网下载词表。具体 Rust 库可在执行计划阶段确定，但必须通过固定编码的互操作样本校验。
- 编码、分词规则或资源发生改变时建立新统计配置，旧事实不重算、不与新配置直接合并。

### 4.3 区间与分桶

区间或时间桶的速度为 `1000 × Σ有效正文参考 Token ÷ Σ有效正文观测毫秒`，不是每条速度的算术平均。样本数 `n` 是正文消息条数，不是 IPC 帧数、模型请求数或用户回合数。

沿用现有 15 分钟／1 小时／5 小时／24 小时范围、完成时刻归桶及边界包含规则。新样本的统计结束时刻取 `L` 对应的墙钟时间，确认成功后入库；确认较晚可使过去桶在后续查询中增加事实，但不改变已固定的读数快照。

同一口径内跨会话加权汇总；并发正文各计各的观测时长，不把累计时长称为实际墙钟用时。无有效样本时数值为 `—`，不填零、不延用旧值冒充当前值。

## 5. F03：图表下计算注释

计算说明固定放在截图箭头所指位置：图表和缺口图例下方、排行榜上方。沿用现有次要文字样式和自适应换行，不新增横幅或弹窗。三个公式常驻，选中第三标签时也能直接了解它与前两个口径的区别。

中文文案：

> 流式输出速度 = 输出 Token ÷ 首个有效输出至生成完成的秒数（不含首输出等待）；
> 响应吞吐（含等待）= 输出 Token ÷ 对应响应的含等待总秒数；
> 分词器估算 = 正文参考 Token 数 ÷ 首次正文增长至最后一次正文增长的秒数；
> 分词器估算只统计可见正文，不含隐藏思考和工具输出；三种口径不混排，参考 Token/s 不与原生 Token/s 直接比较，估算误差尚未校准。

英文对应文案：

> Streaming output speed = output tokens ÷ seconds from first effective output to generation completion (excluding the initial wait);
> Response throughput (including wait) = output tokens ÷ elapsed seconds for the corresponding response, including the initial wait;
> Tokenizer estimate = reference tokens in the visible text ÷ seconds from the first to the last observed text growth;
> The tokenizer estimate covers visible text only, excluding hidden reasoning and tool output. Rankings are separate for each metric. Reference tokens/s should not be compared directly with native tokens/s. Estimation error has not been calibrated.

同时删除旧注释中的“差额即等待”，因为两个速度之差不是等待秒数。参考编码、资源版本和计时边界进入采集管理详情，不在主界面堆技术字段。

首版只有 Codex 支持时，第三榜单可以只有 Codex 各组合。未来其它工具采用同一参考编码、同样的正文边界和有效性规则后，可以进入该榜单；不能把它们的原生总输出 Token 直接放进估算榜。

## 7. F05：实时采集与样本生命周期

### 7.1 采集方式与授权

复用现有 Desktop IPC 连接、owner 校验、revision 镜像和只读跟随，在桌面后端记录事件到达时间。观察点位于手机 SSE 和 UI 合并刷新之前；界面仍按现有节奏查询已结算统计，不把轮询或浏览器渲染时间当正文时间。

沿用采集总授权，采集管理增加该来源的状态和单源停止入口。采集开启且 Desktop 运行时，旁观已受管的活跃 App 会话；不为测速跟随全部历史会话，不主动触发模型请求。

实时观察具有不可补采的特点：速度页隐藏时可停止前端查询，但轻量 IPC 观察随采集授权驻留。此规则补充旧设计的文件读取／视图租约规则，不把实时事件读取限制为后台每 600 秒一次。Tuvis 退出、总授权关闭或单源停止时结束估算观察；不建立独立系统守护进程。

测速只读租约与手机远程界面的租约分别计数：任一侧退出不能撤销另一侧仍需要的跟随。开启测速不自动开启远程 HTTP 服务、自动适配写权限或其它操控权限；关闭自动适配写开关本身不使有效只读测速失效。

### 7.2 从候选到结算

1. 首次 snapshot 仅建立基线，已有正文和已有终态均不计新样本。
2. 看到新消息的空正文后，进入可观察状态。若消息首次出现已非空，无法证明捕获首输出，本条不计速度。
3. 至少两次非空增长且发生在不同单调时刻，才形成正时长候选。每次增长只更新本条消息的末点；一次帧或一次接收块不能当作多个 Token。
4. 正文仅追加、身份及 revision 连续时继续观察。发生改写、删除、重连、owner 换代、revision 缺口或中途 snapshot 重建时，相关未结算候选作废；从新基线之后的新空正文重新开始，不拼接断链前后时间。
5. 取得可验证的消息成功终态后结算。当前若只能确认回合 `completed`，就等待该回合成功再分别结算其中合格正文，时长仍停在每条消息自己的最后增长点。
6. 回合失败、取消或终态未知时不结算尚未确认成功的消息。若明确观测到错误／重试，且无法分清同一正文是否跨尝试拼接，本条也不计；缺少 attempt 字段不等于证明没有重试。失去完整性只影响估算事实，不中断原会话、手机显示或其它采集来源。

已有成功结算按稳定的宿主／会话／回合／item／参考配置去重；snapshot 重放、重订阅和 Tuvis 重启不能重复增加样本。owner 代际用于判断观察连续性，不靠每次重连创建新事实主键。

### 7.3 资源和隐私

复用现有镜像内存预算，只处理受影响的正文，不在每个 patch 中扫描和复制全部历史。新增暂存正文以单条 1 MiB、全局 16 MiB 为上限；超限或分词队列拥塞时丢弃本条估算并记原因，不阻塞 IPC 接收与操控。完整正文只在内存参与一次收尾分词，CPU 工作离开连接接收任务。

仅保存稳定脱敏身份、计数、时长、结束时间、请求配置模型、参考配置、来源 build、质量及排除原因。不持久化正文、思考、命令、文件路径、原始帧或可逆正文摘要。候选作废／结束后释放暂态文本。

离线期间、未授权期间和连接之前的正文不能回填估算值。图上展示缺口；不以重连 snapshot、历史日志或结束后的整块正文补造实时首点。

## 8. F06：数据与能力隔离

复用现有速度看板和 TPS 存储／查询底座，但第三口径必须拥有独立的计数范围和有效性判断：

- 模式增加独立的 `tokenizer-estimate`；计时方法标为 IPC 正文观察，输出范围标为可见正文，计数依据标为参考分词器。
- 原始模型／渠道相同也不能将估算分子写入现有 `stream` 或 `response` 统计列；不改费用或原生 Token 账本。
- 保存参考配置身份；不同编码／规则版本不跨配置聚合或连成同一精确曲线。
- 稳定键、足够统计量和来源能力需在 Rust／TypeScript 两端一致表达。具体采用增量字段或独立事实表由执行计划确定，但不得用伪装现有原生 scope 的方式绕过隔离。
- 组合选择跨模式按工具／模型／渠道寻找对应方法，而不是要求两种方法的完整 series key 相等；无对应项则显示该模式空态，不遗留旧数值。
- 沿用现有 24 小时速度事实保留和清理策略。旧事实、旧游标不重释为新口径，也不扫描历史正文重建新事实。
- 采集管理分别显示“支持但暂无新样本”“未连接”“需要检查”“当前平台未验证”；能力可得不等于已有有效数据，零样本不等于协议故障。

## 10. 本轮明确不做

- 不安装 Codex 监控插件，不切换 Happy／独立 app-server，不修改模型 API、provider、认证或传输方式。
- 不增加代理，不将原生遥测排障并入本批实现。
- 不承诺误差百分比，不通过重复测得相近速度证明准确率。
- 不把字符/s、原生总输出 Token/s 和参考正文 Token/s 混为同一榜单。
- 不提供生成中持续跳动的“精确瞬时 TPS”；沿用现有页面查询节奏展示已结算样本。

## 11. 一致性核对后的补充约束

- **授权与晚到结果**：总授权和单源开关共同决定捕获资格；关闭任一开关会推进捕获代际，丢弃未结算正文及排队中的分词结果。旧工作在关闭、重开后完成也不得落账。已经保存的事实按保留期保留；总授权关闭时看板沿用现有 disabled 空态，单源停止不删除其历史。
- **事实时间与确认时间**：使用单调时钟计算 D；墙钟仅用于记录和分桶，不能用完成确认或分词完成时间替换 L。记录确认后才可查询，确认前不显示临时速度。
- **展示与统计边界**：小样本、短窗口属于记录质量；保存相应计数，在选中桶／区间详情中展示，不能由聚合后的时长反推“没有短窗口”。首版参考配置固定，升级后的不同配置保留独立组合身份，不自动选中旧配置数据。
- **受管会话范围**：来源是现有会话监控认定的活 App 会话，包括其空闲期；不为测速枚举 Desktop 的全部历史线程。新发现线程如果已开始输出，当前不完整消息舍弃，后续新空正文仍可采集。
- **订阅与丢帧**：既有手机 read/follow/unfollow 也必须经过同一用途租约仲裁。观察队列溢出不是可忽略的小误差，受影响的在途样本必须失效；慢分词或停采不能拖慢、关闭正常 IPC 操控链。共用的跟随容量不足时，统计让位于交互跟随，明确报告覆盖缺口。
- **平台与字段能力**：macOS 当前已观测 profile 使用结构门接入；未知 build 只有通过同样的 snapshot／patch／owner／revision／正文身份校验才可观察。Windows 本批不启用。缺少模型字段只影响归组；缺少消息身份、连续性或终态则影响样本有效性。
