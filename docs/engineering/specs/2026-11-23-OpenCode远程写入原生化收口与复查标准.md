# OpenCode 远程写入原生化收口与复查标准

本规格落实[项目总纲](../../MASTER-PLAN.md) D20–D23 和 OpenCode 逐操作收口裁决。产品功能、协议和平台证据见[原生功能总表](2026-11-01-OpenCode原生功能总表.md)。操作 ID 用于关联测试、实际通道及验收结果。

## 1. 决策与适用范围

- **macOS 收口。** 发送、审批、答题、切模式、回合控制和后台派发等可改变 OpenCode 会话、回合或请求的操作，只允许经过已绑定并有证据适用的同实例原生通道。缺能力、身份不明或语义未证时拒绝。历史兼容设置无法启用旧写，也不能用旧屏读、终端按键、粘贴、无头代投或终止进程补足。旧设置开关在已收口平台下架。保留必要的拒绝协议，维持鉴权及可审计的稳定错误响应。
- **Windows 替代门。** 原生现仅对 macOS 开放。Windows 的已验证旧能力按当前适用范围保留，在对应原生替代达标后逐项退役。至少用真机证明新建原生会话、起窗及首句在原 TUI 与正式记录各一次，再退役旧新建和首句通道。禁止扩大或自动开启旧通道，原生专测保持隔离。
- **本机辅助和读取。** 保留独立的目录准备、附件上传准备和预览、打开／恢复原 TUI、关闭明确信认的 TUI、看板、历史、动作只读核对、草稿和本地元数据。辅助的本机副作用仅限实际请求授权的动作。关闭 TUI 不替代停止回合，不得终止共享 `serve`。保留桌面远控总开关、插件状态与修复入口、用户直接在桌面操作和其他 CLI 的共用引擎。

按实际副作用收口，可共用已有鉴权、读取和 Windows 路由。保留共享拒绝会增加分流回归，换取旧客户端可预期的错误和其他工具的行为连续性。具体行为以矩阵适用范围为准。

## 2. 派发与历史恢复

- **验证和幂等。** 写前核验授权设备、工具、会话、规范目录、执行服务、原窗口身份及代际，检查该操作的契约和语义证据。在预留和最终认领处防止目标变化。受理、实际生效与结果未知分别呈现。可能已写、丢回执和结果未知只按原动作 ID、原目标和原代际核对，禁止自动换通道或换执行者重发。旧代际迟到结果只归原动作。
- **唯一派发权。** 未暂停时，忙时已证范围内默认交 OpenCode 原生队列；暂停后新意图留兔维斯。本地确认内容用持久 action ID，暂停与认领原子协调。明确未认领项可由属主事务撤回，认领后不能退回本地。远程关闭停止新认领，已认领请求自然完成或核对。上游待发按原生条目 ID 读取、撤回或插队，停止不清空 inbox。
- **插队语义。** 未发本地项经校验认领后单次原生 `steer`。上游待发项走已验证的 `PATCH /api/session/{id}/inbox/{itemId}`，将该条目 `delivery` 改为 `steer`，回读同项、实际消费和残留。两种插队均禁止预先停止再发送或重投已经受理的请求。
- **历史 `pending`。** 旧状态无法证明从未写出，升级及重启后冻结可疑项。原行、认领屏障和审计继续可查。只读列表只返回属主所需元数据。只有核验会话、属主设备、条目及原代际后才可显式放弃本地项。缺代际证据或核对失败继续冻结；不能自动迁移、重投或声称原生撤回。

### D-1 显式重选（2026-11-18 用户裁决）

同目录恢复读通且服务登记换了 ID，仍需用户显式重选；`OC_TARGET_CHANGED` 不为自动采纳开放特例。历史 `draining` 按保守恢复处理，禁止交回旧写。先按原动作核对未决结果并维持屏障，存在可核验死亡代际时仍须满足对应豁免和显式确认条件。向手机显示预览中的规范目录、服务及 PID，说明保留草稿和未决核对记录。一次确认使用固定请求 ID、预览令牌和路由版本 CAS，窗口和服务须在提交前重新核验。超时、断开或丢回执只查询同一请求终态，分辨已提交、未应用和仍未知；刷新、重启或迟到回执本身不能采纳新目标、重放已有动作。

保留历史屏障可能需要用户多一次确认或等待核对；原请求仍可审计，已可能发出的动作不会随换代重复派发。独立、明确未认领的本地待发项按权限管理。

## 3. 逐操作通道矩阵

下表末两列分别记录源工作区 2026-11-23 的工程复查及还需验证的边界。历史 macOS 产品实证按[功能总表的实测范围](2026-11-01-OpenCode原生功能总表.md#3-平台启动形态与实测范围)引用，最终候选的结果需重新归因。旧 HTTP 路径的共同前缀为 `/m/api/v1`。macOS 下的拒绝均需在对应副作用之前完成。

| ID／操作 | 实际入口与保留通道 | 正反验收断言 | 已有工程结果 | 待验范围 |
| --- | --- | --- | --- | --- |
| OC-01 发送／继续 | 原生消息接口。旧 `/session-send` 与旧队列禁止注入或无头追加。继续用新动作 | 原会话恰一次；旧入口、首次无目标、丢回执零代投 | 历史兼容值仍拒绝，首次快照未命中零入队，原生集成通过 | 最终候选对照原 TUI 与正式记录 |
| OC-02 附件准备及发送 | `/session-attachment` 的受控本机准备和预览保留，正式交付仅原生发送，覆盖纯附件和混合消息 | 上传本身零消息写；原会话收到所选文件；超限、错误目标、旧引用交付零派发 | 同名并发分别交付和读回各自副本；旧写请求拒绝 | 单文件 5 MiB 以上实际送达未证，旧上传容量不能替代交付证据 |
| OC-03 排队／暂停／恢复 | 本地未发由持久队列管理，条件满足才交由原生；保留 `GET /session-queue`。旧启动回放和 flush 无 OpenCode 旧写 | FIFO、后台派发、暂停后上游仍独立；归属失效和旧行重启零误发 | 旧行冻结，后台跳过冻结队首，认领屏障仍生效 | 通用裸 ID 写入对跨工具同名会话继续拒绝歧义，完整分流未证 |

| OC-05 撤回／放弃 | 原生项走已证撤回，本地未发项事务撤回；冻结项按 §2，旧 `/session-queue/retract` 无远程写 | 显示原生撤回或仅本地放弃；归属错误、已认领或核对失败时不误删 | 旧撤回拒绝并保留原行；只读冻结入口仅属主可见 | 历史旧行缺原代际，维持冻结 |
| OC-06 停止回合 | 原生会话级 `interrupt`，以实际终态核对。禁止替代性发键和杀进程 | 所选会话在服务收到请求时的执行回合停止，原进程与其他会话存活 | 原生停止和面板回归保留 | 最终候选对照回合终态及原进程存活 |
| OC-07 关闭 TUI | `/session-close` 为独立本机操作，要求可验证的目标进程身份。macOS OpenCode 暂明确拒绝远程终止，用户可在桌面关闭 TUI。 | 若开放，仅目标窗口退出；共享服务、歧义、PID 复用和身份不明均零终止 | macOS OpenCode 请求明确拒绝，看板传实际工具，其他工具与 Windows 既有入口保留 | 进程代际与实际终止的原子保证、关窗真机正例 |
| OC-08 新建及首句 | `/opencode/create-native` 原生创建，经绑定起窗、交付首句；已有旧 `/session-create` 按平台退役。按 D21 准备合法目录并再次确认实际落点 | 合法目录准备；原生创建与首句各一次；非法目录零落盘，目标不明零创建、起窗或首句，重放和并发零重复 | 占位固定摘要后落盘，同 ID 只准备胜出目录，非法链接拒绝，预览不补建 | 父目录并发移动或路径重解析的副作用边界，最终候选首句对照原 TUI 与正式记录 |
| OC-09 打开／恢复 TUI | 历史页和 `/session-open` 保留已核验的原会话恢复。起窗需核对会话 ID、规范目录及实际服务连接 | 窗口展示原会话；目标不明零起窗，恢复零重复创建、零代发正文 | macOS 先读登记服务与同 ID 会话，目录命中后起窗，未核验零起窗 | 已退出历史会话的真机正例 |
| OC-10 审批 | 原生允许一次／拒绝。旧审批、选项屏读拒绝，独立 `/session-plan-feedback` 旧链仅 Claude | 工具效果或拒绝正式可核对；重复、无能力或已定案不写；禁止普通消息代投 | 旧审批拒绝，首次无目标不重扫其他对象，原生回归保留 | 真实工具效果和两端竞争；永久授权与独立反馈不在本期 |
| OC-11 答题及取消回显 | 一次原生整组提交；手机本地改稿，桌面取消后只读回显。旧 `/session-question/answer` 等拒绝 | 原表单恰一次，正式结果可追溯；编辑／放弃草稿及旧取消零远程写 | 原生提交和正式结果覆盖保留，旧端点拒绝 | 真实两端竞争、自由作答后下一题与后续回显；手机主动取消未开放 |
| OC-12 Build/Plan | 原生空闲切换并回读，拒绝旧 `/session-mode` 系列屏读和按键 | 后续回合使用实际目标值；忙时、错误目标零写，权限无扩张 | 旧端点无目标不重扫、不发键，原生面板回归通过 | 最终候选核对后续回合及已入队项作用时点 |

阻断验证先于删除。先固定旧行为与保留正例，随后验证阻断及全部共享路径，再反查调用方并删除确已闲置的专用资产，重跑同组断言。最终从入口向下复查副作用与拒绝点，从删除位置向上复查 HTTP、IPC、定时器、启动恢复、配置和客户端调用。记录两向结论及仍有实际调用方的共享代码。

## 5. 验收标准 / 测试要点

1. 逐行记录平台、启动形态、入口及实际通道、候选代码与构建指纹、OpenCode 版本、目标和代际、正例及工程、实机或产品证据。禁止跨候选或跨平台套用结果。历次源工作区的通过记录仅覆盖当时的构建和断言。
2. **保留能力通过**要求从实际入口证明副作用和原执行者正式结果。**阻断并删除通过**要求有删前、删后相同断言及调用方反查记录。**共享拒绝通过**要求返回稳定原因码，OpenCode 对应副作用为零，且其他 CLI、鉴权及原有只读能力回归通过。**明确不可用**需 UI 与服务端一致给出原因，并验证零副作用。
3. 必测负例包括历史兼容位、旧客户端直调、原生不可用、实际目标换代或歧义、跨设备与跨工具、并发或丢回执、历史 `pending` 升级重启及 `draining` 原请求终态。按行观察原生写、终端注入、无头代投、进程终止、窗口启动、文件交付和账本持久化。只读受控审计及明确授权的本机处置单列观察。
4. 候选实机使用专用会话和隔离数据，从看板及真实入口核对设备、绑定、窗口、服务、目录与正式效果。仅有能力探测、渲染或受理回执的行维持待验证。保留可复查的步骤与脱敏结果，证据不足时继续限制对应写入。

关窗进程竞态、新目录移动或符号链接竞争、上游对目录字符串的再次解析均为独立边界。历史退出恢复、原 TUI 及首句、超预算附件与完整手机实际操作按矩阵继续举证。Windows 替代和 macOS 关账分别记录。
