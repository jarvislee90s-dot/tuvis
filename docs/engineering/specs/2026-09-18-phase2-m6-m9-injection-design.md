## 2. 总体架构

```
手机会话详情页输入框（多行；回车换行、按钮发送）
   │ POST /m/api/v1/session-send · /m/api/v1/session-approve（PIN 设备 cookie 过闸，沿 v1 前缀惯例）
   ▼
注入路由表（宿主形态 → 通道 + 可见性预期）
   ├─ injector/（终端注入引擎）
   │    ├─ macOS：tmux send-keys -l / iTerm2 write text / Terminal do script
   │    └─ Windows：M6 探测定案（M9 实现）
   ├─ headless/（无头通道）——M11 批次，本批次仅路由表预留分支
   └─ 不可注入（WorkBuddy/dsh 待评/APP 形态）→ 输入框禁用 + 原因
   ▼
queue/（状态门控：黄入队 → 可输入态逐条 flush → 单会话串行 → 立即发送插队）
   ▼
SQLite：写审计表（只增）+ 队列表（持久化）    SSE/轮询：回执与队列状态
```

**新增落位（实现细节以实施计划为准）**：`src-tauri/src/inject/`（引擎+队列+路由）、DB 迁移（队列表+审计表）、`src/mobile/` 详情页输入区与审批选项卡、设置页审计查看入口。**复用零新增**：PIN 门禁与设备指纹（M5）、SessionWatcher 跃迁（队列触发源）、`window/` tty/pane 定位（跳转同源）、adapter 宿主形态判定（路由输入）、SSE 与轮询降级。

**跨模块红线继承**：`store.with` 持 DB 锁不可重入（M4 实锤教训）；会话扫描预算契约不受影响；单实例插件互斥与 co-tenant 端口隔离（E2E 期沿用 M4 经验）。

## 3. 任务分解（T1–T4 ↔ M6–M9）

### T1 · Windows 注入探测（M6，不占主线关键路径）

- **目标**：Windows 终端会话的**外部写入路径**定案——GO / PARTIAL（缩小范围）/ NO-GO（降级登记）。
- **候选路径**（探测对象：Windows Terminal 与经典 conhost 两类宿主；目标 CLI：claude / codex / kimi，由简到繁）：
  1. **ConPTY 附加写入**：`AttachConsole(pid)` + `WriteConsoleInput`（输入记录写入目标控制台输入缓冲区）——前置实证：jump marker 三轮验收已证 AttachConsole(pid) 对 claude ConPTY 附加成功（issue #43），本探测补「写入后 TUI 是否真实收到」；
  2. **Windows Terminal 专用通道**：WT 无官方脚本 API，探测 ConPTY 输入缓冲区在 WT 宿主下的可达性差异；
  3. **SendInput 全局键击**：仅登记为应急参照（等价 macOS keystroke，D7 定位，不作为正式路径）。
- **探测矩阵**：宿主（WT/conhost）× 目标 CLI × 行为（单行+回车、`\n` 归一长串、中文/emoji、`[mobile]` 前缀、非聚焦窗口写入）。
- **交付**：报告入 `docs/research/refs/phase2-消息注入/`（沿一期 M0 模式）+ 独立评审落盘。
- **排期**：与 T2 并行启动；结论仅 gate T4。

### T2 · macOS 终端注入全链（M7，首个可验收版本）

- **注入引擎（由简到繁：tmux → iTerm2 → Terminal.app，裁决 14）**：三通道（tmux `send-keys -t <pane> -l --` + Enter；iTerm2 `write text`（newline NO 先文本后回车两步）；Terminal.app `do script`（转义反斜杠/引号））；**多行 `\n` 归一纯函数**（换行符→字面 `\n`，单测锁定）；`[mobile <设备花名>] ` 前缀；定位复用 `window/`（tty/pane），定位失败=明确失败回执不入队。注入为**应用级脚本，不需解锁不抢焦点**——锁屏可用性列入实测。
- **状态门控队列**：SQLite 队列表（设备/时间戳/内容）；黄入队，**可输入态**（红·等待 / 绿·完成空闲）逐条 flush（SessionWatcher 跃迁驱动）；一次一条、等下一可输入态=单会话串行；红·中断挂起+移动端明示；可查可撤回；**「立即发送」插队（裁决 12）**——任一排队项手动越过状态门即刻注入（运行中的 TUI 把消息放进自身输入缓冲，Claude Code 官方支持运行中排队输入；各家行为 = 本任务实测确认项）；「按最新内容发」= 撤回旧项 + 立即发送新项；持久化重启不丢。
- **路由表**：宿主形态→通道决策+可见性预期（实时/刷新后/不可见）返回移动端；不可注入（WorkBuddy/dsh 待评/APP 形态）输入框禁用+原因；**无头分支预留**（本批次显示「未开窗会话驱动：后续版本」降级说明）。
- **移动端**：详情页输入框（多行，回车换行、按钮发送）+ 队列状态指示（排队第 N 条/已送达/失败重试 + 立即发送/撤回按钮）+ 回执语义（已送达终端=注入动作成功；agent 处理由状态流体现）；斜杠命令原样放行。**挂载面（2026-09-19 用户裁决）**：输入框与审批红卡在详情页**全部预览布局态**（正文 / 纵向分屏 / 横向分屏）均挂载可用——分屏是「对话列 + 文件列」并列，对话列须保有完整对话能力；「仅正文视图挂载」的原实现无设计依据，已修。
- **写审计**：表只增不改（设备/时间/会话/通道/动作/摘要/结果）；设置页查看入口。
- **验收**：三通道真实会话各实测（手机→终端出现 `[mobile]` 输入，Claude/Codex 先行）；黄→可输入态 flush 实测；插队/撤回实测；锁屏注入实测；审计逐条可查；不可注入卡禁用；一期零回归（全量门禁）。

### T3 · 审批应答（M8，统一选项卡 + TUI 按键路径）

- **统一 UI**：红卡结构化选项卡（批准 / 拒绝 / 选项 N / 「不要再问」）——通道无关的移动端交互件；**预留选项卡→无头控制消息的分派接口**（claude 双向通道 M11 接入）。
- **TUI 路径（首批 Claude/Codex，由简到繁）**：按键映射**探测入库**（提示形态→键位：批准/拒绝/选项 N/计划模式「执行计划」批准键/「不要再问」扩展键）+ **版本探针**（CLI 版本变化提示复核）；映射缺失降级为普通发消息（不发错误键位）；选择→注入按键（复用 T2 引擎）。
- **审批边界三档（裁决 13）**：会话内应答（含计划模式批准执行）= 本期；权限模式主动切换 = 三期；APP 形态 = 延后表 #3。
- **审计**：action=approve/reject 与内容摘要入审计表。
- **验收**：Claude/Codex 红卡一键批准/拒绝→终端按键生效（实机）；计划模式「批准执行」实机；降级路径可用；审计可查。

### T4 · Windows 注入实现（M9，条件执行）

- **前置**：T1 结论 GO（全量）或 PARTIAL（缩小宿主范围）。
- **实现**：按探测定案路径接入 `injector/`（与 macOS 同口径：`[mobile]` 前缀、`\n` 归一、队列、插队、审计、回执、路由表 Windows 宿主分支 + 审批按键映射 Windows 侧复核）；Windows 宿主形态判定接入路由表。
- **降级**：NO-GO → 本任务降级登记为已知限制（二期 spec 附录 A/C 标注），批次其余照常交付，回报用户裁决是否另立替代方案。
- **验收**：Windows 实机（mam-win 场景）手机发消息→终端出现 `[mobile]` 输入；审批按键生效；真机蜂窝复验；与 macOS 同口径的队列/插队/审计行为。

## 4. 批次执行策略（一个批次尽量多做）

```
T1 探测 ────────────────┐（只 gate T4）
T2 macOS 注入全链 → T3 审批应答 → T4 Windows 实现
```

- T1 与 T2 **并行启动**（探测在 Windows 实机进行，不占 macOS 主线关键路径）；
- T4 排批次末尾：届时 T1 结论已定、T2/T3 的同口径组件（归一/队列/插队/审计/回执/选项卡）已沉淀，Windows 只做通道适配；
- 一份设计文档（本文）+ 一个实施计划 + 一个 PR；任一里程碑探测/实测不通过即走登记的降级路径，不阻塞批次内无依赖项。

## 5. 安全与横切

1. PIN 即信任（裁决 5）：写端点全部位于设备门禁后，无额外授权层；
2. 纯文本语义：不拼 shell 元字符；`-l` 字面量；注入内容不做事前过滤（裁决 4，审计留痕）；
3. 单会话串行 = 天然限速；「立即发送」插队仍受单会话串行约束（前一注入动作完成才发下一条）；写审计只增不改全覆盖；
4. 版本门控+探针+降级（宪法横切 6）：TUI 按键映射、Windows 通道带版本登记（docs/research/README 跟踪清单同步）；
5. 桌面体验不回退（横切 5）：注入不触碰 monitor 扫描路径与预算契约；全量门禁六件套 + 一期回归 E2E。

## 6. 验收与证据

**批次总验收**：手机对 tmux/iTerm2/Terminal 会话发消息→`[mobile]` 标记入终端（Claude/Codex 实测）；黄排队、可输入态 flush、插队/撤回可用；红卡一键批准/拒绝与计划模式批准执行生效；Windows 终端注入同口径实机复验（T4 GO 时）。ZCode 无头条目随 M11（延后表 #1）。每任务另有上节所列专项出口标准。

**证据基线**（详见二期 spec §9）：三通道注入 A-（本机验证在库）；TUI 按键映射 D（M8 探测入库）；Windows 写入路径 A-→待证（M6）；运行中注入行为各家差异 = M7 实测。

## 7. 风险与已知限制（预登记）

1. **TUI 按键映射漂移**：CLI 升级改变审批提示形态/键位——版本探针+复核提示；映射缺失降级路径兜底；
2. **运行中注入行为差异**（插队场景）：各 TUI 对 busy 态输入的缓冲/忽略/中断行为不一——M7 逐家实测，行为不明家禁用插队（仅排队）；
3. **多行 `\n` 展示限制**：桌面终端与 MAM 详情页不换行展示（裁决 6 已接受，延后表 #6）；
4. **Windows Terminal 探测不确定性**：WT 无官方脚本 API，ConPTY 可达性差异可能导致 PARTIAL/NO-GO——降级路径已定（T4 节）；
5. **锁屏注入待证**：应用级脚本理论上锁屏可用，M7 实测确认（不可用则登记边界文案）；
6. **E2E co-tenant 干扰**：探测与验收用临时端口隔离（M4 经验），不触碰用户自有隧道与实例。
