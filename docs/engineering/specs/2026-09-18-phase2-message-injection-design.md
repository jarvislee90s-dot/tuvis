## 1. 目标与范围

二期交付一条主线：**手机给特定会话发消息，agent 真实收到并处理，桌面自然可见，不打断运行中的会话**。按交付顺序展开为四块：

1. **已开始的对话框（终端里的 TUI）**——终端注入引擎直达：macOS 三通道（tmux/iTerm2/Terminal.app）+ Windows 终端通道（D18），打字+回车语义，实时可见；
2. **等待批准的红卡**——手机一键应答（注入对应按键，D12 第二层）；
3. **任务交接**——会话摘要导出 HANDOFF.md（F2.7，双档：注入自总结 + 规则摘要兜底）；
4. **未开窗的会话**——无头通道五家一次做齐（zcode/claude/codex/kimi/opencode，M11 二期收尾后移）。

**已移出二期**：推送网关（Bark/ntfy）与 APK 壳/manualChunks——三期收尾（裁决 16，宪法 D15/D17 再修订）。

**二期不做（边界，非选项）**：切模型/切模式（F3.1 结构化选择器 UI 属三期；斜杠命令**文本**原样放行，见 W4）；会话管理操作；自动流转导入侧（ImportService 属三期 F3.7）；绕过各 harness 自身权限体系；keystroke/accessibility 正式功能（仅 W10 文档级应急预案，D7）。

## 2. 写通道总体架构

```
手机输入框（会话详情页，多行）
   │ POST /m/api/v1/session-send（PIN 配对设备 cookie 过闸，沿 v1 前缀惯例）
   ▼
注入路由表（会话宿主形态 → 通道决策 + 有头可见性预期）
   ├─ 终端注入引擎（tmux / iTerm2 / Terminal.app / Windows）→ 打字+回车，实时可见
   ├─ 无头通道（zcode / claude / codex / kimi / opencode）→ 子进程一次 turn，回执返回
   └─ 不可注入（WorkBuddy 黑盒 / dsh 待评 / APP 形态）→ 输入框禁用 + 原因说明
   ▼
状态门控队列（黄排队 / 可输入态逐条 flush / 单会话串行 / 可查可撤回）
   ▼
写审计表（SQLite：设备 / 时间 / 会话 / 通道 / 动作 / 内容摘要）→ 发送回执
```

## 3. 第一部分 · 发消息主线（W1–W5，对应宪法 F2.1/F2.2/F2.5/F2.6/F2.10）

### W1 · 终端注入引擎（macOS 三通道）

- **需求**：终端里已开的 TUI 会话收到手机消息——打字+回车语义，桌面终端实时可见。
- **输入**：注入请求（session_id、归一后文本、设备花名）；路由表解析出的宿主终端与定位键（tmux pane / tty）。
- **输出与效果（二期行为定死）**：
  - 三通道：tmux `send-keys -t <pane> -l --` + Enter（`-l` 字面量必需，杜绝 `:` 开头被解析为键名）；iTerm2 `write text`（先写文本再补回车，分两步可校验）；Terminal.app `do script ... in window`（转义反斜杠/引号）；
  - 消息标记：`[mobile <设备花名>] ` 前缀，桌面一眼可辨来源；
  - 纯文本语义：send-keys -l 与 write text 均按字面传递，不拼接 shell 元字符转义逻辑；不用 paste-buffer（TUI 粘贴确认行为语义随版本变）；
  - 定位复用 `window/` 既有链路（跳转功能同源），无新定位逻辑。
- **边界**：keystroke/accessibility 仅应急预案（W10/D7）；定位失败（终端已关闭/会话已死）返回明确失败回执，不入队重试。

### W2 · 状态门控队列

- **需求**：不打断正在运行的会话——黄状态消息排队，agent 空下来能收输入时自动放出。
- **输入**：注入请求 + 会话当前状态（SessionWatcher 提供）。
- **输出与效果**：
  - 黄（运行中）= 入队（SQLite 队列表，含设备花名/时间戳/内容）；
  - **会话回到「可输入态」即逐条 flush**。可输入态 = 红·等待（等批准/等输入）**或** 绿·完成/空闲——通俗说：agent 停下来把光标交回输入框的任何时刻（无论它是在等你批准，还是任务做完了）。宪法原文只写了「转红 flush」，但任务完成（转绿）时 agent 同样停在输入框前等下一条指令，若只在转红时放行，完成场景的排队消息会一直压着不发，所以要扩成两种状态都放（宪法口径的完整化，非冲突）；
  - 一次只放一条，发出后重新等待下一个可输入态 = 单会话串行（天然限速）；
  - 红·中断（写入者已死，终端里没人接消息）不 flush：队列挂起，移动端明示「会话已中断，消息保留」；
  - 移动端可查队列（排队中条目+序）可撤回未发；**「立即发送」插队（裁决 12）**：任一排队项可手动越过状态门即刻注入——运行中的 TUI 会把消息放进它自身的输入缓冲（Claude Code 官方支持运行中排队输入），各家运行中注入行为 = M7 实测确认项；「按最新内容发」= 撤回旧项 + 立即发送新项；队列持久化，MAM 重启不丢。
- **远程关闭=冻结队列（裁决 19，v1.5）**：「停止远程」时投递循环随服务同停，pending 冻结、重开续跑；停服瞬间「已注入未落账」窗口由启动对账补投兜底（M6R–M9R 批次 R3）。
- **边界**：队列仅作用于终端注入通道（无头通道自身按 turn 串行，不入队）；flush 失败（终端消失）逐条降级为失败回执。

### W3 · 注入路由表

- **需求**：每个会话该走哪条通道，手机上一目了然。
- **输入**：会话的宿主形态（MAM 已区分 CLI/APP/终端类型与进程信息）。
- **输出与效果**：通道决策（tmux/iTerm2/Terminal/Windows/ZCode 无头/通用无头/不可注入）+ **有头可见性预期**（实时 / 刷新后 / 不可见）返回移动端展示；不可注入的会话（WorkBuddy 全系、dsh 待评、APP 形态）输入框禁用并说明原因。**路由规则按宿主形态判定，工具无关（v1.3 定死）**：凡宿主形态为终端（tmux/iTerm2/Terminal/Windows 终端）的会话一律优先终端注入——无头 resume 对已开 TUI 会话会分叉出后台续写，开着的界面不实时可见。
- **边界**：路由表是纯决策件（会话属性 → 通道），不带副作用；ZCode 桌面形态固定路由无头（在册限定，D6）。

### W4 · 移动端发消息（会话详情页）

- **需求**：手机上有自然的多行输入体验，发送后知道「到了哪一步」。
- **输入**：会话详情页输入框（多行，键盘回车=换行，**发送=按钮**）。
- **输出与效果**：
  - 多行归一：发送时换行符替换为字面 `\n`（两个字符）拼接为单行 → 走 W1 单行注入；输入端看起来多行，agent 与大模型按 `\n` 理解换行；**已知限制**：桌面终端与 MAM 详情页不换行展示（字面 `\n` 长串），后续里程碑可升级多行展示；
  - 队列状态指示：排队中（第 N 条）/ 已送达终端 / 失败可重试；
  - 回执语义（定死）：「已送达」= 注入动作成功（终端收到输入）；「agent 已处理」不由回执表达，由状态跃迁/内容流自然体现；
  - 斜杠命令文本原样放行（`/model` 等不拦截不审查），写审计留痕——三期 F3.1 的边界是结构化选择器 UI，不是文本拦截；
  - 授权面 = PIN 配对设备即信任，无额外开关；
  - **挂载面（2026-09-19 用户裁决修正）**：composer 在会话详情页的**全部预览布局态下均须挂载**——非分屏正文视图、纵向分屏（`split`）、横向分屏（`split-h`）三态同等可用。原实现把 composer 排除在分屏分支外（仅正文视图挂载），致分屏看文件时无法发消息；该行为**无设计依据、系实现越权**，已修（同批修正见一期内核设计 P9 的文件预览条）。
  - **审批红卡（W6 联动）同口径**：`waiting` 态的 `ApproveCard` 与 composer 同步挂载于三态，分屏时同样可见可应答（原实现与 composer 同一处被排除）。
- **边界**：不做出站内容过滤（用户对自己设备负责）；单会话发送受 W2 串行约束。

### W5 · 写操作审计

- **需求**：每一次写动作可追溯。
- **输入**：注入 / 队列 / flush / 撤回 / 审批应答 / 无头驱动，逐条。
- **输出与效果**：SQLite 审计表只增不改——设备（id+花名）、时间、目标会话（工具+session_id+项目）、通道、动作、内容摘要（首 N 字符）、结果；桌面设置页提供查看入口。
- **边界**：审计不含全文（摘要即可定位，避免审计库膨胀）；移动端不暴露审计查询（桌面侧能力）。

## 4. 第二部分 · 通道扩展（W6–W8，对应宪法 F2.9/F2.3/F2.4/F2.1 扩展）

### W6 · 审批应答（通道统一，D12 第二层）

- **需求**：会话红·等待批准时，手机上直接批准/拒绝，不用回电脑——**终端会话与无头会话都要能应答**（无头不应答 turn 就卡死）。
- **输入**：审批请求的识别信号——终端会话 = 红卡状态 + 解析器识别审批提示（各家提示形态探测入库）；无头会话 = headless 进程的审批事件（claude `control_request{can_use_tool}`）。
- **输出与效果**：
  - **移动端结构化选项卡是统一 UI**（批准 / 拒绝 / 选项 N / 「不要再问」），机制按通道分派：
    - **终端注入通道（TUI）**：选择后注入对应按键（复用注入引擎，键位而非文本）；**按键映射表：每 CLI 一次探测入库 + 版本探针**——CLI 版本变化提示复核，映射缺失时降级为普通发消息（不发错误键位）；首批 Claude/Codex 只做批准/拒绝，「不要再问」等扩展键位随映射表由简到繁跟进；
    - **无头通道（claude）**：经 `--permission-prompt-tool stdio` 双向控制消息应答（AionCore 实证：claude 发 `control_request` 后阻塞，宿主回 `control_response` allow/deny）——选项卡选择 → 控制消息；
    - **无头通道（codex exec / kimi / opencode）**：无交互审批面 = **审批策略驱动**（spawn 时给定 approval policy，turn 不因审批而阻塞；拒绝/需批准事件回流到回执，用户可调策略后重试）；
  - **watchdog 超时兜底**：无头 turn 超时（默认可配置）自动回收进程并回报超时回执——设计保证「双向应答 / 策略驱动不阻塞 / watchdog」三机制必居其一，**无头 turn 永不静默卡死**。
- **审批边界三档（裁决 13）**：①会话内审批应答属**二期本期**——含工具权限批准（Yes/No/选项/「不要再问」）与**计划模式**的两类操作（发消息继续改计划 = 普通发消息走 M7 注入；点「执行计划」= 批准键注入走 M8）；②权限/模式**主动切换**（计划模式 ↔ 完全访问 ↔ 需人批的设定）属三期 F3.1 切模式，本期不做；③APP 形态会话（WorkBuddy/Codex APP 等）无外部写 API，唯一通路 computer-use/keystroke（需解锁+抢焦点，宪法 D7 应急预案级）→ **本期不做**，登记延后表（附录 C）。
- **边界**：TUI 按键映射首批 Claude/Codex 探测入库（M8），其余工具按探测结论由简到繁跟进；claude 无头双向通道随 M11 无头通道落地（首批预留选项卡→控制消息分派接口）；终端注入为应用级脚本（tmux/AppleScript），**不需解锁也不抢焦点**——锁屏可用性 = M7 实测确认项；协议原生审批通道（app-server/ACP request_permission）属三期 D12 第一层，本期不碰。

### W7 · 无头通道（五家一次做齐 · 里程碑 M11 二期收尾后移，裁决 11）

- **需求**：未开窗的会话也能被驱动（R2.4）；一次 turn 的结果有回执。**近期需求不强，后移至二期收尾（M11，现为期末里程碑）**。
- **输入**：session_id + 文本（多行同样 `\n` 归一，与 W4 统一语义）。
- **输出与效果**：
  - 五家通道：`zcode --resume <id> --prompt <text> --cwd <项目> --json`（**限定在册工作区**，D6 判定 F——桌面刷新后可见）/ `claude -p --resume <session> --output-format stream-json`（配 `--permission-prompt-tool stdio` 承接审批应答，见 W6）/ `codex exec resume <id>`（审批策略驱动，turn 不阻塞）/ `kimi -p -S <id>`（恢复含运行时状态）/ `opencode run`（附 A 矩阵 ✅ 并入）；
  - 进程管理按 **AionCore 骨架**：Spawner trait、进程注册表、空闲挂起、崩溃重生、版本门控；
  - 回执：turn 完成返回末条 assistant 消息 + token 用量；无头产生的新回合经读链路在移动端与桌面 MAM 自然可见；
  - 单会话同时至多一个无头 turn：**端点层按会话串行（v1.3 定死）**——新请求在已有 turn 进行中时返回「排队回执」（含队列位置），turn 结束自动依序执行；审批事件按 W6 分派（claude 双向应答 / 其余策略驱动）+ watchdog 超时兜底。
- **边界**：无头对已开 TUI 的会话默认不路由（W3）；Codex 无头追加后桌面索引不保证刷新（官方 #28259，已知限制明示）；zcode / kimi / opencode 的无头审批与回执行为 = M11 首任务逐家探测确认；OpenClaw 无头（sessions CLI）走后续里程碑，gateway 模式另评。

### W8 · Windows 终端注入（D18）

- **需求**：Windows 实机（mam-win 场景）上的终端会话同样可发消息。
- **输入**：M6 探测里程碑的结论（写入路径定案）。
- **输出与效果**：Windows 终端写入通道（候选：WriteConsoleInput / ConPTY 附加写入 / Windows Terminal 通道，以探测报告为准）；与 macOS 通道同口径的行为（`[mobile]` 标记、`\n` 归一、队列、审计）与同口径验收。
- **边界**：M6 探测报告 + 独立评审先行（类似一期 M0 模式），探测不通过则该里程碑降级登记为已知限制并回报用户裁决。
- **v1.5 注记（M6R 复核）/ v1.5.1 收口**：M6「消费墙」机制学结论被推翻（输入缓冲无界 / 错误 122 非 OS 层——官方文档与 conhost/ReactOS 三重源码实证；方法论硬伤清单与补测实验见 `docs/research/refs/phase2-消息注入/`《Windows控制台写入语义与消费墙复核》）。**M6R 修正版探测已完成，gate 通过**（2026-09-18）。Windows 通道重写规格（定案见批次设计 §8）：分片节流且注入层不截断、**自适应节流**（慢消费者切占用率背压）、**写入确认双层为必要件**（层次职责见批次设计 §8.1）、事件构造**按家分支**（B 族控制键必须 VK 形态、禁裸 ESC/BP）、进程级串行 + 附加自动复位守卫、占用率监控 + 冻结自动解冻兜底、未取证审批映射严格档、脆弱常量可配置（版本复验走项目技能 `win-console-inject-probe`）。

## 5. 第三部分 · 交接与触达（W9–W12，对应 F2.7/F2.8 + D15/D17 移入项）

### W9 · 会话交接导出（F2.7）

- **需求**：任务可以交接出去——摘要导出人可读、agent 可续；**下一个 Agent 拿到足够信息无缝衔接是第一目标**。
- **输入**：会话卡「交接」按钮；交接面板（**两级单选联动，裁决 17 定死**）——第一级「工作类型」按钮组（编码 / 设计 / 文档 / 不选），点击类型后第二级**自动展开**该类型对应的环节按钮（如编码 → 需求与方案设计/实现中/待验证/待收尾）；两级各选**一项**（环节为任务**主环节单值**，不支持多选——模板侧重是「加权」不是「裁剪」，九段式全量信息恒在，跨环节任务选主环节即可，选错格子代价低）；自动预判结果预填两项、用户可改、清空任一级 = 不满足分类走公共兜底；确认后点「导出」执行。摘要档位自动：会话可注入 → 注入自总结；不可注入 → 仅规则摘要。
- **输出与效果**：
  - `~/.mam/handoffs/<时间戳>-<来源>-<目标>-<项目>.md`（HANDOFF v1 九段式：Objective / Work Completed / Current State / Decisions & Rationale / Next Steps / Environment & File Context / Session Log / Smart Defaults / Verification Steps + 原始会话指引）+ SQLite 索引表登记；九段式骨架对所有模板恒定（保持 agent 无关的可续格式），**模板作用于 LLM 摘要提示词与各段内容的侧重**，不增删段落；**同名 `.json` 无损附本默认随文件落盘**（设置页可关）；
  - **分类矩阵（提前预备，封闭枚举，裁决 15）**——情形分类必须先于使用建成，共 10 格：

    | 类型 ＼ 进度环节 | ① | ② | ③ | ④ |
    |---|---|---|---|---|
    | **编码** | 需求与方案设计 | 实现中 | 待验证 | 待收尾 |
    | **设计** | 探索与调研 | 方案迭代中 | 已定待评审/制作 | — |
    | **文档** | 大纲搭建 | 内容撰写中 | 待审校 | — |

  - **提示词 = 组件拼装，不写格格全文**：每格提示词 = **公共骨架（1 份）+ 类型模块（3 份）+ 进度模块（10 份）** 组合生成，共 14 个组件覆盖 10 格（新增类型/环节只加组件，不改矩阵机制）；
    - **公共骨架**（所有格子共用）：按九段式产出 HANDOFF.md；强制保留项（见下）；事实源真实引用（文件路径/git 提交不得编造）；面向「下一个执行者无缝接续」行文；
    - **类型模块**（留存偏向）：**编码** = 改动清单化（已完成/进行中/未开始）+ 关键代码**实际签名**（不转述）+ 文件与改动范围 + 测试与构建状态 + 报错原文；**设计** = 目标与约束 + 方案演进史（考虑过什么、为何淘汰）+ 最终方案结构与理由 + 未决权衡；**文档** = 读者与口径 + 大纲结构现状 + 已写/未写章节 + 事实与引用核对状态 + 术语表；
    - **进度模块**（接续点侧重，交接价值 = 这一环节没做完、下一个人能否接上）：编码①=需求理解、候选方案与选型理由、待确认决策点；编码②=进行中模块的接续点（下一动作从哪个文件/函数/分支继续）+ 依赖与阻塞；编码③=验证步骤 + 每步预期结果 + 已知风险与失败路径；编码④=重构点 + 文档/发布清单 + 遗留 TODO；设计①=已调研事实、信息缺口、下一步调研计划；设计②=当前迭代版本、上一轮反馈与差异、待改点；设计③=方案定稿要点、评审关注点、交付物制作进度；文档①=大纲结构、章节目标、素材清单；文档②=当前章节、素材缺口、口径待定项；文档③=审校清单（事实核查/口径统一/术语一致）；
  - **模板选择机制（三级，定死）**：① 用户显式选择（类型 3 选 1 或「不选」，进度轴随类型联动）；② 未选择 → **自动预判**（M10 交付的启发式规则，非 LLM：仓内文件构成〔源码为主→编码倾向 / 设计稿与图床→设计倾向 / md 为主→文档倾向〕× 会话关键词〔构建/测试/编译→编码；方案/评审/草图→设计；章节/审校→文档〕，证据冲突或不足 = 不满足分类；预判结果在面板预填、用户可改）；③ **落格 → 该格组合提示词；不满足分类 → 公共默认模板**；
  - **公共默认模板（兜底正文，定死）**：当前进展与关键决策 / 重要约束与用户偏好 / 剩余工作与清晰下一步 / 关键数据与引用（Codex checkpoint 口径，即四家 compact 共同五要素基线）；
  - **强制保留项（无论哪格）**：失败路径清单（「不要重走」）+ 带预期结果的验证步骤；
  - **双档执行（裁决 17，v1.4 定死）**：
    - **注入自总结（默认档）**：执行者 = **该会话正在对话的 Agent 本体**（已持有全部上下文，零额外配置）。流程五步：① 组装模板提示词（公共骨架 + 类型模块 + 进度模块 + 输出约定）；② 经 **M7 注入通道**发给会话（带 `[mam] ` 前缀与来源标记，受状态门控：黄排队 / 可输入态 flush / 可插队）；③ Agent 在**项目根目录**写 `MAM-HANDOFF-<会话短id>-<时间戳>.md`（多数 Agent 仅有项目目录写权限——这正是落盘位置选项目根的原因）；④ MAM 检测写入完成（回合结束 + 文件出现且尺寸稳定）；⑤ **自动收割转移**至 `~/.mam/handoffs/<规范名>.md` + SQLite 索引登记 + `.json` 附本——无需用户手动命令。超时（默认 10 分钟，可配置）未产出 → 交接失败回执并建议规则摘要兜底；
    - **规则摘要（兜底档）**：零依赖离线（= 极简交接档定位）；会话不可注入（已死 / APP 形态 / 黑盒工具）或自总结超时失败时使用；
    - **独立 LLM 摘要执行器不做**（v1.4 定死）：需把全量 session 喂给另行配置的模型——首次输入 token 开销巨大且引入配置负担，全面劣于让已持有上下文的会话本体直接总结。
- **边界**：导出侧 only——ImportService（投递/确认回执）属三期 F3.7；LLM 摘要在无头通道不可用的工具上自动降级规则摘要；**近期只做预设矩阵，用户自定义模板（设置面板配置侧重点/自建组件）为远期规划不入本期**（裁决 10）；类型与进度枚举**封闭**（不做自由文本自定义），扩类 = 加组件 + 修订本 spec。
- **MAM 落盘文件族保留期管理（v1.5 追加，2026-09-18 用户裁决）**：MAM 自建落盘文件（handoffs 交接件、事件文件、未来可能新增的提示词/附件文件等）统一设计保留期与清理策略（防长期膨胀；现状仅事件文件有 30s TTL），M10 设计时随交接目录一并落地。

### W10 · keystroke 应急预案（文档级，F2.8/D7）

- **需求**：万能兜底手段记录在案，不承诺、不默认。
- **输出与效果**：AppleScript keystroke / accessibility 作为应急遥控手段写入文档（适用场景、前置条件、风险：抢焦点/前台要求/中文输入法需切 ABC/自动化权限）；不实现、不暴露 UI。

### W11 · 推送网关（Bark/ntfy · **三期收尾**，裁决 16 / 宪法 D17 再修订）

- **输出与效果**：**推送网关抽象**（同一事件源多出口）：Bark（iOS）/ ntfy（Android；华为无 GMS 机型默认出口）/ APK 出口（W12 内置长连接）预留；标题=工具+项目，正文=跃迁方向+预览；失败静默重试一次；设置页测试按钮（即华为机到达率实测入口）；默认公共 ntfy 的隐私提示文案随附。

### W12 · APK 壳（**三期收尾**，裁决 16 / 宪法 D15 再修订）

- **需求**：网页链路验收后的原生壳交付。
- **输入**：与网页版完全相同的后端服务。
- **输出与效果**：Capacitor 壳 + **内置长连接推送**（APK 与 MAM 推送网关自有长连接，页面关闭仍收系统通知，通知归属 MAM 自身、点击直达具体会话）+ 前台服务与电池白名单引导页；manualChunks 移动端分包同批（D17 附注）。

### W13 · 一键 resume 窗口（v1.5 新增，裁决 18b；F3.4 前置件提前到二期）

- **需求**：手机或桌面点一下，MAM 在本机自动打开终端、进入项目目录、恢复该会话并聚焦——用户零额外操作。服务 B 兜底（注入走不通的会话经无头驱动后的「可见性」半部）与「回电脑继续」场景。
- **输入**：会话卡/详情页「在电脑上打开」（移动端走 PIN 门禁内端点；桌面端 IPC 命令）；会话元数据（项目目录、会话 id、工具类型）。
- **输出与效果**：本机 spawn 终端（Windows 优先 Windows Terminal、未装回退 conhost；macOS 优先 iTerm2、次选 Terminal.app，复用既有脚本基建）→ cd 项目目录 → 执行该工具 resume 命令（各家映射表探测入库：claude 已知，其余查证）→ 聚焦窗口；不可行情形明示（项目目录缺失→按钮禁用+原因）；写审计（动作「打开」）。
- **边界**：只负责「打开与恢复显示」，不承担消息投递（投递仍走 W1/W8 注入与 M11 无头）；M11 落地前注入不可行会话仅显示原因，B 兜底的「发」半部随 M11 补全。

## 7. 非功能需求

- **安全**：PIN 门禁覆盖一切写端点（宪法横切 1）；写审计全覆盖、只增不改；消息标记可归因到设备；注入纯文本语义（不拼 shell 元字符）；单会话串行天然限速；无头/注入通道版本门控+探针+降级（横切 6）。
- **性能**：点发送 → 目标终端出现文字 ≤3s（公网隧道链路）；队列 flush 在静息跃迁后 1s 内；无头回执随 turn 完成返回。
- **可靠性**：注入失败明确回执+可重试；队列 SQLite 持久化重启不丢；无头进程崩溃重生；一期能力零回归（横切 5：桌面监控/通知/资源管理不受影响）。
- **体验**：中文界面与 MAM 一致；回执清晰区分「已送达终端」与（由状态流体现的）「agent 已处理」；不可注入会话明示原因；可见性预期（实时/刷新后）在发送前告知。
