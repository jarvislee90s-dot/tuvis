## 1. 背景与定位

MAM 已有一个移植自 DSH 插件 foxbell-pet 的桌宠功能（独立 OS 窗口、图集动画、状态卡片、语音与字幕）。本次为它增加 **token 用量看板**与**用量记录**。

MAM 与原插件的根本差别决定了本次不是照搬：

| 维度 | 原插件（dsh-foxbell-pet） | MAM |
|---|---|---|
| 数据来源 | 单一 harness 的运行时事件流（`session.snapshotEvents()`） | **7 个工具各自的磁盘文件 / SQLite**，格式互不相同 |
| 会话可见性 | 宿主持有全部会话 | 会话扫描「无进程 = 无会话」，**agent 退出后即不可见** |
| 历史留存 | 无持久化，按需从事件流重算 | 必须自建账本，否则「今日用量」会随 agent 退出而归零 |
| 多工具归因 | 不存在 | 工具 / 项目 / 供应商 / 模型四维交叉是核心价值 |

因此本次的定位是：**一套 7 工具通用的用量采集底座 + 三级呈现（浮窗 / 大看板 / 记录页）**，而不是把原插件搬到 MAM。

## 2. 目标与非目标

**目标**

1. 在不违反会话扫描预算契约（AGENTS.md 明文的 L1/L2/L3 三层预算与预过滤反模式禁令）的前提下，为 7 个工具采集 token 用量并持久化。
2. 提供三个呈现面：宠物浮窗（全局速览）、大看板（趋势与分布）、用量记录（按组合的明细账）。
3. 支持按 **工具 / 项目 / 供应商 / 模型** 四个维度及其交叉聚合。
4. 支持分享图导出（含宠物立绘）与 CSV 导出。

**非目标（明确不做）**

- **不做阈值告警、里程碑播报、告警音效**（【用户裁决】原插件的告警链、跨阈值去重、里程碑整数关口、3 个内置音效资产全部不做）。
- **不做成本 / 金额折算**（沿用原插件宪法「纯 token」；本机实测 OpenCode 的 `cost` 恒为 0、cc-switch 的定价链路约 1700 行 + 800 行价表，均为不必要负债）。
- **不做小黑板（L2）**（【用户裁决】宠物侧只保留一个容器，定为浮窗）。
- **不做外部用量数据导入**（原插件也没有此能力）。
- **不做 OpenClaw 统计**（【用户裁决】走 Gateway 形态，且需新写扫描器）。
- **不修 OpenCode 2.x 会话上板问题**（【用户裁决】本次只做用量采集兼容，会话上板缺口单独开一条线；见 §9）。

## 4. 术语与统一口径

### 4.1 四桶

| 桶 | 含义 |
|---|---|
| 未缓存输入 `input_fresh` | 本次请求真正新读入的输入 token |
| 缓存读 `cache_read` | 命中提示缓存的输入 token |
| 缓存写 `cache_write` | 写入提示缓存的输入 token |
| 产出 `output` | 模型输出的 token |

派生量：**请求输入**、**命中率**、**用户输入(估)**、**请求次数**。

- **reasoning 计入 `output`**：opencode / zcode / dsh 等源的 `reasoning_tokens` 在四桶里没有独立槽位，一律并入 `output`；否则 hero（= 请求输入 + 产出）与各源自身的 total 对不上，产出会系统性偏低。
- **「请求次数」逐源口径**（契约 `metrics.requests`；与 turn 数不是一回事）：claude = 去重后的 `message.id` 数；codex = 相邻去重并剔 stub 后的 `token_count` 事件数；kimi = `usage.record` 条数；opencode = 带 `tokens` 的 assistant 消息数；workbuddy = 带 `usage` 的 assistant 消息数；zcode = `model_usage` 行数；**dsh = `sessionStats.val.steps`（LLM 调用步数，≠ `turns` 回合数）**。
- **展示别名映射**（UI 文案 ↔ 本节/契约字段）：「请求输入(全文累计)」= 请求输入 = `requestTotal`；「缓存命中」= 缓存读 = `cacheRead`（**不是** cacheRead + cacheWrite）；「产出」= `output`；「用户输入(估)」= `userEst`。
- **术语**：全文统一用「**浮窗**」指宠物侧的迷你条容器；契约的 `miniBar*` 前缀（`miniBarRange` / `miniBarToolRows`）是同一容器的字段别名，不是第二个 UI。

### 4.2 缓存语义三态（本次最关键的口径设计）

各工具对「缓存读是否已包含在 input 里」的定义**不一致**，且**同一工具在不同版本/不同模型上也会变**。本机 Codex 实测：35,935 条事件中「包含」16,900 条、「互斥」16,298 条，且 **31 个文件内两种语义混存**。因此：

| 语义 | 含义 | 请求输入 | 命中率 |
|---|---|---|---|
| `Exclusive`（互斥） | 缓存读与未缓存输入互斥 | `input_fresh + cache_read + cache_write` | `cache_read ÷ 请求输入` |
| `Subset`（包含） | 缓存读已含在 input 内 | `input`（已含 cache_read） | `cache_read ÷ input` |
| `TotalOnly` | 只有总量、无四桶拆分 | 不参与 | 不参与 |

> **实测更新**：七源探测后，**没有任何源默认属于 `TotalOnly`**（WorkBuddy 的四桶在 jsonl 里、dsh 的 `totals` 四桶 **99/99 恒存在**）。该态保留为**运行时兜底**，且**只在某源某条记录确实拿不到四桶时**才按此处理，不得据此把整个源降级。注意：dsh 的 `val.last == null`（本机 10/99）**不是四桶缺失**——`totals` 四桶恒在，`val.last` 缺失只影响**逐轮**指标（turn / 时长）不产出。

规则：

1. **逐条判定优先于声明式默认**。Codex 的判据是 `total_tokens` 算术：`t == input+cached+output` → 互斥；`t == input+output` → 包含（`cached == 0` 时两式等价）。**禁止**用「`cached > input`」单条判据——本机实测查准 100% 但**漏判 4.5%**。
2. **判据缺失时一律按 `Exclusive`**（【默认裁定】采纳 cc-switch 的结论：算错的后果是**命中率偏低**，而不是**静默多算**；与规则 5 的声明默认是同一条兜底）。
3. 算错的代价（本机 Codex 全量实测）：正确判据命中率 **92.69%**；一律按包含 → **201.69%**（>100%，物理不可能）；一律按互斥 → **66.85%**。
4. 语义判定必须落在**唯一的归一化层**，7 个采集器不得各自计算命中率。
5. **各源的默认语义**（探测 + 计划复核后定案）：claude / kimi / dsh / **opencode** 为 `Exclusive`（opencode 本机未取得可用的 `total_tokens` 类算术判据，正是按规则 2 的安全默认）；**codex / zcode / workbuddy 三个源必须逐条判定**——它们的数据里都有可用的 `total_tokens` 类算术判据（codex 见规则 1；zcode 的 `computed_total_tokens` 与 workbuddy 的 `total_tokens` 本机实测**均等于 `input + output`**，指向 `Subset`）。**只有判据缺失的记录才落声明默认 `Exclusive`**（规则 2 的安全默认）。语义**逐条记录进账本**（明细表 `cacheSemantics` 列），**不得按源一刀切**，也不得按日期或版本批量改判。

### 4.3 其余口径

- **用户输入(估)**：CJK 每字 1 + ASCII 每词 1（沿用原插件）。**只对能读到用户文本的源计算**（claude / codex / kimi）；其余源该指标**返回 `null` → 显示空态（不可用标记）+ 不可用原因**，**不得填 0**（与 §8.2 / §9.5 一致；契约只有 `null` + `availability` 通道）。
- **模型名**：完全一致才算同一模型（D9）。
- **供应商**：**供应商归因三态** `实测 / 推断 / 未知`（值对象 `sourceKind`，存储列 `provider_kind`），UI 必须可见地区分。
- **子代理 / 侧链**：其用量**计入合计**，口径说明中必须出现「含子代理」字样（沿用原插件纪律）；**「计数类」按 D17 分层**（只数父会话）。逐源归属**已实测定案**：claude 侧链在同一文件内（`isSidechain` 标记）架构上天然计入（本机无侧链样本，`isSidechain` 全 false）、codex 天然含（父子同 rollout）、kimi **默认不含 → 必须 glob 全部 `agents/*/` 目录**、dsh 有 **47/99 个投影文件本身是子代理会话**、opencode / zcode / workbuddy 本机无子代理会话（详见 `docs/research/七源字段可得性矩阵.md` §3.5）。另：用户切到 `subagentMode = "parentsOnly"` 时合计不再含子代理，**页脚口径文案相应改为「不含子代理」**（见契约 `UsageFilters`）。
- **命中率分母为 0 时记 0**（不得显示 NaN 或空）。
- **通用去重原则（跨源适用）**：同一次逻辑请求产生的多条样本不得重复计入。**去重键必须包含「源 + 会话/文件」而不能只用消息 id**——本机实测 claude 的 `message.id` 会跨会话复用，仅按 id 去重会误删。Codex 的具体判据见 §5.3.4；另需防「同一 rollout 内含多条 `session_meta`（父/子线程同文件）」被按 thread_id 双计。其余源若存在重试 / 重放样本，按同一原则处理。
- **「数据截止时间」的定义**：指**账本数据的截止时刻（数据新鲜度）**，不是当前时刻；在非「当日」的时间视图下同样成立。

### 5.3 Codex 采集的实测约束（本机全量实测得出，实现必须遵守）

1. **扫描范围必须是两棵树**：`sessions/**`（398 文件 / 2135.9 MB）+ `archived_sessions/*.jsonl`（27 文件 / 78.2 MB）。归档树命中率仅 51.5%，漏掉会失真。
2. **不需要 SQLite 作路径来源**：sqlite 里 424 条 distinct `rollout_path` 全部落在这两棵树下（0 条在外），反而有 4 个 rollout 未被 sqlite 登记。sqlite 只用于取标题/归档标记等元数据，且**查询前必须探列**（本机两套 state 库 40 列 vs 29 列不同）。
3. **不得使用 `threads.tokens_used`**：仅 44.1% 与 rollout 吻合，30% 被放大 10~100 倍。
4. **逐轮累加前必须做相邻去重**：存在真实重放（1,945 条相邻重复事件 / 114 文件）。相邻四桶完全相同则丢弃；去重后与累计值吻合度由 74.4% 升至 98.1%。**禁止用 `turn_id` 去重**（`turn_context` 非每轮写入，`turn_id` 缺失 1.5%）。
5. **stub 事件必须剔除**：四桶全 0 而 `total_tokens` 非 0 的 840 条 / 86 文件。
6. **性能基线**：单遍流式扫 425 文件 / 2.21 GB / 226,035 行 ≈ **4.4 秒**（**口径 = Python 流式解析 token 四桶**，内存恒定；全指标单遍的口径见 §7.2 的 1–3 分钟，两者不是同一件事），坏行 0 条。故「首次全量 + 之后增量」可行，**但绝不可放进 3 秒轮询**。

**是什么**：一个可缩放的独立窗口，承载长周期回看与分布分析。

### P2 · 浮窗（宠物侧）

**是什么**：悬停宠物约 0.5 秒后在宠物侧浮现的全局用量速览；移开即消失；**除尾部一个「详情 »」按钮外无任何可点元素**（其余区域不拦截点击，见 D12）。
**输入**：全局速览口径（默认「当日」，可配）+ 分工具**条数**上限（设置项 `miniBarToolRows`，默认 3，见 P7）。
**输出（行序）**：

1. `请求输入 X · 命中率 Y%`（所有工具 + 所有会话加总）；
2. `缓存命中 X · 产出 Y`；
3. **分工具汇总（1 行）**：`Codex 123.46万 · Claude 45.60万 · Kimi 12.35万`，超出折「等N」（见 D20；样例按 2026-10-06 裁决的 2 位小数）；

5. 尾部 `详情 »` —— **唯一可点元素**，点击直达大看板并关闭浮窗。

**触发与关闭（两个触发方式、一个容器）**：悬停约 0.5s 出现 → 移开即消失（含短暂宽限）；右键菜单「今日用量」可手动唤回**同一个浮窗容器**（手动模式下点浮窗外部或 ESC 关闭，见 D12）。
**交互规则（见 D13）**：滚轮**不劫持**（事件穿透回下层，宠物与浮窗永不抢页面滚动）；拖拽宠物期间浮窗隐藏、悬停检测挂起，松手 0.5s 后恢复；ESC 逐层关闭（一次一层）。
**约束（全部来自探测实测，实现不得偏离）**：

- **固定 5 行**（D20），不做「每工具一行」。
- **不加宽窗口**：单行最宽实测约 187px / 可用 320 单位（58%），**水平不紧张，瓶颈只在高度**；宽度常量 `px(340)` 写死在 `FoxbellPet.tsx:510`，不要改。
- **必须加 `maxHeight` 兜底 + 内部滚动/截断**：最坏组合仍可能触及可用区上限（5 行 × 1.25 倍 × 3 卡片 = **673px**（同 D20 公式口径，含外沿估算）vs 可用 ≈705px，余量仅 ≈32px）。
- **`syncSize` 的高度公式必须改**：现为 `px(268) + max(卡片区, 菜单, 候选浮层)`（`FoxbellPet.tsx:505-512`），浮窗与卡片是**竖直堆叠**关系，须改为**求和**（卡片 + 浮窗），否则浮窗会被算漏。
- **位置与字号随宠物三档缩放等比适配**；明细行可用 11px（参考实现的 dim 行即如此）。
- **⚠️ 吃点击面积会增加**：**穿透恢复路径当前不可达** —— `setIgnoring(true)` 全仓零调用点、`ignoringRef` 恒为 false（`usePetWindow.ts:125-135,198`）；`registerInteractive` / `hitTest` **两设施已就位**（`FoxbellPet.tsx:77,79,259`、`usePetWindow.ts:195`）但不改变穿透行为 → 宠物窗口**整窗常驻交互，透明像素也吃 OS 点击**，且 **CSS `pointer-events:none` 无法穿透到别的 OS 窗口**（参考实现是网页内嵌 HUD 才能这么做）。挂浮窗会让吃点击面积增加约 `340 × Δh`（逻辑 px × scale）——这是本方案必须接受的代价，实现时不得假装可穿透。
**依赖模块**：宠物窗口前端组件 + **采集触发 + 只读查询两类 IPC**（悬停浮窗要即时出数，但前端绝不自行触发全量扫描，见 §7.2/§7.3）+ 宠物右键菜单新增一项。

### P4 · 导出

| 能力 | 说明 |
|---|---|
| **复制文本摘要** | 纯文本，格式 = 头部一行（看板名 + 时间范围）+ 各指标行「标签: 值」+ 分组明细行（沿用原插件的文本结构） |

**分享图的实现要点**（参考实现的踩坑记录 + 本次实测，实现必须遵守）：

1. 画布**两遍绘制定稿**——第一遍干跑只累加高度、第二遍实际绘制，两遍步进常量必须逐段一致（否则页脚出界，参考实现历史上正是此 bug）；
2. 宠物立绘用**固定高度、不随内容压缩**；
3. **图集加载方式**：外部宠物的 `spritesheetUrl` 是 `asset://localhost/...`，与页面（`tauri://localhost`）**跨源** → 直接 `<img>` 画会**污染 canvas 并让 `toBlob()` 抛 SecurityError**。**必须走 `fetch(assetUrl) → blob → createImageBitmap / objectURL → drawImage`**（本仓已有同协议 fetch 成功先例）；加载失败时**不画立绘也要出图**，不得让整张分享图失败；
4. **帧几何从真实图集尺寸推导**（`frameW = naturalWidth / 8`、`frameH = naturalHeight / rows`，`rows` 取 9 或 11），**不要硬编码 192/208** —— 实测两者恰好相等，但推导写法对未知宠物更安全；
5. **姿态可选项必须按 `rows === 11` 门控 look 动作**（9 行图集没有 look 行，画出来是空白；运行时 `FoxbellPet.tsx:391-393` 已有同样门控）；
6. **代表帧取 `min(col, 该动作帧数 - 1)`**：实测每行非空列数恰好等于该动作的帧数数组长度，**跨宠物不存在通用的「最好看」列**，通用安全默认是 **col 0**；
7. 落盘走 `export_save_bytes`（base64 → Rust 写 `系统下载目录`（2026-10-07 裁决 A2）），**不用对象 URL + `<a download>`**，故参考实现那条「对象 URL 延迟回收」在本方案**不再适用**（仅当仍用 ObjectURL 做中转时才需要）；
8. 默认 1× DPI，不做 2× 高清导出。

### P5 · 分组维度

四个维度：**工具 / 项目 / 供应商 / 模型**，**供大看板切换**；**记录页的卡片分组只接受「工具 / 项目」两值**（D7），且**卡内每行固定为「供应商 / 模型」**（D6）——`groupBy` 只驱动卡片分组，不改卡内行维度。
**项目归属**（D21 定案）：采集时随会话一并记账；项目名显示时再取（改目录名不污染历史账）。**四条规则**（本机实测得出）：

1. **分组键 = `projectName.toLowerCase()`，显示名 = `projectName` 原文** —— 对齐首页会话卡片（`src/components/sessions/SessionCard.tsx:151` 直接渲染 `session.projectName`；首页另经同文件 `truncateProjectName` 按 15 单位宽度预算截断成 `…`（英文 15 字符 / 中文 10 字），**仅长度、不改大小写**——看板**有意显示全名**、列宽足够，两者不是两套命名）与仓内既有约定（`pairing.ts:31` 的 `pairingKey` 即小写）。**禁止**用 `projectPath` 作键：它在各源有三种形态（原生反斜杠 / claude 归一化后的小写正斜杠 / 空串）。
2. **命名函数复用既有 `monitor/project.rs:10` 的 `project_name_from_path`**（basename，**不做** realpath / 大小写规范化 / trim / 软链解析）；`realpath` **只留档**（会话维度列 `project_realpath`），**不进展示与分组键**——**不要**另造一套带 realpath 的命名，否则看板与首页会叫两个名字。
3. **一律取记录内的 cwd/目录字段，禁止用日志目录名反推**（claude 的项目目录名会把非 ASCII 有损压成 `-`：`163邮箱归档-20260820起` → `163-----20260820----`）。
4. **一个会话文件可能跨多个项目**（本机 claude 有一个 jsonl 内出现两个 cwd），归属按「记录级 cwd」而非「文件级」判定，多值各自计入。

**另存备用**：会话维度表里同时保存 `project_realpath`（realpath 规范化路径，**只留档**、不做 UI 用途与分组键），以便日后若要修归类时无需重扫。

**已知代价（须在 UI 上诚实接受）**：Windows 上 claude 的路径被 `normalize_cwd_for_match` 转成小写，而 zcode / workbuddy 保留原生大小写 → 同一目录可能裂成两组；无 cwd 的会话全部落 `Unknown` 桶。
**模型合并规则**：完全一致才合并（D9）。
**供应商归因**（D8）：优先读各工具配置文件（各家配置文件里列出模型清单）→ 尽力归因；归因不到则**该行只按模型维度呈现**；**供应商归因三态**的来源标记必须在 UI 可见。

### P6 · 时间范围

五档：**近 5 小时 / 当日 / 近 7 天 / 近 30 天 / 自定义**（D5）。

**「近 5 小时」的精确定义（沿用参考实现的裁决，实现不得自由发挥）**：

1. 窗口 = **最近 5 个完整整点桶**，**不含进行中的当前小时**；桶按整点对齐（如现在是 14:37，则窗口 = 09:00–14:00 五个桶）；
2. **整点锚定，不做秒级滚动**——理由：秒级滚动重算不经济，整点语义对观察窗口足够；
3. **重算时机只有两个**：(a) 任一源的用量数据发生变化（指纹变化）；(b) **跨整点 / 跨日**。其余时刻直接复用已算好的值，不做重复计算；
4. 「近 5 小时」是**观察窗口，不是订阅计费窗口**（参考实现已把「订阅窗口剩余额度」列为存档不做，本次同样不翻案）；
5. **粒度映射**：近 5 小时 → 每小时一个点；近 7 天 / 近 30 天 / 自定义 → 每天一个点。

**其余四档**：
- 「当日」= 自然日 0 时至当前；
- 「近 7 天 / 近 30 天」= 含今日在内的滚动窗口，日粒度；
- 自定义 = 日粒度，跨度 ≤31 天（含首尾），超限截断并**常驻提示**「已截断为最近 31 天」；
- 跨源日界：**一律以宿主本地时区为基准**（**2026-10-05** 用户裁决〔落盘提交 `53f7cdf`〕，**取代**此前「优先用各源自带时区、缺失才回退宿主本地」的写法）。理由：① **基准必须唯一且可复现**——落库键用源自带时区、而查询窗口键只能用宿主本地时间构造，就是两套时钟；δ≠0 时边界行落到窗外，表现为**静默少算**（跨整点 ≤1h、跨日 ≤1d），且只在特定时区的特定时刻复现；② **宿主是运行 MAM 的那台电脑，其时区不会变**；而会话可能来自时区会变动的设备（如手机），以它为基准反而引入漂移；③ 统一到宿主本地后，落库与查询天然同源，无需额外换算。
  - **实现纪律**：各源自带的时区信息（如 Codex rollout 的 `turn_context.timezone`）**可以读入备查，但不得参与任何键计算**——实现处必须写明这一点，避免后来者把「读得到却不用」当成 bug 修回去。参考实现 Codex++ 被本文件原先判为"有缺陷"，**该判断随本次裁决作废**。
  - **代价如实记录**：跨时区使用时（例如同一天在两地各跑一段），日键按宿主本地日切分，与"以会话发生地当地日切分"不同。这是**为可复现性付的代价**，不再作为待办。
- 【默认裁定】区间数据的查询结果做**短时缓存**，避免同一视图反复触发采集。

> 统一为「不带单位 → 0 位；带单位 → 恒 2 位」，**两档一律不再剥尾零**。唯一出处仍是

**环比（与上一等长周期对比，见 D14）**：指标网格各项与趋势区都显示对比值。**「上一周期」= 紧邻当前区间之前的等长区间**：

**隐私白名单（纪律项，沿用参考实现）**：看板、浮窗、记录页与导出的所有内容**只允许出现静态文本与结构化摘要**；**禁止**显示 prompt 原文、代码内容、密钥或任何会话正文。

## 7. 存储与采集架构（概览）

### 7.1 存储（MAM 自己的库 `~/.mam/mam.db`，绝不写他人库）

| 表 | 用途 | 保留 |
|---|---|---|
| 用量明细 | per-(源, 会话, **项目**, **小时桶** `hourKey`=YYYY-MM-DDTHH, 模型, 供应商) 的增量账，另存派生列 `dayKey` 供日聚合与保留期清理 | **保留期可配**（默认 90 天） |
| 日聚合 | per-(日, 源, 项目, 供应商, 模型) 的汇总 | **永久**（长期趋势靠它） |
| 采集游标 | per-(源, 会话) 的水位 | 永久 |
| 会话维度 | per-(源, 会话) → **项目归属的会话级近似**（取首个带 cwd 的记录）、标题、活跃区间 | 永久 |

**关于「项目」维度的一点说明**（D21 规则④的必然结果）：**项目归属按「记录级」落在明细表**——同一个会话文件可能含多个 cwd（本机 claude 实证：一个 jsonl 内两个 cwd），因此项目**必须进明细表主键**，不能只挂在会话上。对应地，**会话维度表的项目列降为「会话级近似」**（取首个带 cwd 的记录），仅供会话列表展示，**不作为任何聚合依据**；日聚合按（日 × 项目 × 供应商 × 模型）折叠。**为什么明细按小时桶存**：「近 5 小时」档要求小时粒度，按日存产不出小时桶；日桶由 `hourKey` 前缀聚合得到，不重复落一份（与契约 §4 同口径）。

**时间归属（2026-10-07 用户裁决，dsh 采集器改造）**：明细行的 `hourKey` 一律是**事件发生时间**（宿主本地整点），**不是采集时刻**。dsh 的两条取数路径里只有原始日志带逐事件时间（`assistant/message.data.usage` + 顶层 `time`），投影缓存只有会话级累计值 ⇒ 采集器逐事件归桶；日志已被清理、只能从累计差额补录的部分**只进日聚合**（明细行的 `hourKey` 落**日键**、`cacheSemantics = "backfill"` 作来源标记）——因为「什么时候用的」这一信息在源头就不存在，把它记进某个小时桶就是编造。总量护栏：`Σ(实测小时档) + Σ(补录日档) == 投影缓存累计`，偏差 ≤ ±0.5%（采集侧由 `D − E` 对账保证，含「日志领先投影缓存一轮」的防重复入账）。**历史数据不回填**：改造只对生效之后的采集生效。

【默认裁定】采用「明细 + 日聚合」两层：参考实现 cc-switch 也是这个分层，但它硬编码 30 天且聚合后直接删明细；本次把保留期做成可配，并在 UI 明确告知边界。

### 7.2 采集（C′：自包含子系统，不改既有 3s 热路径）

- **触发**：按需（打开大看板 / 悬停浮窗）+ 稀疏兜底（默认 10 分钟，**仅窗口可见时**）+ 应用启动一次。
- **不采用** cc-switch 的每 60 秒盲目轮询（其调研文档自身也建议 MAM 不要照抄），也不采用「搭 3s 会话扫描便车」——因为该路径「无进程 = 无会话」，恰恰看不见已退出会话的尾部增量。
- **增量**：游标 + 尾指纹；**并入既有 `SessionFileScan`（L2 内容摘要缓存），不另起第二套缓存**；文件型源叠加字节双水位（借鉴 Codex APP 官方 `thread_history_projection_state` 的 `(next_rollout_byte_offset, next_rollout_ordinal)` 设计）。
- **并发**：单飞锁 + 后台线程（对齐 MAM 既有单飞模式），**禁止**在采集路径上做「先全量解析、后按时间窗过滤」的反模式。
- **一次扫描出全部指标**：同一文件**只允许流式读一遍**，在同一遍里同时产出四桶、turn、工具调用、报错与时长——**禁止为不同指标重复扫描**（codex 全量单次实测 **1–3 分钟 / 2.21 GB**——口径 = **全量 grep 全部指标**；§5.3.6 的 4.4 秒是 **Python 流式解析四桶**口径，两者不是同一件事，重复扫仍会直接不可用）。耗时类指标另建议做「按天 / 按会话索引」，避免每次全量。
- **合并统计前的去重分两类，不得混用**：① **用量（四桶）**按「**相邻样本四桶完全相同则丢弃**」处理（§5.3.4 的 codex 真实重放），opencode V1/V2 同会话并存、dsh 同会话多版本文件、kimi 主/子代理分目录三类重复源按同一原则处理；② **`(源, 会话 id, turn id)` 只用于 codex 的时长样本配对去重**（同 turn 多条 `task_complete`，2,885→2,308），**禁止**用它给用量去重（`turn_id` 缺失 1.5%、`turn_context` 非每轮写入，见 §5.3.4 / §10）。
- **⚠️ 写库不得阻塞 3 秒轮询（本机已证实的风险）**：MAM 的 SQLite **未启用 WAL、未设 `busy_timeout`**，全局只有一把 `Mutex<Connection>`（`src-tauri/src/database/connection.rs:21-28`），而 3 秒的会话轮询会频繁取用同一把锁。因此采集**必须分小批短事务提交、批间主动让出锁**，**禁止**开一个大事务写完整轮采集（否则会话卡片 / 通知 / 宠物状态会一起卡顿）。若需进一步并发能力（独立连接 + WAL + `busy_timeout`）【默认裁定】留到计划阶段评估并单独提请裁决——**因为它会改变整个 `mam.db` 的既有行为，不属本功能可自行决定的范围**。
- **SQLite 源**：一律只读打开；缺 `-wal/-shm` 的库需回退 `immutable=1`，且优先「先复制再读」以避开撕裂风险。

### 7.3 对外接口

**前端只调一个口**（这是「不用一个一个工具去查询」的落点）：后端内部 7 个采集器必然按格式分别实现，但对前端只暴露 **8 条命令**（契约 §3 冻结）—— **采集触发 `usage_collect`**（唯一的扫描入口，含单飞与最小间隔保护）、大看板数据、记录数据、CSV 文本、设置读写、两条落盘命令。参考实现 cc-switch 没有抽象接口，只有一个手写分发函数；本次做得更进一步：用统一的采集器契约（对齐 MAM 既有 Adapter 模式）收敛 7 个实现。

## 8. 边界与已知限制（必须诚实标注，不得静默）

1. **WorkBuddy 的 token 数据在 jsonl 而非 DB**（DB 的 `used/size` 是上下文填充量）：它有四桶、可进命中率；但它**无供应商、无回合概念**，且模型须取 jsonl（DB 值会过期）。
2. **用户输入(估)** 只对 claude / codex / kimi 计算；其余源该指标**返回 `null`、显示空态（不可用标记）**，**不显示 0**（与 §4.3 / §9.5 的「不可得就空着」原则一致），UI 需标注不可用原因。
3. **供应商归因三态**：ZCode / OpenCode / Kimi 为实测，**dsh 为部分实测（28.3% 有值）**；Codex / Claude Code 等靠配置与映射推断；**WorkBuddy 完全不可得**；推断不到则只按模型维度呈现。
4. **Codex 的 `model_provider` 无区分度**（全 `custom`）；真身靠 `config.toml` 的 `base_url`，而它只有当前值 → 需按时间采样配置快照，否则历史归因会漂移。
5. **明细保留期之外只有日聚合**：区间越长、粒度越粗，UI 必须明示。
6. **「工作小结」区各指标数据源已逐个源实测定案**（会话数 / turn 数 / 报错次数 / 最长单 turn / 工具调用）：参考实现取自运行时事件流，MAM 走磁盘采集，逐源结论见 §9.5 与 `docs/research/七源字段可得性矩阵.md`；**不可得的一律显示空态而不是填 0**。其中 dsh 的报错 / 最长单 turn / 逐工具属**部分覆盖**（原始日志只覆盖一部分会话 → `available=true + reason=部分覆盖`；**比例不写死**，见 §9.5 末的登记。⚠️ **该「部分覆盖」不在界面表达**——用户 2026-10-06 裁决，理由见同处登记与 `src/lib/usage/availability.ts` 的口径 ④）。
7. **dsh 的供应商与模型维度已核实为「部分实测」**：其投影缓存 `tokenUsage.totals` 只有四桶、无路由信息；路由信息在 `rows.modelSelection.val.lastUsed.{provider,model}` 同一对象里，但该 row **仅 36/99 存在（有值 28/99 = 28.3%）**，缺失时该行只按模型维度呈现（§8.3）。
8. **子代理 / 侧链用量已计入合计**，各源是否天然包含**已逐源实测定案**（codex 天然含、kimi 需 glob 全部 `agents/*/` 目录、claude 架构上含但本机 `isSidechain` 全 false、dsh 47/99 个投影文件本身是子代理会话，详见 §4.3）；口径说明中一律标注「含子代理」（切 `parentsOnly` 时改为「不含子代理」）。**「计数类」指标按 D17 分层**。
9. **turn 数不跨工具合计**（D16）：各源回合判据语义不可比，只在「按工具」维度各自显示并逐源标注口径。

#### 9.5.1 登记：「部分覆盖」**不在界面表达**（2026-10-06 用户裁决）

- **裁决**：dsh 的报错三层 / 用户打断 / 最长单 turn / 逐工具调用与耗时属**部分覆盖**（只有一部分会话仍留有原始日志），但界面上**不为它单开一档** —— 能显示的就显示，显示不出的位次走空态。
- **理由 ①（模型是布尔两态）**：`UsageAvailability` = `available` + `perSource`，**没有「部分」这一档**；要加一档就得改 `available` 的 wire 形状 —— 那是**冻结契约**，不在本阶段范围内。
- **理由 ②（前端不直渲后端 `reason`）**：`reason` 是给日志的中文散文（如 `部分覆盖` / `mock-empty`），不随语言切换 ⇒ 直渲会在英文界面里印中文；用户可见的原因一律走 `i18n`（`usage.work.*` / `usage.turnBasis.*`），见 `src/lib/usage/availability.ts` 口径 ③ 与 ④。
- **落地**：某源只覆盖一部分会话时，界面照常显示它给得出的数字，给不出的位次是 `EM_DASH`。用户裁决原文：「DSH 能提取哪些数据，能显示哪些就显示哪些。不能显示的话，就用斜杠或横杠表示没有这个数据。」
- **覆盖率本身不写死比例**：它随机器与 `~/.dsh/sessions/` 的清理策略变化 —— 本表「本机实测」列的 `19/99`（以及 §5.1 表格里的同一数字）是**探测期**的矩阵口径，**已作废**；2026-10-06 复核：账本口径下近 7 天与全时的 dsh 会话都拿到了「只有原始日志才有」的那几类指标（原始日志口径下，能对上投影缓存的会话约占七至八成，会话目录总数也从探测时的 101 涨到 279）。该比例只留在后端 `reason` 与本节审计记录里，**不参与界面表达**。

### 9.6 图表库｜【默认裁定】纯 SVG 自绘，零新增依赖

MAM 前端目前**没有任何图表库**（全仓零 recharts/d3/echarts，只有 radix Progress）。本功能所需的图形只有两种：**折线 + 渐变面积趋势图**与**占比条**。参考实现的趋势图正是这两者，且是**纯函数式 SVG**（84 行、无依赖、可直接搬）。故定：**不引入图表库**，沿用纯 SVG 自绘；占比条用纯 CSS。若将来要加更多图形类型再评估引入。

### 9.7 导出通道与图集 canvas（2026-10-03 实测结论）

**导出落盘**：`<a download>` + Blob URL **在本仓 webview 上不成立**——wry 在未注册 download handler 时对 download 类导航直接 Cancel（**失败静默**），未标成 download 时则把窗口导航到 blob URL（**界面跑飞**）。且 `plugin-fs` 未安装、`dialog:allow-save` 未声明、**新窗口不在任何 capability 的 windows 白名单里**（插件命令会被 ACL 拒，而应用自定义命令不受影响）。**结论：走 Rust 落盘**（`export_save_text` / `export_save_bytes` → `系统下载目录`（2026-10-07 裁决 A2），复用既有 `reveal_dir` 定位），**零新插件、零新权限**。

**图集可绘制性**：帧几何实测**正确**（foxbell 1536×2288 与仓内样例 starry-dew 1536×1872 均整除得 192×208，逐帧 alpha bbox 无错位）；`asset://` scope 已放行 `$HOME/.mam/pets/**`；但 **asset 与页面跨源，直接 `<img>` 绘制会污染 canvas** → 必须走 fetch → ImageBitmap。

**测试限制**：**Vitest/jsdom 没有 canvas 内核**（未安装 `canvas` 包）→ 分享图单测必须 mock `getContext`/`toBlob`，并把「画什么」抽成纯函数来断言。

**仍须真机验收的 4 项**（探测无法替代）：① 外部宠物在 fetch 路径下 `toBlob()` 是否真的不抛 SecurityError；② 文本剪贴板的 `pbpaste` 闭环（现状证据缺口）；③ 若上「复制图片」，剪贴板里是否真是 PNG；④ CSV 中文编码（已定 UTF-8 BOM，但本仓无先例）。

## 10. 测试与验收要点

- **口径正确性（最高优先级）**：语义三态的判定必须覆盖本机实测的三类样本（纯包含文件、纯互斥文件、单文件混存），并用本机全量数据回归：正确判据命中率应落在 92.69% 附近；一律包含会得到 >100% 的荒谬值（作为反例断言）。
- **去重正确性**：相邻重复事件的丢弃逻辑需有黄金用例；断言「用 `turn_id` 去重」会产生错误结果（防回归）。
- **采集增量**：游标 + 尾指纹在「文件被外部截断/重写」时的行为需可测（参考实现有对应算法可借）。
- **时间窗正确性**：「近 5 小时」必须是**最近 5 个完整整点桶且不含当前小时**；跨整点时窗口整体前移一格；有测试断言「不做秒级滚动」。
- **环比正确性**：五档时间范围的「上一等长周期」边界需逐档断言（尤其 5h 的跨日回绕与自定义区间的等长前移）。
- **显示规范**：万/亿格式化（**不带单位 0 位、带单位恒 2 位**，见 P8 表；2026-10-06 用户裁决修订）、hero 千分位、命中率 1 位小数、时长三档，均需黄金用例（参考实现这套规则已被其测试钉死，可直接搬用例）。
- **UI 状态三态**：空态 / 加载态 / **错误态**（错误态必须可见且可重试，不得静默回落）。
- **缩放适配**：浮窗在小/中/大三档缩放下位置与字号等比、不越界、不加宽宠物窗口。
- **主题适配**：看板 / 记录页 / 浮窗 / 设置分组在浅色与深色下都需可读（断言关键颜色取自主题 token 而非硬编码）；分享图导出为固定浅色版式、不随主题变化。
- **写库不阻塞轮询**：需有测试或实测断言「一轮采集的任一事务不超过约定行数/时长」，且采集期间 3 秒会话轮询不被阻塞。
- **隐私白名单**：断言看板 / 浮窗 / 记录页 / 导出内容中不出现会话正文或密钥类字段。
- **性能**：采集不得进入 3 秒轮询路径；需有测试断言大看板/浮窗查询不触发全量扫描。
- **UI**：浮窗（含唯一可点元素「详情 »」与右键唤回）、大看板五档时间范围、记录页**两维度卡片分组（工具 / 项目）+ 固定的「供应商 / 模型」行维度**、导出（文本/图片/CSV）各需可验证的验收用例。
- **门禁**：`pnpm check`（format + lint + i18n 对齐 + build）与 Rust 侧 `cargo test` 全绿。
