# 移动端子 Agent 观察台 · 需求说明（第二批）

日期：2026-10-08 ｜ 状态：待用户审阅 ｜
前置：子 agent chip v1（`2026-10-08-mobile-subagent-chips-design.md`）已实现；
真机验收报告 `docs/release-notes/c3-subagent-chips-acceptance-2026-10-08.md`（甲/乙两部分）
为本批全部需求的事实底稿。

## 背景

chip v1 真机验收确认：出现、多卡并发、时长走字、token 增长全部符合预期；但**完成消失
环节失灵**——同一台机器上 Claude Code 存在**两套后台子 agent 机制**，v1 只读懂了第一套：

| | 经典机制（v1 依据） | teammate 机制（真机新发现） |
|---|---|---|
| 登记档案特征 | 无机制标记 | 带机制标记、带名字、编队名 |
| 完成信号 | 任务通知块（含编号） | 空闲通告（只有名字，没有编号） |
| 续跑方式 | 向编号发消息 | 向名字发消息 |

teammate 机制的子 agent 完成后，chip 收不到停止信号，一直挂着「走字」（验收实测：一枚
zombie chip 走了 25 分钟）。本批 = **修好完成识别**，并在修好的地基上补齐验收过程中衍生的
四个观察特性。

## 一、修复：完成信号的全面识别（真机验收 FAIL 项）

**功能要求**：

1. 系统识别两种机制并存，按登记档案自带的机制标记自动分派各自的事件格式，用户无感；
2. 经典机制行为不变（v1 已验证）；
3. teammate 机制：**完成信号 = 空闲通告**；因它只带名字不带编号，系统需按登记档案把
   名字与档案对应（名字→编号归一），完成与续跑两个方向都经同一对应关系；
4. 修复后的用户可见行为：teammate 子 agent **完成即从活跃区消失**（chip 消失、清单卡
   转灰冻结，见二），**续跑即重新出现**；与经典机制混跑互不干扰；
5. 两种机制都必须有用例锁定「完成即消失、续跑即复现」，防止将来任何一套格式再失明。

**边界**：机制的选择标准（何时走 teammate、何时走经典）由上游决定，本批不预测、只按
档案标记分派；档案里没有机制标记的按经典处理（与既有行为一致）。

## 二、子 Agent 清单（单一列表，按派发时间排列）

**功能要求**：

1. 会话详情的**文件看板**里新增「子 Agent」卡区，本会话派生过的子 agent 全部在同一份
   列表里：**按派发时间从上到下依次排列，新派发的附在名单末尾**——与桌面看板 zcode、
   dsh 的子 agent 排列惯例一致；
2. **卡片四要素**：Agent 的名字、它在做的任务（内容摘要）、运行时长、token 消耗；
3. **状态用圆点区分，列表不重排**：
   - **活跃**：卡片前**绿点**；时长与 token 持续更新（走字）；
   - **不活跃**（已完成/已停止）：卡片前**灰点**；时长、token 等数据**冻结不动**，
     保留在原位（按派发序不动、不折叠、不删除）；
   - 被续跑的：灰点转回绿点，从冻结值继续走字（时长从首次派发连续累计，不归零——
     与 v1 实测口径一致）；
4. **点击活跃 chip = 直接进入该子 agent 的实时预览对话框**（见三），不经过清单；
5. 点击清单内任一卡片（绿点或灰点）：活跃的进实时预览，不活跃的进定格快照（见三）；
6. **历史可回溯**：磁盘档案永久留存，应用重启后整份名单照常重建，无需新的落盘；
7. 本会话没有子 agent 时，卡区整体不渲染（不占空间）。

## 三、子 Agent 详情（实时预览对话框 · 逐步输出）

**功能要求**：

1. **进入方式**：点击活跃 chip 直达该子 agent 的预览对话框；点击清单卡片同样进入——
   活跃的进实时预览，不活跃的进定格快照；
2. 对话框位于预览空间（与文件预览同区域，支持同样的分屏/全屏布局切换），展示该
   子 agent 的**执行过程**：任务原文（首条指令）、思考过程（默认折叠）、工具调用与
   结果（折叠为单行，点开细看）、输出正文；
3. **活跃子 agent：逐步输出的界面**——对话框打开期间自动刷新（数秒一拍），输出内容
   随子 agent 的执行不断增长，视觉上呈流式滚动；关闭即停；
4. **不活跃子 agent**：定格快照（内容不再变化，时长/token 与卡片冻结值一致）；
5. 渲染与会话消息同一套视觉与交互（折叠、图片降级等），不另造一套；
6. 覆盖范围：Claude 全量；其余工具（opencode / kimi / codex）**清单照常**（见二），
   点入详情时明确提示「该工具暂不支持查看详情」——它们的转写格式尚未普查，
   留待后续批次（如实申报，不空白页也不假数据）。

## 四、子 Agent 回报提醒开关

**背景**：子 agent 完成回报会唤醒主会话、让会话卡转绿并弹提醒。有的用户需要这个提醒，
有的觉得吵——验收实测 7 条提醒里 4 条由子 agent 回报触发，其余是主会话自身动作，
两者可区分。

**功能要求**：

1. 设置页新增全局开关「**子 Agent 回报提醒**」，默认**开**；
2. 关闭后：仅滤掉「子 agent 回报导致」的提醒；主会话自身动作（如用户自己发了消息、
   主会话回合结束）的提醒**照常**——验收实证两者不会混淆；
3. 判定信号与修复项（一）的完成识别**同源**，不靠提示文案匹配——上游文案变化
   不影响判定；
4. 覆盖范围：v1 仅 Claude（判定证据齐）；其余工具如实申报「未区分」。

## 五、本批不做（非目标）

- 不向子 agent 发消息或操控它（属于注入域，另立设计）；
- 不动桌面看板的子 agent 计数徽标（已知旧布局失明问题，issue #134 单独跟踪）；
- 其余工具（opencode / kimi / codex）的详情视图与提醒判定，待各自的转写格式普查后
  另立批次。

## 六、验收清单（真机）

1. teammate 会话：起后台子 agent → chip 与清单卡出现（绿点）→ 完成后 chip 消失、
   清单卡**原地转灰点冻结** → 续跑 → chip 复现、卡片**灰点转绿继续走字**（时长连续）；
   双 agent 并发时一绿一灰同屏、各自独立更新/冻结，排列按派发序（新的在末尾）；
2. 点击活跃 chip 直接进入该子 agent 的实时预览对话框，输出逐步增长可见；
   不活跃卡片点开为定格快照；
3. 经典机制回归：既有行为不劣化；
4. 关闭「子 Agent 回报提醒」：子 agent 完成不再弹窗，其余提醒照常；重开恢复。

## 实施批次（2026-10-09 用户裁决：单批到底）

修复项（一）与全部特性（二/三/四）**一批做完**，在当前实现分支上顺序推进：
先修判据（地基），再做清单与预览（消费判据），最后做提醒开关（复用判据信号）。
每个任务独立提交、独立验收。
