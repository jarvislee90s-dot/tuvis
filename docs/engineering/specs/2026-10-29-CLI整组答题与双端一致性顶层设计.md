# 四 CLI 消息交互与双端一致性规范

适用于 Claude Code、Codex CLI、OpenCode、Kimi Code 的手机远程消息与交互链。分期、授权和原生优先遵循[项目总纲](../../MASTER-PLAN.md) D20、D22、D23。独立的工具规格定义每项操作实际可用的语义、平台、现行通道与证据。本规范用于跨工具的兼容底座 [#174](https://github.com/jarvislee90s-dot/tuvis/issues/174) 和消息链交付 [#188](https://github.com/jarvislee90s-dot/tuvis/issues/188)。

## 1. 共用交互契约

| 交互面 | 合同 | 权衡 |
| --- | --- | --- |
| 操作目标 | 从用户明确选择的原桌面会话识别原执行实例、会话、请求对象、规范目录及运行条件。目标不明时阻止写入 | 工具自有身份和能力保持独立，通用入口需提供逐工具错误状态，避免用目录或焦点猜执行者 |
| 准备和确认 | 草稿、未发送附件选择、切题、模式候选及清稿留在手机。发送、答题、审批等操作各自以用户对应的确认为交付边界。清稿的效果限于本地。撤回、取消、停止按不同能力处理 | 减少每步等待和桌面焦点竞争，提交时仍要重验目标、权限及字段规则 |
| 正式状态 | 正文、运行结果、待处理请求、已提交答案、真实生效模式和权限以原工具的可核对状态展示。原生通道使用已绑定接口、事件和可靠记录。实际终端注入通道遵循 D20 的屏读核验 | 可复用既有可靠读源，需区分不完整、未知、已受理和实际生效。允许页面、光标和未提交草稿在两端不同 |
| 队列和执行 | 每项只有一个派发者。尚未交付的本地队列由兔维斯管理，已交付的队列以原工具为准。显示停止、补充、排队、取消和继续的实际语义 | 维护本地与原生状态的映射，避免将本地撤回冒称上游撤回，或将某工具的控制语义推广到其它工具 |
| 异常和竞争 | 用动作 ID 和原目标只读核对丢回执或结果未知的动作。曾可能写出时保持原意图，禁止自动重发。用户在桌面先处理、手机先处理、同时竞争时均按实际结果收敛 | 部分动作可能长期显示待核对，保留证据与执行归属可避免两端重复决定或误判获胜者 |

## 2. 逐操作兼容和验收记录

查证粒度为工具 × 平台 × 启动形态 × 操作。记录会话绑定证据、所需契约、操作语义证据、实时可执行条件、实际执行通道、降级条件、阻断原因和已验证范围。定义的状态分别描述兼容性、当前可操作性及产品验收程度。例如答题契约可用但桌面已定案，界面只读取答案。版本和构建用于记录证据来源与有效范围，接口名称只能定位证据。原生欠缺的操作、已验证的终端能力及产品整体可用性分开统计。

覆盖接入、消息和工具结果、正文和附件、队列、运行控制、审批、整组问答、草稿、模式权限及恢复。原生专项开发和专测按 D23 隔离目标工具的旧通道。收官前逐项审核实际选用通道及有效证据。新增模型切换、通用远程终端与跨工具流转独立确定范围。

按操作分配可以延续已有产品能力，也要求复查不同版本与工具依赖。运行控制尤其需要记录验证的是会话级、回合级还是消息级语义。权限读取、权限修改和工作模式也各自举证。

## 3. 验收标准 / 测试要点

- 从正在使用的原桌面会话贯通状态读取、编辑、发送或排队、执行、审批或答题、正式结果及下一条消息。穿插模式／权限操作、桌面手动处理、前后台切换与异常恢复。单项通过只能结算对应场景。
- 覆盖同目录多会话、特殊启动、真实两端竞争、模式应用时点及已排队消息的行为。验证只读／未知回执、部分结果、断流补读、写前及写后断线、重启和旧代回执均与当时实际效果一致。
- 同条件对比本地编辑等待、确认等待、完整任务耗时和回到桌面的次数。记录采样环境、操作范围和产品入口。提速与安全降级分别评价，性能门槛按交付需求确定。
- 报告代码与自动化、真实协议及实际浏览器／用户终端的结果，注明只读、未测、受阻及不支持项，并记录是否依赖终端屏读。macOS、Windows 和各启动形态分别核对。
