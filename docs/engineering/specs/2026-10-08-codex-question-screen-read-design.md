## 1. 需求（REQ）

对照 claude / opencode / kimi 三家既有能力，codex 的问答链路存在六项缺口。本设计按一批补齐。

| REQ | 需求 | 验收标准 |
|---|---|---|
| **R1** 状态权威源 | codex 问答卡的卡面状态可由终端屏读纠偏（MAM 重启、页面刷新、终端手动作答后的漂移恢复），与宪法「卡面状态权威源=终端屏读」对齐 | GET 拉取问答载荷时附带终端当前题快照；卡面题号/未答数与终端一致；漂移场景刷新后纠偏 |
| **R2** 回执快照 | 每次远程作答动作的回执携带动作后的屏读快照（编排内置闭环核验），与其他三家同构 | select / 切题 / 自由作答回执含快照字段；核对不符时卡面回退屏读态 |
| **R3** 题屏解析 | 终端问答屏可被结构化解析（题号/总数/未答数/题干/选项/焦点），解析失败保守降级不猜 | 四场景（§4）全部可解析；未知形态第一次出现即自带失败证据（日志自报成因） |
| **R4** 多题切题 | 远程可切换题目（上/下一题），环形语义如实透传 | 切题到达验证 + 回执快照；单题弹窗切题如实回「无效」 |
| **R5** 提交闭环 | 「提交」为显式阶段且有屏读前置闸——全部答完的核对证据在手才发提交键（用户定案方案） | 末题提交前必有「未答清零」屏读证据；提交键永不在证据缺位时发出 |
| **R6** 探针与体检 | 永久只读活体探针（零注入），可对任意活会话输出「认识/不认识」体检清单 | 探针可跑四场景；输出解析器全产物 |
| **R7** 测试交付 | 四场景 × 三层（自动化回归 / 活体探针 / 手工验收清单） | §4 矩阵全部落地 |

**非需求（明确排除）**：多选题形态（工具不存在）；代答「未答完确认屏」（见 §3.6）；模式切换/审批链路（已有能力，本设计不动）；屏幕已选态的权威读出（见 §5.3）。

### 2.2 屏形规格

```
  Question 1/2 (2 unanswered)          ← 题号头
  Which DB?（单选）                     ← 题干（折行拼接）
                                        ← 1 空行
  › 1. Postgres (Recommended)     使用 Postgres 作为数据库。
    2. SQLite                     使用 SQLite 作为数据库。
    3. None of the above          Optionally, add details in notes (tab)
                                        ← 1 空行
  tab to add notes | enter to submit answer | ←/→ to navigate questions | esc to interrupt
```

| 元素 | 规格 | 证据 |
|---|---|---|
| **题号头（有未答）** | `Question {i}/{n} ({k} unanswered)`——题号 i / 总数 n / 未答 k（全局累计，答一题减一） | 〔截图〕两份逐字 |
| **题号头（全部已答）** | **计数段消失**：只剩 `Question {i}/{n}`——这是归零的可读信号 | 〔实测〕定案 |
| footer | 四段 `tab to add notes \| enter to submit {answer\|all} \| ←/→ to navigate questions \| esc to interrupt`；**v2.2 更正**：`all`↔`answer` 随「**是否存在其它未答题**」切换，**不是末题信号**（S1 实测：Q2 未答时即使当前题已答也是 `all`；末题判定以题号头 i==n 为准，footer 不互验）；`←/→ to navigate questions` 段**仅多题渲染**（单题三段无此段——底料 §7） | 〔截图〕+ 底料 §7 更正 |
| 选项行 | `{缩进}(› )?{N}. {label}{对齐空格}{描述}`；`›` 前缀标记**当前选中/焦点行**（源码按 selected 渲染前缀；「焦点记忆」与「选中标记」两解释对编排无行为差异，留一个拆分实验 §6）；描述列动态共列、按双空格剥列 | 〔截图〕+〔源码〕 |
| **未答完确认屏**（新形态） | 标题 `Submit with unanswered questions?` + 选项「Submit with N unanswered」/「Return to the first unanswered question」——**仅在未答完时按提交才出现**；全部答完的提交**无任何确认**（1–3 题均如此，只看计数不看题数）。**v2.2 实测降级**：0.160.0 活体取证**未复现**该屏（末题含未答题回车 = 直接交卷，answer 记焦点项——底料 §3 S2）；词形转**unverified**（设计/源码在档构造，账本行 evidence 如实登记），保留为防御性检测（命中即中止不代答）；复现登记为版本复验触发点 | 〔源码〕+ 底料 §3 S2 降级 |
| 已提交摘要（正文回显） | 提交后弹窗收起、正文出现汇总块：`Questions {n}/{n} answered` 头 + 逐题回显（题干 / `answer: {选项}` / 可选 `note: {文本}` 并列）——终态正向锚（头行）+ 落账对账面（rollout `answers` 与 `user_note:`，戊探C 在档） | 〔实测〕汇总逐字 + 0.155.1 在档 |
| 面板形态 | 无边框线深色面板；上下界锚 = 题号头与 footer；旧面板滚出时旧题号头+footer 成对残留 → 解析必须**取最后一对**（last-pair-wins） | 〔截图〕 |

### 2.3 键序语义规格（定案表）

| 键 | 语义 | 证据 |
|---|---|---|
| 数字 `1..9` | **选中该项并直接进入下一题**；行为 ≡ 「高亮该项 + 回车」。末题上 ≡ 「选中 + 整卷提交」（**故末题编排禁用数字**——选中与提交耦合，无屏读闸插入点） | 〔实测〕定案 (1)(7) |
| `↑`/`↓` | 移动焦点行；**上下均环绕**（末项↓回首项、首项↑到末项）。**注入通道更正（v2.2）**：↑/↓ 语义由用户真键盘定案，但 VT 序列（ESC[A/B）与真 VK 箭头**对 codex 面板注入全部无效**（底料 §1 多帧 dump）——MAM 编排走位用 **vim `j`/`k`**（字符形态注入已验证），语义同构 | 〔实测〕定案 (3) + 底料 §1 更正 |
| `空格` | **仅选中**焦点行（不推进）；未答计数 −1；**对已选中项 = 反选**（未答计数 +1）——toggle 语义。**已答换选非原子（v2.2 消歧）**：已答题上焦点在**非已选项**时空格 = 清掉旧选中（计数 +1）、新项未选中——「换选」是多拍净效果而非单键原子（底料 §3 #5 dump 链）；焦点在已选项本身上的空格行为待消歧（验收批 b5 对照：计数未重现）。编排裁定：已答 ∧ 焦点≠目标 → 零键中止不代答 | 〔实测〕定案 (5) + 底料消歧 |
| `→` / `←` | 切下一题 / 上一题；**环形**（末题→回首题、首题←到末题）；切题后已答题焦点落在已选项、答案保留；单题上无任何效果。**注入通道更正（v2.2）**：同 ↑/↓——MAM 编排切题用 **vim `h`/`l`**，语义同构 | 〔实测〕+ 底料 §1 更正 |
| `回车`（非末题） | 选中焦点行**并进入下一题** | 〔实测〕定案 (10) |
| `回车`（末题） | **整卷提交**，无确认（全答完时）；未答完时先入未答完确认屏（§2.2） | 〔实测〕定案 (7) +〔源码〕(11) |
| `tab` | **全局键**：任何焦点状态（含已用空格/数字选中某项后）都可按 tab 进入当前题的 note 填写；TUI 自动确保焦点行选中（源码 ensure 逻辑）。**note 与 answer 并存**——note 不替换选项答案，两者一起进入答案汇总（实测汇总中同一题 `answer:` + `note:` 并列） | 〔实测〕更正 +〔源码〕 |
| notes 态 `回车` | 提交输入；**末题/单题上连带整卷提交** | 0.155.1〔实测在档〕，0.160.0 留复验 |
| notes 态 `esc` | 取消输入回到选项 | 〔实测〕 |
| 弹窗态 `esc` | 中断（MAM 不主动发） | 旧档 |

**换选路径**（由上表推导，(5) 定案）：数字选错已推进 → `←` 切回该题（焦点在已选项）→ 走位到新目标 → `空格`（旧选自动被替换，单选互斥；互斥原子性留一次实验核验 §6）。**v2.2 更正**：底料 dump 证明单次空格对已答题是「清旧选（计数 +1）」而非原子换选——远程换选路径按「已答 ∧ 焦点≠目标 → 中止」收缩（不冒进多拍编排）；换选请到终端人工完成。

### 2.4 状态模型

```
[题屏：第 i/n 题] ──数字/回车──> [题屏：第 i+1 题]          （非末题）
[题屏：末题] ──回车（k=0）──> [已提交：摘要头，弹窗消失]
[题屏：末题] ──回车（k>0）──> [未答完确认屏] ──esc/回退──> [第一个未答题]
[题屏] ──tab（任意焦点状态；TUI 自动确保焦点行选中）──> [note 输入] ──回车──> 提交/推进
[题屏] ──←/→──> [题屏：环形邻题]
```

## 3. 系统行为规格（输入 → 行为 → 输出）

### 3.0 通用规则

- **每动作 = 发键前读屏闸 + 发键后核验**（屏读为准原则）；任何闸不符 → 中止零键、回执带成因（区分「读不到屏」与「屏在但形态不符」，后者附屏面摘要）。
- 提交类不可逆动作（回车 on 末题）**必须**有前置屏读证据（R5）。
- 全链路读屏走既有屏读通道；发键走既有注入通道（B 族键形态不变）。

### 3.1 GET 初始化纠偏（R1）

- **输入**：会话挂载 / 状态跃迁为问答等待。
- **行为**：读终端屏 → 解析题号头与面板（§2.2）；成功产出快照，失败降级 null。
- **输出**（wire 快照，字段为**输出契约**，类型实现留计划）：

```json
{ "questionIdx": 0, "questionTotal": 2, "unanswered": 2,
  "isLast": false, "heading": "Which DB?", "options": ["Postgres", "SQLite", "None of the above"],
  "focused": 0 }
```

- 前端消费：卡面题号 ← `questionIdx`（**题号对位**，不依赖题干文本匹配）；未答数提示 ← `unanswered`；本地已选记忆作乐观显示照常、快照不覆盖该面（与 kimi 同口径）。

### 3.2 单选作答 · 非末题（R5）

- **输入**：作答请求（载荷题号 q_idx、目标选项 index）。
- **行为**：
  1. 读屏闸：题号 == q_idx+1（记未答基线 k_base）；
  2. 发数字 {index+1}（定案：选中+自动推进）；
  3. 轮询核验（窗尽才判未变）：题号变为 q_idx+2 **且** 未答数 == k_base−1 → 完成（新答）；**窗尽未推进** → 复核仍读 q_idx 后**重发数字**一次再核验（定案 #1：数字=选中+推进**原子**，i 未变 ⟹ 数字被吞、该题未答——**不得补 →**，那会跳过未答）→ 仍未推进 → 中止「数字未生效，请核对终端」；**题号到位而计数未减** = 该题进闸前已被答（漂移/手动作答）→ 改答成功，回执标注 `reanswered`；
  4. 漂移分支：进闸时该题已被手答（基线已含）→ 数字后题号推进、计数不变 = 改答成功（回执标注「改答，未核持久」——换选语义核验见 §6；定案 #1 下「数字被吞但题号推进」不可达，无需补发数字复核路径）。
- **输出**：回执 = 键序 + 到达帧快照（§3.1 形状）。

### 3.3 单选作答 · 末题与单题（R5 核心）

- **输入**：作答请求（目标选项 index）。
- **行为**（末题一律**禁数字、禁回车做选中**）：
  1. 读屏闸：题号 == n/n（footer `submit all` 段互验）；
  2. 走位：读 `›` 焦点行 → 逐键 `↑`/`↓`（**可用最短环绕方向**）→ **每步复读核验到位**（不批量盲发——选中态若错，归零闸发现不了「选错了谁」）；有界（选项数 + 2）；读不到焦点 → 中止不猜；
  3. **已答特判**：焦点已在目标行（改答同项）→ 跳过空格；已答但目标不同 → 走位 + 空格；
  4. 发 `空格`（仅选中，不推进）；
  5. **归零闸（双验）**：轮询题号头**计数段消失**（k=0 定案词形）**且** `›` 焦点仍在目标行（选中不改高亮位——若取证 §6 相反则本半句回退为仅计数）——未归零窗尽 → 中止（可能空格反选了已选项，如实报）；
  6. **提交双条件闸**：题号头在场 ∧ 计数段消失 → 发 `回车`（显式提交整卷）；**题号头已不在场（弹窗已消失 = 已被提交，如 notes 回车连带交卷场景）→ 零发键**，直接转终态核验按「已交卷」处置；
  7. 终态核验：已提交摘要头在场（`Questions {n}/{n} answered`，正文回显块的头行，§2.2）∨ 面板双锚消失 + 会话推进；落账对账（rollout answers / user_note）为回归测试面。
- **输出**：回执 = 键序 + 提交前末帧快照（与 3.2 的「到达帧」语义分别标注，前端消费点不同）；读屏失败 → 快照 null 如实。
- 单题（n=1）：同本路径直达（无切题面）。

### 3.4 自由作答（Other 行 note）（R2）

> **v2.2 取证回填：本节远程编排整体收缩为具名中止。**
> 0.160.0 活体取证（底料 §5）：notes 态打字后回车，**notes 文本不随卷提交**——摘要 `answer` 落在焦点行（打字后焦点跳回第 1 项），用户文本静默丢失；净效果 = 「把焦点行提交为答案」。任何远程代答编排都会静默丢弃用户输入，违反屏读为准与「不假装能发」纪律。
> **实施形态**：`free_text_supported("codex") = false`；`StagePlan::CodexFreeTextRetired` 零注入零读屏，回执具名中止（「codex 自由作答（Other/notes）经实测不能安全代答：备注文本不会随卷提交（回车会把当前高亮项当作答案提交）。请到终端直接作答」）；GET 旗标 `multiFreeText`/`freeTextOverwrite` 对 codex 收 false（前端不渲染入口）。既有 `run_codex_notes_stages` 编排保留备用（复活前须按版本复验）。
> **验收批 F1 对照**：验收批 notes 态回车摘要出现 `note: ...` 行（底料「不落卷」未复现——可能焦点宿主差异），两批合读不定案；**「notes 文本去向 + notes 态回车交卷事件」登记为版本复验触发点**，零注入具名中止在两种解读下都安全。

- **输入**：自由作答请求（文本；覆盖/清空语义旗标）。~~以下为 v2.1 原编排设计，v2.2 起停用留档~~：
  1. 走位到 Other 行（`None of the above`，按屏上实读定位，不假设恒在）；
  2. **直接发 `tab`**（定案更正：tab 为全局键，任意焦点状态进 note 填写；TUI 自动确保焦点行选中——无需先发空格。注意副作用：焦点行未选中时 tab 的自动选中使计数 −1，编排按读屏核验而非假设）；
  3. 覆盖模式先清空 → 打字 → 发 `回车`；
  4. **回车后的分叉**（末题/单题连带整卷提交 vs 仅提交本题——0.160.0 留复验 §6-A）：按读屏分派——题号头消失 = 已交卷 → 终态核验零发键；仍在题屏 → 走 §3.3 步 5–7（归零闸 + 双条件闸 + 显式提交）；
  5. note 态 `esc` = 取消输入（中止场景零键回执）；
  6. **note 与 answer 并存语义**：note 不替换选项答案——用户「已选某项 + 补 note」的请求按 [选中路径（§3.2/§3.3）+ note 路径（本节）] 两段编排，汇总中 `answer:` + `note:` 并列（实测）。
- **输出**：回执 = 键序 + 终态快照 / 中止文案。

### 3.5 多题切题（R4）

- **输入**：切题请求（方向）。
- **行为**：发 `←`/`→` → 轮询题号头变化即停 → 回执快照。单题 / 轮询窗尽未变 → 如实「未生效，可重试」。环形语义透传前端（无边界禁用，卡面标注环形导航）。**v2.2 注入通道更正**：MAM 编排实际发 **vim `h`（上一题）/`l`（下一题）**（箭头族对 codex 面板无效——底料 §1）；到达验证用基线变化轮询（陈旧帧不误判）。前端环形透传已落（advance 回执 `screen.questionIdx` 直读对位，末题 ▶ 环回首题时卡面跟回第 1 题）。
- **输出**：回执 = 方向 + 到达题快照。

### 3.6 异常与中止行为（闸门矩阵）

| 异形 | 处置 |
|---|---|
| 未答完确认屏（`Submit with unanswered questions?` 在场） | **中止不代答**（出现在 MAM 面前 = 前序动作已错位），回执点名该屏，请终端人工处置 |
| 读不到屏 / 面板锚不在场 | 中止零键；区分「读不到」与「形态不符」（后者附屏面摘要） |
| 滚回区残留面板（多对题号头+footer） | 解析取最后一对（last-pair-wins）；夹具锁 |
| footer / 锚词形漂移（版本升级） | 锚词表 append-only 吸收；查不到时报错点名候选与本机版本 |

### 3.7 回执契约汇总（R2）

所有动作回执统一携带：动作类型 / 发出的键序（**走 endpoint 审计日志**——三家既有机制，wire 不重复携带）/ 终态（成功·中止·失败三分类，中止带段名与成因）/ 快照（成功与中止可带，失败不带）。快照形状见 §3.1；**快照承载的容器选型（类型统一）留实施计划**，但契约要求：codex 快照字段集与 claude/opencode 不同，承载方案不得迫使 codex 降级为无快照（kimi 先例教训）。

## 4. 场景验收规格（S1–S4 × 三层交付）

**多选场景废除**（§2.1 工具无此形态）。

| 场景 | 形态 | 预期行为（验收点） |
|---|---|---|
| **S1 两题全单选** | Question 1/2 → 2/2 | 非末题：数字+推进核验；末题：走位逐步复核+空格+归零闸+双条件提交；GET 题号对位；切题 ←/→ 环形 |
| **S2 三题上限** | 1/3 → 3/3 | 上限边界；环形交叉（末→首）；footer `all` 仅在 3/3 |
| **S3 单题** | Question 1/1 (1 unanswered) | 单题路径（走位+空格+归零+提交）；←/→ 如实「无效」 |
| **S4 Other 自由输入** | 单题或 S1 变体 | 走位 Other + **tab 直接进输入**（全局键，TUI 自动确保选中——§3.4）+ 输入 + 回车分叉处置；覆盖/清空；esc 中止零键；「已选某项+补 note」复合请求（answer+note 并存） |

三层交付：
1. **自动化回归**：四场景活体屏形逐字入档（取证批自建会话采集）+ 解析断言 + 编排驱动断言（假终端：键序逐键、闸门触发、中止路径、**推进主路径与键丢失兜底双驱动**（数字自动推进为主路径、键丢失补 → 为兜底路径，两者都要有驱动用例）+ 滚回区残留 + 已答改答分支）。
2. **活体探针**：只读探针对自建会话四场景逐屏输出「认识/不认识」体检表（含未答完确认屏、摘要头两个新屏形的识别）。
3. **手工验收清单**：每场景 × 六核对点（出卡/点选/切题/末题提交/漂移恢复+续答/重启恢复），S4 追加 notes 链与 esc 中止。

## 5. 边界、降级与风险

1. **末题数字 = 选中+整卷提交**（定案）——编排禁用数字与回车做选中，唯一提交出口 = 双条件闸后的显式回车。
2. **未答完确认屏是「编排已错位」的信号**——MAM 永不代答；它的存在使「证据缺位就发提交」的后果从静默错交变成可拦截，但闸门设计仍以前置证据为准。
3. **已选态不权威读出**：卡面本地乐观显示照常，快照不覆盖（与 kimi mqSelected 同口径）；`›` 前缀的「焦点 vs 选中标记」语义两解释无行为差异（§6 留拆分实验）。
4. **footer 两度换词前科**（0.155→0.156.1 权限菜单事故）——锚词表 append-only + 版本复验纪律（AGENTS.md 触发③）。
5. **Other 按题开关**——编排按屏上实读定位，不假设恒在。
6. **取证失败降级**：若任一 §6 余留项取证结果与本规格冲突，以取证回填规格后再实施对应段——规格不超证据。

## 7. 实施批注（决策备忘，细节留实施计划）

- 解析器与快照并入既有「非 claude 方言解析」文件（kimi 同居先例），不新建文件。
- footer / 摘要头短锚进既有**锚词账本**（append-only 候选全集试匹配）；题号头为含数字结构锚，不进账本、正则参数化（计数段可选）。
- 回执快照承载容器选型（codex 字段集 ≠ claude）在实施计划定案，契约要求见 §3.7。
