## §1 Claude Code 标杆机制全清单

claude 的问答交互（AskUserQuestion）目前拥有八层机制，是四家中唯一全链闭环的：

### 1.1 屏读机制（读的一面）

| # | 机制 | 落点 | 说明 |
|---|---|---|---|
| R1 | **可见窗逐行屏读** | `windows_console::read_screen_window` | 整窗 ReadConsoleOutputCharacterW，多行块（含选项簇/页签/底栏），A 族通用 |
| R2 | **题屏行块解析（双锚）** | `question.rs::parse_question_rows` | 锚 A=最靠后推进行（Submit/Next）向上收连续编号块；锚 B=页签栏向下收（多题流单选子题无推进行时的兜底）；产出 `QuestionRow{number,label,checked…}` |
| R3 | **题屏快照协议** | `question_screen_snapshot` → `{heading, checked[], freeText, freeTextPresent}` | 每次交互动作的**回执**与 **GET 载荷**统一携带——「卡面状态权威源=屏读」，前端对位纠偏（mqIndex/勾选/输入框），快照失败保守维持本地状态 |
| R4 | **Review 确认屏判别** | `probe_review_screen` | 更特异判据优先：确认屏在场 → 快照转 `{review:true}` → 前端直接进确认卡 |
| R5 | **输入行尾读** | `read_input_tail` | 光标处同行向前读——滞留草稿确认、插队草稿核验 |
| R6 | **锚点账本** | `anchor_ledger`（append-only，scenario×slot×文案×证据） | 终态回执锚 / Review 锚 / 忙态锚 / 队列提示锚 / 计划批准框锚——文案漂移由账本吸收，KV 可覆盖 |
| R7 | **回合忙/闲稳定闸** | `confirm::poll_turn_stopped`（忙锚连续 2 拍缺席） | 单帧不可信（重绘瞬态），稳定闸才算数——发送/插队共用 |

### 1.2 交互机制（写的一面）

| # | 机制 | 键序要点 | 屏读闭环 |
|---|---|---|---|
| I1 | **单选 select** | 屏上编号数字单键即选即交（K1）；焦点在自由作答行时先 ↑ 摘离（焦点守卫） | 定位后重读复核行仍在场 |
| I2 | **多选 toggle** | 数字直选自适应探测（数字在多选屏=toggle 不切页）→ 失败回退方向键**逐步走位复核**（每步核验位移恰 1 行）→ **空格**切勾 → 屏读核验翻转 | 全链闭环 |
| I3 | **提交 submit** | 走位到 Submit 行 → enter 进 Review → 屏读确认 Review 屏 → 抄屏上编号确认 → 终态回执锚核验（`User answered Claude's questions:`） | 全链闭环 |
| I4 | **切题 advance** | ←/→ 双向导航（navBoth），末题直达 Review、Type something 行先 ↑ 先决；opencode 仅有 tab 前向（会回绕） | 阶段机推进 |
| I5 | **自由作答（单选卡）** | 定位 `N. Type something` 行 → 发定位数字（仅移焦点不提交）→ 重读复核 → 打字 → enter 提交 | 打字前守卫复核 |
| I6 | **自由作答（多选/多题内联编辑）** | 直接在勾选行打字 = 内联编辑（勾选自动置上）；enter 会取消勾选 → 编排**零后续键**；覆盖写入 = 先退格清空再打字；清空 = 空文本+overwrite | 屏读回执带 text/checked 真值 |
| I7 | **能力位协议** | `answerable / freeText / multiQuestion / advance / navBoth / multiFreeText` | 前端按旗标渲染，旧后端缺字段前向兼容 |
| I8 | **销卡/建卡双通道** | 通道 A=钩子标记（question_wait_marks，tool_input 随标记落库）；通道 B=尾部形态扫描（兜底） | 与审批标记互斥（硬约束①） |

### 1.3 横切纪律（比任何单一机制都重要）

- **每步复核、不盲发**：凡是移动焦点/切勾的键，发完必屏读确认落点（D20 时序三窗+命中即停是同一哲学）；
- **不猜起点**：需要「当前位置」的编排（导航步进），解析不到唯一锚点就拒绝出手；
- **裸打字守卫**：任何打字前必须有屏读证据证明「输入行已开启」——裸打字会被当导航/勾选指令（戊探A §4 实锤）；
- **首错即停**：序列中途失败不盲目重发全序列（已发键已生效）；
- **中止带屏面摘要**：失败回执区分「读不到屏」vs「屏在但形态不符」，后者附摘要——未知形态第一次出现就自带证据（四闸门 2）；
- **审计不落正文**：自由作答内容只记字符数占位。

## §3 复用分类结论

### 3.1 可直接复用（机制本身工具无关）

1. **屏读原语层**（R1/R5/R7）：read_screen_window / read_input_tail / 稳定闸——四家同宿主（A 族×3 + B 族×1）全部可用；
2. **锚点账本**（R6）：append-only + 证据字段 + KV 覆盖——新增工具只是加行，不动机制；
3. **横切纪律**（§1.3 全部）：每步复核/不猜起点/裸打字守卫/首错即停/中止带摘要——这是 claude 全链可靠性的来源，推广时**逐家逐字执行**；
4. **能力位协议**（I7）：旗标向量 + 前向兼容（缺字段按 false）——新能力加位即可，前端零破坏；
5. **卡面权威源=屏读**原则（R3 的原则面）：任何交互回执都应带落点证据；
6. **双通道建卡/销卡**（I8 的结构）：钩子优先、形态扫描兜底——codex/kimi/opencode 已按各自存储形态落地同构通道。

### 3.2 需参数化适配（同一机制、方言不同）

把 claude 阶段机的**骨架**保留、把**动词**抽成方言表（per-tool dialect）：

| 方言槽 | claude | codex | kimi | opencode |
|---|---|---|---|---|
| `row_granmar` 行语法 | `N. [ ] label` | `N. label`（request_user_input） | `[N] label`（Other 多选无编号） | `N. [v] label`（`[v]`/`[ ]`） |
| `toggle_verb` 勾选动词 | space | space（未取证） | 数字（Other 之外不适用） | **enter**（且已勾选时双 enter=取消→再勾） |
| `edit_gate` 编辑门序列 | （无门） | tab | 数字定位 | enter ×{1\|2}（按勾选态） |
| `save_verb` 保存动词 | enter（=提交整题） | enter（=提交） | enter（=提交） | enter（=仅保存，推进另发 tab） |
| `cursor_after_edit` 光标位置 | 行内（claude 直接打字） | — | — | **末尾**（追加型；覆盖需退格） |
| `advance_verb` 切题 | ←/→ 双向 | Ctrl+P/N（未验） | tab/←→（未验） | tab 单向前向（回绕） |
| `submit_flow` 提交流 | Review+编号 | 即交/确认弹窗 | Review+[1] | tab→Confirm→enter |
| `receipt_anchor` 终态锚 | 账本行 | 账本行 | 账本行 | 账本行 |

### 3.3 需要为其他家补齐的（claude 有、他家缺）

按价值排序：

1. **opencode 快照回执**（缺口最大）：OpencodeOwnAnswer/Submit 的 `screen_text/screen_checked` 恒 None——把 claude 的 R3 快照协议移植：行块解析器已能读 `[v]/[ ]`（本次 toggle 语义实现已依赖它），补 `parse_question_rows` 的 opencode 方言（`N. [v] label` 行语法 + footer `⇆tab…` 推进行锚）→ 回执与 GET 带快照，前端卡面对位/纠偏即刻同权；
2. **opencode 走位复核**：现 ↓×(pos-1) 盲走（高亮字符层不可见）——升级为 claude 式逐步复核不可能（无可见高亮），但可用「选项行内容不变化」弱校验 + 行数/编号核验（读屏确认行仍在、编号未跳变）；盲走边界已登记，此处是**降险**不是消除；
3. **kimi 多选形态取证 + 自由作答快照**：`[3] Other` 已定案（戊探B E-B8），多选 Other 无编号已登记；补多选 toggle 键与 Review 交互的实机样本后即可参数化接入同一骨架；
4. **codex 实机键击复验**：0.155 源码键位 vs 实机一致性（矩阵 §2.1 的 GO 带复验条件）——relay 修复后 30 分钟快路径；notes（Tab 备注流）已实现，需补快照回执；
5. **各家清空/覆盖写入语义统一**：目前 claude/opencode 有、kimi/codex 无——按「光标位置方言」参数化后补齐（kimi Other 数字定位后光标形态需探）。

## §4 通用机制抽象设计（下一阶段的实现蓝图）

> 原则：**骨架一次写对，方言以数据登记**。新工具接入 = 填一张方言表 + 补账本行 + 探测定案，不再新写阶段机。

### 4.1 方言表（`QuestionDialect`，数据而非代码分支）

```text
QuestionDialect {
  // 行语法
  row_regex:        编号/勾选框/标签 的解析规则（复用 dialog::parse_option_line 扩展勾选段）
  checkbox_markers: { checked: ["[v]","[x]","[✓]"], unchecked: ["[ ]"] }   // opencode 有、claude/kimi 无勾选段
  own_answer_label: "Type your own answer" | "Type something" | "Other"
  // 动词
  toggle_verb:      space | enter_toggle{ recheck: true }   // opencode enter=toggle 且已勾选时双 enter
  edit_gate:        none | { keys: ["enter"], recheck: row_unchecked_then_open }
                             | { keys: ["enter","enter"], when: checked }
  clear_verb:       backspace_from_end{ cursor: end } | right_then_backspace{ cursor: start }  // opencode vs claude
  save_verb:        { key: "enter", advances: bool }   // opencode advances=false（仅保存）；其余 true
  advance_verb:     both_arrows | tab_forward | walk_next_enter
  submit_flow:      review_confirm{ anchor } | direct | tab_confirm{ footer_anchor }
  receipt_anchor:   账本 (tool, QUESTION, RECEIPT)
  highlight_visible: bool   // claude/kimi 可见（❯/→）；opencode 不可见 → 走位复核降级为弱校验
}
```

### 4.2 通用阶段机骨架（`generic_question_stages`）

以「状态 + 判据表」驱动，替代 per-tool 函数堆：

```text
locate_row(dialect, screen) -> RowRef            // 标签行 → 末编号行回退（本次 opencode 已实现该策略）
walk_to_row(row, highlight_visible)              // 可见=逐步复核；不可见=盲走+弱校验（登记残余）
open_edit(dialect.edit_gate, row_state)          // 逐键屏读复核（toggle 落点复核已在本次 oc 实现中落地）
clear_if_needed(overwrite, saved_len, dialect.clear_verb)
type_text(text)                                  // 裸打字守卫前置
save(dialect.save_verb)                          // advances=false 时停在保存态
verify(receipt_anchor | snapshot_delta)          // 终态锚 / 快照差量核验
receipt { sent_keys, screen_text, screen_checked }  // ← 所有工具统一带屏读回执
```

claude 现有六台阶段机（select/toggle/submit/advance/freeText/multiFreeText）与 kimi/codex/opencode 的对应机，逐步收敛到该骨架的方言实例；**迁移一批、回归锁一批**（既有键序脚本锁就是回归资产）。

### 4.3 快照协议推广（`QuestionScreenModel`）

- `parse_question_rows` 增加方言参数（行语法/勾选标记/推进行锚），产出统一 `QuestionScreenModel`；
- GET `/session-question` 的 `screen` 字段与各 action 回执的 `screen` 字段对四家开放（当前 claude-only）；
- 前端对位逻辑（heading 匹配→勾选纠偏→freeText 回填→Review 进确认卡）零改动直接复用——它消费的是统一 schema；
- 「快照失败保守维持本地状态」「不假清不假同步」原则照抄。

### 4.4 能力位协议演进

现有六旗不变，新增按需扩位（每旗：后端按方言+取证状态给值，缺字段=false 前向兼容）：
`multiFreeText`（本日已加）→ 后续可能的 `overwrite`（覆盖写入支持面）/`snapshot`（快照可用面）——**旗标即取证状态的声明**，未取证不出手。

### 4.5 红线继承清单（推广时逐字带走）

对话框在场=控制类注入红线（blocks_control_injection）｜不猜起点｜裸打字守卫｜首错即停｜中止带屏面摘要｜审计不落正文｜探测八条铁律｜锚文案禁止手造｜结论不超证据。
