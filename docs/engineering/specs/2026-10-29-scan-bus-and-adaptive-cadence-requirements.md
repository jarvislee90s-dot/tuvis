# 扫描总线与自适应节奏 · 需求说明书

- 日期：2026-10-29
- 分支：`design/scan-bus-and-adaptive-cadence`（基于 `origin/main` @ `5a53b9a7`，v0.6.3）
- 状态：待评审

## 1. 背景与目标

### 1.1 现象（2026-10-29 实测，安装版 0.6.3）

| 指标 | 现状 |
| --- | --- |
| 空闲 CPU | 11.2% 单核（45s 采样 5.05 CPU-s） |
| 全量扫描频次 | 56–61 次/分（≈1.05s 一次） |
| 单轮成本 | ≈0.1s CPU，其中进程刷新 44–57ms（466 进程） |
| 用量采集 | 只在模型用量页激活时每 10 分钟一次；切走即停（实测滞后 4.5 小时） |
| 扫描发起方 | 后端 watcher 2s、桌面主窗 3s、桌宠 3s、手机 REST（含配对计数 `System::new_all()`）各自触发 |

### 1.2 目标（量化）

1. 空闲 CPU 降到 **≤3% 单核（挂机）/ ≤6%（远控在线但无活跃会话）**；
2. 全量扫描降到 **≤30 次/分（有活跃会话）/ ≤6 次/分（挂机）**；
3. 远程时效不回退：活动档会话发现 ≤2s，动作回执 p95 不劣于基线；
4. 用量数据"看得见时 ≤1s、看不见时 ≤10 分钟"，不再依赖用户切页。

## 3. 功能点

### F1 单一扫描器与共享快照

**1. 我需要做什么**

- 后端只保留**一个**扫描者，产出"带版本号 + 扫描时刻 + 健康状态"的共享快照；
- 桌面主窗、桌宠、手机、托盘、通知、远控 watcher 全部读同一份快照，不再各自触发全量扫描；
- 扫描单飞（同一时刻只跑一次）与崩溃自愈由扫描器统一负责。

**2. 技术选型（方向）**

- Rust 常驻后台任务（沿用现有 tauri/tokio 运行时），`Arc` 快照 + 单调递增 `version`；
- 现有单飞护栏从命令层下沉到扫描器；保留 panic 清位护栏；
- 增加看门狗：扫描循环 panic/退出后可自动重建（对齐现有 watcher 的自愈思路）。

**3. 验收条件**

- 同一时刻的并发请求只产生 1 次全量扫描（用日志计数验证）；
- 主窗与桌宠在同一时刻读到相同 `version`；
- 人为 panic 扫描任务后 ≤30s 自动恢复，看板不冻结；
- 冷启动首屏不返回空会话（保留"无快照时同步扫一次"的旧语义）。

---

### F2 自适应节奏（2s / 10s / 30s）

**1. 我需要做什么**

- 扫描间隔由三个信号决定：**活跃会话**（processing/thinking/compacting/waiting）、**远控在线**（SSE 连接或最近 60s 有 API 请求）、**有人在看**（主窗可见且聚焦 / 桌宠迷你条展开 / 远控在线）；
- 档位：`Active 2s`（仅活跃会话触发）、`Idle 10s`（远控在线或有人在看但无活跃会话）、`Away 30s`（三者皆无）；
- 升档立即生效，降档稳定一个周期后才切换（防抖）；档位切换要有可观测日志。

**2. 技术选型（方向）**

- 节奏状态机放后端（纯函数、可单测），前端只消费当前档位；
- 档位与版本随会话响应一起下发，Tauri 事件仅作"立即重取"的加速通道（事件无重放，不能作为唯一来源）。

**3. 验收条件**

- 全空闲（挂机）连续 10 分钟：扫描 ≤6 次/分、CPU ≤3% 单核；
- 远控在线但无活跃会话：扫描 ≤10 次/分、CPU ≤6% 单核；
- 活跃会话期间：会话发现延迟 ≤2s；
- 档位切换日志只在切换时出现，不逐轮刷屏。

---

### F3 动作路径的新鲜度保证（ensure_fresh）

**1. 我需要做什么**

- 所有**动作路径**（远程发送、打断、问答 GET、恢复、会话归属查询、新建会话校验）不得直接读可能过期的快照；
- 快照龄超过阈值（2s）时在扫描器单飞内补扫并等待，等待上限 3s；超时返回旧快照，并在 `scan_bus_status` 诊断接口标记 `degraded` 与 `snapshotAgeMs`（不扩展动作回执协议），不得伪造成功。

**2. 技术选型（方向）**

- 扫描器提供"保证新鲜"的补扫入口（带超时），补扫必须复用同一把单飞，禁止另起第二份快照；
- 沿用现有"失败如实申报"的原则，不吞错误。

**3. 验收条件**

- 新建会话后立即从手机发送消息：成功率与改造前一致（≥20 次实测全成功）；
- 补扫超时场景返回 `degraded`（`scan_bus_status` 可查）且日志可查，不出现"假成功"；
- 动作路径的补扫与周期扫描不会并发产生两份快照（version 单调、无回退）。

---

### F4 消费方改造

**1. 我需要做什么**

- 桌面主窗/桌宠：读取间隔跟随档位；窗口重新可见/聚焦时立即刷新一次；
- 手机看板：**维持现状**（SSE 跃迁 + 30s 对账，REST 仅降级/首连），REST 改为读快照；
- 手机配对计数：并入扫描器快照，或自带 ≥10s 限频（现状是每请求一次全进程刷新）；
- 托盘：快照版本变化时更新，最小间隔 30s；状态跃迁立即更新；
- SSE `/events` 首帧：快照龄 >2s 时先补扫再发，并携带版本号供对账。

**2. 技术选型（方向）**

- 前端沿用现有查询层，只调整间隔来源（跟随档位）；
- 托盘/SSE/手机均消费同一份快照，不新增独立扫描；
- 事件通道只做加速，状态一致性以版本号为准。

**3. 验收条件**

- 手机看板行为与改造前一致（跃迁秒级到达、30s 对账兜底）；
- 配对计数不再触发独立全进程扫描（日志可证）；
- 托盘状态跃迁 ≤2s 反映；周期刷新不超过 30s；
- 手机首连不会看到比 2s 更旧的快照。

---

### F5 扫描副作用的归属

**1. 我需要做什么**

- 扫描过程中原有的副作用（未读池维护、会话状态缓存、屏读过期清理、WorkBuddy 补偿）继续随扫描执行；
- 但**由用户动作引起的展示变化**（标已读、隐藏卡片、归档）必须在命令执行后立即重算，不能等下一个节奏周期，保证卡片不回弹。

**2. 技术选型（方向）**

- 副作用拆分为"随扫描"与"随命令"两类；
- 命令层在动作后触发一次补扫或本地增量修正。

**3. 验收条件**

- 标已读/隐藏/归档后，卡片在 1s 内不再出现（含快速切页、重启）；
- 未读数量、状态缓存与改造前一致（对照用例）；
- 长时间挂机（Away 30s）后，已读状态不发生回弹。

---

### F6 事件唤醒

**1. 我需要做什么**

- 用廉价信号在"有事发生"时立即补扫一次，使低频轮询只承担兜底；
- 监控源：hook 事件目录 + **每个活跃会话的事件文件 mtime**（原地写不改目录 mtime）、用量 facts 文件、TPS 数据文件、活跃会话文件；
- 合并节流：同批事件 500ms 内只补扫一次；
- 顺手清理 hook 事件目录中超过 5 分钟的陈旧文件。

**2. 技术选型（方向）**

- 1s 级 mtime 轮询（每次仅数次 `stat`），首版不引入文件监听依赖；
- 事件只作为"请求补扫"的信号，不直接承载业务数据；
- 与 `Away 30s` 绑定：没有事件唤醒就不允许把间隔放到 30s（hook 事件 30s TTL 会丢审批卡）。

**3. 验收条件**

- 新 hook 事件产生后 **≤5s** 触发一次扫描（事件最小间隔 5s；Active 档周期扫描本身 ≤2s）；
- 挂机档连续 30 分钟：审批/问答事件零丢失（与桌面端卡面核对）；
- 无事件期间不产生额外扫描（扫描次数与档位一致）；
- 事件目录陈旧文件数量受控（不再无限增长）。

---

### F7 用量采集时机

**1. 我需要做什么**

- **可见即采**：模型用量页切回可见、桌宠迷你条挂载、设置页打开、点「立即采集」时立即采一次（前端 60s 去抖）；
- **后端兜底**：常驻定时任务每 10 分钟（步长 = 设置间隔 + 2 分钟缓冲）采一次，不依赖任何页面；
- 采集成功后通知前端刷新看板；
- 开发构建默认不启动**新增的兜底 ticker**，避免污染真实账本；应用启动时的一次采集沿用既有行为（所有构建，不在本条约束内）。

**2. 技术选型（方向）**

- 复用现有采集服务与单飞/最小间隔机制；可见即采用强制模式绕过最小间隔；
- 后台用系统线程定时（对齐 TPS 调度器既有做法），不做前端轮询；
- 采集域改动遵守 `AGENTS.md`（停 dev 或用影子目录）。

**3. 验收条件**

- 切回模型用量页 ≤1s 看到最新数据（含"距上次采集 <10 分钟"的情况）；
- 整天停留在其他页：数据滞后 **≤ 设置间隔 + 2 分钟**（默认 10 分钟设置 → 12 分钟）；
- 兜底采集不会隔轮空跑（相邻两次间隔 ≥ 设置值）；
- debug 构建默认不采集、不写账本。

---

### F8 进程扫描两段式（第二刀）

**1. 我需要做什么**

- 降低每轮进程刷新的成本：先取 PID + 名字（轻量），只对命中工具白名单的进程读取命令行/工作目录/可执行路径；
- 白名单必须包含 node/bun/python 等解释器名（npm-shim 宿主，如 kimi），并保留 exe > 进程名 > argv[0] 的回退与 cwd 配对能力。

**2. 技术选型（方向）**

- 继续使用 sysinfo，拆两次刷新：全量只刷新名字层，再按 PID 集合二次刷新候选进程的昂贵字段；
- CPU 字段按托盘需要降频刷新。

**3. 验收条件**

- 单轮进程刷新从 44–57ms 降到 ≤25ms（同机同进程数下 5 次取中位）；
- 7 个工具的进程识别零退化（含 npm-shim 宿主、MSIX/Desktop 形态）；
- 会话与项目的 cwd 配对结果与改造前一致（对照用例）。

---

### F9 解析器与日志（第二刀）

**1. 我需要做什么**

- dsh：缓存每会话的代际文件路径，减少逐轮目录枚举（**不**使用目录 mtime 预过滤）；
- opencode：维持每次开库读取，不做长连接复用；
- 日志：扫描相关 INFO 改为"状态跃迁才打"，降低日志量与写盘。

**2. 技术选型（方向）**

- 复用现有 `(mtime,size)` 缓存与解析器，只调整路径查找与日志级别；
- 不新增依赖。

**3. 验收条件**

- 热扫文件 stat 次数显著下降（对照测量）；
- 日志体积从 4.6MB/天降到 ≤1MB/天，排障所需的跃迁日志仍可查；
- 7 个工具的用量/会话数据零回归（对照 3 天账本）。

---

### F10 验收测量与可观测性

**1. 我需要做什么**

- 提供一套可复现的测量脚本与前后对比报告，覆盖：空闲 CPU、扫描次数、会话发现延迟、动作回执 p95、用量滞后；
- 运行时可观测：当前档位、最近扫描耗时、失败退避状态、补扫次数。

**2. 技术选型（方向）**

- CPU 用 `TotalProcessorTime`：release 构建、预热 2 分钟后 5 分钟 ×3 取中位；统计**进程树**（`tuvis.exe` + 其 `msedgewebview2.exe` 子进程），同时报告"仅主进程"与"含 WebView2"两个数；
- 日志计数 + 现有 mam.log；指标只读、不新增遥测上报。

**3. 验收条件**

- 脚本在 release 包上可重复执行，同一状态两次测量差异 ≤10%（按 3 次中位）；
- 报告包含改造前后对照，且 §1.2 四项门禁全部达标；
- 出现退化时能从日志定位到档位/补扫/退避中的哪一段。

## 4. 非功能门禁汇总

| 指标 | 门禁 |
| --- | --- |
| 挂机 CPU | ≤3% 单核 |
| 远控在线空闲 CPU | ≤6% 单核 |
| 扫描频次 | 活跃 ≤30 次/分；挂机 ≤6 次/分 |
| 活动档会话发现 | ≤2s |
| 事件唤醒时效 | ≤5s（最小间隔 5s） |
| 动作回执 p95 | 不劣于实施前基线 |
| 用量滞后（不可见） | ≤ 设置间隔 + 2 分钟（默认 12 分钟） |
| 用量可见时刷新 | ≤1s |
| 日志体积 | ≤1MB/天 |
| 兼容性 | IPC 契约不变，旧前端可继续工作 |

## 5. 非目标

- 不改远程注入/屏读协议与"卡面状态以屏读为准"的契约；
- 不重构各工具解析器内部算法；
- 不引入 Windows 进程创建/退出事件（WMI/ETW）；
- 不改 TPS 调度器节奏（可见 60s / 后台 600s）；
- 不做前端纯推送改造（保留命令读取契约）。

## 6. 已裁决与已否决

### 6.1 用户裁决（2026-10-29）

| 决策点 | 结论 |
| --- | --- |
| 托盘刷新 | 快照版本变化 + 30s 限频；状态跃迁立即更新 |
| 手机看板 | 维持 SSE + 30s 对账；REST 读快照，不跟随档位 |
| 动作路径补扫等待 | 3s；超时返回旧快照 + `scan_bus_status` 标记 `degraded`/`snapshotAgeMs`（不扩展动作回执） |
| 用量不可见滞后 | ≤ 设置间隔 + 2 分钟（默认 12 分钟），不牺牲防空跑缓冲 |
| 事件唤醒时效 | ≤5s（最小间隔 5s）；Active 档周期扫描仍 ≤2s |
| 验收环境 | release 构建、预热后 3×5 分钟中位、进程树 CPU（含 WebView2） |

### 6.2 经实测否决的方案

| 方案 | 否决理由 |
| --- | --- |
| opencode 长连接复用 | open+TOP200 仅 1.07ms，长持 WAL 读句柄风险大于收益 |
| dsh 目录 mtime 预过滤 | dsh 原地 append，目录 mtime 不变，会漏更新 |
| IPC 增量帧/压缩 | 会话数 1–3、单帧 1–3KB，收益可忽略 |

- **第一刀**：F1 扫描器与快照 → F2 节奏 → F3 ensure_fresh → F4 消费方 → F5 副作用归属 → F6 事件唤醒 → F7 用量采集；
