## 1. 目标与分工

兔维斯统一展示电脑上 DSH 主会话，适合手机快速看消息、看文件、查看子 Agent 工作及临时补充文本或附件、回答结构化问题。复杂操作通过“打开 DSH 控制台”进入同一宿主的官方网页。浏览器或桌面中的原会话继续使用，无需迁移数据或另起执行器。

| 入口                  | 一期责任                                                           | 一期不在此重做的交互                                             |
| --------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------- |
| 兔维斯主会话卡与详情  | 状态、消息与图片、文件、文本/附件发送、普通问答、子 Agent 只读浏览 | 执行/计划审批、原生队列管理、会话管理、技能/命令执行             |
| DSH 控制台新页面      | 转发已授权实例提供的官方网页，使用官方会话导航及允许的业务         | 兔维斯不另建这些操作的状态机和操作卡，不承诺上游版本未提供的能力 |
| 本机设置的 DSH 工具卡 | 实例选择、插件安装/修复/卸载、本机绑定/撤权及连接诊断              | 不向手机提供插件装卸、宿主配置任意透传或凭据提取接口             |

采用此分工的原因：兔维斯的价值是跨工具统一关注、适合手机的阅读、子 Agent 观察与轻量发送；普通问题在原生页处理；复杂操作由随宿主更新的官方前端处理，减少重复适配。

### 1.1 已确认的产品裁决

1. 用户已经启动的 `dsh web` 与官方 DSH Desktop 都纳入一期；不因只识别到某种宿主就自动启动另一种宿主替代。
2. 主列表以主会话卡为主。子 Agent 复用 Claude 的 chip 形态、活跃点击跳转及文件预览窗的 chip 详情入口；一期只读，文本和附件只发主会话。
3. **本轮修订：** 原生消息区做文本、附件与普通问答；执行/计划审批和其他复杂交互留给控制台。普通消息不能代替答案或审批。
4. 控制台进入用户所选实例的完整网页；不保证锁定当前会话，用户可在网页内自行切换该实例的其他会话。
5. 点击控制台按钮新开浏览器标签页/窗口；手机如何呈现新浏览上下文由浏览器决定。原兔维斯页面不导航、不更换 URL，不嵌入原页面内的 sheet。
6. 多实例时必须由用户明确选择；选择可以记住。无法确认仍为原实例、实例消失或身份变化时提示重新选择，绝不静默改连另一个实例。
7. 控制台继承当前渠道已配对设备的授权，通过自动委托打开，无第二条隧道配置、第二次设备配对或社区账号。宿主凭据仅由自有插件和本机代理处理。
8. 本机授权配置放在远程设置的“③ 工具特殊配置 → DSH”，借鉴 PR #190 的默认折叠卡结构。
9. 实现与自动检查先推进，完整 GUI 端到端验收集中后置；最终验收未完成不记整项完成、不发版。各子操作仍须有可靠契约，不能借此省略安全检查。

### 1.2 非目标与不可替代条件

- 兔维斯不提供原生会话管理。原生会话设置使用 DSH 官方投影与目录。空闲时才可切换，只有同一会话的投影回读才能确认变更。权限操作只构造官方 `/permission <preset>`，用户确认后派发；模型与思考强度使用 `session/selectModel`，提交前提示 DSH 会后台保存该配置的默认模型选择。
- 不通过读取 Electron 私有 IPC、偷取 Cookie/密钥、写原始会话文件驱动执行或降低认证来接入。
- 兔维斯自身不新增任意目标 URL 代理、通用 shell、通用 RPC 或主机电源入口。依据总纲 2026-11-24 用户裁决，官方控制台可用 DSH 自身登记和授权的接口，兔维斯保留固定上游、设备授权和主站隔离。
- 历史文件可读不表示当前 Host 拥有该会话的写资格。另一个宿主持有 writer 锁时不得接管。
- “完整网页”是复用官方页面及其可代理能力；Electron 专属动作和必须本机处理的功能允许有明确降级，不伪造桌面能力。

## 2. 路线选择与架构

| 已讨论方案                 | 收益                                 | 代价                                        | 本轮结论                     |
| -------------------------- | ------------------------------------ | ------------------------------------------- | ---------------------------- |
| 全部原生接入八类功能       | 多工具统一操作、精细策略和跨工具流程 | 重做大量界面、业务状态与版本语义            | 后续候选，不作为一期完成条件 |
| 只打开完整 DSH 网页        | 完整原生体验最快，业务适配少         | 失去兔维斯手机阅读、文件和子 Agent 观察优势 | 不采用为唯一入口             |
| 轻量原生页＋官方网页控制台 | 原生观察和快速发送，复杂功能复用上游 | 需要可靠实例归属、授权与网页代理            | 用户已选择                   |

```text
手机 / 外部浏览器的兔维斯页面
  ├─ 原生会话页 → 已认证业务接口 → 实例与会话核验 → 官方 RPC / Mux
  │                                  ├─ 消息、文件、附件、普通问答
  │                                  └─ 子 Agent 列表及转写
  └─ 打开 DSH 控制台 → 新浏览页面 → 兔维斯授权委托 → 固定实例网页代理
                                                    ↓
                                     用户已启动的 Web 或 Desktop Host
                                                    ↑
                                     自有最小插件：身份、授权、发现、撤权
```

网络渠道沿用兔维斯的局域网（LAN）、临时隧道（Quick）、自有域名（Named）和外部域名（本轮 Tailscale）四种入口。渠道承担可达性，不构成授权依据。控制台入口基于当前渠道已验证的可达配置生成，不硬编码公网地址、端口或开发机路径，不另装社区隧道或建立第二套设备表。

自有插件只补宿主身份、授权交付、必要发现和撤权能力，不复制聊天/审批业务。原生页使用既有 Rust 官方协议客户端；网页代理透传官方前端所需的已许可 HTTP/流式请求和 WebSocket，不重新生成页面里的业务回执。

## 3. 双宿主发现、实例选择与会话归属

### 3.1 两种宿主的共同点和差异

| 项       | `dsh web`                                                 | 官方 Desktop                                                      |
| -------- | --------------------------------------------------------- | ----------------------------------------------------------------- |
| 定位依据 | DSH 进程及启动参数、实际 home/profile、监听属主、插件身份 | 官方应用/Host 路径、Desktop 启动参数、profile、监听属主、插件身份 |
| 认证机制 | 官方 token/Cookie/Peer 机制；优先插件内取得，不抓终端输出 | 同类 Host 机制，token 经应用内部交付；由插件在宿主内兑换          |
| 插件管理 | 目标安装来源和 profile 的正规管理入口                     | Desktop 自带 CLI、已初始化的 desktop profile；安装前正常退出      |
| 转发主体 | 当前 Web Host 的网页/API/流                               | 当前 Desktop 内 Host 的网页/API/流                                |

不能靠窗口标题、`localhost`、固定端口或会话名称区分宿主。进程识别必须与监听 PID、实际 profile 及受信插件握手交叉验证；普通 Node 进程或伪装路径不能取得写资格。

### 3.2 身份与记忆

- 持久实例身份由受信插件身份、实际 home/profile 及安装来源等已核实事实共同约束；PID、启动时间、动态端口属于当前运行代际，不单独作为持久身份。
- 保存选择不等于保存宿主 Cookie。每代重新定位并取得当代凭据，旧请求不能投向新代连接。
- 首次发现多个候选时展示类型、可区分的实例名称/profile 和运行状态，由用户选择。不得采用“第一个进程/端口即目标”。
- 恢复已保存选择时重新核验同一实例。实例不可用或身份不能连续确认时，停止新写并显示“重新选择实例”；不得因只剩另一个候选就自动切换。
- 选择变更不搬移旧队列、已上传文件的会话归属或动作。旧目标下的在途状态保留解释，未发内容由用户明确处理。

### 3.3 会话归属

每次原生写和控制台打开都绑定明确实例。原生发送还须证明该主会话由该实例实际提供并可写；不同实例出现同名或同 ID 会话时不得混合。数据目录或共享 `DSH_HOME` 只提供线索，不能证明运行期 writer 归属。

原生页的会话归属与控制台目标必须一致。无法确定时，允许在现有授权范围内看历史，并显示具体原因；发送、上传绑定和控制台目标确认不能依靠猜测。控制台进入后可自行导航该实例的其他会话，因此不能把入口会话参数当作会话级安全隔离。

### 4.1 消息与故障状态

保留 `Queued`、`Reserved`、`Accepted`、`Succeeded`、明确失败与 `UnknownDelivery` 的区别。`Accepted` 只证受理；关联到本动作的原生 `user/message` 才证明消息进入会话，不表示模型回答或整个回合已完成。效果关联依当前官方增量信封、snapshot records 及 `data.source.kind/rpcId`，不能用正文相同或无关 turn/end 确认。

同 ID 的既有动作核对先于新写门，核对设备、原会话与载荷身份；宿主换代不应迫使用户用新 ID 重发未知动作。旧记录无法证明身份时使用保守回执并保留草稿/幂等锚。明确未执行的失败、新逻辑发送与未知运输重试分别处理，不互相转换。

所有直发、队列推进和凭据恢复后的发送均在最终写出边界重评当前能力/开关、绑定、实例、连接代际和会话条件。连接复用不放松逐动作检查。暂不可用凭据保留未发队列，凭据就绪后唤醒；重启只恢复可解释状态，不重投已发未知动作。

**本轮修订：用账本状态驱动回执。**

`POST /session-send` 的 DSH 回执与现有 `GET /m/api/v1/dsh/action/{actionId}` 共用账本。前端为每笔动作保留跟踪 ID，独立于当前草稿和防双发用的重试 ID。状态定义如下：

| 账本状态                                | 原生页显示                                             |
| --------------------------------------- | ------------------------------------------------------ |
| `queued`                                | 排队中                                                 |
| `reserved`                              | 正在发送                                               |
| `accepted`／`running`                   | DSH 已受理，等待确认进入会话                           |
| `succeeded`                             | 已进入 DSH 会话，显示 3 秒后收起                       |
| `rejected`／`failed`／`cancelled`       | 对应的拒绝、失败、取消提示                             |
| `unknown_delivery` 或状态查询暂时不可用 | 投递待核实；可以只读核实，同一动作有歧义时不换 ID 重投 |

发送的最终确认继续由宿主 `user/message.source.rpcId` 与本笔动作匹配，既不是文案相同，也不是 Agent 空闲或模型回复结束。非终态有限重查，前台恢复可补查，不给其它工具加轮询，不让旧请求覆盖新实例或新动作。

执行或计划审批、未知交互由状态区提供控制台入口，保留未发草稿。网页或桌面处理后，原生页重新取得实际状态；浏览器可见时恢复刷新，不依赖特定按钮回调。

### 4.2 子 Agent 的可靠关联与预算

父子关系优先采用经核实的官方 `origin:'subagent'` 与 `parentSessionId`/会话头 `parentSession`，并考虑 `delegationDepth`。fork 也可能有父 ID，单凭父 ID 不足以认定子 Agent。真样本已证明单层父子与 fork 对照，代码已有列表、详情及续页；真实嵌套和活跃状态仍须验证。

嵌套子任务保留实际父子关系；缺字段、孤儿节点、循环或不确定身份不猜挂树。未知状态显示未知，不以“没有进程/最近无输出”直接伪造完成。活跃 chip 的跳转沿用现有 Claude 行为；DSH 没有可证目标时提供只读详情及不可达原因，不新增终端注入或私有 Electron 控制。

只读是服务端约束：伪造发送/附件请求直指子 Agent ID 也必须拒绝，不能只隐藏输入框。读取详情时核验设备、实例、父会话与子会话关联，不允许客户端用任意文件路径代替子会话身份。

列表按父任务聚合，详情按需读取；不为每张卡全量扫描或建立无界订阅。遵守项目 `SessionFileScan`、stat 预过滤、缓存与既有扫描预算；详情分段读取、卸载释放资源。不存在的子转写返回真实不可用原因，不显示虚构空内容。对按需归属证明的冷历史，按[专项裁决](../decisions/2026-11-06-dsh-cold-history-window.md)有界补读：超窗首次最多 512 个会话头、每头 64 KiB，按文件身份与 mtime/size 缓存，覆盖不足不猜归属；不放宽主列表扫描窗口。

### 4.3 通用附件与原生媒体（本轮修订）

**上传**复用 `POST /m/api/v1/session-attachment` 和已存在的 Composer 路径标记。请求仍由服务端根据当前会话确定 cwd，固定为 `<实际 cwd>/.tuvis-attachments/<sessionId>/`；远程客户端只给会话／实例、文件名和字节。恢复 Mac DSH 上传，采用与现有通用项目上传一致的信任模型：不承诺抵抗拥有相同本地写权限的进程在最后一次复核到发布之间移动项目目录。保留已实现的目录句柄、不跟随链接、发布前对位、独占发布、取消收尾、实例选择与关闭代次、上限 20 MiB；发现路径变动或缺证就拒绝。取消仅能阻止尚未发布的附件；已成功发布不用假报撤销。传完文件不会自动发消息，仍等用户发送。项目外普通文件预览遵循 [D22](../../MASTER-PLAN.md)。

**读媒体**必须保留两类结构化来源。截图对应原生 `user/message.content[]` 的图片块带 `attachmentId`、名称、媒体种类与尺寸；`present` 生成的是带调用标识的 `deliverables/presented`，文件路径与描述挂在对应消息／回合。服务端映射为可选的结构化媒体引用，关联原事件和块位置；同一引用再供正文、文件池去重。不得以正文中像路径的文字伪造原生附件。图片读取沿用经过核实的官方附件读取能力，或经独立验证的历史只读解析；访问接口只接收会话已有引用的标识，按设备、实例、会话和预算验证。对无法证明的离线对象返回「暂不可预览」，不放开整个 DSH 对象目录。普通交付件继续复用通用预览保护。

保留已有文件名清洗、附件索引。Git 本地 exclude 是发布后的尽力便利操作，只写已证项目内的规则路径；上传拒绝／取消不改 Git 配置，路径不可证则跳过；Composer 沿用当前非空正文要求与 file/image 路径标记，不新增原生 DSH upload receipt 写链、不宣称上传即原生多模态。控制台自己的上传按官方网页另验，不能替代兔维斯原生附件验收。

### 4.4 普通结构化问答（本轮修订）

普通实时待答通过已授权的同一 Peer 接收 `user-questions/request` 并提交 `$events/result`。定时题进入 `continued` 后，经官方 `userQuestions/answer` 整组应答。执行审批与带操作意图的题交给官方控制台。详情见 [实时问答的官方契约](../evidence/2026-11-23-dsh-live-question-gap/root-cause.md)与 [Mac RPC 报告](../evidence/dsh-native-rpc/received/macos-report.md)。

- **宿主状态。** 在已授权实例的现有连接上消费官方问题事件与投影，以实例、宿主代次、会话、Agent、call、题组版本和原生题目 ID 标识；Peer/event ID 留在服务端用于当代派发。实时待答走原事件回执；只有官方投影确认已进入可补答才允许走 `userQuestions/answer`。重连同题可重新核验并恢复；连接换代、题组改变、未核实或已答不能旧卡直接写。限时题按官方 `attachWait` 等待认领语义管理，活动范围结束释放；主动编辑不等于已提交答案。
- **浏览器草稿。** 借鉴 Codex APP 分组卡的逐题状态、整组提交和宿主回读，而不沿用它的投递封包。按设备、实例、会话、题组及版本存每题 `selected[]`、`custom`、显式跳过、当前页和未决动作 ID；同一浏览器标签页刷新可恢复，跨设备共享草稿不在本批。默认未填写不等于跳过。单选自定义答案按官方规则与选项互斥，多选按题型可保留选项及自定义答案。旧稿可按本地规则保留或放弃，绝不自动套到新题、自动提交。
- **批量写入。** 用户点「提交全部」才派发。服务端用实时题组重验题集合、原选项和题型，按一个 action ID 认领整组、一次发送；问答不入普通文本队列。对同一 ID 重试只回读，不再写宿主；同 ID 异载荷拒绝。宿主先答按外部结算显示；未知结果保留待核实，不静默从实时应答改走补答。答案成功以官方投影或同组结果为准，模型是否继续输出不当作证据。

### 4.5 停止与会话设置

回合运行时主按钮用于停止，即使输入区已有草稿。通过 `session/cancel` 请求停止，操作绑定观察到的回合，受理结果和转写终态分别呈现。官方接口停止当时的当前回合，缺少原子预期回合参数。

权限、模型和强度来自官方会话投影。空闲时可使用宿主实际目录中的选项。权限固定为 `/permission <preset>` 并要求确认。模型和强度通过 `session/selectModel`，提交前提示将被保存为宿主配置的默认选择。强度写入绑定原模型，未知回执沿用动作 ID，宿主回读确认结果。

## 5. DSH 控制台转发与授权

### 5.1 用户路径

在主会话页点击“打开 DSH 控制台” → 服务端确认设备仍有效、实例仍为用户选择且网页能力可用 → 新页面进入该实例官方网页。无需第二次社区配对或账号登录；必要的兔维斯重新认证仍走当前地址现有流程。

新窗口使用 `noopener` 等方式断开 opener 控制。浏览器拦截新窗口时显示可点击的“在新页面打开”链接，不导航原 Tuvis 页面。返回原页面后保留草稿、附件草稿与阅读位置，并重新核验宿主状态。

网页内允许正常切换该实例的会话；不强制定位入口会话，不跨实例替用户切换。上游页面不存在或 Electron 专属功能不可代理时给明确原因，不改连其他宿主。

### 5.2 网关责任

- 只代理受信实例登记的当前 loopback authority，校验监听属主和代际；URL 不能携任意上游地址。不跟随跳出目标的重定向，不受系统代理截获宿主认证。
- HTML/JS/CSS、相对及绝对资源地址、API、流式响应、上传下载、WebSocket、重定向和 Cookie 均需一致处理；不能仅转发首页 HTML 就宣称网页可用。
- 宿主 token、owner/browser Cookie 留在本机。内部请求的 Host/Origin/认证改写只在外部设备已认证后执行；内部 Cookie 不原样下发给手机。
- 控制台授权委托绑定设备、实例和会话有效期；这里的“会话”指授权会话，不把控制台锁成单个 DSH 会话。代理不因来源为 LAN/loopback 而豁免设备认证。
- 如新浏览权限域需要一次性授权引导，使用短时、单次消费且绑定设备/实例的委托交换；不得把长期设备令牌或宿主凭据放入新页 URL、浏览器历史、Referer 或访问日志。它不是第二次用户配对。
- 直接跳转、资源访问和 WebSocket 升级共用设备/实例授权。撤设备、停远程、撤实例绑定、关闭控制台代理时，拒绝新请求并关闭相关活连接；已执行副作用不承诺回滚。
- 四渠道接同一逻辑授权和代理规则，入口根据当前有效外部地址构造；临时域名变化不恢复旧入口权限。换地址沿用该地址现有认证，不假设 Cookie 自动跨域共享。

### 5.3 浏览器与控制范围隔离（本轮修订）

控制台加载的官方及其插件脚本不得因此获得兔维斯自身设置、设备管理、电源及其他工具的 API 权限。仅加路径前缀或 `noopener` 不构成同源脚本权限隔离。工程方案必须通过独立浏览器 origin 或经验证的等效隔离实现；同一四渠道入口可以引导到受控控制台入口，不意味着所有脚本必须与 Tuvis 共用浏览器权限域。可达性与隔离无法同时满足的渠道不得放行控制台功能，不能静默降低认证。

控制台按实例级授权，该实例中由 DSH 提供和授权的官方功能可经生产控制台入口使用。按 2026-11-24 总纲裁决，兔维斯将 HTTP、SSE 和 WebSocket 转发给固定的受信宿主，官方业务路由及消息由宿主处理。兔维斯设备管理和其他工具权限仍与控制台隔离，配对、实例归属、服务端凭据保护、到期及撤权由入口负责。

网页兼容按资源/代理协议判断，不要求兔维斯识别网页内每一种审批题型或模型字段。原生文本、附件、普通问答仍独立执行逐操作能力门；网页可用不能给原生业务开全权限。

生产路径在 `/console/{token}/` 下运行。仅在入口 HTML 安装内存存储兼容层，避免官方页面在 opaque sandbox 中访问浏览器存储时中断。保持 `allow-same-origin` 缺席。隔离和跨浏览器实机状态见验收矩阵。

四渠道复用当前远程入口。用户打开控制台时沿用当前地址与配对，生产使用同一路由挂载。

- **参考其它项目证明可行性，不照搬其信任边界。** [旧 WebUI 的设备认证网关](https://github.com/zhu1090093659/dsh-web/blob/dev/packages/dsh-remote-web-ui/README.md)用同一入口承载官方页面与认证代理，[DSH Go 1.3.0](https://github.com/ccch1mneyyy/dsh-Go/releases/tag/v1.3.0)与 [ds-harness-remote 0.6.7](https://github.com/liguobao/ds-harness-remote/releases/tag/v0.6.7)也有宿主官方 Web 入口或隧道支持。前者所在站点专供 DSH，后两者使用自己的客户端或网关，不等同于兔维斯的管理 API 与 DSH 页面共用入口时已经隔离。
  验证覆盖真实官方页面启动、历史和问答，以及设备或实例撤权后的活连接关闭。
  官方页面内的权限和设置由宿主处理。原生会话设置按 §4.5 独立走受限官方 RPC。

## 6. 本机设置与双宿主插件生命周期

位置：兔维斯桌面设置 → 远程接入 → 默认折叠的 **DSH** 工具卡。原方案借鉴 PR #190 的工具特殊配置结构；当前分支实际名称为「DSH 桌面端远控」。本轮在现有入口收口，不依赖原参考分支；若要改到别的位置，另作 UI 裁决。

| 小节       | 展示/操作                                                  | 必须区分的事实                                             |
| ---------- | ---------------------------------------------------------- | ---------------------------------------------------------- |
| 连接实例   | Web/Desktop 候选、名称/profile、运行状态、选择与重新选择   | 已保存选择不等于实例在线                                   |
| 自有插件   | 检查、安装、修复、卸载、作业进度、取消及需要用户重启的步骤 | 已安装、已启用、正在运行分别核验                           |
| 本机授权   | 身份核对、绑定、撤权、重新绑定及诊断                       | 设备配对与 DSH 宿主授权是两层，不重复让手机配对            |
| 能力与故障 | 原生读/文本/文件/图片/控制台分别给可用性、版本与原因       | 不把一个操作成功显示成全功能通过；不输出秘密或完整敏感路径 |

表中安装、卸载、绑定和撤权是开关驱动的步骤，不是额外的常驻按钮。首次无凭据时仍能安装自有固定包，不循环依赖控制面；不要求用户复制命令或安装系统 Node。Web 与 Desktop 分别使用经核实的正规 profile 管理入口，不能将 npm 全局 CLI 冒充 Desktop 自带 CLI。目标运行中需要退出时等待用户正常退出，不强杀任务；卸载先撤所有匹配绑定再移除包。

自有包预构建、无生命周期安装脚本、字节与 manifest 哈希对账；安装依赖稳定版本化缓存。依赖、bundle 选择、实际装载和卸载残留分别核验，不能仅凭 CLI exit 0 或 `node_modules` 路径判成功。保留用户其他 profile/插件与配置；用户修改的自有项冲突可见，不整文件回灌。

本机授权为受 OS 身份保护的双向握手；持久信任与临时 Cookie 分离。Unix 使用受限 UDS；Windows 须实现当前用户限定 DACL、拒绝远端 pipe、内核 PID/启动身份和可取消关闭，并对密钥/身份目录施加实际 ACL。交叉编译通过不表示这些运行期条件已完成。

### 6.1 尽量一键的首次配置

唯一生命周期开关为「远程控制 DSH」：自动发现 → 多实例时明确选择 → 检查并安装自有插件 → 自动核验插件运行和OS进程身份 → 对选定实例的一次明确授权 → 建立持久信任并显示结果。若主按钮前已明确展示目标和授权范围，可把该点击作为本次实例级授权意图，自动完成后续签名挑战；不得扩大为批准所有未来待批客户端。

用户不复制命令、token或端口，不输入社区账号，也不在每次开控制台时重新绑定。首次未知身份和身份变化不得无提示信任；必要的实例选择和授权说明保留。内部核对码可作为异常排障和人工核验入口，不要求正常用户手工搬运口令。简化流程由 §6.3 的单开关承载，设置状态仍以实际宿主事实为准。

Desktop未初始化时给“打开一次DSH”的按钮；官方要求退出后安装时，流程停在“等待退出”，自动等待后继续，并提供明确的重开入口。不强杀任务、不隐式重启宿主。系统权限确认由系统负责，不能承诺所有机器零弹窗。插件已经运行且身份未变时，重启后自动握手和兑换当代凭据，无需重复人工授权。

“授权委托”是后端概念，用户界面不显示独立委托配置项。每个新控制台页面由当前有效的Tuvis设备授权自动生成受限委托；长期信任配置在本机DSH卡内，临时凭据按需自动刷新。

### 6.2 已确认的本机专属限制

本机官方Electron源码确认：目录选择调用 dialog.showOpenDialog 且限定Desktop主窗口主frame；原生Platform用量/充值视图限定 dsh-app://app 主frame；客户端更新、设备信息和部分onboarding状态通过Desktop IPC。普通远程浏览器不能直接获得这些主窗口能力。

因此一期控制台不承诺远程弹出电脑的系统目录选择器、打开Desktop内的原生充值/用量窗口，或操作Desktop应用更新流程。可用的官方Web替代入口应保留；若某动作必须主窗口处理，则明确提示回本机。手机文件选择与上传、普通消息、模型切换、原生审批并不因此被禁用，它们各走已有网页/业务接口。

打开文件、外部编辑器、外部链接和通知不能一概判为“做不了”：需分别核对Web RPC/浏览器替代路径。普通浏览器没有Electron主窗口桥接；是否可经已有服务端接口打开电脑上的应用，仍须按实际接口判断，不能直接断言不可用。系统终端/shell仍遵守项目总纲边界，不因Electron或Web存在入口而自动代理。

### 6.3 单开关与配置反馈（本轮修订）

正常界面只有一个「远程控制 DSH」开关和可折叠的「修复插件」。开启按「检查 → 等待正常退出 → 安装 → 提示重开 → 核验加载 → 授权」推进，已就绪步骤跳过，正常最多一次确认；取消不开始。关闭即禁止新写与旧授权复活、吊销该实例控制台，先撤权后卸载，运行中等待宿主退出；历史转写在已配对、实例归属可证时继续可读。同钥正常重启不需重批；完全卸载、身份退役后再开启是新的明确授权。关闭 A 不得中断 B 的活控制台，整域停用才全局撤权。

开关旁分开展示所选实例、插件安装及版本、加载、授权、等待退出/卸载、原生发送和控制台就绪或原因。授权成功不能替代网页可用；关闭等待期即使进程和旧连接还在，也不能把写能力显示为可用。UI 收在本轮 T10，依赖前面的真实能力结果。

## 7. 兼容、证据与可行性

### 7.1 既有支撑的使用原则

旧 PRD 和原生八类全控稿留下的官方协议、授权、模型、审批、问答及上传证据可作回归；不因此恢复所有原生操作。自有插件完成身份与授权，Rust 业务侧复用已有账本与连接。上游及社区网页可参考原版前端与浏览器隔离做法，不作为兔维斯生产依赖。设计取舍和当前可用性见 §9。

### 7.2 最大化兼容的边界

- 原生已接入操作按当前包的参数、响应、事件和必要语义识别；未知 build 可在规则匹配且运行守卫满足时兼容尝试，不等待全 build 人工登记。
- 文本、文件、图片、只读内容、子 Agent 解析和控制台代理独立降级。一类不支持不关闭整张 DSH 卡。
- 同 build 重打包、换规则、换插件或换 profile 后重新归因；包扫描前后有效快照必须一致，缓存存已验证快照；失败时本次写也拒绝，不只是不缓存。
- 只读成功不解锁写。契约匹配显示“兼容可尝试”，不能宣称本机业务实测通过；DTO 字段的历史命名不得改变这个产品口径。
- 控制台使用宿主同版前端减少逐功能语义镜像；仍需验证授权、资源、HTTP/WS 与本机专属路由，不对未来版本承诺无条件可用。
- 官方事件是状态权威；网页/桌面手动操作后原生页应纠正状态。未知交互显示控制台出口，不从正文猜审批或问答 payload。

### 7.3 实机证据与隔离前置

Agent 的自动化及本机浏览器联验只在隔离测试宿主、账号和数据根验证。短 IPC 路径下先确认实际打开的数据库、DSH home/profile、实例状态目录与监听渠道都属于测试环境。**`TUVIS_HOME` 仅在启用 debug assertions 的构建中生效**；如果关闭断言或验 release 包，必须用独立 OS 账户、经实际路径核验的隔离 HOME 或独立虚拟机，而不是只设置 `TUVIS_HOME`。探针、验证器与应用同样检查；未证不得启动带写入的验收。这一前置覆盖 [11-20 候选误写事件](../decisions/2026-11-24-dsh-remote-acceptance-and-release.md)。

用户用自己的手机和现有配对做最终产品验收；如要覆盖首次配对，可以用独立测试浏览器或设备新配一次，不需要重置现有设备。记录通过、失败及版本、渠道即可，不采集 PIN、二维码内容、Cookie、真实聊天或身份资料。

优先重复验证新改动的真实页面、问答题型与状态、附件宿主实读、关后再开；既有旧版协议或单平台证据可以复用来设计，但不能用作最终包效果。Windows 原生、子 Agent 活跃态和四渠道逐格通过 H14 后才能记整期完成。
