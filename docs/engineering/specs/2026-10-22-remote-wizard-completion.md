## 用户目标

Tailscale 与 Cloudflare 自有域名均沿时间轴逐步配置。每步操作在右侧，完成变绿，错误及备选方案留在本步骤。
所有必需步骤完成、通道运行且公网看板响应通过后，自动收起为固定地址摘要，提供复制、打开、二维码和「查看配置步骤」。
成功时将摘要滚入可见区域并提示一次地址位置；用户主动展开后，同一配置的后台更新不再反复收起。

后续网络异常保持折叠，在摘要显示原因与「查看诊断」；历史地址明确标为暂不可用，暂停二维码与打开操作。
关闭通道显示「已配置，未开启」。修改 Token、目标域名或本地端口后，旧配置的完成记录不可用于新配置。
历史标记只决定默认展示，不证明当前可用；重启仍须实时检查。所有迟到的日志、网络结果与界面回执均须绑定配置/生命周期代际。

## Tailscale

- 普通校验与刷新均只读。公网明确无记录时显示「等待公网 DNS」，无「重试」按钮，约每分钟后台检查一次。
- 后端提供连续等待开始时间；刷新不重置计时，临时进入校验中也不重新起算。界面只显示已等待时间，不制作倒计时。
- 等待提示为「可能需要几分钟，最长约 10 分钟」，同时说明本地看板及 Funnel 已正常、地址通过后会显示在本卡。
- 超过 10 分钟仍未发布，显示超出预计与排查入口，继续只读检查，不自动重置。
- 公共解析服务不可用、DNS 无记录、HTTPS 不通、看板特征不符必须区分，不能均写成「DNS 等待」。
- 原重开逻辑归入独立「重新开通」修复入口，需明确确认并继续使用后端状态门与 serve 配置归属守卫。
- macOS 系统扩展已可用时标绿并说明无需重复授权。后端停止不等同未批准扩展，先引导检查客户端；有明确未批准证据才给系统授权动作。

## Cloudflare 自有域名

前提是域名已接入 Cloudflare；域名购买、迁入与帐号注册不纳入本向导。
流程为创建隧道、带回 Token、保存并连接兔维斯、在浏览器绑定域名、校验访问、显示完成摘要。
已有 Token 的用户可跳过创建步骤。站外操作先显示「已操作，待核验」，公网访问验证通过后整体完成。

连接器进程存活不等于已连接：需实际注册连接事件；启动、重连、断开及配置变更均需重置对应代际状态。
校验使用公共 DoH、钉住解析 IP 的 HTTPS 与兔维斯看板特征响应，不经本地 DNS/系统代理，不跟随跳转。
DNS 等待显示已等时长，不套用 Tailscale 的固定估时；认证失败、未配置域名、DNS 未生效和源站响应错误分别显示可执行的下一步。
兔维斯只提供网站入口与可复制配置值，不自动登录或代写 Cloudflare 网站设置。

## 接口与验收

等待元数据包含开始时间和可为空的预计时长；现有六态可达性语义保留。

## 实施追记（2026-10-22 独立终审闭环）

终审在首轮集成全绿后新增三个 P2，均已闭环，随本轮同批验收：

1. **首开持久化通道意图**：向导开通 Funnel 成功（含登记的延迟恢复）即写通道 KV 并发审计
   与 `remote-changed` 事件——否则新完成门要求的 `probe.enabled` 永不成立，重启也不恢复。
2. **`remote_status` 补 Tailscale `configKey`**（DNS 主机名+端口稳定哈希的纯快照 getter，
   不加 CLI）：本地端口等配置变更可被父级 3 秒轻量轮询识别并驱动子向导失效重探。
3. **批准链接生命周期**：子向导把「真失效」（配置标识换代 / 通道关闭 / 总开关关闭）与
   「同配置普通刷新」分开——只有真失效清状态并拒绝在途回执；同配置刷新保留批准链接与
   在途动作。否则首次开通的 `enabled` false→true 翻转自己就会清掉刚返回的浏览器批准链接。

另修一处首帧抖动：等待元数据落地的那一拍本地时钟态尚未起跳，已等时长会闪「0 分钟」、
超期判定首帧恒不成立——时钟未起跳时当场取真值（TailscaleWizard / NamedDomainWizard 同批）。
