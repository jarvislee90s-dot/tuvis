# F9 dsh 代际路径缓存与告警去重

## 背景

内容缓存 `SessionFileScan` 已按代际文件 `(mtime,size)` 缓存解析结果，但 `scan_sessions` 仍每轮为每个会话 `read_dir`、解析文件名并排序代际。未知 header 版本也每轮重复 WARN。内容缓存不能代替目录路径索引。

## 设计

### 代际路径索引

- 对每个会话目录缓存 `generation_logs()` 的路径列表与单调刷新时刻；缓存 TTL **2.5 秒**。缓存只存路径/代际，不存解析产物与文件内容。
- 通过 TTL 到期重新 `read_dir` 发现新增代际、重命名、压缩替换和删除；禁止使用目录 mtime 判定目录未变。
- 当前最快 Active 扫描约 2 秒：2.5 秒 TTL 可让交替轮次命中缓存；新代际在 Active 下最迟约 4 秒内被下轮扫描发现。Idle 下 10 秒扫描时缓存自然过期，每轮重新枚举，不再额外延长该档发现周期。
- TTL 内删除的旧路径仍可能在列表中一次，但既有文件 `stat`/内容缓存入口会发现文件不存在并跳过；TTL 到期后路径被移除，`retain_existing` 收敛内容缓存。
- 内容解析缓存仍用 `SessionFileScan` 的 `(mtime,size)` 指纹。每轮仍按文件 mtime 做 L3 预过滤；不会因路径列表缓存而先打开/解压超窗文件。

### 未知代际告警

对未知 header 版本的 WARN 以 `(session_id, 文件名代际)` 为键，仅当缓存解析内容指纹改变时重报。内容指纹由已读取文件字节产生；不在每轮为命中内容缓存的会话重新读文件。新 session、新文件名代际、文件内容变化均会重新告警；同一文件不变时最多一条。

## 验收

1. 2.5 秒 TTL 内重复热扫复用代际路径列表，路径枚举计数降低；TTL 到点必重枚举。
2. TTL 内追加新代际允许使用旧列表；TTL 到期后找到新代际。压缩文件替换、删除均在下一次 TTL 刷新后反映，旧路径不存在时不出卡。
3. 原地 append、坏文件修复和内容变化继续触发 `SessionFileScan` 失效；路径缓存不以目录 mtime 作为证据。
4. 同 session、同文件代际、同内容签名只 WARN 一次；内容签名变化或 session/代际变化后可再次 WARN。
5. 热扫对照记录每轮 `read_dir` 枚举数和代际预过滤 `stat` 数。路径缓存降低目录枚举；文件 stat 口径如实记录并继续满足先 stat 后 parse。

## 修改范围

- `src-tauri/src/monitor/dsh/log.rs`：可注入单调时钟的代际路径 TTL 缓存与枚举计数。
- `src-tauri/src/monitor/dsh/mod.rs`：生产缓存接线、热扫 stat 计数、内容签名告警去重与回归。

不修改日志 JSON 语义、时区/状态判定、目录 mtime 策略、`SessionFileScan` 内容缓存语义或任何账本写入。
