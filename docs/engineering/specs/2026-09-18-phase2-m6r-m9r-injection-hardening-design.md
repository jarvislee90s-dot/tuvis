## 1. 背景与动因

1. **M6「消费墙」结论被推翻**：官方文档 + 两代 conhost 源码 + ReactOS 三重实证——控制台输入缓冲区无界动态增长、错误 122 非该 API 的 OS 层语义；M6 探测方法论存在硬伤（bracketed-paste 实验因 PowerShell 5.1 转义缺陷从未真正执行、原始日志被覆盖灭失、错误码解读自相矛盾、未做输入模式/占用率观测）。墙的**现象**（约 40 字符后长文本不再进入）大概率真实，但归因需 M6R 重探测定案。
2. **同场景开源先例实证可行**：cc-discord-remote 以完全相同路径（附加控制台→CONIN$→写输入记录）驱动已开终端里的 Claude Code，**注入方向无长度上限**，靠分块节流稳定投递；其写入确认（回车补按/屏幕稳定检测）、事件构造硬约束（非零扫描码、方向键 VT 序列原子批）、busy 语义、版本漂移教训均为可抄规格。
3. **M6–M9 首批实施评审**发现 4 项 P1（附加态复位缺口、进程级附加竞态、投递循环击穿 watcher 零订阅守卫、delivered 回执失真）与多项 P2，均已定位根因并选定修复路径（两路对比与出处见评审记录，未采纳路径的工程亮点已登记）。
4. **用户新裁决**（2026-09-18，落二期总 spec v1.5 裁决 18/19）：A 主通道=终端注入重写后为主力（W3 原样成立）；B 兜底=无头（M11 排期不动）+ 一键 resume 窗口（本批）；文件指针长消息方案延后；远程关闭=冻结队列。
5. **用户新裁决**（2026-09-19，对齐审查）：**A1 写入确认分层落死**——直发以会话文件命中定「已送达」、插队以占用排空+屏读草稿在场确认、屏读回查全程为恢复动作与异常诊断（对齐 W4「agent 已处理不由回执表达」）；**B1 opencode 纳入 M9R 验收矩阵**（三家→四家）。

- **必答问题**：①旧「墙现象」的真实机制（TUI 行编辑器 cooked-read？客户端错误？还是真有约束）；②分块节流形态下任意长度是否全量可达；③codex 系（crossterm）按下+抬起成对事件是否双写；④非零扫描码与 VT 序列原子批对各家接受度的对照；⑤busy 态各家行为（决定插队逐家标注）。
- **证据纪律（吸取 M6 审计教训，硬性）**：日志追加式带 run-id 永不覆盖；所有写入点必记实写数与错误码；实验前先修探测脚本已知缺陷（PS 5.1 转义、错误码采集缺失）；逐 CLI × 宿主控制变量分表，禁止合并陈述；每实验留存截图/日志/会话文件三重证据链。
- **回调条款**：若「分块节流 + 任意长度」被推翻 → 停下上报，长度上限旧三选一重新裁决。
- **验收**：报告 v2 + 独立评审落盘 `docs/research/refs/phase2-消息注入/`；本设计文档追加「参数定案节」。

### R2 · Windows 注入引擎重写（M9R）

- **需求**：已开终端会话（conhost/Windows Terminal × claude/codex/kimi/**opencode**）收到**任意长度**（≤全局一万字符上限）远程消息——可靠、可确认、可审计，与 macOS 通道同口径（`[mobile 设备名]` 前缀、`\n` 归一、队列、插队、回执）。
- **硬性要求**（参数已由 T1 定案，全文见 §8 参数定案节，含 2026-09-19 opencode 修订）：
  1. **自适应节流**投递，注入层**不截断**用户内容——默认 80 字符/50ms 固定节流；**慢消费者或长文（>2000 字符）自动切占用率背压**（每块后轮询占用回落再续；opencode 实证 ~70 事件/秒、固定节流会丢提交回车）；
  2. 事件构造**按家分支**（T1 定案）：回车/控制键（Esc/Tab）三家统一 **VK 事件形态**（B 族丢弃 vk=0 控制字符——现役引擎 codex「打完字不提交」根因）；方向键 A 族 VT 序列**整批原子写** / B 族 VK 形态；按下+抬起成对；B 族禁 bracketed-paste、禁裸 ESC 字符流；
  3. 附加控制台生命周期：进程级串行 + 附加后立即自动复位守卫（覆盖一切错误路径）——同批修复 P1-1/P1-2；
  4. **写入确认双层（裁决 A1 定案）**：**直发**（可输入态）以**会话文件命中**定「已送达」（提交即时发生、秒级命中，免疫屏读漂移）；**插队**（busy 态）以**占用排空 + 屏读草稿在场**确认「已送达（已进入其输入草稿）」——文件命中那刻属「agent 已处理」，依 W4 不由回执表达；**屏读回查全程为恢复动作（滞留检测→补按回车）与异常诊断**；确认器按存储形态可插拔（JSONL grep / SQLite 副本查询）；确认失败才回「失败可重试」（E10 尾字符丢失 1/91 = 必要性实证）；
  5. 注入总预算为真总预算（每轮检查，超时中文错误）——修 P2-1；
  6. 审批键域校验：域外键报错拒绝，不回退「文本+回车」——修 P2-2；
  7. 保留件：CONIN$ 句柄路径、平铺记录布局（编译期断言）、双宿主不收窄、PID 本体→祖先链回退；
  8. **占用率监控 + 冻结检测报告**（选择模式冻结实证：写入成功 TUI 读不到 → 判冻后返回明确中文回执、引导用户点击终端窗口恢复——**不自动介入**，D8 裁决 2026-09-19：自动发 ESC 对忙态 agent 有中断任务风险，撤销自动解冻）；
  9. **脆弱常量全部可配置 + 规格带版本指纹**（分块/间隔/键位/模式指纹/消费速率），大版本升级触发复验（项目技能 `win-console-inject-probe` 快路径 15–30 分钟）。
- **验收**：四家 CLI（claude/codex/kimi/opencode）× 双宿主 × 200/2000/10000 字符三档全量送达（opencode 走背压路径 + SQLite 确认器）；回车补按路径实测；A1 分层确认实测（直发文件命中 / 插队草稿在场）；串行化后跨会话并发注入零互扰（回归测试）；「已注入未确认」必出失败回执。

### R3 · 队列与回执修复批

- **需求**：队列生命周期与回执语义对齐「先落账后回执」原则，恢复被击穿的 watcher 零订阅守卫。
- **要求**：①远程关闭=冻结队列（投递循环随服务停；已知窗口「已注入未落账→重启可能双投」由启动对账兜底并注释声明）——裁决 19，修 P1-3；②启动对账补投 + 周期兜底扫描（纯 SQL 计数门控，守宪法扫描预算契约）——修 P2-5；③投递内核返回结构化四态（已发出/对方忙/会话消失/失败），端点精确映射 delivered/queued/failed——修 P1-4；④撤回与投递共守卫，忙时短回执——修 P2-6；⑤前端失败后以队列查询为准，消息仍在队则恢复排队视图——修 P2-7；⑥版本探测带超时杀进程、超时结果入缓存、Windows 下解析真实可执行路径（已取证工具不再恒显待复核）——修 P2-8；⑦补齐三条回归测试（403 原因透传/会话不存在兜底/忙让位恢复）——修 P2-10。
- **验收**：P1 四项各带回归测试；关闭远程后队列冻结、重开续跑实测；重启后待发消息自动补投实测；delivered 回执与注入事实一一对应（测试断言）。

### R4 · 审批补全（M8R）

- **需求**：Claude/Codex 两家审批应答全程实证可用；触发判定不误报；未取证工具绝不发错误键位。
- **要求**：①按取证手册完成 codex 取证（`/permissions` 切 Read Only 档触发补丁审批必弹；Default 档网络审批）与 claude plan 模式取证，回填版本与键位；②触发词替换为两家源码原文短语（窄匹配）；③**严格档**：未取证=映射缺失，不出按键、提示走普通发送（对齐 W6 原文）。
- **验收**：codex 红卡批准/拒绝实机生效；claude plan 模式「批准执行」实机生效；普通正文含宽词（如 "allow"）不再误出审批卡；probe-pending 状态不出键（测试断言）。

### R5 · 一键 resume 窗口（新功能，F3.4 前置件提前）

- **需求**：手机或桌面点一下，MAM 在本机自动打开终端、进入项目目录、恢复该会话并聚焦——用户零额外操作。服务 B 兜底的「可见性」半部与「回电脑继续」场景。
- **要求**：①双端触发（移动端会话卡/详情按钮，走 PIN 门禁内新端点；桌面端卡片同款命令）；②终端选择：Windows 优先 Windows Terminal、未装回退 conhost；macOS 优先 iTerm2、次选 Terminal.app（复用既有脚本基建）；③各家 TUI resume 命令映射表（T5 首任务探测核实并入库：claude 已知，codex/kimi/zcode/opencode 待查证；zcode 注意在册工作区限定）；④不可行情形明示（项目目录缺失等→按钮禁用+原因）；⑤写审计（动作词「打开」）。
- **验收**：≥2 家工具双端实测（窗口打开、目录正确、会话恢复、自动聚焦）；审计可查。

### 8.1 事件构造与投递规格（M9R 直供；全量证据见报告 v2 §3）

| 项 | 定案 |
|---|---|
| 分块 | 80 字符/块（160 事件单次写入），块间 50ms |
| 提交回车 | 正文后 150ms，**VK 事件形态**（VK_RETURN + 派生扫描码 + '\r'） |
| 字符事件 | keydown+keyup 成对；vk=VkKeyScanW(ch)&0xFF；scan=MapVirtualKeyW(vk) 派生非零（保守项）；UnicodeChar=ch。无双重写入（keyup 被各家过滤或忽略） |
| 回车/控制键（Esc/Tab） | **三家统一必须 VK 形态**（B 族实锤丢弃 vk=0 控制字符——现役引擎 codex「打完字不提交」的根因） |
| 方向键 | **按家分支**：A 族（claude/kimi，RAW_VT）= VT 序列整条单批原子写；B 族（codex，crossterm）= VK 形态 |
| bracketed-paste | A 族可用；**B 族禁用**（序列头 ESC 被当按键吃、泄漏字面文本） |
| 长度 | 注入层不截断；万字符实测 8.1~9.3s（快消费者；慢消费者见背压行） |
| 写入校验 | 每次核 BOOL+实写数；实写<分片长从偏移续写；**仅 ok=false 时读错误码**（ok=true 时为噪声） |
| 写入确认（双层，裁决 A1） | **直发以会话文件命中定「已送达」**（stamp 命中轮询；claude JSONL / codex rollout / kimi wire.jsonl / opencode SQLite 只读查询〔D3 裁决 2026-09-19 追认活库只读路径〕）；**插队以占用排空+屏读草稿在场确认**（文件命中那刻=agent 已处理，依 W4 不由回执表达）；屏读回查=恢复动作（补按回车）与异常诊断；确认失败→失败回执。E10 尾字符丢失（1/91）= 必要性实证 |
| 背压与异常 | **自适应节流（2026-09-19 opencode 实测修订）**：默认 80 字符/50ms 固定节流；**慢消费者（opencode ~70 事件/秒，A 族内亦有异类）或长文（>2000 字符）切换占用率背压模式**（每块写入后轮询占用率回落至阈值再续，实测 10k 全量精确 110~183s）——固定节流对慢消费者会堆深队列并**丢提交回车**（消息边界破坏、两条并一条）；判冻口径=「无逐样本下降持续 ≥5s」（评审 C1 细化：背压锯齿稳态不误判；codex 瞬时 ≤~120 事件亚秒消化属正常）；**宿主选择模式冻结**（写入成功 TUI 读不到）→ 检测后返回中文回执「点一下该终端窗口后重试」（点击即清除选择模式）——**不自动解冻**（D8 裁决 2026-09-19：自动发 ESC 对忙态 agent 有中断任务风险，撤 PostMessage 自动介入） |
| 写入确认通道 | 每家独立定路径：claude/codex/kimi = JSONL 读路径；**opencode = SQLite 活库只读连接**（D3 裁决 2026-09-19 追认：复用既有只读读路径 + 1s busy_timeout + 500ms 轮询兜底，极端竞争下假阴性方向安全——「拷贝 db+wal+shm 副本查询，勿查活库」的最初措辞作废，常态拷贝成本不值）——确认器按存储形态可插拔 |
| 单实例假设 | opencode 同项目跨窗口草稿实时互串（实证）——引擎按「同项目单实例」假设设计，多实例行为登记已知限制 |
| 生命周期 | 一次性子进程 / 进程级串行；附加后立即自动复位守卫（R2 既定） |
| 已知修剪 | kimi 去尾随空格、codex 同类（长度对账按 TUI 语义归一） |

### 8.2 族模型与版本漂移对策
