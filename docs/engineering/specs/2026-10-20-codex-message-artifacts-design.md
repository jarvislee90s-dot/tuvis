## 一、目标与用户裁决

让 Codex APP 正文中的已知文件引用、上传附件和生成图能进入现有文件预览，并能从文件预览返回正文中的最近引用。

1. 正文中已有识别能力支持的文件路径和文件名，继续显示为可点击的文件链接，打开现有预览窗口。
2. 文件身份沿用现有路径解析、规范化和去重规则。不同路径或不同文件名分别指向各自文件，不猜测版本关系。
3. 同一路径后续被覆盖，所有会话链接均打开该路径的当前内容。用户明确不需要历史文件存档，后续阶段也不规划此能力。
4. 从文件预览返回正文，从最新消息起逆序查找该文件最近一次可识别引用，并定位、高亮。
5. 最多搜索五页消息，包含最新一页；当前尾窗算第一页，最多再读取四页更早消息。找到即停止，范围内没有就结束。
6. 五页之外不继续自动加载，也不提示用户为了该次定位继续加载。文件预览保持可用，未命中可以显示简短提示。
7. 来源标注区分上传、生成、修改、查看；查看过文件不等于生成或修改了文件。

## 二、范围与现有能力复用

### 2.1 现有能力

- `src/mobile/message-render.tsx`：`sortedPaths`、`linkifyMarkdown`、`linkifySegments` 及对应渲染器，将文件池已知路径链接到 `openFile`。
- `src/mobile/SessionDetail.tsx`：由 `fileEntries.path` 派生正文链接用的路径集，管理宽屏分栏、窄屏全屏预览。
- `src-tauri/src/remote/files.rs`：已有相对路径解析、Windows 路径归一化、文件去重及排序；新增关联必须复用其身份口径。
- `src-tauri/src/remote/content.rs`：生成图目录已扫描入池，不重做这条链路。

现有正文链接按已知路径原文匹配、长路径优先；不会自动从绝对路径派生文件名别名。本期保留既有识别范围，不另加文件名猜路径或猜版本规则。

### 2.2 本期增量

- 将现有正文链接渲染接入 IPC 的 `m.text` 分支。
- IPC 投影增加结构化文件引用，覆盖目标为 `imageGeneration`、用户内容中的 `localImage`／`mention`／HTTP(S) 图片链接、`fileChange`、`imageView`。
- 正文增加图片卡、文件 chip、外链及不可用占位。
- 文件池与文件预览增加正文定位入口，复用同一有界查找流程。
- IPC 增加只读历史分页，供上述最多四次更早消息读取使用。

### 2.3 边界

首期针对 Codex APP 的 IPC 投影。其他工具的现有正文链接能力保持原样，跨工具 artifacts 统一单独跟踪。

结构化产物抽取只使用已核验字段，不从工具输出正则抓取新路径。正文对文件池已知路径的现有链接化继续复用；这与抽取新产物是不同职责。

外部 HTTP(S) 图片只提供外链，不经服务端代理。生图 base64 不进入投影、日志或审计。

### 2.4 方案选择

| 方案                                           | 覆盖能力与代价                                                   | 结论                   |
| ---------------------------------------------- | ---------------------------------------------------------------- | ---------------------- |
| 仅给 IPC 正文接入现有链接化                    | 能点击正文已知路径；无文本的生图和附件仍缺少卡片及结构化来源     | 作为本方案的一部分复用 |
| IPC 结构化附件 + 现有正文链接化 + 五页逆序定位 | 同时覆盖附件卡片、正文引用与有界反向定位，需要扩展投影和只读分页 | 本期采用               |

### 2.5 模块职责与数据流

| 模块                                                  | 职责与边界                                                                                          |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 共享文件身份纯函数                                    | 从现有文件池提取可复用的路径身份计算，文件池与 IPC 提取共同调用；保持现有语义，不引入文件存在性依赖 |
| `codex_desktop_ipc/history_view.rs`                   | 提供 canonical 回合／item 顺序与完整性判断；不混入 UI 或文件读取逻辑                                |
| `codex_desktop_ipc/types.rs`、`mirror.rs`             | 定义附件与回合元数据，按已核验字段投影，执行字节预算；附件抽取可拆成同目录纯函数模块                |
| `codex_desktop_ipc/adapter.rs`、`remote/codex_ipc.rs` | 只读历史取得、同代分页及鉴权后的 HTTP 输出；不增加写控制能力                                        |
| `remote/files.rs`                                     | 继续负责文件池与安全读取；给文件条目附加相同口径的身份键，原有字段兼容                              |
| `mobile/codexIpcApi.ts`、`useCodexThread.ts`          | 对齐 DTO，维护当前尾窗和同代历史页，处理会话切换及迟到响应                                          |
| `mobile/message-render.tsx`、新增附件组件             | 分别复用现有正文链接、渲染附件卡片；统一调用既有预览入口                                            |
| 新增文件关联纯函数与定位 hook                         | 合并来源和文件条目、执行总共五页的搜索状态机；`SessionDetail` 只负责接线、布局和滚动                |

数据流为 Desktop canonical state → Tuvis 附件投影／分页 → 移动端消息渲染与文件关联 → 现有 `/file` 预览。反向定位由文件身份触发，按当前页及最多四页更早消息查询，命中后交给消息区滚动。

服务层不反向依赖 HTTP 模块；文件身份只共享纯函数。实施计划细化新增文件名、函数签名和测试位置，不在大型页面里内联第二套路径规则或搜索编排。

## 三、数据与投影约束

### 3.1 真实字段证据先行

基线未包含上述五类 IPC item 的配套 observed 样本或 schema。编写详细实施计划前先核验目标 Desktop build 的结构定义或脱敏实样，再确定抽取字段；这属于执行者调查的事实，不是待用户重新选择的产品需求。

本轮已补充 macOS 安装包的静态字段读取证据，见 `../evidence/codex-desktop-ipc/2026-10-20-codex-artifact-field-evidence.md`；Windows 目标 build 的真实样本仍未取得，不能将该平台标为已验证。

- 合成 fixture 用于回归验证，不冒充实机字段证据。
- 衍生样本注明原始来源及改动，原始用户数据不入库。
- 无证据时明确申报该类型尚未核验，不通过猜字段宣称覆盖完成。
- 若真实结构与外部方案不同，先记录具体差异；涉及已确认产品语义的变化再请用户裁决。

### 3.2 消息与附件

在 `ProjectedMessage` 上增加可缺省为空的 `artifacts`，Rust 与 TypeScript 对齐。保留稳定消息身份，增加稳定回合身份，支持回合内编号和数量统计。

新增字段以兼容方式扩展。旧载荷没有 `artifacts` 时按空数组处理；旧客户端忽略新字段后，仍可读取原有文本。

附件保留来源类型、稳定附件身份、本地路径或外部 URL、回合内序号、摘要及不可用原因。路径展示值与关联键分开，关联键遵守现有文件池规则；文件已删除时仍能进行引用匹配，不能依赖文件存在才归一化。

文件池条目与附件都由后端提供同口径的 `fileKey`，前端仅以其做关联，不自行推断宿主平台路径规则。旧载荷缺少该键时保留原有路径链接和预览；无法证明同一身份的条目不猜测合并。

生成图、文件修改、图片查看仍按 canonical item 顺序投影；用户附件挂在所属用户消息上。只有附件、没有文字的用户消息也必须保留，开场后备消息及正式消息替换遵守同一身份规则。

“生成图 N”等通用标签由前端按语言生成；用户文件名保留原文。不可用原因使用可翻译的原因码。

### 3.3 预算

- 维持单线程镜像 16 MiB、全局镜像 64 MiB 的既有约束。
- 投影继续限制尾窗最多 500 条、1 MiB；新增附件元数据计入投影预算，不能只累计 `text`。
- 字段长度、单消息附件数量及分页响应必须有界；裁剪使用显式省略信息，不假装完整。
- 图片每回合最多展示 12 张；`fileChange` 每消息最多展示 6 个文件 chip；其余显示数量及文件池入口。
- 回合编号在翻页、重连及尾窗截断后保持稳定；前端展示限额不能替代服务端字节预算。

## 四、文件预览与反向定位

### 4.1 正文打开文件

IPC 正文复用已有 Markdown／纯文本链接渲染器，结构化卡片调用同一 `openFile`。宽屏分栏、窄屏全屏及从正文进入预览的返回规则沿用现状。

图片卡显示图片、序号和来源摘要；文档显示文件 chip；外部图片显示外链。路径缺失或预览失败显示原因，不静默删除卡片。

来源摘要优先取同一回合内、附件之前最近一条非空用户消息，空缺时使用已核验的附件摘要或 `revisedPrompt`，再空缺则显示来源标签。文件池摘要最多显示 24 字；翻页后不能因缺少前文而把上一回合用户消息猜作本轮提示词。

缩略展示当前只能复用原图读取接口，不代表服务器已提供缩略图。必须进入视口才加载、限制并发与缓存，取消无用请求，并释放 object URL。已缓存图片的复用与刷新不能把旧文件内容当作历史版本提供。

缩略图请求同时最多两个，离开视口且无消费者的 object URL 及时释放；缓存只用于当前页面的缩略展示。每次显式打开文件预览均走现有文件读取流程，不以缩略图缓存替代预览文件；切换会话清理该会话缓存。缓存淘汰策略在实施计划中确定。

### 4.2 最多五页查找

定位入口以文件身份为输入，执行以下流程：

1. 以动作发起时的最新投影尾窗为第一页，从尾到头检查可识别正文链接和结构化附件引用。
2. 命中即定位该页最近一次引用，并短暂高亮所在消息；同消息多次引用时优先定位最后一个对应节点。
3. 未命中且仍有历史时，使用当前最早消息游标读取下一页更早消息，每页最多 50 条，同时受响应字节预算限制。
4. 最多执行四次更早页读取。最多五页的计数是消息读取批次，不是手机屏幕高度；已缓存的更早消息也不能使本次搜索超出相同边界。
5. 真正到头或五页查完即结束，未命中只提示“最近五页消息中未找到引用”，不暗示该文件从未被引用。

无需为此建立全历史 path → messageId 索引。来源映射只作已搜索范围内的派生结果；未知来源的文件仍可发起同一有界查找，不伪造消息 ID 或来源摘要。

窄屏从文件预览定位正文时，先切回消息区，等待目标 DOM 可用，再滚动高亮。定位失败保留可返回文件预览的能力。

### 4.3 分页一致性

新增只读消息分页端点，复用远程鉴权及 session → thread 解析。移动端继续只消费 Tuvis 投影，不接触原始 Desktop IPC。

分页结果区分可继续、真正到头、历史尚未取得、不可用及游标失效。镜像受预算限制，不能承诺任意旧消息可读；游标未找到不能直接解释为到头。

SSE、当前尾窗和历史页使用一致的历史代际。切换会话、owner 换代或历史重建时，清理失效页和正在进行的定位；迟到响应不能回填到新会话。重叠消息以当前 canonical 投影为准，不把旧页按 ID 永久保留。

普通新消息到达不重新启动无限搜索；历史代际失效则结束当前动作并明确提示可重试。投递与加载失败不消耗成“已完整搜索的一页”来伪造未命中。

搜索状态分为查找中、命中、范围内未命中、历史不完整／加载失败、游标或代际失效。失败或失效立即结束本次定位，不自动重试到超过四次更早页请求，也不显示为正常未命中；用户再次点击是一次新动作。

### 4.4 文件池合并

已有后端文件条目优先；仅给缺失的结构化引用补条目。使用与后端一致的身份键去重，保留上传／生成／修改／查看语义；修改文件不能一律设为 `modified: false`。

补充条目的来源映射为：用户附件 → `user`，查看 → `tool_read`，文件修改 → `tool_write`，生成图 → `session_artifact`；生成等具体行为另以来源标签呈现。命中已有条目时沿用现有来源优先级和“写过后不撤销已修改”规则，不用较弱来源覆盖较强来源。

不把 IPC 消息顺序伪装成 rollout 的 `seq`。IPC 详情中，已取得本次五页范围内引用顺序的条目按最近引用倒序展示；没有该范围引用证据的既有条目随后显示，保持原后端顺序。补充条目参与同一引用排序，不用负数 `lastSeq` 决定先后。其他工具文件池排序不变。

同一文件在搜索范围内多次出现时，来源定位指向最近引用。显示当前文件内容，与定位历史引用各司其职。

## 五、现有权限与失败态

当前 `/file` 是全盘读取加敏感目录黑名单及大小限制，cwd 用于解析相对路径，项目目录不是访问边界。外部方案中的“项目外一律 403／allowlist”应据此纠正，本期沿用已有权限规则。

预览失败区分路径缺失、文件不存在、非文件、敏感路径、体积超限、读取或解码失败；不能把所有 403 统称项目越界。现有图片 5 MB、其他文件 500 KB 限制继续遵守。

本任务不修改 `docs/MASTER-PLAN.md` 和既有 IPC 冻结 spec，不扩展模式、权限或审批动作，不修改真实用量账本。

新增界面文案同步中文与英文，错误原因采用现有错误码及翻译机制；不提高错误码棘轮。新增 DTO 字段不能使旧载荷或现有来源筛选失效。

4. 给 IPC 正文接入现有链接渲染器，增加附件卡片、懒加载及资源释放。
5. 接入文件池合并、文件预览定位入口和总共五页的逆序搜索。
6. 完成自动化门禁，并分别申报 Windows 实机、macOS 实机和移动端验证结果。
7. 整理实现记录与跨工具 artifacts 跟踪事项；默认只做本地提交，推送、开 PR 或发布按后续用户指令执行。

必须覆盖的回归场景：

- 五类结构化来源、外链、缺失路径，以及纯图片／纯文档用户消息。
- 普通 IPC 正文复用已有文件链接，点击打开当前文件内容。
- 同文件路径的不同表达只合并一次，不同文件不错误关联。
- 同回合多 item 的编号、12 图／6 chip 上限、分页边界和超大元数据。
- 当前页命中、第二至第五页命中、五页未命中最多四次更早请求；最后一次引用优先。
- 已加载更早历史不扩大五页范围；仅正文链接出现的文件也能反向定位。
- 历史未加载、预算拒绝、游标失效、SSE 重连、owner 换代及跨会话迟到响应。
- 窄屏预览返回正文、文件来源／修改状态、图片视口加载及资源释放。

实施后运行 `pnpm test`、`pnpm check`、`pnpm build:mobile`，以及 Rust fmt、clippy、lib 和 IPC 相关集成测试。目标 Windows Desktop build 与实机证据保持绑定，未执行的实机项明确标记未执行。
