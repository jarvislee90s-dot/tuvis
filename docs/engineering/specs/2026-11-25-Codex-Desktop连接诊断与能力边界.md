# Codex Desktop 原会话远程操控 · 总体设计

本页是 Codex Desktop 新版专项的路线和**唯一完成台账**。当前候选收尾范围是 macOS 纯文本热修。已有 IPC 能力按原构建、实例和操作保持，不以 AX 候选覆盖。详见 [Mac 实现规格](codex-desktop-macos-text-hotfix.md)、[Mac 验收](../acceptance/codex-desktop-macos-text-hotfix.md)和 [Windows 交接](../acceptance/codex-desktop-windows-hotfix-handoff.md)。

## 0. 不变边界

手机对已打开的官方 App 原会话操作，不另起或迁移宿主。先确定当前宿主身份、操作契约和证据，再选择通道，不静默启动 CLI、无头、daemon 或恢复历史。版本及包指纹用于证据追踪，不把整台工具作为一个能力开关。操作可能已提交时只读核对，不换通道重发。苹果辅助功能候选只纳入经过授权的纯文本专测，默认关闭，正式开放仍按[项目宪法](../../MASTER-PLAN.md) F2.1、F2.5、F2.8、F2.10 和 D7 单独裁决。

## 1. 证据边界

- Windows 官方 Store `26.1120.6357.0`、常规启动的历史观察未发现可达且可归属的旧命名管道；`26.1117.4957.0` 是独立负向观察。两项均非 Windows 当前最新版结论，不代表已验证操作失败或所有入口已退役。[旧版 Windows 空闲异步答题验收](../acceptance/2026-11-04-codex-async-contract-windows-layout-acceptance.md)仅适用其记录的构建、通道和子项。
- macOS 官方 `26.1120.50957`／`30866` 的历史审计未在默认路径确认当时旧 IPC 为现有实例所用，也未找到可供第三方连接该常规启动实例的正式契约。公开 App Server 支持其自身连接与队列，不等于可附着原 Desktop 宿主。后续 AX 只读、隔离写入以及真远程纯文本手测另见 [Mac 验收](../acceptance/codex-desktop-macos-text-hotfix.md)。

## 2. 降级路径与展示

看板按归属显示已保存历史和已批准文件，在无远程写资格时仍可保留手机草稿。文件暂存不等于 Codex 收到附件。已落盘或旧投影不是当前回合、待处理或实时流的权威。已知的 Tuvis 本地待发项、历史卡片展示按各自保护规则保留，不把未知或上游已受理动作退回本地，也不在写入不可用时暗入队。

连接诊断、逐操作资格和此前动作结果分别展示。IPC 断开不否定已独立获准的 AX 发送，AX 权限也不保证写入。当前纯文本不代验其它写操作，各功能无证据时为不可用或未证。错误归属、短暂恢复与未决动作不能用历史能力打开。UI 只解释后端状态，不自行补权限。

## 3. Windows 接续

按实际构建重新核证旧 IPC、同一原会话定位、真实远程页和结果回读。最新版入口证实不可用或归属未知时先验安全降级，再独立评估受支持的新连接或 UIA。macOS AX 不参与 Windows，Windows UIA 在本候选没有生产写入实现。交测步骤及回填格式见 [Windows 交接](../acceptance/codex-desktop-windows-hotfix-handoff.md)。

## 4. 测试与准入

报告区分只读取证、隔离动作、真实远程手测和产品开放。真机只对本次明确获准的测试会话执行。对匹配、唯一目标、本机草稿、在途投递和回执分别取证，不以编译或直调接口代替手机。真实写入无法安全约束时停止，不通过改权限、猜按键、坐标、剪贴板或私有接口绕过。

## 5. 分阶段路线

| 阶段 | 范围 |
| --- | --- |
| P1 · macOS | 诊断、落盘接收、草稿和文件暂存独立验证。当前热修只收口已验的原会话纯文本，附件和少量问答审批留待各自取证 |
| P2 · Windows | 同一用户效果逐项复验，独立确认入口与适用构建。后续再考虑停止和附件扩展 |
| P3 · 交互 | 阻塞问答、空闲异步、命令与文件审批、原生题卡关闭分别验证 |
| P4 · 持续与复杂操作 | 同宿主实时快照和断线追平、运行中正式答题、引导、队列及原生设置 |

## 6. 完成台账

只勾已证的操作。人工手测、进程探针和自动化回归各记其范围。宏观目标不从子项通过直接推定。
