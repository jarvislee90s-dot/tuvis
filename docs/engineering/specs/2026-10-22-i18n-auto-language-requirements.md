## 1. 统一原则（三产物同一条，【用户裁决】）

1. **未手动选择过语言 → 自动跟随**：
   - 官网、桌面端：跟随**浏览器 / 系统语言**；
   - 远程端（手机页）：跟随**桌面端 APP 当前语言**；桌面语言不可得时，兜底**手机浏览器语言**；再兜底**英文**。
2. **手动选择过 → 一律以手动为准并记住**（自动跟随不再覆盖手动选择）。
3. **语言归流**：简体中文系（zh / zh-CN / zh-SG 等）与繁体中文系（zh-TW / zh-HK / zh-MO 等）一律显示**中文**（现有简体版本，不做繁体翻译）；其余任何语言一律显示**英文**。
4. **不做繁体中文翻译**（zh-Hant 归流简体版即可）。
5. **手动记忆独立计算**【用户裁决 U14】：桌面端与远程端（各配对设备）的手动语言记录是**各自独立的账本**，互不覆盖：
   - 桌面端手动切换语言 → 只改变桌面端自身语言，并影响远程端**无手动记录**设备的跟随（见 §5 M1）；**不影响已有手动记录的远程设备**；
   - 远程端某设备的手动选择 → 只作用于该设备的手机页语言，**不影响桌面端**语言。

### 功能需求

**语言跟随与记忆**

- **M1 跟随桌面端语言（仅作用于无手动记录的设备）**：已配对手机连接时，若该设备**无**手动语言记录 → 显示语言 = 桌面端 APP **当前**语言（该当前语言无论来自自动跟随还是桌面端手动切换，均跟随；桌面端手动切换会传播到无记录设备，§1.5）。桌面端换了语言，手机**下次连接**即跟上；该跟随**不作用于已有手动记录的设备**（M3 / §1.5 独立计算）。
- **M2 兜底链**：桌面语言不可得（未配对阶段 / 获取失败）→ 手机浏览器语言按 §1.3 归流（中文系 → 中文，其余 → 英文）；再不可得 → 英文。
- **M3 手动选择 + 配对设备记账**【用户裁决 U3】：
  - 远程端可手动切换语言（二值：中文 / 英文）；
  - **桌面端按配对设备逐一记录**「该远程端是否设置过手动语言选择 + 所选语言」；
  - 手机连接时：有手动记录 → **沿用记录，不随桌面语言变化**；无记录 → 按 M1 跟随桌面当前语言；
  - 手机上做出手动切换时，**同步给桌面端记账**；
  - 该记录**独立于桌面端自身的语言记录**【用户裁决 U14】：手机手动选语言不改变桌面端语言；桌面端手动切语言不覆盖本记录（桌面切换只影响无记录设备的跟随，M1 / §1.5）；
  - **重新配对的新设备视为无记录**（回到自动跟随）；
  - 该机制以「配对设备」为身份，**不随 IP / 网络变化丢失**（消解了浏览器本地存储按 origin 隔离的固有问题）。

## 6. 验收标准

### 6.1 通用门禁（远程端文案改造部分）

- **g1 键集一致**：`pnpm check:i18n` 通过（中英目录键集对齐）。
- **g2 无中文残留**：§5 范围清单全部文件中，中文文案字面量清零（扫描命令建议见附录）；豁免项（确需保留的原文展示）须显式登记。
- **g3 双语可切换**：每个涉及页面在中 / 英两语下完整可用，无漏网中文（含 toast / 错误提示 / placeholder）。
- **g4 a11y 文案不漏**：aria-label 等 a11y 文案同步双语化，英文为**等价描述**而非逐字直译。
- **g5 新错误文案走既有体系**：新增错误类文案不得绕过 `formatInvokeError` 双语体系私造硬编码。
- **g6 构建与既有测试全绿**：`pnpm check`、`pnpm build:mobile`、`cd src-tauri && cargo test` 全部通过（server 测试依赖移动端构建产物，先构建再测试为既有约定）。

### 6.2 官网场景（范围外，供独立实施后对照验收）

（验收基线地址：**https://tuvis.app**；下列根路径 / 深链场景均为该域名下路径。）

1. 英文浏览器首访根路径 → 英文版；zh-TW / zh-HK 浏览器首访 → 中文版。
2. 手动选择后记住，后续访问不被自动分流覆盖；自动判定结果不占用「记住」。
3. 外链直达 /en/...（或 /zh/...）深链 → 尊重来路语言，不被自动分流改写。
4. hreflang 含 zh / en / x-default 三条。

### 6.3 桌面端场景

1. 系统语言 zh-TW / zh-HK 首次启动 → 简体中文界面；系统语言 ja / de → 英文界面。
2. **未手动选择时**，改系统语言后重启应用 → 界面跟随新语言（U8 核心新增语义）。
3. 手动选择中文后，系统语言改英文并重启 → 仍中文（手动优先）。
4. 托盘菜单文案始终与界面语言一致（含切换语言后的即时重建）。
5. 手动切换多次（中 → 英 → 中）后重启 → 以**最后一次**手动选择为准（D2 / U14）。

### 6.4 远程端场景

1. 桌面中文 + 无手动记录的手机连接 → 手机页中文；桌面切英文后手机下次连接 → 英文（M1 跟随）。
2. 手机手动选英文 → 桌面记账；此后桌面保持中文，手机多次重连 / 换网络 / 换 IP 重连 → 仍英文（M3 记录优先且不随 origin 丢失）。
3. 该手机重新配对 → 记录清零 → 回到跟随桌面语言。
4. 未配对手机打开配对页：zh-TW 系统手机 → 中文配对页；英文系统手机 → 英文配对页（L1 + M2）。
5. 全部页面中 / 英双语完整可用（g2/g3/g4 清零）。
6. 标题与 PWA 名称在两种语言下均为「Tuvis 远程」现状不变（M6）。
7. 桌面端手动切英文后：无手动记录的手机下次连接 → 英文（桌面手动切换传播至无记录设备，M1）；已有中文手动记录的手机 → 仍中文（§1.5 独立计算：桌面切换不影响有记录设备）。
8. 手机手动选英文 → 桌面端界面语言保持不变（远程设备的手动选择不影响桌面端，§1.5 / U14）。

## 7. 明确不做清单

- 不做繁体中文翻译（zh-Hant 归流简体版）。
- 不做「恢复自动跟随」三态开关（二值即可，U6）。
- 不为「未配对手机提前拿到桌面语言」放松远程安全闸门（L1 保持）。
- 不翻译会话内容 / 终端原文 / 文件内容。
- 官网与桌面端不新增语言切换入口（沿用现有）。
- 不做桌面端与远程端语言记录的跨端同步或统一覆盖（两套记忆独立计算，§1.5；桌面切换仅作用于无手动记录设备的跟随）。
- 不修改 `docs/MASTER-PLAN.md`（宪法对齐：`MASTER-PLAN.md:175,257` 既定「移动 UI 复用 i18n」方向，本需求与其完全一致）。

## 附录：中文残留扫描命令建议（验收工具，供参考）

```bash
# 字面量三形态（双引号 / 单引号 / 反引号内含中文），代入范围清单文件；
# 本命令为宽松口径（命中含中文注释与「代码行 + 行尾中文注释」），命中后须逐条归类：
# 文案字面量命中应为 0，注释 / 裸文本命中经人工 diff 确认非文案后放行并登记
grep -n "[\"'\`][^\"'\`]*[一-龥]" src/mobile/<文件…>
```

注：JSX 裸文本（无引号中文）与中文注释无法用 grep 区分，由验收时人工过 diff 兜底（门禁 g2 的组成部分）。g2 的清零对象是**中文文案字面量**；中文注释不属清零对象，禁止以删除中文注释的方式通过门禁。
