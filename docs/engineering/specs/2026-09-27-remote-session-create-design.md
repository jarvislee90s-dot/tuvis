# 远程新建会话（session-create）设计 spec

> 日期：2026-09-27 · 状态：设计定稿（探测批次先行，编码批次待探测回传后另立计划）
> 背景动机：2026-09-25 手工实机验证了一次「主机开终端 → 起 claude → 注入首句 → 会话上板 → 移动端可收发」的完整链路（Test 目录实测，中文注入原文落盘无乱码）。本设计把这条链路产品化为移动端一键操作。
> 宪法裁决（用户 2026-09-26）：「远程新建会话」**提前为二期收尾功能**（MASTER-PLAN D 裁决 + F2.x 新条目，正文修订随编码批次执行）。三期红线「不暴露任意 shell」边界声明：仅限四家固定 CLI 命令（无参数拼接、无任意命令），目录受黑名单约束，不属于任意 shell 暴露。

## 1. 范围

四家终端 TUI 工具：claude / codex / kimi / opencode。zcode（APP 形态，M11 无头）与 dsh（web 宿主）不在本批。

平台：**Windows 先行**（全链实机交付）；macOS 后补。**Mac 通道档位已由探测定案（2026-09-27）：锚点式**——Terminal.app / iTerm2 / tmux 三路屏读全部实测可达且均有免焦点注入原语（Terminal.app「读不可达」的预期被推翻）；落位首选 Terminal.app 可见窗（与起窗语义一致），tmux 专用 socket 备选。定案细节见 `docs/research/refs/phase2-消息注入/2026-09-27-新建会话四家探测定案.md`。

## 2. 用户流程（移动端）

首页看板右上「+ 新建会话」入口 → 表单三步：

1. **工具**：四选一；未安装 / 未启用的置灰并标原因（数据源 = 现有 enabledTools ∩ 安装探测；安装探测 = PATH 解析（`where <tool>`）结果缓存，探测 P0 已取证四家解析路径形态）。实现备注（2026-10-03 裁决落地）：安装探测名单随 /host 载荷 `installedTools` 下发（探测单点 = `create::tool_installed`，与 session-create 工具门第三道同源），前端两名单分列置灰（「未启用」/「未安装」），服务端 400 `tool_unavailable` 兜底仍在。
2. **目录**：两种来源——
   - **候选列表**：`GET /create-projects?days=7`，项目 = 当前看板快照的 project_path ∪ session_archive 按 last_seen 过 7 天窗的 project_path，去重、按最近活跃排序、带工具集合。「7 天」是查询窗口（归档只增不删，与历史页同口径）。
   - **手填完整路径**：前端格式提示 + 服务端权威校验（语法合法；**v1 路径限纯 ASCII**（用户裁决 2026-10-02：非 ASCII 路径拒绝并回原因码 `non_ascii_path`，候选列表同规过滤——CJK 路径全链留后批）；盘符/卷存在——**首版仅本地卷，UNC/网络路径拒绝并回原因码**（网络凭据与时延语义不入本批）；**黑名单 = 文件读取凭据表（create 域策略扩展为全局段匹配）∪ 系统关键目录清单（create 专属新表）**；目录不存在则**递归创建**，无权限/受保护目录创建失败如实回执）。
   - 同项目同工具已有活跃会话 → **黄字提示**（服务端算好信号返回）：「该项目已有该工具的活跃会话，多实例下后续消息路由可能混淆（桌面域已实证配对交叉；远程投递将附加提示）」。
3. **首句**（可选）：默认固定探针 `hi`（四家会话文件均首条用户消息后才落盘，空回车不物化——探针是会话物化的必要条件）；用户可自填替换。

提交后**异步任务 + 进度态**：`校验 → 开终端 → 处置弹窗 → 注入首句 → 等待上板`；新会话卡物化后自动跳入会话页；总预算 90s（探测定案维持：实测最坏 codex 双框 ~23s，余量充足；分阶段各 30s），超时回执**分阶段失败原因** + 可重试。

## 3. API

| 端点 | 方法 | 语义 |
|---|---|---|
| `/m/api/v1/create-projects?days=` | GET | 候选项目列表（只读，gate 下） |
| `/m/api/v1/session-create` | POST | `{tool, projectPath, firstMessage?}` → `{taskId}`；校验失败 400（带原因码）；**全局单飞**——已有创建任务在执行时新请求一律 409 |
| `/m/api/v1/session-create/status` | GET | `{taskId}` → `{phase, detail?, sessionId?}`；phase ∈ opening_terminal / dialog_handling / injecting_first / waiting_materialize / done / failed（**校验是同步 400，不产生任务**——故无 validating 态） |

- **任务态为内存态，不持久化**：MAM 重启丢任务，手机端查不到（404）即引导重试。创建是一次性动作，不值得新表与迁移成本。
- **并发**：全局同时只允许 **1 个**创建任务在飞（进程发现与弹窗处置互斥语义）；重复提交 409。
- **审计**：`action=create`（成功 / 失败+阶段原因）；每次弹窗自动处置**逐条留痕**（锚点类型 + 所发按键）——「全自动 + 审计留痕」用户裁决（2026-09-26）的落点。

## 4. 创建管线（服务端状态机）

1. **校验**：工具在场；路径校验 + 黑名单 + 递归建目录；多实例黄字信号。
2. **起终端**：复用 resume 开窗机制，命令 = **裸工具名**（四家定案：`claude`/`codex`/`kimi`/`opencode`，双宿主 8/8 实测成立）。Windows：WT 优先（`wt -d <dir> cmd /k <tool>`，并入用户既有窗口开新标签——探测登记为可接受，清场只杀本标签进程树）/ conhost 兜底；macOS：Terminal.app `do script` 首选 + iTerm2（default profile + write text）备选。**环境红线：起会话一律带 `DISABLE_AUTOUPDATER=1`**（Mac 实测 claude 自动更新器会在 ~3 分钟后就地升级用户全局包，打乱锚点账本与用户环境）。实现形态定案：服务端 spawn 时对直接子进程显式设 env（Windows 传递链 S2 已实测：conhost / WT 两宿主 × 父继承 / cmd 行内两种形态 4/4 透传，证据 `mam-probe-m6r/evidence/create-probe/20260927-s2-envchain/`）。安全加固备注（2026-10-03 评审落地，create 与 resume 同规）：起窗载荷经 `where` 解析为**绝对路径**（cmd 解析裸名时当前目录优先于 PATH，spawn 的 cwd 恰是项目目录——同名恶意 .cmd/.exe 劫持面归零；元字符路径经 raw_arg 外层包裹引号，`Program Files (x86)` 类不拆解）+ 子 cmd 设 `NoDefaultCurrentDirectoryInExePath=1` 兜底。**该变量的会话级副作用（如实登记）**：终端窗口存续全程不搜当前目录且随子孙进程继承——用户在该窗口裸名调用项目目录内可执行体（如 node_modules/.bin 工具）不再命中，需 `.\` 前缀（与 PowerShell 默认行为一致的安全取舍）。
3. **进程锚定**：起窗后按「目标目录 cwd + 新进程」发现 TUI 进程并记 pid（实测 ~4s 出现；macOS 用 tab `tty` 属性 + `ps -t` 效果回查）；后续屏读 / 按键 / 注入全部锚定该 pid，不受同项目多实例干扰。
4. **弹窗处置（方案二，屏读锚点驱动）**：周期屏读（2s 间隔、单阶段 30s 窗，与探测采样同口径；Windows CONOUT$ 屏读层四家×双宿主实测全通；macOS `contents of tab`）→ 匹配**屏读锚点账本**（复用单一真源账本，新增「新建会话」场景槽位：信任框 / 更新提示 / 引导流 / 空闲输入框四类，锚文案与键序以探测定案表为准）→ 按类分派处置键；**见到空闲输入框锚才进入下一步**。**键序红线（探测实证）**：claude 信任框默认项是 `❯ No, exit`——必须 ↓+Enter，直按 Enter=退出；codex 更新框默认项是 `Update now`（动全局 npm）——必须字符 `'2'`（Skip），esc 无效、Enter 禁用；codex/kimi 信任框默认即信任项，Enter 直通；opencode 无信任框。锚匹配**换行容忍**（文案随窗宽换行）；claude idle 锚行随版本漂移（2.1.278/2.1.283 不同）——按锚点账本 2026-09-23 裁决以**同槽多文案**承接（各版锚行并入同一 idle 槽位，版本号仅作诊断备注、不参与筛选）；codex 残留更新横幅不构成 idle 排除条件；kimi `No session yet` 是新建特有锚（兼验确为新会话）。首装态不可自动处置（claude 403 网络墙 / codex 登录三选屏）→ 失败回执「未识别界面」兜底。连续 N 轮无命中 → 同兜底 + 现场快照落档 `~/.mam/create-evidence/`（产品态证据目录，审计行附路径）。实现备注（2026-10-03 裁决落地）：落档形态 = **末次屏读的文本逐行快照**（管线内已有逐行屏读，文本可 grep 可 diff；PNG 截图需另起 PrintWindow 通道，排障价值不抵增量）——文件名 `create-<taskId>-<时间戳>.txt`，task.detail 与审计 result（`failed:unrecognized_screen evidence=<path>`）均附路径。
5. **首句注入**：pid 锚定直调生产注入引擎（此时无会话 id，不走常规投递路径）；文本 = `{首句} [mobile 发起设备花名]`——设备身份在创建请求过闸时记录，服务端全程使用，**不依赖手机持续在线**。首句注入落 `action=send` 审计行（设备 = 发起设备，与常规投递同词表），「谁开的首句」可追溯。
6. **物化等待**：监看项目目录**新会话文件**出现 → **物化判据 = 首句戳命中**（探测定案：codex rollout 文件在信任处置时即创建，只看文件出现会假阳；实测注入→落盘 claude 2.4s / codex 4.4s / kimi 2.4s / opencode ~2.1s）→ 会话卡自然上板 → 回执 sessionId。**opencode 轮询红线：拷 db+wal+shm 三件套查副本**（写入进 WAL，主库 mtime 不动）。
7. **失败语义**：各阶段失败原因独立回执 + 可重试标注；**失败不自动清场**（已开终端窗口保留供用户查看现场，回执说明）。
8. **附带行为**：codex 0.160.0 起 hooks 审查框会**阻塞 composer**（实机修正，推翻原判「新建成功后不阻塞」）；处置=**核验式自动信任**——hooks.json 条目全为我方注册时发 '2'+enter 接受信任，混杂/存疑时 esc 跳过并回执提示（用户实机裁决 2026-10-02；核验判据=monitor::hooks::codex_hooks_all_ours，esc 后既有「信号健康度」提示继续引导用户信任）。

## 5. 配对不确定门扩展（附带修复项）

发现层暴露「同工具同项目 ≥2 进程」的配对不确定状态到会话数据；远程投递命中该态时回执**附加提示字段（不拦截）**。**与表单黄字是两个分层信号，不混用**：表单黄字（§2）= 同工具同项目**已有活跃会话（≥1）**，由 create-projects 响应的 `activeTools` 字段携带；配对不确定标记 = **≥2 运行进程**（投递域提示）。依据：桌面跳转域第四轮实机验收 3c 实证 codex 同项目双开两次静默锁错（issue #48 系），根因是发现层 pid 位置配对可交叉；远程注入路径共享同一 pid 产物且现无守卫（用户裁决 2026-09-27：门装上、提示不拦截）。

## 7. 验收

- 人工（C 段）：四家新建全链（含信任框路径）；更新提示路径；未识别界面报错路径；多实例黄字；路径边界（黑名单命中 / 盘不存在 / 深层创建 / 非 ASCII 拒绝 / UNC 拒绝）；审计逐条可查（create + 弹窗处置留痕 + 首句 send 行）。
- 自动化：`#[ignore]` 实机 E2E（新建 → 物化 → 戳命中全链，复用 m9r_e2e 模式）。

## 8. 不做清单

任意命令/参数（宪法红线）；macOS 编码交付（本批 Windows 全链；探测已定档 Mac 锚点式 + Terminal.app 落位，后补批直接消费探测结论）；任务持久化表；**无核验的** codex hooks 门自动信任（核验式自动信任见 §4.8——hooks.json 全我方才发 '2'+enter，混杂 esc 跳过）；同项目多实例的注入隔离（只提示不拦截，按裁决）。
