### 2.2 子代理文件形态（5.9.3 新增）

路径：`~/.workbuddy/projects/<mangled-cwd>/<parentSessionId>/subagents/agent-<agentId>.jsonl`

- `<parentSessionId>` 目录名 = 父会话 UUID（如 `d0de8a03-...`），可直接作为 `parent_session_id`
- 文件名 `agent-<agentId>.jsonl` 中的 `agentId` ≠ 行内 `sessionId`（两者都是 UUID，但不同）
- 行内身份：`sessionId`（子代理会话 UUID，每文件唯一）、`providerData.isSubAgent: true`、`providerData.model`、`cwd`、`timestamp`
- 用量位置与主会话一致：`message.usage.{input_tokens, output_tokens, cache_read_input_tokens, cache_creation_input_tokens?, total_tokens?}`
- 实测样本：`agent-9bf48a4f-...jsonl`，121 次请求，`sessionId=01a18a39-174c-7065-9d83-be2a4e76a0a0`，`isSubAgent=true`，`model=deepseek-v4.1-flash`，`cwd=/Users/jarvis/Documents/tuvis-worktree3`
- 个别文件同时出现 `agent-<uuid>` 与 UUID 两种 `sessionId`（`session-meta` 行用 agentId），取**带 `providerData.isSubAgent=true` 的 message/function_call 行**上的 `sessionId` 为准
- 首次出现时间：2026-10-27 23:02（`/Applications/WorkBuddy.app` 于 10/27 17:25 升级到 5.9.3）；10/24 及更早会话目录只有 `tool-results/`，无 `subagents/`

### 2.3 看板掉线根因（WorkBuddy 侧行为变化）

- 会话发现完全由 `~/.workbuddy/sessions/<PID>.json` 心跳驱动（[adapter/workbuddy.rs:24](../../../src-tauri/src/adapter/workbuddy.rs#L24)）
- 心跳必须 90 秒内新鲜（[workbuddy_parser.rs:41](../../../src-tauri/src/monitor/workbuddy_parser.rs#L41)），且 pid 存活、sessionId 严格 UUID、kind 非 prewarm（[workbuddy_parser.rs:402](../../../src-tauri/src/monitor/workbuddy_parser.rs#L402)）
- 实测：`sessions/35950.json` 的 `lastHeartbeat` = 07:38:22（`startedAt` +4ms），`sessions/36335.json` = 07:39:25（`startedAt` +18ms），此后两小时不再更新；对应 jsonl 一直写到 09:34
- WorkBuddy 5.9.3 CLI 打包代码（`app.asar.unpacked/node_modules/@genie/agent-harness/cli/dist-server/shared.cjs`）中，`SessionRegistry.register()` 写一次心跳，`startHeartbeat()`（30 秒刷新）**没有任何调用点**；属上游行为变化/回归
- 附带后果：心跳失效时 jsonl 尾部是运行中的工具调用（非 Idle），未读补偿按规则跳过 → 连未读卡也不产生
- **DB 活性可用**：`sessions.updated_at` 在运行中持续刷新（实测 12:00 为 11:57:26 / 11:57:45）；`last_activity_at` **不刷新**（冻结在 10:40:23 / 10:52:36，与心跳 `updatedAt` 同刻），只能作展示字段，活性判据用 `MAX(last_activity_at, updated_at)`。`deleted_at IS NULL` 可过滤已删会话；cloud 形态需同时接受 `deleted_at <= 0`（-1 为未删哨兵）。

### 2.4 既有产品契约（直接沿用，不是新决策）

- `is_subagent` 语义 = 「本会话自身就是子代理会话」；查询层 D17 分层：**会话数 / turn 数只计父会话，token 总量仍含子代理**（[query.rs:1006](../../../src-tauri/src/services/usage/query.rs#L1006)、[query.rs:1037](../../../src-tauri/src/services/usage/query.rs#L1037)）
- `usage_session` 的 `is_subagent` 是 `MAX(is_subagent, excluded)` 只升不降，`parent_session_id` 取 `COALESCE`（[dao/usage.rs:432](../../../src-tauri/src/database/dao/usage.rs#L432)）
- Claude 先例：子代理会话独立登记、`is_subagent=1`（[collectors/claude.rs:313](../../../src-tauri/src/services/usage/collectors/claude.rs#L313)）
- 当前 WorkBuddy 采集器只读主会话 jsonl（[collectors/workbuddy.rs:310](../../../src-tauri/src/services/usage/collectors/workbuddy.rs#L310)），`caps` 也仍声明无子代理概念（[caps.rs:68](../../../src-tauri/src/services/usage/caps.rs#L68)）

### 2.5 明确不是问题的部分

- 主会话采集完好（逐日与账本完全相等）
- TPS 链路准确（读 `~/.workbuddy/logs/<日期>/*.log` 的 `qua.end`，包含 `request_type: subagent:*`），本次不改
- WorkBuddy 工具在账本 `agent_tools` 中 `enabled=1`，看板不是被停用导致
- WorkBuddy 自身 `session_usage.credit_json` 只有 credit，不是 token 桶；不作为 token 来源

## 3. 需求

### R1（P0-A）子代理用量入账

WorkBuddy 采集器必须枚举并增量读取 `projects/<mangled-cwd>/<parentSessionId>/subagents/agent-*.jsonl`：

1. 每个子代理文件独立游标（游标键 = 相对 `~/.workbuddy` 的路径，与主会话同一 `file_key_of` 规则）
2. 明细行 `session_id` = 行内 `sessionId`（子代理会话 UUID）；`usage_session` 登记 `is_subagent=1`、`parent_session_id=<父会话 UUID>`
3. 用量四桶、model、cwd/project_key、provider、tool/error/interrupted 等口径与主会话完全一致；`model` 缺失时按现有 WbState 继承，绝不写 `model=""` 幽灵行
4. 同一请求不得重复入账（主会话文件中不存在子代理 usage；子代理各自独立文件）
5. 文件消失/轮转/截断按现有 `rescan`/`collect_with_home` 语义处理，不允许静默少算（沿用 W-06/D-24）
6. **历史回填**：新增子代理文件的游标首次从字节 0 读取（用户 2026-10-30 裁决：回填全部历史）；主会话既有游标不动

### R2（P0-B）看板心跳兜底

在心跳文件不新鲜（5.9.3 只写一次）时，仍能发现并渲染 WorkBuddy 会话：

1. 候选会话来源 = 心跳文件 ∪ `workbuddy.db` 中 `deleted_at IS NULL` 且近期活跃的 `sessions`
2. 在场判据 = 心跳文件存在 ∧ 内容 pid 存活 ∧ sessionId 匹配（**不要求 lastHeartbeat 新鲜**）；`status='working'` 时保持卡片；completed / DB-only 候选才用 DB `MAX(last_activity_at, updated_at)` 或主 jsonl mtime 的 300s 窗口
3. 去重键 = `sessionId`；优先使用心跳文件提供的 pid，无心跳时 pid=0（App 形态跳转走应用激活兜底）
4. 卡片状态：DB `status='working'` 且活性新鲜时**上拉为 Processing**（覆盖主 jsonl 尾部为 Idle 的子代理运行期）；其余情况仍由主 jsonl 尾部推导，避免子代理干活时父卡误绿/误 Waiting
5. 已结束/已删会话不得复活；不得与心跳路径产生双卡；沿用现有 kind/UUID/prewarm 过滤
6. 移动看板与桌面看板同源（`remote/server.rs` 复用 `adapter::get_all_sessions`），只需修一处
7. 心跳丢失补偿（W4）与活性判据**同源**：心跳失效且 DB/jsonl 均不活跃才算 vanished，防止活跃会话被提前补成未读卡；**正常完成（unregister 删除心跳文件）且 DB 状态不是 `working` → 立即补未读**，只有心跳文件残留但过期（崩溃/异常）才等 300s

### R3（回归保护）

1. 主会话用量数值不变（同一天采集前后主会话部分逐字节一致）
2. TPS、国际版、其他工具行为不变
3. 新增 5.9.3 真机形态夹具（子代理文件、DB 活跃时间、冻结心跳），禁止用旧 5.8.3 夹具冒充
4. `cargo test` / `cargo clippy` / `pnpm check` 通过

- AC1：修复后对 2026-10-30 数据重采，WorkBuddy 账本总量与 jsonl 真值一致（允许 ±1 个采集轮次的增量差）；主会话部分与修复前逐项相等

- AC3：10/30（09:40 快照）的 847 次子代理请求全部有账（抽检 3 个 agent 文件，requests 与 jsonl 内 `message.usage` 行数一致）
- AC4：两个活跃 WorkBuddy 会话在心跳冻结（07:38/07:39）的情况下仍出现在看板，状态与实际相符
- AC5：正常完成（unregister 删除心跳文件）后卡片/未读立即按完成态处理；心跳文件残留但过期（异常/崩溃）则等 300s 后下板（不复活、不残留）
- AC6：`~/.workbuddy-ai`、TPS 表、其他工具账目零变化
- AC7：新增/修改的测试在 CI 与本地均通过，且至少包含：子代理入账、父子归属、跨轮增量、心跳冻结兜底、已删会话不复活
- AC8：回填后历史日期（10/27 起）的子代理用量补齐；主会话部分逐日数值与修复前相等；首次采集的耗时与新增记录数记录在实施记录中
- AC9：子代理运行期间父卡显示 Processing（DB `status='working'` 上拉），不会长时间显示绿色 Idle

## 6. 关键决策（已裁决）

| 编号 | 决策 | 依据 |

| D2 | 子代理按「独立会话 + `is_subagent=1` + `parent_session_id`」入账；token 总量计入、会话数/turn 数不计 | 既有 D17 分层契约 + Claude 子代理先例，不新增产品口径 |
| D3 | 主会话采集逻辑与数值不变；主 jsonl 不含子代理 usage（实测 0 行 `isSubAgent=true`），无双计风险 | 真机核算 + 代码证据 |
| D4 | 看板在场 = 心跳文件存在 ∧ 内容 pid 存活 ∧ sessionId 匹配（**不要求 lastHeartbeat 新鲜**）；`status='working'` 时保持卡片；completed/DB-only 才用 `MAX(last_activity_at, updated_at)` ∪ 主 jsonl mtime 的 300s 窗口 | 心跳只写一次；`updated_at` 随父写入刷新、非独立心跳；08:05–08:15 十分钟父静默 + 子代理在写 |
