# ZCode 读取恢复、工具设置卡与统一远控界面设计

日期：2026-10-24。状态：**v3，按用户最新裁决整理，交付审阅**。同步产出分任务计划；本轮不修改产品代码。设置／读取可直接计划，官方协议身份／桥接设前置定案门，未封版部分不伪造完整施工单。

## 1. 本轮用户要求与设计修正

用户已明确：

- 恢复 ZCode 消息上看板；手机正文、文件等继续复用 Tuvis 已有读取能力。
- 设置顺序固定为：远程通用设置→四个通道→访问与安全（含设备列表）→工具特殊配置→无头注入相关配置→注入审计。工具卡默认折叠，首版只有 ZCode。
- 用户从 ZCode 应用内开启移动远控，复制链接或扫码取得链接，再粘贴保存；提供教程，不做网页自动引导或模拟点击。
- 官方链接不可用时，提示局限在配置输入框和手机发送／控制区；不关闭看板、正文或文件。
- 手机发送、审批、问答、打断、切模型／思考强度的 UI 希望统一为 Tuvis；按键底层复用官方控制链路。
- 官方页面这些功能已有用户约两个月的真实使用证据，不重复证明。
- 用户明确裁决：H3 无头注入与 Codex 兼容发送默认开启；保留用户已保存的显式开／关，不覆盖旧选择。
- 访问与安全的 4 位密码默认遮罩；眼睛按钮点击显示，再次点击遮罩；适合截图，不改变实际密码或配对状态。

**本稿替代 v1 的“仅打开官方页、Tuvis 不出现可写 UI”近期方案。** 现在的产品目标是统一 UI；外部官方页仅可作显式辅助入口，不作为默认偷偷代点的执行器。保存链接本身不足以完成统一控制。

已知证据与边界：

- 双平台新旧 ID 共存；旧 parser 门只接受 sess_＋UUID，新 session_＋32 hex 被拒。
- Windows 已运行新无头回合和自建取消；不等于 resume 或手机闭环通过，本轮不以该路线替代官方控制。
- 官方源码有审批／问答 broker、v4 resolveInteraction、session/stop。
- APP 本地 stdio 被 host 持有；官方 Web 远控经账号、SID、短期 token、relay 和 RPC bridge 到 APP。
- 官方 SID 可持久复用但会失效；用户新报告两个月前链接显示 Not Found。此截图不证明具体失效原因或固定 TTL。
- 官方页面可用不等于 Tuvis 独立客户端身份、连接和逐动作映射已成立。

## 2. 权威与文档关系

最高依据 docs/MASTER-PLAN.md，不修改。读取恢复属于现有能力修复；官方协议接入按三期 F3.3／相关模型设置范围归类，不假称 F2.3 CLI 无头已完成。GUI 自动点击不纳入正式实现（D7）。

旧接入 spec 的宿主、状态、未读、资源管理继续有效，ID 合法域按 §6 更新。#117 H7/H10 及其真实 hi 自动探针不在本轮接入路线；其他工具不因本稿改变。竞品说明漂移仍留待用户裁决，不改宪法。

现有探测报告保留真实来源和历史含义；旧设计审阅结论仅适用于 v1。本稿与当前分任务计划成套交付；实现前审阅两者，官方控制受前置定案门约束。用户手册和发版账本在交付时同步，不提前宣称功能上线。

## 3. 三种技术路线与取舍

| 路线                     | UI 与机制                                                                                   | 结论                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 外部页面导航             | Tuvis 保存链接，浏览器打开官方页，由用户操作官方 UI                                         | 已有用户实测；只能作辅助入口，不能满足统一 UI                                    |
| 官方协议适配             | Tuvis 的按钮→受配对保护的本机 API→ZCode 控制适配器→官方认证／relay／RPC→APP；事件回流 Tuvis | **统一 UI 的推荐路线，认证／客户端复用方式需最小验证后封版**                     |
| 隐藏浏览器／DOM 自动点击 | 桌面浏览器承载官方登录，再按 DOM 点击／输入并读取页面                                       | 本轮不采用：布局和登录状态耦合、审批／回执难以精确绑定，也不是 D7 允许的正式通道 |

手机普通网页不能直接读取／操作另一个 origin 的官方页面 DOM；嵌入 iframe 也不产生跨域控制权限，还受官方嵌入策略约束。桌面浏览器自动化技术上可以模拟点击，但不是“给同一按钮换一个参数”就等价于协议适配。

若官方提供可复用的客户端／SDK／类型和测试，优先选取相关模块或按协议实现最小客户端；不整体嵌入整个官网。源码可读不意味着每条链路已适合第三方直接使用，需记录模块边界、许可证和版本指纹。

## 4. 设置页：工具特殊配置卡

### 4.1 位置与布局（2026-10-24 用户最终顺序）

设置页“远程接入”大块内严格按以下顺序展示：

1. 通用设置（远程总开关、保活、本机名、来源标记等既有项）。
2. 四个通道及唯一展开的通道详情（不改变通道策略）。
3. 访问与安全：4 位密码、设备重置、已配对设备列表。
4. 工具特殊配置：折叠工具卡，首版只有 ZCode。
5. 无头注入：H3、超时、并发上限、Codex 兼容发送；两个偏好开关默认开启。
6. 注入审计（本大块最后）。

不新增侧栏一级分类，不拆散设备列表，不把 ZCode 配置当第五个通道。建议抽出无头配置与工具配置组件，保留现有 RemoteSection 前三段；在 SettingsPage 中与 AuditLogSection 按同一顺序装配。

首版只放 ZCode 工具卡：

- 收起头部：工具图标、ZCode、简短配置状态、展开指示。
- 默认收起；点击卡头展开卡内配置，不另跳独立设置页；键盘 Enter／Space 可操作，使用 aria-expanded／aria-controls。
- 首版不渲染没有特殊配置的空工具卡，不预建多工具配置框架。
- 展开状态为临时 UI 状态，链接设置独立持久化；折叠不删除设置／不触发连接。

### 4.2 展开内容

- 官方远控链接输入框、保存、删除；空白保存与删除同源。
- 保存失败保留已存值和草稿，错误紧邻输入框并关联可访问性说明，不只有 toast。
- 获取教程：在 ZCode APP 打开移动端远程控制→开启远控→复制链接（或从二维码获取）→粘贴。无需 Tuvis 自动打开菜单或网页引导。
- “查看获取教程”“打开官方页面”是显式动作；不自动扫描登录态、注册设备、打开／关闭用户 ZCode。
- 准备统一协议控制后，连接／官方身份状态放在同一卡内。**仅填链接不显示“已联机”**。

配置归属为运行 Tuvis 的主机；每台电脑首版保存一条 ZCode 设备链接，配对手机共享。首版桌面编辑，手机可从发送区看到更新说明；若需要手机编辑另行定范围。不是按配对手机 device_id 存一份。

### 4.3 链接校验与失效

保存校验仅判断格式：标准 URL、https、精确官方主机 zcode.z.ai、/remote/vN 版本化路径、非空唯一 sid、无 userinfo／非默认端口、长度上限 4096。已知身份字段不得重复，官方新增 query 保留，不因新增字段或 v5 路径强制更新 Tuvis。前后端校验单点在服务端，读取历史值同样复验。

格式通过≠远端可用；不保证一个月有效或只有大版本会失效。完整链接不写日志、公开文档或测试夹具。

失效证据分层：

| 状态                       | 确认依据                                   | 配置区提示                 | 手机控制区                      |
| -------------------------- | ------------------------------------------ | -------------------------- | ------------------------------- |
| 未配置                     | 本机无链接                                 | 输入框旁提示如何复制       | “请在电脑端配置 ZCode 远控链接” |
| 格式错误                   | 本地／后端 URL 校验                        | 输入框下具体错误           | 不下发坏 URL                    |
| 连接待确认／未认证         | 尚未完成官方身份／relay 就绪               | 说明待联机／待官方授权     | 保留草稿，显示连接原因          |
| 已确认设备／SID 不可用     | 官方接口结构化拒绝，或用户报告链接不能打开 | “请复制新的远控链接并更新” | 在发送位置提示更新；控制禁用    |
| 暂时离线／网络失败         | 连接超时／设备离线等可区分原因             | 显示相应状态               | 提示重试，不擅自判链接永久失效  |
| 仅打开外部页看到 Not Found | Tuvis 无法跨域读该页；用户手工反馈         | 可手工替换，不自动删除设置 | 不冒充 Tuvis 已自动检测具体原因 |

所有状态下，看板、正文、文件预览继续走已有读取链。不得在会话页上方整页报错、隐藏只读内容或把“未联机”当成“无消息”。

## 5. 手机统一控制 UI 与适配边界

### 5.1 用户界面

- 阅读区域复用现有 SessionDetail、消息和文件预览；修 ID 后恢复发现，不重建一个 ZCode 专用阅读器。
- 发送沿用 Tuvis MessageComposer 的布局／输入习惯，底层分派给官方控制适配器；不把 zcode 直接加入 CLI HeadlessKind。
- 审批／问答沿用 Tuvis 卡片视觉和交互结构，但请求字段、选项与应答必须来自官方新鲜事件，不固定造“允许／拒绝”字段。
- 打断、模型、思考强度沿用 Tuvis 控制区样式；选项取官方实际支持值，不只凭版本号或网页文字猜命令。
- 尚未有逐能力运行证据时，对应控制保持不可用并给就地原因；不能因为发送成功就一并开放审批和权限设置。
- 链接不可用时发送区保留草稿并提示更新；发送／审批等受影响，阅读不受影响。
- “打开官方页面”可作用户主动选择的辅助动作；不把官方页接管当作原生发送成功，也不默认同时建立两个客户端。

### 5.2 推荐的数据链

Tuvis 手机 UI → 本机已有配对认证的控制 API → ZCode 专用适配器 → 官方认证／token／relay → 官方 RPC／会话控制 → APP 目标实例。

反向：官方事件／动作回执 → 适配器的会话、请求和动作投影 → Tuvis REST／SSE → 控制 UI。

关键合同：

- 官方链接的 SID／MID 只是定位信息，不是完整官方身份。Tuvis 现有配对 cookie 也不是 ZCode JWT。
- 官方授权必须使用可行的官方流程，不从 Safari 跨域 cookie、其他进程内存、用户环境或日志偷取 token。是否有可复用授权入口及客户端模块，尚待接入级验证。
- 本机适配器持有一条上游连接，配对手机通过 Tuvis 使用；不让每个浏览器组件自行注册同 SID terminal。官方每 SID／role 单 owner 的规则可能使 Tuvis 与官方手机页面互相替换，必须展示真实连接状态并禁止无限互抢重连。
- 发送前必须把 Tuvis session ID 绑定到官方当前可写 session／workspace／实例；仅 cwd、标题或某张卡的 PID 不足以猜目标。
- 审批／问答绑定 session／turn／request（或 interaction）及连接代际；错目标、过期、已消费、重复动作不得误消费别的请求。
- 开始、已受理、完成、失败、取消、结果未知分开；超时／断线不自动重发原消息。
- APP 控制态以新鲜官方协议快照／事件为准；普通正文文件继续用既有磁盘读取。此处不改变终端 TUI 的屏读权威纪律。
- 授权撤销、换链接、SID／连接代际变更后，旧 pending 和迟到结果不得在新连接上生效。
- 官方凭据只留本机受保护存储；手机不拿 JWT／短期 token，不在 query／日志返回秘密。具体授权和保护存储方案未封版，不能先落默认读真实账号文件的实现。
- H3 无头 CLI 开关不决定官方协议是否可写；仍需 Tuvis 配对门、官方认证及逐能力守卫。

### 5.3 必须补齐的接入证据

不再探测“官方页面会不会发送／审批”。要验证的是第三方 Tuvis 客户端能否：

1. 通过明确授权取得官方身份，复用／实现其客户端和短期 token 流程。
2. 加入正确 SID 和目标工作区，收到可用于精准 session／pending 绑定的新鲜快照。
3. 单次发消息、批准／拒绝／回答、打断、切模型／思考强度，并取得各自可核对的结果。
4. 处理同 role 替换、断线、重连、链接失效、两台配对手机并发和结果未知。
5. 在 Mac／Windows 上以同一产品合同工作，保护真实数据与账号。

只读源码和用户的官方页面使用证据不足以替代这五项。当前设计产品目标已明确，但完整实现计划必须在授权／连接路线可行后才能冻结；可先确认并独立计划设置卡与读取修复。

## 6. 读取修复契约

主会话 ID 同时允许：

- sess_＋严格 8-4-4-4-12 ASCII hex UUID；
- session_＋32 ASCII hex。

保持现有 hex 大小写兼容，保留原 ID，不转写、不删横杠、不合并为同一键。继续保留 interactive、空 parent、24h 窗、上限、归档删除、工具启用、宿主、未读与隐藏各自规则。空字符串 parent 沿用现有视为空口径。

不改变合成条目过滤、子代理／后台仲裁、状态与已读规则。桌面 IPC 和手机 REST／SSE 使用同一聚合口，必须验证新 ID 正文和文件可读取。保留 SQLite L1 和有界查询，不引入无关扫描框架。

文件兼容现有 artifact URI 和历史 source.path；缺失的历史源文件如实不可用，不全盘搜索补齐。正文展开显示项和附件引用序号须对齐同一消息来源，具体缺口实施前定位；不扩展未证实的新附件来源。

## 7. 默认值与密码可见性（用户已裁决）

### 7.1 H3 与 Codex 兼容发送默认开启

两个独立设置：remote.headless_enabled、remote.compat_send_enabled。统一规则：

| 存储值                         | 结果                              |
| ------------------------------ | --------------------------------- |
| 缺键（新装或升级后的未配置项） | true                              |
| 字符串 true                    | true                              |
| 字符串 false                   | false，保留用户明确关闭           |
| 空串／其他非法值               | false，标为异常值；不猜成用户允许 |

不写全表迁移、不把所有旧 false 改 true、不自动调用 toggle 伪造用户操作审计。代码读取缺键采用新默认；保存时仍写显式 true/false。超时 600000ms、并发 2 及合法区间保持现状。加载中用 loading／disabled，不以 false 默认值短暂展示“用户关了”。

Codex 兼容发送的“偏好开启”与“当前可用”分开：保留 read-chain/build/owner/设备/pending/投递证据等既有守卫；默认开启不等于允许未知审批、修改权限或自动重复发送。已验证 build 的原有行为不因此改道。用户明确关掉 H3 时，依赖该通道的兼容路径仍按后端规则不可用，UI 就地说明；官方 ZCode 协议适配不依赖 H3。

历史默认关源于后台 CLI 直驱与旧 ZCode yolo（裁决 10/14）；本轮用户已明确变更新默认，两份设置文案、后端解释函数、测试和升级说明同步更新，旧共享设计仅保留历史含义。

### 7.2 4 位密码眼睛按钮

访问与安全的密码框初始为 password 类型，显示四位掩码；点击眼睛切为 text，再点切回。底层值仍为原四位数字，数字过滤、随机生成、保存和设备重置合同不变。

- 状态仅在当前设置页内存，不落库、不写日志、不改变 PIN、不触发重新配对。
- 切换按钮 type=button，aria-label 为显示密码／隐藏密码，aria-pressed 反映当前可见；键盘可操作。
- 页面初次进入、离开再返回、切换设置大块或窗口失焦时恢复隐藏，避免重新打开截图时仍显示；轮询刷新不把隐藏状态改为显示。
- 隐藏时仍允许编辑／随机／保存；这几种操作不自动揭示密码。
- 不是对输入框内容加 CSS 模糊；密码值不出现在新增可见 label、title、提示文本或测试快照中。
- 这是本机设置页的显示保护，不改变协议中配对校验或二维码原有行为；不暗改分享入口。

## 8. 验收范围与暂缓项

- 六段顺序严格满足 §4.1；设备列表仍在访问与安全；仅有 ZCode 卡且默认折叠；注入审计在最后。
- 教程描述应用内开启远控和复制／扫码，不做虚假的网页自动引导。
- URL 格式／持久化／替换／删除／坏值不下发，字段错误就地显示。
- 只读内容不因控制状态变化消失；新旧 ID 混存、过滤、正文和附件引用正确。
- 官方协议连接后仅启用已验证的能力；UI 样式统一不等于未知命令可直接发送。
- 动作精确归属、断线／迟到／重复请求、账号／设备代际隔离、无自动双发。
- 官方页面“Not Found”不被当成 Tuvis 能跨域读取的信号；协议可判原因和用户反馈分开。
- 不新增隐藏浏览器自动点击，不默认采集真实账号凭据，不改 MASTER-PLAN。
- H3 与 Codex 兼容默认开启按 §7.1 验证；明确 false 保留，非法值保守关闭，资格守卫不被绕过；密码眼睛不产生存储／配对副作用。#117 CLI 移植仍不是 ZCode 本轮路线。
- 配套计划 A 可实施设置／读取；计划 B 先验证第三方授权／连接／精确动作合同，不把未知 wire 或凭据来源留给后续任务猜。
- 初期不需要用户操作的单测、假 relay、源码对照由 Agent 完成；官方登录／配对由用户本人完成。使用用户提供链接配置不意味着默认同意向生产会话发送或审批；真实动作仅在用户指定测试会话和批准的实验范围内执行。

## 8.1 分阶段验收与人机分工

- 第一段（编码前／接入骨架阶段）：确认可用官方授权方式、角色 terminal 的认证／relay／bridge、SID 到目标 session 的绑定和逐能力合同。先源码＋假服务，再由用户本人官方登录／配对，使用专用测试会话做最小闭环。该门不过，协议生产适配和可写 UI 不开放。
- 第二段（编码期间）：任务内单测／fake relay／断线／错目标／重复应答用例，由 Agent 自动执行，不需要用户反复参与。
- 第三段（末期集成）：用户在手机确认 UI、指定测试工作区／会话；Agent 按已授权范围测试发送、审批、问答、打断、模型／思考强度。只要能通过现有已授权工具完成，就不要求用户代点每一步；登录／扫码及本人账号授权仍由用户操作。
- 第三段不重复证明官方网页已有能力，而是证明 Tuvis 的独立客户端、状态、回执和界面闭环。
- 连接冲突、设备不存在／旧链接、临时离线各按就地控制提示处理；只读功能持续可用。

## 10. 追加裁决：ZCode 授权凭据持久化（2026-10-27，本批）

本节覆盖 §5.2「官方凭据只留本机受保护存储」中此前未封版的落点，只规定账号 JWT 的保存与恢复；
不改官方协议、不改读取链、不改能力闸，也不改 `docs/MASTER-PLAN.md`。

### 10.1 方案 A：账号 JWT 落系统保险箱，进程重启后恢复

| 项 | 裁决 |
| --- | --- |
| 保存位置 | **系统凭据保险箱**（macOS Keychain / Windows Credential Manager / Linux Secret Service）；单条目、单账号，不落 settings、SQLite、文件或浏览器存储 |
| 保存内容 | `{schemaVersion, provider, jwt}`；不含 terminal token、SID、正文、设备 cookie |
| 内存副本 | 仅 `AuthService` 受控字段持有，供现取 terminal token；不实现 `Debug`、不序列化给 IPC／手机、不进日志／错误文本 |
| 恢复入口 | 启动接线先 `restore_authorization()`（非阻塞、只读保险箱），再启动既有自动连接 worker；显式「连接」也允许先恢复一次 |
| 自动连接 | 用户自动连接意图（`remote.zcode_auto_connect`，缺键 = true）与远程总开关、已保存链接同时满足才自动连接；恢复授权本身不连接、不 OAuth |
| terminal token | 仍每次连接现取、只在内存、用后即弃；不持久化、不跨进程复用 |

**首次升级需授权一次**：旧版本（含 B1–B4 探针与旧产品构建）只把 JWT 放内存，没有持久记录；
升级后第一次启动恢复只会得到「无记录 → 需要授权」，用户必须在 ZCode 卡完成一次官方授权。
这次授权成功后 JWT 才写入保险箱，**后续进程重启不再要求重新授权**（除非过期、撤销或用户忘记）。

**本批与旧探针的关系**：旧探针／旧 run 的「JWT 仅内存、进程退出即弃」结论只描述**当时的实现与取证口径**，
历史报告与 run 记录原样保留、不追改；本批生产装配采用方案 A，`contract.json` 的
`auth.credentialPersistence` 同批注明这一分界。两者不是矛盾证据，而是不同时间点的实现事实。

### 10.2 断开、暂停与忘记的区别

| 用户动作 | 连接 | 自动连接意图 | 持久凭据 | 链接 | 结果 |
| --- | --- | --- | --- | --- | --- |
| 「断开」 | 立即断开 | 持久写 `false` | **保留** | 保留 | 重启后不自动连接；手动「连接」或重新「授权」可恢复 |
| 远程总开关关闭 / KICKED | 断开／停 | 关闭：不改；KICKED：写 `false` | 保留 | 保留 | 总开关重新打开才可能自动连接；KICKED 停在本轮冲突 |
| 「忘记授权」 | 立即断开 | 持久写 `false` | **删除** | **保留** | 重启后无记录、不恢复、不连接；需重新授权 |
| 换／删链接 | 断开旧连接 | 不改 | 保留（换链接不重新 OAuth） | 新值／空 | 按新目标连接；删链接后停在「需要配置」 |

删除失败（`delete_failed`）或保存失败（`storage_failed`）必须如实显示，不得假装已记住／已删除；
删除失败时本进程仍保持「已忘记、不恢复」，新授权保存成功才重新允许恢复。锁定／不可访问
（`locked_or_denied` / `unavailable`）、记录损坏或超限（`invalid_record` / `too_large`）时只报原因，
不自动打开浏览器、不静默重试、不把旧记录当成有效身份。

### 10.3 失败提示与手机边界

- 卡面区分「正在恢复授权 / 已记住授权 / 已授权但未连接 / 本次授权可用但未记住 / 存储不可访问 / 记录无效或过大 / 需要重新授权」；
  无记录时是「需要授权」，不是「已连接」或「离线待重连」。
- 授权过期／被撤销（401）时删除持久记录并回到「需要重新授权」；网络错误／5xx／403 不删除凭据。
- `AuthStatus` 仅桌面 IPC；手机只读既有 `ConnectionView`，**永远不拿 JWT、terminal token 或保险箱原文**；SID 只是定位信息，不是官方凭据；手机动作仍经本机配对门与能力闸。

### 10.4 验证口径

- 自动化：`wire_e2e` 以同一回环假官方 + 同一 fake 持久存储，**重新构造** AuthService/Hub 模拟整进程重启，
  证明 OAuth 仍一次、terminal token／WS 每次连接重新发生、断开／忘记后重启零上游、恢复不放开能力闸。
- 平台：真实系统保险箱读写、真实官方 OAuth 与真实进程重启必须在 macOS／Windows／Linux 各自实机验收；
  未跑的行在验收报告里保持 `awaiting_platform_validation` / `not_run`，不以 fake 结果标 PASS。
