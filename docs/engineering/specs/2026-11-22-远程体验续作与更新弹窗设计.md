## 2. 消息送达、核销和插队

- 继续使用 [正式归账入口](../../../src-tauri/src/remote/codex_ipc.rs#L4176)。动作身份以唯一的正式 `userMessage.clientId` 为首要依据，核对线程、动作、尝试和回合，再提交回执、补绑内存占位并同步远程视图。参数回显、任意历史同文、多义哈希或缺失身份时保持 `Unknown`，禁止自动重发。
- 精确终态证据使 `verified_complete` 与该动作的 DB fence [同事务提交](../../../src-tauri/src/database/dao/codex_actions.rs#L1361)，提交后 [按所有者清理内存](../../../src-tauri/src/services/codex_control/router.rs#L1281)。旧动作的证据不得清掉新动作。提交失败保留原限制，提交后的内存缺口由对账修复。现有[兼容终态分支](../../../src-tauri/src/remote/codex_ipc.rs#L1644)可以清理屏障，保留 `Unknown`，且未统一落 `verified_complete`。先明确兼容证据能核销的范围，再决定如何补齐记录。
- [显式插队的 HTTP 路径](../../../src-tauri/src/remote/codex_ipc.rs#L6619)应让无关历史对账退出前台关键路径。线程 idle、无真实 writer 且选定条目仍合法时，历史对账延迟不应阻挡该条。active 时仍须复核 `expectedTurnId`，确认对应回合停止后发送。停止结果未知应零写入。保留锁、单条授权事务和排队暂停语义，旧 Unknown 的送达事实照实保留。
- 首次漏确认单列调查。取证聚焦初次确认窗口、正式回显到达顺序和动作关联。续作验收覆盖 active 时仅收敛送达，终态后精确放行，旧 A 迟到不影响新 B，事务失败可恢复，历史对账超时仍能单条插队，以及真实 writer 最大并发为一。

## 3. 文件诊断与容量

- 在[统一读取入口](../../../src-tauri/src/remote/files.rs#L142)区分权限拒绝、缺失、非普通文件和其他 IO。保留相对会话 cwd、canonicalize、普通文件检查、只读访问及设备总闸门。验证 Temp PNG、原目录限制涉及的隔离样本、无有效 home 和真实 ACL 拒绝。[创建会话路径](../../../src-tauri/src/inject/create_path.rs#L92)继续按 D21 校验，HTML 预览继续隔离脚本与凭据，产物响应继续使用既有内容与缓存约束。
- 扩容候选值按净字节计。文本完整预览 10 MiB（10,485,760 字节），图片预览与每个上传文件分别为 50 MiB（52,428,800 字节）。容量定案后，同步预览常量、附件引用检查、HTTP body limit、普通消息与 ZCode 两处上传校验、双语阈值和错误提示。现有 XHR 按单个 `File` 原始字节上传，保留逐文件进度、取消和独立失败。
- 定案后的验证包括等于阈值、超一字节、`stat` 后增长以及路由提前返回的 HTTP 413。大文本按预算提供完整可读的纯文本，明确指出超限，严禁静默截断或返回空内容冒充成功。上传 50 MiB 文本成功与其预览超过 10 MiB 分别呈现。图片保留懒加载、有限并发和对象 URL 回收，并实测渲染与传输开销。

## 4. 会话列表控件归属

- [会话详情](../../../src/mobile/SessionDetail.tsx#L1856)的共享书签栏以当前可见消息源决定是否展示通用过程折叠开关。App 投影激活时，普通与分屏布局均隐藏只操作通用缓存的控件。切回 CLI、ZCode 等通用分支后，展开实际作用于可见内容。
- 通用消息仍可在列表顶部加载更早历史。每次扩窗 200 条，最多 1000 条，加载后保持阅读锚点。回最新按钮距底大于 240 像素显示，点击只滚动。Codex 投影保留健康和截断提示，文件定位仍可沿原游标加载历史。
- 使用超过 200 条同时含可折叠过程消息的通用缓存测试 App 投影。覆盖普通与分屏布局、源和会话切换、通用历史加载保锚，以及投影文件定位分页。

## 5. Windows 更新弹窗裁切

用户截图中升级弹窗在窄矮窗口里被上下同时截断。在 Windows 上使用仓库自带更新模拟数据、480 × 390 CSS 像素浏览器视口复现。修复前卡面跨越约 `-66.7…457.0px`，标题、关闭按钮和“忽略本版本”被裁。共享弹窗居中时，更新组件只有说明正文的 224 像素限高，整张卡仍可超过视口。

- [升级弹窗](../../../src/components/common/updater-dialog.tsx)的整卡高度按动态视口限制，上下预留边距。优先缩小并滚动说明正文，说明滚动状态随窗口尺寸和正文尺寸更新，标题、关闭和操作区保留在可视范围。
- 矮窗口减少卡面内边距。宽度够时横排三个动作以给正文留出空间，更窄时维持竖排，极端低高度允许整卡滚动到剩余内容。
- 以启动更新提示和关于页手动入口验收。覆盖窄矮窗、窄窗竖排、常规窗、滚动到底和“稍后”关闭。标题、关闭和“立即升级／稍后／忽略本版本”应可达。下载态按现有行为显示进度和禁关语义。浏览器验证和 Windows 原生 WebView2 安装包验收分别记录。

浏览器回归覆盖启动和关于页手动入口、480 × 390 横排、360 × 360 竖排、1280 × 720 常规尺寸、滚动到底和“稍后”关闭。紧凑布局修复后，360 × 360 的滚动提示及三个动作均完整可见。下载时禁关由组件测试覆盖。Windows WebView2 145 隔离宿主验证了约 500 × 400 的关于页和约 800 × 600 的主页渲染。Tauri 应用的真实窗口仍待复测，当前已安装实例持有单实例锁。见 [验收截图和测量](../evidence/2026-11-22-updater-dialog-acceptance/)。
