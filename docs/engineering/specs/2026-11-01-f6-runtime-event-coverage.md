# F6 运行时事件覆盖能力表

## 现状与目标

Scan Bus 当前把 `dsh`、`openclaw` 固定列为无事件覆盖工具。`workbuddy`、`zcode` 因而可能在进程仍运行时进入 Away 30 秒档；钩子配置注册状态也没有进入 cadence 判定，Kimi helper 缺席或注册失败时仍会被当作有事件信号。bash hook 对同一 sid 使用原地重定向，Idle 会话不在逐文件 mtime 监控集合时，事件目录 mtime 不变，可能漏掉下一回合。

本组补齐逐工具覆盖契约：覆盖表明确每个已登记工具的唤醒来源；需要运行时 hook 的工具只有在当前启动配置核验通过或注册成功后才视为已覆盖；缺少可靠唤醒信号的运行工具或活跃会话将 cadence 限制在 Idle。bash hook 对已有 sid 也以同目录原子替换发布事件。

## 覆盖表

| 工具 | 唤醒来源 | 覆盖判据 | 无覆盖时 |
| --- | --- | --- | --- |
| Claude | Hook 事件目录 | 当前生效命令所需产物存在（helper 直启，或 bash 脚本内容等于托管版本），配置核验通过或注册成功 | 运行中/有活跃会话时 Idle |
| Codex | 保守兜底 | TUI 的 hook trust 状态无法由应用可靠读取，配置注册不等于事件可运行 | 运行中/有活跃会话时 Idle |
| OpenCode | 固定文件 | `facts.jsonl`、数据库与 WAL 的 mtime 监控 | 维持固定文件覆盖 |
| OpenClaw | 无可靠低成本信号 | 固定表声明 | 运行中/有活跃会话时 Idle |
| Kimi | Hook helper | helper 可用，配置核验通过或注册成功 | 运行中/有活跃会话时 Idle |
| WorkBuddy | 无可靠低成本信号 | 固定表声明 | 运行中/有活跃会话时 Idle |
| ZCode | 无可靠低成本信号 | 固定表声明 | 运行中/有活跃会话时 Idle |
| dsh | 无可靠低成本信号 | 固定表声明 | 运行中/有活跃会话时 Idle |

覆盖表必须与 `adapter::TOOL_IDS` 完全相等。未知工具也按未覆盖处理，新增工具不能静默获得 Away 档资格。活跃会话仍直接进入 Active；Idle 会话本身不算活跃，但其所属工具进程在跑时仍触发未覆盖兜底。无进程且无活跃会话时不因工具曾安装而限制节奏。

覆盖表分类所有已登记工具；实际 cadence 兜底只针对设置中已启用的工具，因为既有 W5 契约规定未勾选工具不参加会话扫描。用户停用 WorkBuddy/ZCode 时，即使桌面进程仍开着，也不为它们额外降低全局扫描间隔。

## 运行时状态

- Claude 与 Kimi 的覆盖状态只在当前进程内保存；新进程启动时默认为未覆盖。
- `register_all_hooks` 在注册循环开始时先清空本轮 hook 覆盖状态。仅当当前生效命令所需产物存在（bash 脚本内容匹配托管版本，或实际直启的 helper 在场），且配置已核验或本轮注册成功时，才将 Claude/Kimi 标记为覆盖。
- 缺 config path、读取失败、Kimi helper 缺席、注册失败均保持未覆盖。
- Codex 即使配置已写入也不标为覆盖：当前没有可读的 TUI trust 状态；在该状态可观测前继续用 Idle 兜底。
- OpenCode 由现有固定文件监控提供信号，不与 hook 配置状态耦合。
- 脚本写入失败但旧文件仍存在时，按文件内容是否匹配当前托管脚本判断；旧原地写版本不能算覆盖。

## Hook 文件发布

bash hook 通过白名单校验 sid 后，在 `events/` 内使用唯一临时文件写完完整 JSON，再 `mv` 到 `<sid>.json`。临时文件与目标文件同目录，使替换具备原子可见性并更新目录 mtime；写入失败时清理临时文件。原生 helper 已有同目录临时文件加原子替换，本组保持其行为不变。

## 冷启动事件对账

冷启动扫描读取 hook 事件与 wakeup 线程建立首个文件签名之间存在时间窗口：窗口内新写入的事件会被首个签名吸收，后续比较无法发现。wakeup 线程首拍仍先建立基线，但必须随即请求一次 Event 对账扫描；该请求经 Scan Bus 单飞/合批处理，覆盖冷扫描读事件后的写入。没有实际变化时最多多一次启动扫描。

## WorkBuddy 宿主发现

WorkBuddy 的 adapter 会话进程只由新鲜心跳驱动，因此“无新鲜心跳”不代表桌面宿主已退出。对已启用的 WorkBuddy，Scan Bus 复用本轮两段刷新后的共享 `System`，通过既有宿主判定补入运行工具集合；不新增进程刷新线程。WorkBuddy 已运行且暂时无心跳时仍锁在 Idle；任务会话变活跃后仍直接升到 Active。

## 边界

- 不增加第二套进程扫描，不新增固定文件监控面，不承诺无信号工具的 1 秒唤醒。
- 新开的已启用无信号工具在首次被 Scan Bus 发现前，仍受现有 Away 周期的启动发现延迟；WorkBuddy 宿主一经共享进程快照识别，即使没有新鲜会话心跳也切到 Idle。缺少低成本事件信号的首次发现延迟仍存在。
- dsh / OpenClaw 已有 Idle 兜底保持不变。
- 本组不改 F6 R-1 清理并发语义、500ms 合批或 5 秒事件期限；这些属于后续独立组。

## 验收

1. 覆盖表与所有已登记工具一一对应，所有 hook 工具只有当前启动的可用注册状态才能算覆盖；未知工具保守视为未覆盖。
2. Kimi helper 缺席、缺配置、注册失败时保持未覆盖；Claude/Kimi 核验或注册成功时记为覆盖；Codex 始终保留 trust 兜底。
3. 已启用的 WorkBuddy 宿主运行但没有新鲜心跳，以及已启用的 ZCode 宿主运行时 cadence 目标不进入 Away；空闲宿主启动任务后仍由 Idle 周期发现，会话活跃后照常进入 Active。未启用的工具不影响 cadence。
4. shell hook 对已有 sid 使用同目录原子替换；Idle sid 不在逐文件监控集合时，替换仍改变事件目录签名并触发唤醒。
5. wakeup 首拍对账扫描只触发一次；冷扫描之后、首个文件签名之前写入的事件不能被基线吸收。
6. 相关 Rust 与前端检查通过；不启动真实应用、不写用户事件目录。
