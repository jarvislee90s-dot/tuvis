# 交互卡 UI 裁决

## 2026-09-24 · 审批与问答统一蓝系（已被 2026-10-28 取代）

- 背景：审批/问答/计划多套卡交互不一致。
- 决定：审批卡与问答卡统一为 sky 蓝系、纵向编号列表。
- 状态：superseded；`superseded_by: 2026-10-28 审批红/问答蓝`。

## 2026-10-28 · 选择题蓝卡、审批卡红卡

- 决定：问答/选择题使用蓝色 `InteractiveCard`；审批使用红色 `approve` token；CLI 与 Codex 共用同一容器/选项行。
- 后果：覆盖 2026-09-24 的蓝系裁决；计划待确认等独立形态不强行套审批红。
- 状态：active；`supersedes: 2026-09-24`。

## 2026-10-28 · 底部只放有效卡：一张展开 + 其余一行

- 决定：只有当前可答组，或本机有 action 锚的待核对组进入底部；一张完整卡展开，其余有效组收成一行切换；卡片保持挂载以保留草稿。
- 后果：不再有历史区、分组 tabs、inbox 折叠；已答组自动退出。
- 状态：active。

## 2026-10-28 · 单选可见选中态、下一题紧凑

- 决定：选中样式由 `checked` 独立驱动（单选也可见）；`[✓]/[ ]` 字形只在真实 multiSelect 下出现；上一题/下一题使用小号紧凑按钮。
- 后果：不再出现“点了但看不出选哪项”；多选不伪造。
- 状态：active。

## 2026-10-28 · 不再提供历史/正文退路入口

- 决定：移除历史区、忽略/收纳、按组 tabs；无 action 锚的 Unknown 不展示；已提交 Unknown 只留只读核对。
- 后果：这是用户接受的简化；不承诺 Desktop 原 Question 清卡。
- 状态：active。
