# 裁决：H08 冷历史窗口放宽为「有界补读」

日期：2026-11-06。裁决人：执行控制器（依据 `AGENTS.md` 既有预算条款，非新增授权）。

## 冲突

`src/monitor/subagents/dsh.rs` 的严格扫描要求**全目录 ID 唯一**才能证明子任务归属。
原实现对 mtime 超过 24h 且无缓存命中的日志直接「不读、整轮覆盖不足」，
导致**旧会话的子 Agent 永久不可见**——这是功能缺口，不是环境限制。

同时，既有测试 `cold_aged_header_is_skipped_before_data_read` 断言「超窗必须零字节读取」，
与放宽直接冲突。

## 裁决依据（引 AGENTS.md 原文）

> **预过滤反模式禁令**：窗口判定必须发生在**打开/解压文件之前**——先 `stat` 代际文件
> mtime，超窗**且无缓存命中且无活动进程回退需求** → **不解析**（文件直接不读）。

条款给「跳过」设了**三个并集条件**。「有活动进程回退需求」正是子 Agent 归属判定的场景：
用户在界面上正查看某个活跃父会话，要求列出它的子任务，这就是一次明确的需求。

因此放宽**不违反**条款精神；真正要守住的是「不无界解析」。

## 裁决内容

1. 超窗且无缓存的日志**允许补读**，但受 `COLD_FILL_LIMIT = 512` 硬上限约束；
2. 超过上限 → 仍返回「覆盖不足」（fail-closed，**不发布未经完整核验的归属**）；
3. 读取仍是预算内 header 读（`HEADER_BUDGET = 64KiB`），不是整文件；
4. 补读结果按 `(dev, ino, mtime, size)` 进缓存，同一文件只付一次代价；
5. 上限**只对超窗文件计数**，正常新鲜历史不会耗尽额度。

## 证据

| 方向 | 用例 | 变异验证 |
| --- | --- | --- |
| 冷历史可见且只付一次 | `cold_aged_header_is_filled_once_within_budget` | — |
| 超上限仍 fail-closed | `cold_history_beyond_the_fill_budget_fails_closed` | 去掉上限判断 → 该用例变红 |
| 原有预算纪律未被破坏 | 其余 58 项源回归 | — |

## 未采纳的方案与理由

| 方案 | 否决理由 |
| --- | --- |
| 维持「超窗不读」 | 旧会话子 Agent 永久不可见，功能缺口不闭合 |
| 完全移除窗口判定 | 违反「不无界解析」纪律；历史很大时首次调用耗时线性膨胀 |
| 提高窗口到 7 天/30 天 | 只是把边界推远，同样会在大历史上变慢，且没有解决「超过就永久不可见」的结构问题 |

## 已知残余

- 上限 512 是经验值：单实例历史超过 512 个**冷**会话时，需多次调用逐步推进
  （每次已读的进缓存）。当前没有对「需几轮才收敛」做度量。
- Windows 侧同一实现与同一上限，**无运行证据**。
