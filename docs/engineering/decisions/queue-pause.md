# 队列暂停裁决

## 2026-10-28 · 暂停是保护闩，不在 GET 中自动删除

- 背景：按“无 queued/无屏障”自动删除暂停行会误删并发新建的 token，且 30 秒无法证明在途任务结束。
- 决定：读取路径不删除持久暂停；无旧队列时仅隐藏暂停条；保留显式“恢复队列”和“本条先发送”。
- 后果：空暂停不再产生无意义黄条；暂停行仍可能阻止后续已入队消息自动接力。
- 状态：active。

## 2026-10-28 · 入队后必须显示“恢复后发送”

- 背景：空暂停隐藏后，新消息遇忙入队不会自动接力，用户容易误以为空闲后会自动发送。
- 决定：保留“入队后仍需用户恢复”的产品取舍；`codex_queued` 后立即重拉 send-info，显示暂停提示和恢复/先发入口。
- 后果：不自动清闩、不全局放宽旧队列；恢复后按原 FIFO 继续。
- 状态：active。
