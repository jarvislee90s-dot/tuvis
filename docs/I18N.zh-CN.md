# 国际化 (i18n)

## 用户可见错误的检查

Rust 的 `CODE: 原文` / `CODE:param: 原文` 与前端自产码，通过
`scripts/check-error-codes.mjs` 对账 `errors.*` 双语键；展示入口仍须调用
`formatInvokeError`。`pnpm check` 与 CI frontend job 均执行错误码对账和 `check:i18n`。

- Rust 扫描先按词法边界剔除纯测试 `cfg` 项：任意哈希数的原始串、嵌套块注释、生命周期、
  enum 变体和 match arm 均有隔离回归用例；可在生产目标成立的 cfg 保留。
- 前端使用项目已有 TypeScript 编译器的语法树提取字符串和模板，避免 regex/JSX/嵌套模板
  中的引号打乱扫描。两侧的带码正文与裸串跨文件对照，包含 const/helper 中的裸串。
- `UsageError::new` / `internal` 参数中的固定文案使用英文机器诊断，保留表名、路径和
  底层错误等定位参数。`usage.rpc.*` 模板继续保留 `{{err}}`，由 W-28 测试守护。
- `scripts/error-code-baseline.json` 按文件记录未迁移候选预算；新增错误请直接添加码，
  迁移后只降低相应预算。`node scripts/check-error-codes.mjs --report-pending` 可查看当前值，
  更新预算须检查差异，不能直接以输出覆盖基线。候选定义为剔除测试/日志/结构化码调用参数后，
  裸中文字符串所在行前后各三行内含错误上下文关键字；它不是运行时可达错误的精确总数。
- `pnpm test tests/lib/errorCodesGate.test.ts` 在系统临时目录运行真实 CLI，探针不写入源码树。

边界：扫描器不是全程序数据流分析；间接传入 `UsageError` 的常量/变量、动态拼接结果和
底层库错误中的中文不受 detail 字面量断言保证。`src/mobile/**` 的 UI 全量翻译、既有七处
mobile sink 的历史无码夹具仍由 #157 跟踪，门禁通过不能表述为「英文界面已经零中文」。

## 概述

本项目使用 [i18next](https://www.i18next.com/) 实现国际化，支持多语言自动检测和持久化。

## 支持的语言

- **英文** (`en`) - 默认回退语言
- **简体中文** (`zh`) - 中文

## 架构

```
src/i18n/
├── index.ts           # i18n 配置和初始化
└── locales/
    ├── en.json        # 英文翻译
    └── zh.json        # 中文翻译
```

## 配置

### 检测策略

语言按以下顺序检测：

1. **localStorage** - 之前保存的用户偏好
2. **navigator** - 浏览器/系统语言

### 关键设置

```typescript
{
  fallbackLng: "en",           // 默认语言
  interpolation: {
    escapeValue: false         // React 已经转义
  },
  detection: {
    order: ["localStorage", "navigator"],
    caches: ["localStorage"]   // 持久化用户选择
  }
}
```

## 使用方法

### 应用初始化

应用会在 `src/main.tsx` 中统一初始化 i18n：

```typescript
import "./i18n";
```

### 推荐 Hook

项目内提供了一个包装 Hook：

```typescript
import { useAppTranslation } from "@/hooks/use-app-translation";

function MyComponent() {
  const { t } = useAppTranslation();

  return <h1>{t("app.title")}</h1>;
}
```

`useAppTranslation()` 会：

- 返回 `t`
- 监听 `language-changed` 事件，保持多个 Tauri 窗口之间的语言同步

### 基础翻译

```typescript
import { useAppTranslation } from "@/hooks/use-app-translation";

function MyComponent() {
  const { t } = useAppTranslation();

  return <h1>{t("app.title")}</h1>;
}
```

### 带插值

```typescript
// 翻译文件
{
  "updater": {
    "versionAvailable": "版本 {{version}} 可用。"
  }
}

// 组件
const message = t("updater.versionAvailable", { version: "1.2.0" });
// 输出: "版本 1.2.0 可用。"
```

### 语言切换

```typescript
import { useTranslation } from "react-i18next";

function LanguageToggle() {
  const { i18n } = useTranslation();

  const toggleLanguage = () => {
    const newLang = i18n.language === "en" ? "zh" : "en";
    i18n.changeLanguage(newLang);
  };

  return <button onClick={toggleLanguage}>切换语言</button>;
}
```

只有在需要使用 `i18n.changeLanguage()` 这类方法时，才直接使用 `useTranslation()`。

## 添加新语言

### 1. 创建翻译文件

```bash
# 创建新的语言文件
touch src/i18n/locales/ja.json
```

### 2. 添加翻译

```json
{
  "app": {
    "title": "Tauriアプリテンプレート",
    "welcome": "Tauri + Reactへようこそ"
  }
}
```

### 3. 在配置中注册

```typescript
// src/i18n/index.ts
import ja from "./locales/ja.json";

i18n.use(initReactI18next).init({
  resources: {
    en: { translation: en },
    zh: { translation: zh },
    ja: { translation: ja }, // 添加新语言
  },
});
```

## 最佳实践

### 1. 命名空间组织

按功能分组相关翻译：

```json
{
  "auth": {
    "login": "...",
    "logout": "..."
  },
  "profile": {
    "edit": "...",
    "save": "..."
  }
}
```

### 2. 一致的键命名

- 使用 **camelCase** 命名键：`checkForUpdates`
- 使用 **点号** 表示嵌套：`updater.checkForUpdates`
- 保持键名描述性但简洁

### 3. 避免硬编码字符串

❌ **错误：**

```typescript
<button>检查更新</button>
```

✅ **正确：**

```typescript
<button>{t("updater.checkForUpdates")}</button>
```

### 4. 保持一致性

确保所有语言文件具有相同的结构：

```bash
# 检查缺失的键
diff <(jq -S 'keys' src/i18n/locales/en.json) \
     <(jq -S 'keys' src/i18n/locales/zh.json)
```

## 测试

### 测试翻译键是否存在

```typescript
import { renderHook } from "@testing-library/react";
import { useTranslation } from "react-i18next";

test("翻译键存在", () => {
  const { result } = renderHook(() => useTranslation());
  expect(result.current.t("app.title")).not.toBe("app.title");
});
```

## 故障排查

### 语言未切换

1. 检查 localStorage：`localStorage.getItem("i18nextLng")`
2. 清除缓存：`localStorage.removeItem("i18nextLng")`
3. 验证语言代码与语言文件名匹配

### 翻译缺失

1. 检查控制台警告
2. 验证键路径正确
3. 确保回退语言有该键

### 插值不工作

```typescript
// ❌ 错误
t("message", "value");

// ✅ 正确
t("message", { variable: "value" });
```
